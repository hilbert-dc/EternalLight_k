# Novel Codex 实际体验与优化（2026-10-02）

## 体验方式与证据边界

两个独立 AI 子代理分别承担 Codex、Cursor 产品经理分析视角；主实现者
负责生产客户端实际操作与集成。没有两家公司真实员工参与或官方背书。
本轮基于当前未提交版本增量修改，保留已有创作、授权续期和恢复改动。

主实现者启动隔离 userData 的生产 Electron main/preload 与本地 Rust
Story Runtime，实际创建测试作品、手写中文正文、保存、切页、审阅并
显式采用。两个产品角色执行隔离 React/Electron 的交互旅程与复现探针。
只读模型连接在此环境尚未验证，本轮没有真实模型推理或供应商认证。
真实作品未被修改；测试中的模型事件来自本地夹具。

## 本轮问题与实现

| 优先级 | 实際复现 | 实施 |
| --- | --- | --- |
| P1 | 第一章手写 50 字及新标题，切总览选择保存后仍显示旧标题、尚无正文、0 字；回章节候选完整存在。 | 总览从既有工作区读取候选与正式修订，预览当前章节；有正式稿时默认正式，作者可切候选；仅候选时明确未采用。加载失败不显示空正文。 |
| P1 | 写完第一章后，已有章节页只有前后切换，缺少创建第二个独立章节入口。 | 统一首章与后续章创建表单，标题带入工作稿；创建后按回执定位。未保存、未完成审阅及执行期间阻断创建。 |
| P1 | 搜索“明日”返回当前 `draft` 结果，点击只关闭结果，没有打开章节。延迟读取还可串入另一作品。 | 严格匹配 `draft-${chapterId}` 并通过现有导航门禁定位；规划类型打开对应页面。加载、错误、空结果和覆盖不足就地可见，查询变化及作品切换丢弃迟到回执。 |
| P1 | A 输入未发送构思，切 B 再回 A，两边输入均为空。 | 在当前作者会话中按作品保留草稿；发送或清空后不复活。最多 10 份、单份沿用现有字符/字节上限，容量不足阻止切作品，原文不截断、不驱逐。登出及删除作者会话清空缓存。 |
| P1 | 新建作品表单双提交，在 IPC 延迟期间调用创建两次。 | 同步提交锁保护所有提交与关闭入口，失败保留输入并可重试。 |
| P1 | 实际后端创建第二章成功，但手写保存返回 `InvalidChapter`：请求只有章节 ID，没有章号，Runtime 默认按第 1 章检查。 | 保存现有章节同时传准确的 ID 与章号；首章和第二章夹具均严格验证两者对应，实际后端第二章保存已复验成功。 |
| P2 | 模型不可用提示与输入框横向排列，窄协作栏中文字拥挤，发送禁用状态不明显。 | 提示与输入垂直排列，禁用发送与追加按钮降低强调并显示不可用指针。 |

## 实施前五维评审

按 `DESIGN_REVIEW_TEMPLATE.md` 检查；以下为 AI 分析与独立代理复核，
不是外部真人签字。

- 架构：APPROVE。总览、搜索和草稿拆独立模块，复用既有 IPC；不改
  Rust/Core、正式数据投影、模型历史、任务权限或 schema。
- 技术 A：APPROVE WITH CONDITIONS。请求绑定作品及读取身份，创建
  同步防重；成功写入但读取失败保留回执，恢复只能读取。
- 技术 B：APPROVE WITH CONDITIONS。以实际 React/App 旅程验证导航
  门禁、候选可见、第二章、防重、迟到回执及故障恢复，并审阅快照。
- 产品：APPROVE。创作内容可找回、来源可信，手写续章不要求可用模型。
- UI/UX：APPROVE WITH CONDITIONS。保留中文输入法、键盘、焦点与
  未保存保护；加载、失败、空内容和未采用分别说明。
- 零兼容：PASS。当前契约同步更新，不新增版本判断、迁移、fallback、
  双写或旧协议路径；正式和候选是当前权威状态。

## 实施后复核与验证

独立复核发现新章创建后仅确认 `getState` 不足：创作工作区异步读取失败
时可能用旧工作区初始化新章。实施调整为同时确认章节与工作区读取，
成功后才清除创建回执；失败沿既有只读恢复入口重试。

新增 `manual-author-journey-ui`、`search-experience-ui`（含实际 App
导航集成）与 `app-author-input-ui`，纳入 `npm run test:ui`。
现有 `app-domain-retry-ui` 的总览夹具同步使用候选/正式修订的实际场景
内容，避免把仅在旧章节投影中的文字当作候选修订内容。

实际客户端实施后已复验：第二章创建后自动选中；正文保存并切总览显示
“第二章：灯塔的回答”、26 字、候选 v1 未正式采用；搜索“明日”后点
合法 `draft` 结果，打开第 1 章并恢复此前 50 字正文。右栏提示与输入
已改为垂直排布。第一章正式采用和第二章候选并存，未自动采用第二章。

本轮包含已有大组件的提取、独立测试夹具及快照，审阅可按三个独立阶段
拆分：先搜索定位与异步隔离（最小、无写入依赖），再作者输入保留与
作品提交防重，最后总览来源及后续章节创建/保存。后两阶段不依赖搜索
模块；当前工作区完成全部集成，未创建提交或 PR。

最终 `npm run build` 通过；`npm run test:ui` 非更新模式 44/44 通过，
用时约 86 秒。新增与受影响界面快照已逐段检查。独立实施后复核结论
为 APPROVE，零兼容门禁 PASS；第二章章号修正另经严格夹具和实际
后端客户端验证。仓库格式化依规则在验证之后执行，不在格式化后重跑测试。

未发送草稿只在当前进程作者会话保留，不宣称退出应用后恢复。现有
工作区修订没有编辑时间投影时显示“—”，不从夹具时间推断生产支持。
构建仍有既存大包警告；本轮不以局部通过宣称全部产品或供应商验收完成。
