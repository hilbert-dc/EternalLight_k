# Novel Codex 设计评审模板

依据：[架构规则 B01–B10](../ARCHITECTURE_RULES.md)。一个连贯改动使用一份记录；五个视角不等于额外启动五个模型。设计评审不自动触发用户确认。

可在同一记录中精简填写：变更与责任边界、五视角的简短结论及依据、验证计划、实际结果与后审。无影响的项目可合并注明“不适用”及理由；涉及权限、预算、事实权威、生命周期、工具契约、模型决策或跨层依赖时，完整记录实际受影响的合同与证据。精简格式不省略前后审，也不要求为无关项另建文档。

填写路径：所有改动填写概览、责任归属、证据记录和前后审结论；状态/权限/恢复改动增加判定表；工具/传输/定位/评测改动选择专项问题。无影响项合并说明理由，同一事实或证据填写一次后引用编号。仅文档变更无需填写程序状态表或运行应用测试。

## 模块归属与跨层合同（实施前必填）

- 责任模块与适用规则编号：
- 为什么属于这一层，而不是相邻模块：
- 如涉及 Codex 官方来源代码的本地修改（B09）：上层替代方案及不足、拟改文件/符号、升级成本与移除条件；开发者审核者、明确同意的依据和批准范围。未获事前同意不得实施，自审和补丁登记不能代替批准：
- 读取/写入的事实及其唯一权威；其他层是缓存、草稿、账本还是投影：
- 如新增结构或调整准备条件：目标对象、必需原作、确定性检查、派生分析的实际使用方；哪些是必需依赖，哪些允许不构建：
- 经过的公开接口、工具schema、事件和可信身份：
- 同步调整的生产者、消费者、类型、生成资源和文档：
- 模型仍可自主选择什么；工程必须确定保证什么：
- 对权限、预算、来源版本、保存/采用/发布、恢复及UI状态的影响（无影响请说明）：
- 如涉及 UI（B08）：每个新增/调整元素的具体作者任务与必要性；对话及已有入口为何不足；重复入口如何合并/移除；是否可按需呈现；精简后如何保留真实状态、取消、必要作者动作及可访问性：
- 失败、取消、重复、未知结果与版本冲突中受影响的路径：
- 最小有意义的验证计划记入下方证据记录；需要/无需扩大回归的原因：
- 若修复真实故障：原触发/状态与失败证据、根因/责任模块、对应回归用例、受影响拒绝边界、实际应用再验计划（同根因共用用例须标明映射）：
- 若修复问题：根因分类（实现缺陷 / 设计缺陷 / 两者兼有 / 证据不足）、预期行为与现行设计/执行证据；设计本身能否满足要求，尚待验证的判断：
- 对应修复选择：按现有合理设计修正实现，或调整职责/结构/状态模型/契约；选择依据、消除根因所需的同步范围与验证。不调整结构时说明原因；若先止损，列明未解决根因与完成条件：
- 如替换实现前置：新旧条件依据、如何保持作者要求及安全/交付标准、受影响的创建/准入/读取/报告/终验/恢复同步范围、原失败与新结果的记录位置：

不能用“沿用现状”“测试都绿”代替归属判断，不能以固定关键词或固定文学流程补齐接口缺口。不同信任边界可以各自校验，但不能维护相互矛盾的事实或合同。

## 工具与评测专项检查（仅填写受影响项）

规则正文见架构规则 B04、B07、B10及第3节；普通改动无需新增基准或真实模型调用。

- 如精简工具：目录、指南与schema是否同源且符合当前可见性；省掉的内容是否涉及约束、纠错、来源或回执；受信身份由谁绑定，模型仍需提供哪些业务参数？
- 如涉及传输：是否按协议值语义核对完整字段；本地预检和远端错误的原因、可信来源、执行关联与定位经过实际 HTTP/MCP/IPC/持久化后，最终消费方是否仍能据结构化事实判断下一步？
- 如涉及定位/局部编辑：坐标单位、版本、重复匹配、覆盖与权限如何区分；续读、缓存及重试是否保留查询条件；是否复用原保存事务并覆盖过期、锁定或冲突边界？
- 如声称效率改善：对照的任务和正确性是否可比；样本、分母、源码/构建、模型配置、token口径、首次成功、纠错及全流程成本如何记录；受控与真实模型证据如何区分？
- 如新增评测/CI：阶段证据在中断后能否一致恢复并保留失败、在途或未知状态；缺失/重复样本如何判定；预算、取消、清理、阈值依据和未执行项在哪里记录？

## 测试阶段零兼容门禁

- [ ] 未新增用于历史兼容的版本判断、旧字段 fallback、双读双写、升级迁移、回填、降级或 deprecated 路径；如有，按下方明确例外记录。
- [ ] 未因为假设中的旧调用方、旧数据或旧行为降低目标架构质量。
- [ ] 接口或 schema 变化会一次性同步生产代码、类型、fixture、测试和现行文档。
- [ ] 被替代的旧实现和入口随本次改动清除，只保留当前目标合同，无临时兼容或过渡双轨。
- [ ] 如需重建，只处理明确隔离、可丢弃的测试数据；真实作者资料受到保护，未以测试阶段或减少建模为由删除。
- [ ] 当前作品修订、CAS、来源有效性、执行代次与格式校验按受影响范围保留或同步验证，不误作历史兼容删除。
- [ ] 当前版本的数据一致性、故障恢复、安全、并发与跨平台问题仍有明确验证。
- [ ] 如确有兼容代码，已附项目负责人在本次任务中的明确授权；否则评审结论必须为 `BLOCK`。

| E1 | | 前审计划 / 后审通过 / 失败 / 未执行 / 受阻 / 不适用（说明理由） | | |
