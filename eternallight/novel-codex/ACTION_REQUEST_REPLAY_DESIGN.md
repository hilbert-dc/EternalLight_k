# 对话派生动作的原始请求回放

2026-09-28 · C05/S5 · 实施者自检；未声称独立专家已参与。

## 变更概览

- 目标：同一源任务和幂等键的重试仅核对首次收到的不可变请求，返回首次动作及其最新状态；章纲或正文后来变化不能把回执读取变成重新登记。
- 非目标：不让已失效的旧动作获得新领取权限，不恢复被撤销的任务能力，不修改后继任务的来源校验。
- 模块：Rust 当前建库 schema、`task_actions` 登记事务、真实 Runtime/SQLite 测试。
- 当前版验收：首次请求仍根据当前章纲冻结目标并严格检查；同键同原始请求在章纲变化后返回原回执，不产生新 Step；同键改写操作、目标、指令或项目版本拒绝。

## 方案与不变量

在动作表保留两个不同的不可变值：`requested_target_json` 是 HTTP 已完成语法规范化、但领域尚未附加章纲信息的模型请求；`target_json` 是领域对首次请求检查并冻结后的实际执行目标。幂等重试先按源任务及 key 查询，再用前者核对请求，不重读后来章纲；首次登记才补齐和校验 `target_json`。行动领取仍读取后者，并沿原有版本、来源及能力门禁，不把回放等同于重新授权。两个目标字段不向模型暴露为可编辑数据。

原始指令和输入版本同样参与回放比较。改变任一请求字段必须使用新幂等键并经过当时的全部门禁；不能借回放更改已登记的工作范围。新的字段直接进入当前建库 schema；测试库重建，不做旧库迁移或 fallback。

## 实施者设计检查（对应五角色关注点，非独立评审）

- 架构：一个动作、一个 WorkStep；请求证据与执行目标分开，不增加调度状态机。
- 技术可靠性：同事务存储两个目标；先查幂等回执，再执行首次登记的动态校验；跨项目与 source task 仍由仓储过滤。
- 实现：只改当前 schema/事务和相应 fixture；无旧字段双读、回填或降级。
- 产品：用户调整章纲后仍能看到已登记动作原本是什么；旧动作不能自动套用新章纲。
- UX：回放结果展示原动作最新状态，不提示“已按新章纲更新”；失效领取仍保留失败说明。
