## 决策

长输入继续限制单个文本片段 9,500 UTF-8 字节，并对整个组装消息检查总预算。新增 tokenizer 依赖固定 `js-tiktoken@1.0.21`，完整消息以预算编码计数不超过 9,000 token，另设 60,000 字节限制；作者输入预留约束空间，最多 7,000 预算 token、48,000 字节、32,000 JS 字符。预算使用 o200k_base／cl100k_base 对每 256 Unicode 码点分别编码，累计后取较大值；这是有界应用估算，避免长连续 Unicode 输入导致 BPE 耗时异常，预算计数不等于 provider 精确 token 数或计费用量。9000 上限另留 1000 token 安全空间。此处显式审查超过 1K token 的新增输入，不能将多片段假称为多个独立模型消息或无限扩大上下文。

导出从当前指针读取同一数据库快照。默认仅正式正文；公开规划只含明确公开字段；完整创作简报与内部安排属于显式选择的私密资料。候选内容需单独选择，完整候选规划还须同时选择私密资料。文件包含版本和范围说明，只导出已保存内容，不改变任何创作状态。

指标只在本地保存固定枚举的聚合计数与耗时总量，不保存正文、名字、项目 ID 或精确时间戳。耗时按实际可测量行为命名；内容变化保存次数只是返工代理指标；取消任务不自动解释为作者放弃，放弃阶段由作者明确记录。设置可查看并导出匿名汇总。手动放弃另有最近 1,000 项随机回执，不含作品／人物身份且不导出；响应丢失后保留同一凭证重试。候选保存按候选头推进计数，部分采用的内部合并版本不计作者保存或返工。

## 实施后验收

实现包括三部分：共享输入预算和同轮分片；Runtime 权威快照导出及作者选择对话框；固定本地聚合指标及设置查看／导出。原始全量状态下载入口已移除，不新增兼容分支。

交叉复核中已修正：导出 IPC 的 POST 参数形状；私密事实必须保留语义和历史含义；部分采用内部派生版本不计作者保存；手动统计响应丢失后复用同一凭证。真实 Electron 界面测试等待实际焦点到达，不依赖固定 30ms 时序。

最终自动化：`npm run test:runtime` 89/89、`npm run test:agent` 69/69、`npm run test:ui` 3/3 通过。覆盖真实主进程导出／指标请求、长中文同轮交接、Unicode 预算、跨作品隔离与秘密 canary、私密事实语义及历史、部分采用计数、响应丢失后的统计幂等，以及真实 React/Electron 场景编辑、导出和统计交互。TypeScript 和 Vite production build 已通过；包含两套 tokenizer 的主包约 3.8MB（gzip 约 1.77MB），Vite 有 chunk 体积提示，不能把构建通过称为启动性能验收。已检查导出对话框实际样式截图。
