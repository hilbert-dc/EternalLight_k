## 设计形成与审阅方式

主代理核对仓库规则、当前自主创作架构及本次作者要求，承担架构整合。三个审阅代理分别承担技术 A、技术 B、产品经理与 UI/UX 两种视角的只读审阅。下列结论属于代理设计审阅，不能解释为外部专家签字或产品实现认证。

初审要求包括：单一引擎与领域权威；多媒介作用域隔离；固定素材与来源版本；远端生成的未知结果；独立漫画、独立动画与自然语言主导的界面。草稿覆盖这些要求后，进行了全文复核并修订具体问题。

## 五角色最终评审

### 架构专家

- 结论：APPROVE。
- 同一应用与模块化工程复用 Agent Engine、Creative Runtime、会话和版本机制，各媒介采用专属领域类型。
- 模型负责创作规划与判断，Runtime 负责作品事实和授权，Engine 负责外部执行与预算；不复制业务调度器。
- 独立漫画和动画是完整入口，阶段实施顺序不构成媒介之间的运行时依赖。
- 当前小说结构绑定和新增媒体缺口已明确，代码组织示意被标记为目标结构。
- 无未经授权的历史兼容层。

### 技术专家 A

- 结论：APPROVE。
- 能力证据、媒体服务与本地执行器的职责明确；没有把底层 imageInput 声明等同于产品已接通图片功能。
- 媒体请求先登记再派发；未知结果沿原操作核对，不自动换键重提或切供应商；真实素材入库后才形成可交付结果。
- 初审两项 P1 已关闭：补齐 Runtime 与 Engine 的跨库可恢复交接、唯一有效执行所有者与代次；补齐提交中取消及迟到作业 ID 的对账要求。
- 第 17 节增加对应崩溃、撤权、重复确认和取消测试要求。
- 没有把当前版本恢复与安全问题误写为旧格式兼容。

### 技术专家 B

- 结论：APPROVE。
- Project、CanonSpace、Edition、Branch、内容修订、素材修订和来源引用的责任清楚，知识与工作基线按作用域隔离。
- 独立作品从空环境初始化，不创建虚拟小说或改编关系。
- 初审两项必要澄清已落实：读取依赖区分 pinned 与 mustBeCurrent；导入租约保护临时文件及已归档待提交 Blob，垃圾回收与备份协调。
- 固定来源的分支头前移不使历史版本自动失效；目标版本、当前授权和执行代次仍须核对。
- 修订文档适用顺序，明确系统约束与作者当前要求，并按工程规则落实。
- 无双轨、fallback 或半迁移目标。

### 产品经理

- 结论：APPROVE。
- 小说、漫画、动画拥有平等入口，独立漫画与独立动画不依赖其他媒介产物。
- 原创、改编、局部修改、失败恢复和导出分别有完整用户旅程。
- 区分漫画脚本、分镜预览、完整漫画、动画成片、可编辑动画项目和专业分层工程，不以单图或片段替代完整交付。
- M0 与 M1 先证明共同纵向链路，后续阶段分别交付各媒介能力；创建入口只在对应能力通过验收后对用户开放。

### UI 与 UX 设计师

- 结论：APPROVE。
- 保留统一自然语言输入、附件、精确选区与自由回答；没有新建讨论模式、关键词路由或逐条消息的媒介模式选择。
- 当前媒介编辑器承载作品，时间轴和对象操作按需出现；成果在原对话内预览和打开。
- 不重复增加底部执行详情、继续任务或继续讨论入口。
- 草稿、附件、缩放、播放位置、失败恢复、键盘、辅助技术、窄屏与深浅主题均有验收要求。
