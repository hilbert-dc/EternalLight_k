# 对话与执行过程体验优化

日期：2026-10-02。接续 `../docs/designs/PRODUCT_EXPERIENCE_FIVE_ROUNDS_2026_10_02.md` 和 `../docs/designs/KNOWLEDGE_OUTPUT_ROOT_CAUSE_2026_10_02.md`。

## 目标与边界

以作者实际阅读、判断和继续创作为目标：作者指令 → 公开执行进度 → 最终回复。Codex、Cursor 产品经理角色由产品视角代理承担，非厂商官方人员；真实产品操作由根代理统一执行，避免共享桌面冲突。

本阶段不改变章节发布、故事设定确认的权限和证据契约。原始模型历史不重写，不截断 opaque，不新增旧接口 fallback、schema 迁移或双轨。当前接口 `renderCurrent({taskBound})` 及历史渲染一次同步组件、类型和夹具。无数据库 schema 变更，保留已有体验作品。

10K token 以上限保留；允许大于 1K 的既有完整输出条目的边界变更按 P0 额外人工式代理复审，必须以原样多轮记录和真超限拒绝测试通过为条件。

## 实际变更

- `ConversationTimeline.tsx` 独立维护当前回合展开状态。默认展示实际工具/公开 commentary，未知活动为“正在处理”；真实 reasoning 仅为“正在分析”标记，不显示原文。
- `WorkTaskPanel` 以权威 task.goal 显示唯一作者指令，内部执行 prompt 不再作为第二条作者消息。真实 threadId + turnId 合并；创作流程默认收起，保留恢复、暂停、取消和未保存修改保护。
- 相同的当前回合主错误不重复显示，不同错误证据保留。调用进度在最终回复前。停止把未完成步骤标为“已停止”，保留已完成工具证据，迟到事件不能复活终止回合。
- 历史展示投影去掉 reasoning 与 opaque，仍保留公开 commentary/final；原始 Codex rollout/context 不变。
- `useConversationReading.ts` 唯一控制外层滚动：底部跟随、上翻阅读、加载旧记录保留锚点、返回最新。API/作品隔离缓存最多 16 个作品、128 个外层展开状态。工具内部详情跨页记忆不在本阶段承诺中。
- 修复真实回归：空作品第一条记录的短“读取中”占位会将期望 scrollTop 压成零；现在未达到目标时保留期望锚点，长回复加载后再恢复。
- 实机发现真实 App 的全局 CSS 晚加载覆盖新摘要 grid，导致标题隐藏、耗时竖排；增加属性选择器优先级，同时固定步骤区域不产生第二层滚动。夹具使用实际全局 CSS 晚加载复验。
- 全文流式回复移除 aria-live，只保留独立简短状态。公开进度和最终报告默认要求简明中文，不重复整章和内部 ID；结构化工具 JSON/回执核验仍保持完整。

## 输出门禁证据

既有字节代理把超过 40,000B 的条目直接视为超 10K tokens。实测 alphabet 重复条目为 52,000B、2,645 conservative tokens，属于误拒。

修复为：10KB 快速安全路径不变；10KB–256KiB 对完整条目按既有双 encoder 保守计数，仍须 ≤10K tokens；超过 256KiB 单独拒绝为字节资源上限。输入、非流式输出、added/done/terminal 的完整输出使用相同规则。拒绝统计只包含类型/匿名字节与计数，不记录正文、推理或 opaque 值。

真实 Codex + 本地桥接三请求集成验证：首次真超限拒绝、不自动重试、无成功终止/坏历史；第二请求保存 52KB reasoning 与 opaque；第三请求输入保留原样条目。rollout 自身的 turn metadata 也按实际完整对象检查。修正原先用低 token 重复 ASCII 伪装超限的测试数据为真实 >10K tokens。

历史三次超限输出的具体条目类型仍未知，本次不能据此断言其全部原因；10K 上限仍存在。未修改提供方声明的输出 token 设置。

全部界面回归：56/56 PASS；最终晚加载全局样式定向复验：1/1 PASS。浅色、深色实机下回复和状态均可辨认，章节编辑页仍是 351 字、作品 v5。

重启后真实中文进度已出现，按正文检查说明执行过程。第二轮点击停止发现新问题：IPC 包装的取消拒绝先到，被误判为失败；随后停止回执因已终结状态而未能修正。第三轮新指令正常完成，6 秒、3 个步骤，80 字内中文解释空信封警告与钥匙动作没有冲突。只读数据库核对作品版本仍为 v5。

## 实机发现后的最小补修 PRE

架构专家与技术专家 B、产品/UX 同意当前协议最小方案，不改 IPC/schema：同一 scope/project/thread/turn 的停止票据处理返回顺序，权威停止回执与当前精确取消信号共同判断，真实其他错误和停止失败保留；未决票据必须结束，不串到新回合。

另一个根因是被取消的当前领域尝试没有持久 turnId，成功任务才在最终回复阶段绑定，不能仅靠现有 thread/turn 合并。使用当前 host `agent/workflow.task.id` 的真实尝试身份关联，加 thread 校验；双方 turn 都存在时仍必须相等。不靠提示词，不只靠 thread，不回填历史，也不为旧接口增加路径。

停止与身份补修已验证：最终冻结版 Electron 4/4 PASS（包含 8 次请求、7 次停止的回执竞态、双击、旧回执、真实错误和停止未成功后再停，以及取消生成后作者正文保留）；对话、身份、阅读位置与公开事件 29/29 PASS；TypeScript + Vite PASS。

实机第四轮使用真实 DeepSeek，只读检查两章连贯性。16 秒、9 个公开步骤后停止：唯一作者指令、正确“已取消 / 已停止”、无 IPC 误失败，已完成读取和检索保留。第五轮在 6 秒、3 个步骤后完成中文悬念解释，无内部 ID。第一章仍 351 字、已发布 v2；只读数据库核对该作品仍 v5。

## 历史过程连续性补修 PRE

第五轮又暴露展示缺口：开始下一轮时 `AgentRunSummary` 只保留文本，上一轮执行步骤不可再展开。架构、技术 B 与产品/UX 条件批准只改 renderer：公开步骤的有界快照、真实终态与耗时，历史同级复用 Timeline；不保存原始 reasoning，不修改模型历史、IPC 或 Runtime schema。历史过程置于作者指令之后，不藏进业务创作流程；主回复仍按同一真实尝试去重。

新增过程快照最多最近 10 轮、每轮 96 步 / 24KiB，单项标题 160 字、公开文字 512 字、细节 1024 字，超限明确提示。较旧指令与回复保留；重启读取没有完整调用证据时不伪造恢复。不承诺恢复全部实时工具内部详情。另同步“继续分析本章”的 typed 停止通知，避免该入口把正常停止显示成错误。

最终冻结版定向回归 50/50 PASS，包含真 App 停止竞态、旧停止步骤在新轮仍存在、历史快照容量与隐私、同级呈现与精确主回复去重、阅读位置与公开 handoff；TypeScript + Vite PASS。

实机追加验收：真实 DeepSeek 执行 25 秒、7 步后主动停止，只有一条作者指令；展开可查看已完成“读取故事上下文”和已停止重试。下一轮 6 秒、4 步正常完成中文回复。旧轮仍保留 25 秒耗时、7 步和展开状态，与新回复同处对话正文；不再出现重复主回复读取。收起旧过程、点击“回到最新”后按钮消失、恢复跟随。第一章仍 351 字、已发布 v2；未改正文或设定。

## 普通对话表达规则统一

实机又确认普通 `advisoryPrompt` 未引用写作任务的作者报告规范。将既有规范提为固定 882 字节的 `AUTHOR_CONVERSATION_INSTRUCTIONS`，普通对话与写作任务共同引用。只影响新请求，保留工具身份、完整 JSON、证据回执与权限。`node --check`、handoff 13/13 和构建 PASS。

最后真实只读阅读 23 秒、11 步完成，最终中文说明第一章悬念清楚、阅读范围仅第一章。模型仍出现英文公开进度，故不能宣称提示词已保证所有进度为中文；保留原文以避免伪造执行记录。此为剩余表达一致性问题，非执行、保存或历史归属故障。

## 语言一致性修复（续轮）

根因：原先语言要求只在普通用户请求中，基础 Codex 模板含英文进度示例，追加指令未共用语言契约。英文示例不是强制英文输出；不能把模型遵循不足归咎为上游禁止中文。当前产品将固定语言规则写入 supported developer_instructions 配置，并在中央 compose 与追加指令中共用；只读子代理使用相同规则。上游 baseInstructions 不改写。

默认公开进度、问题、解释和最终回复用简体中文。作者明确要求另一种讨论语言时，从模型收到要求后的后续输出一致切换，旧记录保留原文。英文正文、引文、名称、搜索词和工具输出不自动改变对话语言。工具名称、JSON、ID、schema、代码、引用和 opaque 原值保留；没有渲染器强行翻译或隐藏英文。

新增开发者片段受 4KiB / 1K conservative token 双边界约束。生产配置与三处资格 runner 一致透传父子规则，资格 digest 同时包含父规则与完整子规则 hash，规则变化使旧证据失效。实机通过正常设置重新验证并应用真实 DeepSeek · deepseek-flash。

验证：engine Rust 54/54、语言/config/handoff Node 46/46、engine contract/MCP 27/27、TypeScript/Vite PASS。Node 22 下真实 Codex CLI（本地合成 provider）新线程、恢复、活动 steer 三次请求 1/1 PASS：developer 规则恰一次，base 字节不变，原 reasoning/opaque 整对象保持，作者中文原文保留，steer 位于同一 thread/turn。此 CLI 测试只证明协议，不冒充真实模型遵循结果。

实机语言结果：默认中文讨论 10秒/5步，中文公开进度与最终解释；明确英文讨论 9秒/5步，英文公开进度与最终解释，引用中文正文不翻译；活动检查追加英文要求后 28秒/10步最终英文确认，先前中文进度保持原文。原测试作品第一章仍已发布 v2、351字。

新独立作品《语言一致性体验：灯塔来信》空章中文写作的公开进度始终中文，但首轮 119秒/24步未保存，最后服务流断开，无最终答复。只读核对六次保存公开回执：空 payload 为 TaskBindingInvalid，三次字符串 "null" 为 TaskInputStale，两次场景缺 id 为 TaskOutputForbidden；六条 Host 恢复绑定接受不等于正文已保存。任务/作者身份、输出对象和冻结 CAS 均正确。这揭示保存工具 payload 只有 object 加一句描述，模型反复猜结构。首轮不计为写作成功。

保存契约补修 PRE：架构、技术 A/B、产品和 UX 同意只明确当前 MCP Draft schema、调用前结构检查及 handoff。保留合法省略 sceneGroups 的路径、原元数据、绑定/CAS/保护；不把字符串 null 转型，不修改 Runtime / Author 创建行为，不自动发布或重试绕过校验。实际后续保存复验待补齐。

## 语言与保存契约的实机反例及补修

保存 schema 与发送前验证补修后，真实模型在 12 秒 / 8 步保存第一章 163 字中文正文，三条公开进度与最终报告均为中文，后续知识分析也保持中文。再要求英文正文时，实际保存约 97 词 / 520 字符版本，但首条公开进度为英文；不能把这轮语言判为通过。失败与英文进度保留原文。

第一版固定 developer 规则已实际进入模型请求，因此根因包括模型没有稳定遵守英文表述的语言边界，不能声称配置缺失。经五角色 PRE，改成中文固定规则加两条短进度示例。正常重新认证后，默认阅读英文正文 10 秒 / 4 步中文进度与最终解释；明确英文讨论 6 秒 / 4 步英文进度与解释；活动追加切换在 28 秒 / 19 步任务中出现新的英文 Next / Step four 进度与英文最终回复，早先中文保持原文。一次追加点击前任务已结束，没有发送成功，不计为活动 steer 验收。

另一真实反例：空白第二章只要求“写约 150 字”，模型沿用前章英文生成约 150 词。公开说明全中文、正文确实保存，但正文语言和单位判断未通过。其后续知识分析以 provider_output_limit 未完成；界面如实保留“需处理 / 已保存部分产物”，不能算全流程成功。经五角色 PRE，固定规则补充新章首次起草默认中文、不从前章推断新章语言、保留作者“字 / 词”单位；既有英文修订无换语言要求时保持英文，明确全书或本轮语言要求优先。

最终固定规则 1490 字节 / 506 conservative tokens，完整只读子代理规则 1714 字节 / 549 tokens，均低于 4KiB / 1K 双限。更新后 46 定向 Node 与真实 CLI wire 1/1 再次通过；资格证据随根/子规则 hash 失效，经正常设置重新认证。真实 CLI 的本地合成 provider 仅证明传递及历史保留，不计真实模型遵循。

MCP scoped Rust 16/16、native engine 54/54、engine contract 27/27、TypeScript/Vite、实际 native engine 与 Story Runtime 构建通过。MCP 测试通过真实 RuntimeClient 调用及本地 HTTP 证据，证明缺字段/缺组 ID/重复 ID 在发送前拒绝、合法纯正文/空组/元数据透传、CAS null/string 原样及 409 原样；不冒充生产 Runtime 落盘证明。实际落盘由上述实机正文与回执证实。加入 pretty_assertions dev dependency 后仓库 bazel-lock-update 通过，MODULE 锁无漂移。

## 作者可见对话标题独立小阶段 PRE

实机另发现命名完成前侧栏短暂显示“Novel Codex 专用工作约束 / Novel Workflow”。根因是 title 优先使用上游 raw preview，而 preview 正是模型 wire 首条 user 输入的摘要，包含固定内部约束；异步 name 通知尚未到达。五角色批准统一作者标题来源：有效 name、精确当前作品/对话的原作者指令、默认“创作对话”。侧栏、历史、详情、ARIA 与恢复提示同步移除 raw preview 默认展示，原协议字段及模型历史保留，不自动改名、不伪造作者记录。此阶段独立验收，不替代语言实机五场景。
