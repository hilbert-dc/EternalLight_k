## 受影响状态

| 事实与来源 | 动作与副作用 | 恢复 |
| --- | --- | --- |
| 原执行、原问题、合法回答 | Native 保存作者原答及模型问题上下文，Core 回传，再登记投递回执 | 后继任务读取同一作者来源 |
| 同一问题重复提交同一答案 | 核对原记录，幂等继续，不再次追加要求 | 不重复发给已回答的 Core 请求 |
| 同一问题改答、跨执行、暂停或取消 | 拒绝或保持待核对，不向另一执行投递 | 通过原 Work 明确处理 |
| Native 保存失败 | 不回传 Core，不删除待答问题 | 原问题可重试 |
| Core 写入失败或投递回执未知 | 保留持久回答和未确认状态，不伪装完成 | 核对原身份，未知不能盲目重发 |
| 来源更新而下游固定旧版 | 返回变化候选，不直接修改下游 | 模型比较原来源、新来源和现作品 |

## 实施中补充评审

回答使用独立的 `/tasks/{id}/answers` 作者入口，Native 意图账本增加 `recorded` 状态：事实已保存且可由当前来源读取，Core 回传未确认。delivered 记录 Host 已完成传输写入和领域登记，不单独证明模型已理解答案；原追加 steer 的 `pending` 语义不变。后继任务可继承 recorded 原答，不能将其显示为原 Core 已消费；晚到投递仅改回执，不恢复 Work。状态字段与建库、来源读取、消息展示、Host 和测试同步修改；只在隔离新库验证，无历史迁移。

媒体沿用来源关联，新增可选 purpose 与 decision，供模型读取和作者查看改编依据；明确是模型说明，不是作者采用。任务内 `read_media_workspace(section=sourceImpacts)` 比较冻结引用，不返回尚未授予的新文本，不授予下游改写。

五视角补审：架构/产品 APPROVE；两项技术和 UI APPROVE WITH CONDITIONS，条件为新增记录的来源读取、取消后晚到回执、媒体任务隔离及界面投影验证。修改不增加权限、预算或采用能力。

## 实际完成范围

1. 主 agent 常驻职责加入准备深度、关键未知、明确委托、规划结束条件、按需重规划和跨媒介交付层次；同步普通对话、章节按钮、媒体对话和工作方法。复用现有 brief/outline/plan 精确绑定，不引入固定全书步骤或新调度器。
2. Engine 生成配置开启 Default 模式可选提问。真实 Core 供应商出站测试确认工具可见，指令跨恢复保持；专用写作/审阅任务和子会话不直接向作者索要决定，返回主会话整合。
3. Host 验证原执行、任务、线程和轮次，先经作者接口持久保存，再回传 Core，再登记交付。Native 新增 recorded 状态，原回答即使尚未回传也可从作者来源读取；原 steer 的 pending 语义不变。重复问题不会重复发给 Core，迟到回执不会删除新问题、恢复取消或增加预算。
4. 作者历史展示问题与原答，领域证据保留原始绑定；内部传输字段不进入正常作者消息显示。
5. 媒体来源关联可保存用途与模型改编说明，作者来源面板显示这些依据，保持与作者采用分离。现有多对多关联、修订校验、锁定与局部补丁不变。
6. `read_media_workspace(section=sourceImpacts,version=source)` 在真实任务能力内比较冻结引用与当前来源，只返回变化候选，不回传未授予新版本的正文、不自动更新作品。Author 来源界面继续保留其公开读取能力。

## 继续实施前审：跨版本组合来源

当前新建版本界面只接收当前媒体选区，小说章节与其他版本无法同时选入。新增作者来源目录，按 Edition 主分支的已保存快照分页返回精确引用；后续页固定同一快照，拒绝其他分支/项目快照。Native 是引用和快照唯一权威，Runtime 暴露作者只读接口，Host 校验形状，Renderer 选择来源并沿用现有 createEdition 事务与幂等回执。引用只固定阅读来源，不授权执行、采用或发布；不新增调度器，不把引用图当生产依赖 DAG。

界面允许选择多个版本的已保存对象，保留当前选区快捷入口；选定引用不会随刷新升级。创建结果未知时锁住提交参数，重试同一请求，避免改动表单后重复创建。未保存内容不进入目录。此切片不新增电影或自动跨版本派发能力。

五视角同一执行者前审：架构 APPROVE（沿现有领域边界）；技术 A/B APPROVE WITH CONDITIONS（快照归属、分页稳定、实际创建与回读、未知回执重试）；产品 APPROVE（直接与组合来源可实际操作）；UI APPROVE WITH CONDITIONS（来源选择错误可重试、旧版明确、关闭/重开不误报创建失败）。验证覆盖 Native、HTTP 作者/候选隔离、Host 契约、真实组件和构建门禁。

## 第二轮实际完成与验证（2026-10-12）

### 跨版本组合改编来源

作者新建漫画/动画版本时，可从同项目小说的已保存章节、简报、大纲、近章规划和媒体版本中组合来源，也保留当前媒体选区快捷入口。支持直接小说→漫画、小说→动画及小说剧情+漫画内容→动画的**来源选择与版本创建**；创建空版本不证明改编内容或素材已经生成。

Native `media_source_catalog` 从现有不可变快照读取有界目录；续页必须提供同一 snapshotId，核对 Edition 主分支祖先归属，拒绝跨项目/分支。没有建立第二份来源事实或修改存储 schema。公开链路：作者 HTTP `/editions/{edition_id}/source-catalog` → Host `media:source-catalog` → preload `sourceCatalog` → 新建界面。候选任务不能借此读取未获准来源；实际创作仍通过原冻结来源合同读取。

组合选择最多 100 处，精确引用保留当前所选版本。字段顺序不作为 HTTP 身份判断；数组顺序与所有字段值保留。当前对话框内创建结果未知时固定原参数与幂等键，成功创建但打开失败时只重试打开。关闭对话框或应用重启后的创建请求自动恢复尚未新增；界面提示先核对版本列表，不能把本轮恢复范围宣称为持久恢复。
