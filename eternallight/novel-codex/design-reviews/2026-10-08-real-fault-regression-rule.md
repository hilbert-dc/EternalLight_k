# 真实故障的职责纠正与回归规则

## 实施前

用户要求将“修正职责混淆，为每个真实故障补回归验证”落实为工程要求。本次只补充既有架构规则 B10 与设计评审模板，不新增运行时指令、工具、审批、文学流程或测试平台。唯一规则正文仍为 `../ARCHITECTURE_RULES.md`，两个现有 AGENTS 已指向它；模板要求提供对应证据，不复制另一套规则。

每个确认的真实故障应保留触发输入/状态、实际结果、根因和责任层，针对同一公开合同补最小有意义的回归。相同根因的多个现象可共用测试，但要明确映射。权限、来源、预算和恢复修复还须覆盖受影响拒绝边界。应用故障在合同通过后仍须应用入口再验；没重跑或没交付就不能宣布闭环。不得把测试数量、无关绿色或清除失败记录当证据，也不要求所有修复调用付费模型。

| 视角 | 前审结论 | 条件 |
| --- | --- | --- |
| 架构 | APPROVE | 补 B10 工程验收义务，不改变各层职责或引入第二事实权威。 |
| 技术 A | APPROVE | 回归覆盖实际失败与受影响拒绝边界，保护未知结果、授权和预算。 |
| 技术 B | APPROVE | 用当前源码/构建与真实合同验证；相同根因可合理共用用例，不机械每个报错加一文件。 |
| 产品 | APPROVE | 完成以实际交付为准，明确未验证部分，不继续堆新功能。 |
| UI/UX | APPROVE | 不让作者填写调试信息或补指令推进工程纠错。 |

实施范围：B10新增一段，模板增加对应记录栏。零兼容 PASS，无迁移、回填、默认授权或新的用户确认。

## 实施后

已在唯一规则正文 B10 加入真实触发、责任根因、职责修正、对应回归和应用再验的完整要求；既有设计评审模板同步增加实施前/后故障证据字段。原 AGENTS 引用路径有效，未新增另一套规则、运行时行为、用户审批或固定创作流程。

五视角后审均 APPROVE：职责仍由原模块承担；回归按实际合同和影响范围选择；保留拒绝边界、失败记录及源码身份；实际应用再验未完成时禁止冒称闭环；作者不承担内部恢复编排。零兼容 PASS。

当前来源引用故障已有真实 Runtime 5项合同及生产目录证据；恢复故障对应 `recorded_saved_checkpoint_facts_survive_work_stops_without_granting_read_authority` 和既有真实 planning report 状态用例，另复验 Runtime 原预算/未知写/外部修改拒绝。具体测试实际结果、冻结身份和应用再验仍登记在主实施文档及 [资料事实与读取权限评审](2026-10-08-workspace-dependency-facts.md)，不以本规则已写入代替这些验证。
