# Codex 官方补丁上移

## 范围与授权

开发者本次明确要求将当前工程对 Codex 官方源码的修改迁移到上层。本次授权用于迁移和撤回既有补丁，不授权新增官方实现补丁。官方基线为已合入的 `upstream/main`：`12cca49c81c8aa6a37a5cc4e39964ee3b70f9458`；不是本地 HEAD，也不在迁移中混入新的上游更新。

迁移前相对基线有 26 个文件、5 组登记补丁。完整差异与未提交差异已分别备份到 `.release/core-upper-migration/original-core.patch`、`original-uncommitted-core.patch`。不覆盖其他任务的产品改动，不操作作品数据，不产生付费模型请求。

## 根因与目标

两者兼有：部分适配逻辑放进官方内核属于职责设计问题；身份和同一步恢复则存在真实公开接口能力差异，不能通过删校验、伪造身份或重发作者请求来消除差异。目标是官方源码无产品补丁，上层负责策略、协议适配和可信执行关联，仍保持来源、权限、取消、保存及累计账本。

| 补丁 | 上层归属与替代 | 撤回条件 |
| --- | --- | --- |
| unique-state-migration-identities | 产品构建前的迁移版本检查 | 重复编号和独立数据库测试通过；构建入口仍强制调用 |
| bridge-wire-context-compaction | Engine 将本地容量拒绝编码为官方 Responses `response.failed/context_length_exceeded` | 流式/非流式错误、未派发零预留、容量诊断保留的合同通过 |
| bounded-hard-context-recovery | Host 在轮次边界调用官方压缩；容量拒绝后通过空输入轮次接续 | 明示新的 Core 轮次；不重发作者输入或工具调用；同一操作、线程、租约和预算，一次恢复仍失败则终止 |
| trusted-mcp-agent-lineage | Engine/Host 受信请求、线程谱系和工具调用关联 | 父子权限、执行角色、批次及重放拒绝通过；不能由模型参数提供身份 |
| lossless-mcp-input-schema | 工具权威定义经 Engine 在供应商边界精确传输并在执行端校验 | 真实目录到供应商 schema 等值；未知、越权或漂移拒绝；不能接受静默删约束 |

## 五视角前审（本代理自审）

- 架构：同意逐组上移，官方执行循环不扩展产品行为。
- 技术一：官方基线固定；先备份再精确撤回，不能用 HEAD 覆盖已提交补丁。
- 技术二：身份/schema/恢复须具备真实链路证据；未完成替代前保留原补丁并明确状态。

- UI/UX：不新增作者技术参数，不将内部迁移状态伪装成任务完成。

## 实施与验证

已迁移并撤回前三组补丁；剩余两组仍登记，未宣称全量完成。官方源码差异从 26 个文件降为 16 个文件。已撤回的 10 个文件与固定官方基线逐字一致。

### 已实施

- 迁移版本重复检查继续由 `scripts/verify-migration-identities.mjs` 负责，`build-codex-runtime.mjs` 在构建前强制调用；删除官方 state 测试文件中的产品断言。
- Engine 容量拒绝在流式请求中发送官方 `response.failed/context_length_exceeded`。非流式仍返回 HTTP 400，账本与诊断继续保留 `context_input_budget_exceeded`、容量明细及未派发事实。删除官方 API 错误映射补丁。
- Host 维护策略读取官方最近一次上下文用量通知，不把累计计费 token 当作当前上下文。仅有下一轮请求时才调用 `thread/compact/start`，完成前不发送待处理输入；失败或取消不继续。未获得可用通知时不猜测用量，官方原有容量压缩仍生效。该调度提示为进程内状态，不是新的持久账本；全新 Host 进程尚无用量通知时，不保证立即触发可选维护。
- 上层仅对匹配 Core 终止事件中的结构化 `contextWindowExceeded` 执行一次压缩和空输入接续。新 Core 轮次及原失败记录保留，原线程、Host 操作、执行租约和预算不变；不重新发送作者输入、工具输出或工具调用。二次容量拒绝、压缩失败、取消、租约撤销均不再自动尝试。普通错误文字不能触发该路径。
- 自定义 `model_context_maintenance_token_target` 配置及 Core 执行循环改动已撤回，生产配置不再输出它。子代理内部轮次继续使用官方原有上下文管理；Host 不假装接管不可见的内部采样循环。
- Fork 门禁核对有效工作树相对官方基线的差异，同时检查未跟踪文件；已精确恢复的历史补丁路径不再被误报。根目录 `AGENTS.md` 为唯一新增的精确文档入口例外，未放宽其他上游路径。剩余补丁先核对与迁移前备份完全相同，再将登记摘要与当前官方基线对齐；未更改其行为。

### 剩余两组的上层实现边界

不能将官方元数据中的 `subagent_kind` 当成执行角色；它只表示子代理种类。角色须由官方 `thread/read` 的 `agentRole` 等受信线程事实核对。不能用模型参数、任意工具参数里的 threadId 或“最近一次请求”猜测归属。

下一阶段需要 Engine 管理的 MCP 适配合同：在模型工具事件发给 Core 前，按执行租约、真实 thread/turn、采样请求、callId、工具名和参数摘要登记关联；MCP 仅以官方已有的受信调用 ID 查询，交叉核对 Host 获取的线程角色和父子关系，缺失或冲突拒绝。应验证并行批次、跨线程/跨租约重放、取消、角色越权和重启后的未知调用，之后才能撤回身份补丁。

schema 则须从实际 MCP 当前操作的目录取得原始声明，在 Engine 供应商编码前按精确工具身份恢复，只恢复当前已允许/已加载工具，不增加可调用工具。目录版本变化须使旧关联失效；验证目录、实际出站 schema 和执行端校验一致，不能以删约束、静默简化或仅复制静态目录代替。当前不同 operation 的 schema 确有差别，不能用一份全量静态目录覆盖。

## 剩余两组迁移实施（2026-10-13）

已将两组替代实现放到上层，并将剩余 16 个官方来源文件精确恢复到固定基线；`upstream-patches.json` 为空，严格 Fork 门禁通过。当前 `codex-rs` 相对基线零差异。原补丁另备份为 `.release/core-upper-migration/remaining-before-removal.patch`。这覆盖源码迁移，不代表已发布或已安装应用验收。

- MCP 使用实际操作目录向 Engine 的认证回环端点注册原始 schema；按任务能力摘要隔离，目录在该范围内不可漂移。Engine 只恢复 Core 当前传来的工具声明，在发现、输入容量计算和供应商编码前恢复；不增加工具、扩大可见性或改变描述。
- Host 经官方 `thread/read` 查询执行角色；Core 请求头提供线程、父线程、会话和轮次。Engine 在经校验的模型工具调用交给 Core 前，记录租约、epoch、采样请求、工具、callId、参数摘要和目录摘要。MCP 仅用官方现有 threadId/sessionId/callId 查询，并交叉核对参数及目录，之后将 Engine 给出的身份交原 Native 权限校验。模型 `_meta` 内自称的角色、批次或根线程不产生权限。
- 跨线程、跨会话、跨范围、目录漂移、参数变化、租约变化、无调用记录均拒绝；租约重建清空调用记录。相同已登记调用的查询是幂等查询，不是新的写入许可，领域写入仍由原 Native 幂等与版本合同保证。取消后租约撤销使查询不可继续。
- Engine 关联只存通用摘要和身份，不保存正文，不建立第二个作品/费用账本，不发起额外模型请求。当前产品使用直接 MCP 工具；代码模式内部调用若没有已准入模型调用关联则拒绝，不推测归属。
- 测试改走公开 Engine/MCP 协议，删除依赖定制官方 `schema_wire` 示例的验收入口；复杂约束、错误纠正和调用身份分别有实际传输证据。测试中的旧保存回执补上当前必需 completeness 字段，生产验证未放宽。
