# 工具可靠性、编辑锚点与效率验收

2026-10-10；用户授权全部落实四项后续工作。承接工具契约评审，并纠正上一轮把六项修复入口失败统称 fixture 的不充分判断。

## 前审与责任边界

- Host 修复目标按结构比较，覆盖 JSON 往返后的 messageDispatch；测试按当前每对话执行域和持久控制修订建立数据。沿真实 Host 入口验证同对话阻止并发、不同对话不互相阻塞、暂停恢复保留原预算与来源。
- 构建身份严格保留。通过既有构建/来源脚本生成真实身份并更新开发支持记录，运行八项此前未执行的 Core 纠错测试；诊断区分平台无记录、二进制哈希、身份文件、源码摘要和版本，不打印凭据。
- Runtime 保留领域拒绝的稳定原因、阶段与字段定位；MCP 传递原错误，不把能力解析失败压成普通文本。领域身份、版本、范围继续由 Story Core 决定，结构化说明不赋予重试或新授权。
- Story Core 的授权来源解析页为正文片段附带 chapterId/sourceRevisionId/groupId/Unicode scalar 范围；只引用已授权、不可变原文，锁定和未知来源不变成可写。现有 patch 消费该锚点，原文、CAS、范围验证不减弱。原始 JSON 视图与目录不增加阅读证明。
- 新增可复现工具效率评测：真实生产工具、真实 Runtime/MCP，在隔离作品上记录首次调用结果、纠错次数、请求体 token、provider 实报用量（没有即 null）与延迟。明确区分受控模型、分词测量和真实 provider 证据；不得用虚构用量或固定响应证明真实模型改善。评测不是生产的第二 agent loop。

| 状态 | 行为与事实权威 |
| --- | --- |
| 内容相同的 JSON target | Host 接受；任一目标字段变化拒绝 |
| 同对话并发 / 不同对话并发 | 同域拒绝；不同域按既有资源限额执行 |
| 缺少或过期控制修订 | 拒绝，不猜版本、不扩大恢复范围 |
| 构建记录不符 | 分阶段拒绝；仅真实重建和核验后更新开发记录 |
| 版本/CAS/锚点或范围错误 | 结构化拒绝；既有保存及账本权威不变 |
| 来源正文片段 | 返回准确不可变定位；不自动选择文学改法 |
| 评测未取得 provider usage | null/unknown；不得当作零消耗或估算实报 |

五视角前审：架构 APPROVE（B01–B10，无 Core 修改/新循环）；技术 A APPROVE WITH CONDITIONS（跨 JSON 身份、版本和 Unicode 反例）；技术 B APPROVE WITH CONDITIONS（失败全部复验、度量可重跑且分类）；产品 APPROVE（减少技术纠错，不替作者决定）；UI/UX APPROVE（正常流程不增加技术步骤，诊断按需可见）。零兼容：直接同步当前协议和 fixture，不添加旧字段 fallback。

## 验证与后审

四项已实施；既有其他任务的媒体、编辑器、章节历史变更保留。未操作真实作品，未调用外部付费模型，未修改通用 Codex Core。

### 原失败的根因与修复

1. 修复入口确实存在生产缺陷：`messageDispatch` 是嵌套对象，原比较使用引用相等，经过 JSON 运输即误拒绝。现在按 JSON 值做深比较，跨 VM 原型差异也不影响协议判断；messageId/sessionId/revision 任一变化仍拒绝。不能再把原六个失败笼统归因于 fixture。
2. 生命周期测试另有过时假设：全局并发锁已改为每对话执行域，旧钩子监听不到实际 adapter，暂停 fixture 缺失持久对话和控制修订。测试已沿生产 Host 入口验证同对话并发拒绝、不同对话独立执行、冻结来源不变和原预算恢复。
3. 原八项知识纠错曾被构建身份门禁阻断。本轮现有开发二进制、身份与源码摘要已经一致，严格核验通过，故不重复重建或更新支持记录。真正进入工具链后发现 fixture 未实现恢复账本查询，导致空请求体解析失败；现按 GET 协议返回无账本记录，不伪造写入证明。八项均实际执行并通过。

### 契约与反例

- Host 构建诊断区分平台未登记、二进制哈希、身份文件/标识/平台、未签名来源、版本与源码摘要；未授权构建仍拒绝。
- Runtime 对项目/候选版本、任务绑定、范围、锁定、幂等和任务状态返回稳定诊断。真实 HTTP 断言覆盖版本/CAS 字段定位；错误 oldText 定位到 `/patch/edits/0/oldText`。MCP 真实 HTTP→JSON-RPC 反例确认身份拒绝的结构化内容与文本一致，未丢失上游原因。
- Native 仅给自身来源封装中的正文添加锚点，不把作者载荷中同名嵌套字段当作可信来源。Unicode/emoji、锁定标记、片段偏移、跨来源游标、范围和账本拒绝均有验证；锚点不授予写权限。

### 可重复效率证据

入口：`scripts/evaluate-novel-tools.mjs`；原始报告：[tool-efficiency.json](evidence/2026-10-10-tool-efficiency.json)。运行方式：先构建 Native bins，然后设置 `NOVEL_CODEX_NATIVE_DIR` 指向该构建目录，执行 `npm run evaluate:tools -- <report.json> 3`。输出目录需已存在，repeats 为 1–20；脚本使用临时数据库和随机凭证，退出回收所有子进程和临时库。报告保留二进制 SHA-256。

样本为短正文和 3600 Unicode scalar 长正文，各三次，对比同范围、同来源读取下的完整 payload 与锚点 patch。每次读回完整候选，并核对未修改正文及锁定组。十二个有效保存均首次成功；另六个故意的 oldText 错误均返回 rejected，纠正后保存 committed，单独记为六次纠错，不混入有效样本成功率。

| token 口径 | 全文保存 | patch | 减少 |
| --- | ---: | ---: | ---: |
| 六样本所有工具请求，cl100k_base | 22443 | 9457 | 57.9% |
| 三个长正文保存请求，cl100k_base | 19872 | 6854 | 65.5% |
| 三个长正文保存请求，o200k_base | 13389 | 4703 | 64.9% |
| 六样本请求加规范化结果，cl100k_base | 81857 | 68853 | 15.9% |

短正文单次保存差异很小；收益主要来自无需回传长篇未改正文。计数来自具名分词器对工具 name/arguments 和规范化结构结果的精确分词，不包含重复 MCP 文本封装、提示历史或供应商计费；工具目录另列。providerUsage 为 null。全流程本机延迟 p50 为全文 519 ms、patch 483 ms，p95 为 969/604 ms；样本小且未隔离系统负载，只记录观测值，不证明线上速度提升。脚本参数正确率也不等同于真实模型选工具或文学质量提升。

### 五视角后审

- 架构：APPROVE。Native 事实与权限权威不变，MCP 传递诊断，Host 持有生命周期；评测是离线测试驱动，无第二生产模型循环。
- 技术 A：APPROVE。JSON 身份、Unicode 定位、CAS、来源、锁定与拒绝账本有正反例；前轮失败已复验。
- 技术 B：APPROVE。指标可复跑并保留构建哈希，真实 provider 未测部分明确标注，不用脚本成功率冒充模型收益。
- 产品：APPROVE。局部编辑减少重复正文输入，失败提供精确改正依据，不改变作者授权和采用流程。
- UI/UX：APPROVE。正常创作流程不新增技术操作或确认步骤，原有错误展示可读取具体原因。

本次范围无已知未修复 P0/P1。零兼容门禁 PASS：同步当前协议与测试，无旧工具 alias、身份字段 fallback 或双写。
