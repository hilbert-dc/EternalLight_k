# 全球化对话语言与公开进度

目标：地区/系统偏好提供默认语言，模型解释作者交流意图。英文术语、引用、翻译目标或代码不自动触发对话语言切换。交流语言、产物语言与证据分别处理；明确双语需求合法。

事实：第13章评估在已有中文规则下连续13条英文公开进度，整理后恢复中文。现有测试只证明规则传输，未证明真实模型效果。

前审：架构、技术A、技术B、产品、UI/UX五视角 APPROVE WITH CONDITIONS。Host提供系统语言偏好；产品适配器在新回合、恢复后回合和追加指令时附加语言上下文。模型按作者原话决定交流与产物语言，子任务继承交流约定；生成公开文本前自查。Renderer保留原记录，不翻译工具值、不伪造作者消息、不将语言偏离升级为保存失败。Codex Core、Engine及Native权限账本不变。

实施：以统一多语言契约替换中文专用默认值；turn/start与turn/steer统一传递BCP47首选locale，仅作默认值，不推断所在地或身份。不增加关键词路由、英语比例检测或翻译重试循环。公开进度只说明实质发现，语言合规不充当文学完成条件。

验证：地区信息归一化、作者原输入保留、协议新线程/恢复/追加要求、角色生成一致性；真实模型隔离验证中文、英文、日文、正文与交流语言分离、引用及显式切换。区分代码验证、模型效果和实际应用加载，不宣称全界面多语言化。

## 实测后修订：协议角色保真

2026-10-09 的多轮真实 DeepSeek 样本在规则已传入时仍重复出现英文前置进度，以及英文提问得到中文最终答复。继续增加或本地化语言提示没有消除此现象。检查实际供应商协议发现：[DeepSeek Responses 官方说明](https://api-docs.deepseek.com/api/create-response/) 明确将 `developer` 当作 `user`；当前 Engine 对该角色原样透传，故此前“存在于 developer input”测试没有验证供应商端权限语义。这是已确认的协议差异；它对具体模型行为的影响仍须修复前后对照验证，不能把单一根因推断当完整证明。

补充前审（五视角均 APPROVE WITH CONDITIONS）：通用 Engine 增加显式、纳入连接指纹的 Responses `developerRoleMode=system` 适配；仅已声明此差异的产品连接启用。Codex 原请求及历史保留，出站只映射原 developer 文本消息；作者、工具结果、推理密文、来源顺序和内容不变。含非文本的 developer 内容明确拒绝，不能偷偷升级图像或丢内容。该供应商没有独立 developer 优先级，system 映射是有说明的协议折中，不宣称与三层指令体系严格等价。不可按消息正文或工具结果中的 role 字符串升级权限。普通连接保持原样，错误配置应在定义阶段拒绝。

责任：Engine 只做通用已声明的角色适配，无中文、小说或语言识别逻辑；产品目录选择适配方式并更新指纹，旧认证不能覆盖新定义；Host 继续提供 locale，语义语言选择仍由模型负责。没有 Codex Core 缺陷或官方代码改动，不适用官方实现补丁；引用官方 API 合同确认能力差异。删除未产生效果的局部语言提示堆叠，保留统一全球化规则。

补充验证：实际生产编解码器正反例（含来源不升级、图像拒绝、输入不可变、原连接不变、指纹失效）、真实 Codex→Bridge→供应商请求链、六场景真实 DeepSeek 重验。权限/保存/预算不因语言修复放宽；不以测试样本缺回执而放松用量校验。

后审结果与证据见下文；语言效果与协议测试分别报告。

系统消息逐条映射的首次实测仍有语言偏离，不能视为完整修复。进一步采用显式 `instructions` 模式：仅把对话开始前连续的 system/developer 文本前缀按原顺序、保留角色标签写入供应商 `instructions`；历史中后插入的 developer 仍在原位置映射 system，不提升作者/工具内容、不跨作者消息搬运后来的规则。`native`、`system`、`instructions`、`unsupported` 都属于连接自身合同。前审五视角继续同意此有限序列化适配，条件为出站前缀/历史位置与不变性回归及真实模型重验。不能用对话内后来的规则追溯改写前面的作者意图。

## 模型切换与推理设置

用户明确未来会接入多个模型。语言规则属于产品层，协议角色与推理设置属于每个连接，不能按 DeepSeek 名字硬编码或统一覆盖其他模型的参数。连接配置变化后必须重新资格验证；新模型使用同一测试集，不能继承其他模型的行为结论。作者语言偏好和原话、任务身份、权限、保存事实及累计用量不因切换清零。异构模型的私有推理状态可移植性是独立合同，本次不宣称任意模型可无损热切换。

真实六场景对照：`instructions + none` 有三例英文前置说明与中文/日文答复混用；同一配置仅在隔离请求把推理设为 `low` 后，六例可见输出的语言符合预期（三例只有最终答复，无前置进度，不能作为这三例首条进度正确的证据）。这表明角色修正是必要的协议修复，但不足以单独解释全部语言偏离；推理设置与模型遵循能力仍影响结果。

补充前审五视角 APPROVE WITH CONDITIONS：仅把 DeepSeek 目录连接的 `reasoningEffort` 从 `none` 改为 `low`，更新指纹并按正式连接重新资格验证和六场景实测。不修改官方 Core，不替其他模型选推理强度，不添加语言比例判定或隐藏/翻译错误记录。潜在代价是推理费用与延迟增加；保持真实计量，不把本批行为观察当普遍保证。现有自动化测试仍覆盖未指定请求参数时的连接默认值及显式请求参数优先。
