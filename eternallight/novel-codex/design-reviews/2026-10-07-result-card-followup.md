# 成果卡片移除重复追问入口

## 变更概览

目标：普通成果卡片仅展示保存状态与查看成果。移除常驻“继续讨论”，不替换成“引用到输入框”按钮或更多菜单。作者直接在当前对话输入后续问题；精确文本引用沿用文档选区能力。

影响：WorkTaskPanel 的通用成果渲染、对应界面 fixture、现行架构文档。已有伏笔建议的指定提案引用和决策操作不属于本次普通成果卡片按钮，不改变其来源核对。模型提示与执行语义不变。

验收：章节、简报、大纲、章纲等普通成果均无重复追问按钮；查看入口、准确版本定位、草稿和已有选区引用保持可用；不新增菜单、模式或关键词分流。

## 零兼容门禁

无 schema 或 API 变化，无旧格式 fallback、双读写、迁移或降级；同步更新当前调用与测试。保留真实来源约束，属于当前数据可靠性。

## 实施前角色评审（逐角色审查）

| 角色 | 结论 | 意见 |
| --- | --- | --- |
| 架构专家 | APPROVE | 移除重复界面操作，复用既有对话及文档选区。 |
| 技术专家 A | APPROVE | 不变更发送、执行与保存校验，不自动注入引用。 |
| 技术专家 B | APPROVE | 通用成果渲染一次修改，更新已有 UI 用例。 |
| 产品经理 | APPROVE | 当前对话直接追问，精确引用为按需能力。 |
| UI/UX 设计师 | APPROVE | 卡片只保留成果与查看入口，不以新按钮替代旧按钮。 |

综合：APPROVE；无 P0/P1，无兼容例外。

实施中发现：输入框重试统一后，对未保存选区的只读讨论也被 dirty 状态阻止。补充边界：仅当无可恢复写入任务、当前失败请求明确携带 readOnly 引用时允许原请求重试；写入任务仍受 dirty 与来源检查。逐角色复核均 APPROVE，属于保留既有引用能力的当前可靠性修复。

## 实施后复核

实际变更：通用成果卡片删除“继续讨论”；不新增按钮或菜单。保留成果导航与指定提案操作。修复只读选区讨论在未保存状态下重试被阻止的问题，写入任务检查仍然生效。

验证：`npm run build` 通过（现有 bundle 体积提示保留）；`conversation-experience-ui`、`task-results-ui`、`selection-discussion-ui`、`multiple-retry-ui` 共 4 项 Electron 用例通过。覆盖直接输入、草稿保留、全部文档选区、只读重试、成果准确定位、300px 布局及任务来源隔离。更新既有测试的过时重试选择器与建议卡按钮快照。`git diff --check` 通过。
