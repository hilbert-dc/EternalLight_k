# 持久任务成果的界面刷新

日期：2026-10-08。范围：Host 已实际消费的 Work 事件与 App 现有作品刷新入口。

Host 只有取得 Native 的真实 ack 后才发送 `agent/work-updated`。App 尚未消费这个通知，重新启动后的自主任务即使保存完成，当前正文与对话列表也可能延迟显示。当前改动把同项目、具有合法 Work 与根对话身份的通知接到既有 `creativeRefreshToken`，不新增完成事实、任务状态或界面面板。

## 实施前五视角

| 视角 | 条件 |
| --- | --- |
| 架构 | 通知只使界面重新读取真实 Native 数据，不把事件当成成果内容或完成证明。 |
| 技术 A | 外来项目、缺失 Work/对话身份不触发读取；当前项目通知不能调用模型或控制接口。 |
| 技术 B | 复用现有刷新机制和当前 Host 事件，不增加版本 fallback、迁移或另一事件账本。 |
| 产品 | 已保存的结果无需作者再切换项目或重发要求才能看到。 |
| UI/UX | 保留原阅读位置和草稿保护，沿用同一对话与正文入口。 |

五视角是职责审查，不表示五名独立人员。零兼容预审：PASS。使用现有真实 App 的作品切换/阅读位置测试补充事件结果刷新场景。

## 实施后五视角与证据

当前 App 将同项目且有合法 `workTaskId`、`threadId` 的 `agent/work-updated` 接到现有作品刷新。真实 App Electron 夹具在空项目中登记保存成果，外来项目和缺失对话身份通知不刷新；合法通知立即显示新结果，无需切换项目。原有跨项目迟到读取隔离、分页、展开与阅读位置、没有额外模型或写控制断言全部保留。
