## 前审

责任：Story Core 保有来源、授权、版本、幂等、Work与交付事实；Runtime构造读取投影；MCP提供同源schema与有针对性的指南；Host把冻结执行合同放入任务指令并管理接续；Engine提供真实用量。评测脚本只驱动公开生产链并保存证据，不实现第二模型循环。

第一切片：指南不再分页回传完整schema，改为默认操作说明与可选字段说明；实际schema与执行校验不减少。原计划让read_context只返回冻结方法元数据；实施验证后撤销此项，保留全文读取，原因见下文。调用方、测试、技能与当前架构同步。随后处理定位、评测、授权接续及恢复中的具体缺口，逐项追加实际判定与证据。

五视角自审：架构 APPROVE WITH CONDITIONS（单一权威，无第二循环）；技术A APPROVE WITH CONDITIONS（实际参数/结果边界与拒绝反例）；技术B APPROVE WITH CONDITIONS（当前调用方一次同步，证据可复跑）；产品 APPROVE（优先减少协调成本，保持质量和默认计量）；UI/UX APPROVE（不增加作者技术操作）。条件由各切片实际验证关闭，不代表五名独立评审。

零兼容：只实现当前合同，删除被替代入口/字段，不增加fallback、迁移或双写。真实资料不变，测试使用隔离数据。当前改动不涉及官方依赖缺陷或Core修改；若后续确认此类问题，遵循B09先核对和完整同步官方更新的要求。

## 质量优先的方案校正

作者明确创作质量优先后，专项方案改为质量与开销共同基线先行，成本指标不能抵消质量退步，30%token降幅不再作为退出门槛。原五视角前审的产品结论据此细化：优先完成作者目标与作品质量，其次比较效率。

后续凡减少模型可见信息、改变阅读/评审策略或切换模型的改动，先冻结对应质量样本，再完成实际对照；纯观测与确定性校验可继续，涉及质量的默认替换在证据不足时保持待验。不得用Agent模拟人类填写盲评，也不因质量优先新增固定团队或无界调用。


## 实施中发现：附加上下文传输截断

受控真实 Core 出站验证发现：Core `context-fragments/src/additional_context.rs` 对单个 application/untrusted 值按 1,000 approximate tokens（4,000 UTF-8 bytes）截断。Host 将约4,700字符任务规则作为一个值发送，模型实际收到截断标记，实验保存方式指令位于丢失的中部。这是当前调用方未遵守公开运输行为，不修改 Core 或官方依赖，B09 上游改动流程未被触发。

修正职责归 Host：按 Unicode scalar 无损切成不超过3,500字节的有序片段，保留 application/untrusted 身份；同一轮的总预算不重置。sendTurn 与 steerTurn 统一处理，标识冲突拒绝。第一请求的 provider 出站内容验证完整合同与身份。这里可能增加实际 tokens，因为此前有指令被截断；质量与要求完整性优先。

压缩实验另证明，初次发送的附加片段不会因为发送相同值而自动完整重放；不能据此删除 Runtime 中的冻结方法全文。已撤销 read_context 去全文改动，保留既有完整读取入口，并在持续工作规则中明确压缩/委派缺失时回读。压缩后的文学效果和自主回读仍须真实质量场景验证，不能用受控 provider 冒充。

五视角增量自审：架构 APPROVE（Host 运输，领域权威不变）；技术A APPROVE WITH CONDITIONS（出站完整性、分片边界与总预算测试）；技术B APPROVE WITH CONDITIONS（实际 Core、压缩能力范围和真实模型验收分开）；产品 APPROVE（优先保留作者规则，即使 tokens 增加）；UI/UX APPROVE（作者不承担分片或回读协议）。尚未通过项在后审逐项登记。

## 质量与归因基础设施

新增离线归因入口使用 Engine 原账本与现有轨迹，不读写领域数据，不发送模型请求，报告按 operation / Work 归因、工具重复参数与返回、轨迹缺口及未知额度。不给重复调用自动贴“浪费”标签，不从正文长度推断创作思考比例。

新增8类自编固定样本、盲评包与质量优先判定入口。样本为待人类校准的测试素材，非金标或真实已交付结果；测试中的评分仅为合成断言，不能进入产品证据。缺失/失败样本保留在分母；来源/模型配置不一致、保护损坏、质量退步均不接受，成本不参与抵消。LLM评语、空模板和不确定意见不能生成通过结果。身份和领域回执仍须核验原始证据，JSON文件本身不认证人类或保存。

零兼容复核：指南当前 schema 用 field 代替分页 cursor，调用方与测试同步；没有双写、迁移、旧契约降级。当前初步方案的“方法全文省略”已移除实现，而非保留第二套模式。

## 结构修正前审：结束章节复用持久核验，不让模型重抄标准

根因分类：设计缺陷。finishChapter要求模型重传sourceRevisionId、assessmentRevisionId、完整criterionId/issueId与length，而这些已由选中动作、冻结标准和有效报告唯一确定。重复传输不增加文学判断，却增加参数错误与回读。Story Core负责在同一事务内从本Work的当前候选、选定核验方式和冻结标准生成chapterReviewReceipt；模型仍明确选择finishChapter，原报告仍须包含真实阅读、逐项判断和引文。报告缺失、过期、负面、未解决问题或真实篇幅不符仍拒绝。advance按持久回执中的报告身份重新校验，不能在两阶段间悄悄更换报告。

公开合同：request_work_action.chapterReview仅用于verifyChapter；finishChapter不再接受重复review。Core删除重复Review/Check输入模型，MCP删除旧schema分支，Host提示、HTTP fixture、合同测试和架构文档同步。不是自动认为已完成，不合并Work最终自检或费用结算。CAS、暂停/取消、授权及采用/发布不变。零兼容：旧finish review输入直接拒绝，不留双轨。
