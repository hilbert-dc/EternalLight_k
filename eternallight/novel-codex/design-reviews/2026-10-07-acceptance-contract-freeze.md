# 执行目标验收口径冻结：设计与实机验收

## 方案与边界

真实 DeepSeek 重试恢复连接并保存第7章5686字符，但同一 Work 的后续决策保留目标 ID，却删除金额、期限等验收内容，最终误判通过并登记原100章交接。现行 `chapter_delivery_review` 已冻结连续章节的验收口径，普通修订 Work 的 `model_work_plan` 尚未提供同等保护。

本次最小修复：第一次保存 `executeGoals` 后，既有目标的 `acceptance` 和 `kind` 不可改，既有依赖不可删除；执行模式不可降为 `planningOnly`。允许追加目标及依赖，允许修改标题、阅读问题、检查方法、结论、状态与证据；模型继续解释作者意图、选择行动、判断内容。初始 `planningOnly` 可修改并进入 `executeGoals`。作者变更任务仍由真实作者输入建立新的局部工作，不把作品版本变化当成降低标准的授权。

Native 只维护已记录口径的完整性，不解析“继续”等词，不匹配小说金额，不宣称能验证文学语义。该小修复不解决首次计划漏项、错误语义判断、未持久保存解析源阅读进度及内部提示重复保留；这些仍为端到端阻断项。既有正文允许保存，保存回执不能替代质量验收。

零兼容门禁 PASS：只修改当前 Native 校验及 MCP 说明，不增加 schema、版本探测、迁移、回填、兼容字段或双读双写。当前真实应用运行中的任务先保留完整证据，不热换 Native 二进制。

## 验收标准

1. 同 ID 改弱验收、将检查改成产物或删除既有依赖、将执行改为仅规划，均在计划写入前被拒绝。
2. 拒绝后当前计划版本及内容不变；相同幂等重试有效。
3. 方法与检查证据更新、新增目标或依赖、仅规划转执行仍可完成。
4. MCP 说明与现行文档说明冻结边界，不包含固定小说词语规则。
5. 单元及 Repository 定向测试通过；真实稿件独立全文验收仍单列。
