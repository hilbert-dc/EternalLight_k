## 实施前审查

本轮覆盖 S01–S09、R01–R03 及 F01–F04 复核。模型继续决定创作行动；Native 拥有授权、版本、保存、预算和恢复准入；Engine 提供通用失败证据；Host 管理进程/事件/读取健康；Renderer 仅投影。适用 B01–B10，不修改官方 Core，不建立第二份作品或费用账本。

优先复用当前错误 payload、Task、Work、事件及回执。引用诊断由 Native 补路径；预算拒绝返回独立原因；恢复将写入与账务分开；Host 保留原失败并显示自身读取故障。接口变动同步生产者与全部受影响消费者、类型和测试，不保留旧行为分支。真实作品和失败数据不重置。

| 相邻状态 | 应有行为 | 验证 |
| --- | --- | --- |
| 引用无效 / 合法引用 | 精确路径拒绝、零保存 / 正常保存 | Native 输出 HTTP 合同 |
| 费用未结算 / 未知写入 / 状态读失败 | 分别核对账务 / 保存 / 重新读取 | Native + Host + UI |
| 原因相同无进展 / 实际条件变化 | 停止空转 / 原 Work 重评 | 持久事件与模型条件合同 |
| 作者暂停取消 / 重复唤醒 | 保持停止 / 幂等消费 | 真实 Native 事件合同 |
| 供应商文本提及错误名 / 本地结构化原因 | 不推断本地事实 / 精确投影 | 来源正反例 |

五视角前审（同一实施者）：架构批准原边界内修正；技术 A 要求保留未知、费用、暂停与身份保护；技术 B 要求跨层回归和新构建身份；产品要求无需重复输入推进；UI 要求统一状态与真实可用动作。结论 APPROVE WITH CONDITIONS：代码、合同、构建、应用验收分开记录，不以测试数量宣称长篇完成。零兼容策略遵守；无升级、回填、双轨或真实数据删除。

### 验证中追加确认：未绑定会话的失败提示被过滤

实际 App fixture 在 Native 已返回同 Work 的 `WORK_RESUME_NOT_STARTED` 时，提示不可见。根因是展示层将生成 Work 的空 threadId 与选择器的 null 直接比较；不是 Host 未返回失败，也不是作者缺少权限。修正只覆盖同项目、同 targetId、kind=generation、尚无 threadId 且当前未选择会话的提示投影，不扩大恢复准入。已有完整 App 回归覆盖未启动任务恢复、草稿保留、跨项目晚到回执及无重复作者输入；同步补齐该 fixture 的真实取消版本回执。五视角补审：边界不变，允许修正，必须保留跨会话隔离。
