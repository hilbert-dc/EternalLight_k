# Token 优化：操作回执携带可继续使用的状态

## 目标与证据
核心目标是减少无效模型请求及其重复历史输入，不减少正文、作者要求、必要阅读或文学判断。前35—37章完整任务账本（输入含缓存，输出含推理；预留/未知另记）：

不同内容不是受控对照，不能据差值声称节省。此前411万协调成本是混合时间窗口，不是全部无效输入。来源见 `.release/resume-state-validation/live-paused.json` 与真实 Engine budget-task-* 结算账本。

已证实设计缺口：第35章05:30:54保存核验→05:30:56读状态→05:31:01登记结章→05:31:03读状态→完成；第36章同样两个回读，写作安排后另有一次。操作回执缺少已知的新版本和动作，迫使模型发送新请求取得这些事实。正文与作者阅读不属于本次删减对象。第36章还有两次引文纠错，是另一类浪费，不混作本修复收益。

## 责任与方案（前审）
Native在既有操作事务中返回 `decisionStatus`，复用 read_work_status 的同一有界第一页投影。覆盖普通动作、直接核验、结章及幂等重放；操作回执保持原保存身份，附带状态是当前响应快照，重放不伪装旧状态仍可写。读取登记与动作在同一事务内提交，投影失败整体回滚，不能出现提交成功却丢失回执的额外阶段。Runtime/MCP原样传递，MCP指南明确可直接使用回执状态。保留独立查询用于恢复、并发冲突、后续页与主动调查。Host不替模型选行动，Engine/Core不改。

原权限、CAS、未读拒绝、精确引文、独立评审要求、费用账本、完成审核不变。没有新schema或兼容迁移；不新增提示模板、固定写作步骤或token硬上限。

|场景|结果与必要边界|验证|

## 实施与阶段验证
Native 提取同一 `status_in_snapshot` 投影，动作首次提交与幂等重放均在原事务内附带 `decisionStatus`。MCP 原样传递，简短指南和详细指南均使用这一合同，移除了旧的强制状态回读语句。独立读取入口与分页继续保留。

真实 HTTP 核验链 3 项通过（含两种正文来源），验证回执 CAS 直接登记结章，再凭结章回执完成任务，且保持未读、伪造引文、旧 CAS、负面核验及独立核验边界。测试辅助函数原会补读验收原文，已改为与真实 HTTP 第一页比较，未修改业务验收。MCP 结果传输 7 项通过，架构检查 369 文件/7 crate 无诊断。普通 Work 回归、最终构建、部署和自然模型行为仍待验证。

旧窗口中的 9 次动作后纯状态模型请求共 520850 token：累计输入 517732（含缓存输入 506496），输出 3118。这是可消除往返的历史成本，非已实现节省；不据此宣布整章节省比例。证据保存在 `.release/token-action-state-validation/baseline-state-roundtrips.json`。
