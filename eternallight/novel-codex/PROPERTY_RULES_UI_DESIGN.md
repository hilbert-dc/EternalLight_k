# 作者属性规则工作区

## 目标与边界

接通 S1 已存在的 propertyRules 候选、Review、Acceptance 与撤销链，在“世界与规则”
提供可审阅的结构规则。作者主创作仍通过对话完成；此处是可选的规则裁决/编辑，
不是要求作者先填数据模型。对话提案已沿原任务链接通；全来源规则条件解释、
事件状态机和完整 S1–S5 仍需继续实现和验收，不以此 UI 取代它们。

## 当前版本契约

- 展示候选与正式版本、主体种类、属性键、有限值类型、单值/多值和自然语言例外。
  采用结构规则不确认任何属性值；说明不作为代码执行；例外存在时适用性仍待解释。
- 可选编辑使用有限表单，不输入 JSON/代码/DDL。结构与事件数组均清空才表示候选清空规则，
  并不会在保存时撤销正式规则。64 条、16 KiB、字段/例外字节预算与 Rust 一致。
- 事件条件在同份 payload 的 eventRules 中保存，最多16条/单条4KiB，以可读的
  all/any/not 及类型化比较树展示；默认通过对话生成，不要求作者编写 AST。
  属性编辑保留已有事件规则，悬空引用阻止保存；移除条件必须明确操作，冻结
  请求及未知回执期间不得移除。界面明确“尚未进行全来源条件判定”，采用不是
  条件成立或效果执行。长文字比较及嵌套表达式换行，不溢出中央作者栏。
- 保存冻结作品版本、候选版本、完整载荷和幂等键。失败后保持原请求，显式重试
  使用同一键/载荷；不能改字段后继续重用键。放弃仅清除本地输入，不能撤回可能
  已保存的候选。后续读取失败不自动重复写入。
  保存候选不增加正式作品版本。Runtime 按原候选基线计算版本，原请求可在后续
  正式采用后重放原回执；同键改载荷仍须拒绝，不因当前版本变化另造保存请求。
- 保存与建立 Review 分成明确操作；审阅只提交具体规则修订和空 facts/selections，
  不混入建模批次。采用绑定当前 Review、作品版本、候选和锁；最终校验仍归 Rust。
- 撤销只展示原账本允许的最近采用，不建立本地批准指针、撤销栈或另一状态机。
- 初始读取/读取失败/无规则分开；失败保留上次结果并禁用写操作。读取互斥与刷新
  合并；作品生命周期隔离迟到响应。编辑保留输入，外部版本改变须放弃后重新编辑。
- 接入 App 的统一保存/放弃/离开保护。写入中保存、放弃和重复操作同步拒绝。
  用户设置入口也经过统一导航保护，不能直接卸载编辑器。
  整体读取失败时重试只读；不为未知采用结果自动重放。

## 五视角实施者自检（非独立评审）

架构：复用 Rust 修订/Review/提交权威，不改模型授权。技术 A：同步锁、CAS、
幂等键冻结、未知结果可核对。技术 B：真实 Electron 验证保存/采用/撤销、迟到响应、
重复请求与失败恢复；原真实 HTTP 规则测试仍覆盖领域事务。产品：可选裁决而非
手填小说流程；UX：结构规则不冒充事实或语义真相，条件未知明确可见。

零兼容门禁：不增加依赖、schema、旧字段 fallback、双轨或数据升级。
综合决策：按以上契约实施；未完成能力继续列为未完成。
