# 自主创作质量回路

目标：主 Agent 按实际创作需要使用质量工具，独立读者不是 UI 前置操作。模型负责文学判断；工程负责授权、隔离、额度、证据与停止。

流程：主 Agent 读取有效偏好和正文 → 按需记录目标、亮点、跨章观察或有限试写 → 冻结阅读包 → 从 read_work_status 选择 reviewQuality → 同 Work 的新会话阅读 → 主 Agent 读取保存报告 → 在原授权内修改或说明不采纳。不是每章必跑的流水线，不以模型评分认证文学质量。

阅读包保存创建任务来源，只有该任务所属 Work 能自动调度。作者手动准备的包不成为任意 Work 的自动消费入口。ready action 使用现有 CAS、幂等、任务额度和停止门禁；不创建新根预算。冻结正文过期、已审阅或已有执行时不可重复选择。Reader 的编排元数据仅供工程校验，不进入提示词；全新会话只获得分页匿名文本。

UI 保持淡雅：创作回看用于观察、确认长期偏好和可选手动审阅；自动步骤显示在原任务记录。没有质量记录不会阻止创作，读者意见不自动采用。预算不足停止，不偷建新 Work。

直接生成入口：Writer 与简报/大纲/规划任务可只读质量笔记，避免只有主对话能读取作者偏好。仅主 Agent 可以写笔记和调度；独立读者不开放笔记读取。五视角增补审查：APPROVE，属于既有创作范围的只读资料访问，须验证工作者无记录写权、读者隔离不变。

## 实施前五角色评审（同一执行者逐视角自审）

- 架构：APPROVE。复用 Work 决策，不增加第二个调度器。
- 技术 A：APPROVE WITH CONDITIONS。来源归属、冻结校验、全新会话、共享预算均须测试。
- 技术 B：APPROVE WITH CONDITIONS。同步 schema、提示、测试、文档；不写历史迁移。
- 产品：APPROVE。自动按需，保留作者审美决定权，不强制额外检查。
- UI/UX：APPROVE。已有任务状态承载自动流程，手动入口不再是必要步骤。

零兼容门禁：不增加版本判断、fallback、双写或迁移；测试数据库按当前 schema 重建。安全、并发和失败恢复属于当前版本质量要求。无兼容例外。

## 实施后复核

实际变更：阅读包持久化创建任务；Work 自动发现本任务有效包，主 Agent 选择可选阅读动作。Reader 允许经过 Work 冻结校验的编排字段，提示只输出最小任务绑定与阅读方法。回执携带 packetId；只有独立手动根任务保留 readerRestart，自动步骤复用 Work 恢复与预算。失败的阅读是可选分析，已保存报告不重复生成。分页游标纳入质量版本，防止新增包后混用旧分页。

直接创作任务只读笔记，不能写笔记、确认偏好或读取隔离阅读工具。UI 增加一行自动使用说明，不增加面板层级或强制操作。提示词已压缩，保留原长中文作者输入和 9000 预算门禁。

五视角实施复核：架构（单一 Work 调度）、技术 A（绑定/来源/隔离/预算）、技术 B（schema/调用方/测试）、产品（按需而非强制）、UI/UX（观察与干预入口）均按上述实际实现复核；没有新兼容层、迁移、双写或旧入口适配。最终测试证据见下。

验证记录：前端构建通过；Host/交接/自动调度 36 项通过；UI 交互通过；长中文输入通过；真实 Codex/MCP 隔离协议通过（本地模拟模型，不是付费真人/文学效果测试）。最终核心 203 项通过，其中质量专项 12 项，覆盖同 Work 自动往返、单一账本、真实报告回执、来源归属、Writer 只读权限。追加只读权限前 HTTP 集成通过。

最终 HTTP（增补 Writer 权限断言）及 MCP（增补工作者工具集合断言）编译成功，但执行分别在 macOS 动态加载阶段停留数分钟，普通本地重试同样未进入测试。sample 显示 `_dyld_start + 0`、约 96KB footprint；codesign 验证有效。未关闭系统安全机制；已停止本轮四个挂起测试进程。这两项标记为环境阻塞、未验证，不计入通过数。需在本机可正常启动新二进制后重跑 `npm run test:creative-quality`。
