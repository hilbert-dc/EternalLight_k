## 1. 产品目标

让作者通过对话和直接编辑，持续维护一部故事：形成方向、规划近期、写出草稿、审阅接受，再根据实际写出的内容调整后续安排。

本阶段核心验收：从新作品的一句设想出发，生成可编辑大纲和未来三章计划，生成第一章草稿；作者修改并接受第一章后，系统能解释第二、三章哪些安排需要调整、为什么调整，并保留作者锁定的内容。

生成过程可以自动完成规划、写作、检查和草稿保存。正式稿与故事事实的变更，使用一次联合审阅与接受；普通编辑动作不逐项弹窗。

## 3. 用户与成功场景

| 用户角色 | 主要需求 | 本阶段成功结果 |
| --- | --- | --- |
| 从设想开始的作者 | 快速开始，不先填完整世界观表单 | 以一句设想生成可编辑故事方向；缺失信息标为待定 |

已有作品首期支持粘贴单章，保留原始输入，确认章节位置后建立草稿与候选事实。整本批量导入、自动准确还原完整故事世界属于后续范围。

## 4. 范围与默认值

本阶段必需：创作简述、分层大纲、近期章节计划、下一章 Scene/Beat、章节草稿、局部修订、角色知识与信息边界、检查、联合接受、版本冲突与撤销、接受后的局部重规划、真实 Agent 工具调用。

暂缓：漫画/图像/视频、多人实时协作、公开发布、一键生成整本、复杂多 Agent 编排、强制向量库、自动综合文学分数、同轮多候选比较与综合、所有层级的大规模候选搜索。

以下是待试用验证的初始配置，并非研究结论或已验证最优参数：

- 近章窗口默认 3 章，可选 1～5 章；下一章详细，后续章概要。
- 每次生成 1 个方案，作者可修改或重试；保留修订历史，但首版不建设同轮多候选比较与综合。
- 草稿默认 1 版，按场景组织；短单场景章可一次生成，复杂章分场景并全章统稿。
- 自动局部修复最多 2 轮；仍有问题就保存草稿和说明，不无限循环。
- 字数为作者可调整的目标范围；不靠重复段落硬凑字数。

## 5. 三类核心任务

### P-01 大纲生成与修订

入口：右侧对话“帮我设计这部小说的大纲”；或中央“大纲”空态中的“生成大纲”。

输入：作品简述；可选题材、读者、语气、篇幅范围、人物、结局方向、禁改项。缺失字段允许由模型提出可见假设，假设不直接入 Canon。重大创作分歧可提问，其他情况先给候选。

产物：全书方向 → 卷 → 情节弧 Arc。简单作品允许省略卷，不强迫填满全部层级。大纲同时保留可读叙述与必要结构信息：目标、核心冲突、人物变化、关键事件、因果前提、预计结果、信息揭示、伏笔设置/回收、作者锁定。

关键事件用稳定 ID 标识；章节范围只是安排，允许移动。明确区分“已发生”“计划发生”“备选”。未来秘密可以作为作者设定保存，但不能把未来事件当成已经发生。

交互：直接编辑节点、锁定方向、针对一个 Arc 要求修订。修订展示原方案与新方案；重试产生新版本，不自动融合互相矛盾的方案。

验收：从空项目生成可编辑大纲；重开可恢复；锁定的结局不被重生成覆盖；接受大纲不会创建已经发生的故事事件。

### P-02 近章规划

入口：“接着规划后三章，女主只能怀疑师父，不能确认身份。”可以基于大纲，也可基于已确认的现稿。没有大纲时，允许先给本段目标，不阻塞局部规划。

输入：当前阅读位置、故事时间、已接受稿状态、相关 Arc、锁定计划、伏笔、近期读者信息变化。当前未接受草稿可用于试规划，但产物明确依赖该草稿版本，不进入正式状态。

每张章节任务书包含：

| 字段 | 作者可读含义 |
| --- | --- |
| 目的与视角 | 本章解决什么问题，由谁感知 |
| 开场状态 | 从前章承接的人物行动、处境与关系 |
| 冲突 / 选择 / 后果 | 人物面临什么，作出什么决定，改变什么 |
| 信息安排 | 作者真相、读者可知、视角人物已知/怀疑、暂不可揭示 |
| 结束状态 | 可检验的剧情或心理变化；不强制数值化情感 |
| 场景概要 | 下一章详细，远章只列主要推进 |
| 承接 | 下一章的行动、情绪或悬念承接；不强制每章悬崖结尾 |
| 依据与待定 | 引用来源、缺失信息、作者选择 |

细化程度（方向/概要/详细）、作者锁定、当前是否失效是不同维度，不使用模型自报置信度作为作者确认。

规划后运行 Plan Checks。硬约束问题定位到具体章节任务书；动机、节奏等软意见支持忽略并填写理由。作者可局部编辑、锁定或重生成，不必每张卡都单独批准。

接受一章后先比较计划结果与实际结果。只标记依赖失效的后续节点，给出局部修订提议；不整窗自动改写。锁定节点受影响时解释冲突，由作者改动前置安排或解锁。

近期窗口只限制本轮详细规划范围，不限制长篇记忆：更远处的伏笔、人物承诺与结局约束仍须按相关性检索，不能因不在未来三章而被遗忘。

验收：第一章新增“令牌指向错误目标”，系统指出依赖该线索的后章变化；未依赖的支线及锁定章节保持原版本。

### P-03 草稿生成与局部修订

入口：“按这个计划写第一章”；无计划时自动补最小章节/场景计划，并随产物提供检查入口。作者不用先操作所有规划页面。

输入：章节任务书、完整场景安排、当前场景、上一场景衔接、相关世界状态与角色知识、风格约定、作者原文、受保护段落。

生成：Scene/Beat 结构 → 正文草稿 → 全章衔接与重复检查 → 候选事件/状态提取 → 内容检查 → 联合审阅。

风格约定保存视角、叙述距离、语气、对白特点、节奏偏好、应避免的表达，以及作者主动选定的样段。场景允许关系变化、情绪重估和氛围铺垫，不机械要求每场战斗、反转或数值升级。

草稿按完成的场景保存检查点。流式未完成片段可恢复为“未完成”，不能假装完整章节。失败/取消保留已完成草稿，重试从检查点继续。统稿与局部修复不得重写作者锁定段落。

同一章原文和备选草稿独立保存。作者直接编辑草稿产生新版本，使旧检查结果过期。支持仅接受场景级变更组；任意字符级选择首期由“编辑新草稿后重新检查”实现。

验收：生成第一章后中央可读可编辑；重写第二场不改动被锁定的第一场；取消后正式稿不变，重开能找到已保存草稿。

## 6. 中央文章、右侧对话的交互

保持左侧导航、中央作品内容、右侧协作的布局，不把全部内部结构堆到聊天中。

| 区域 | 内容与操作 |
| --- | --- |
| 左侧 | 作品、大纲、近期计划、章节、设定；章节显示草稿/正式稿/需检查状态 |
| 中央大纲 | 可读树形大纲，编辑节点、锁定、比较前后修订 |
| 中央近期计划 | 按顺序排列的章节任务书，展开下一章 Scene/Beat；清晰显示受影响原因 |
| 中央正文 | 正式稿/草稿版本切换，普通阅读与编辑；审阅时切换差异视图 |
| 右侧对话 | 用户意图、简短执行进度、结果摘要、打开产物；技术过程默认折叠 |
| 右侧检查/变更 | 本轮依据、计划、检查意见、关联事实变化；“采用选中变更”“保留草稿”与历史撤销入口 |

产品文案使用“大纲”“近期计划”“故事设定”“待采用”，内部 Canon/IR/ChangeSet/JSON 不成为必学术语。模型名称和执行诊断可在设置与详情查看。

首次使用：只有作品标题也可开始；提供“直接写第一章”“设计大纲”“粘贴已有章节”的真实入口，已有正文后提供“规划下一章”。直接写章时，最小计划随草稿生成、按需查看，不增加前置审批。无模型连接时允许手动编辑、查询及不依赖模型的检查；生成和语义检查明确显示不可用，不输出假草稿。

加载态显示真实阶段与取消操作；空检索说明“尚无已确认依据”；失败保留输入和草稿；成功明确“草稿已保存”或“已采用为正式稿”，二者不混用。

Enter 发送、Shift+Enter 换行，尊重输入法合成，不重复显示快捷键提示。产物和审阅控件支持键盘焦点、可访问名称；状态不能只靠颜色。macOS/Windows 均测试长标题、窄右栏和缩放。

## 7. 接受、事实与版本规则

任务、产物、事实使用不同生命周期：

- 任务：排队 → 执行 → 等待作者 / 完成；另有失败、取消。任务完成可仅代表草稿产出完成。
- 产物：草稿 → 待审阅 → 已采用 / 已放弃。产物再次编辑形成新修订，旧检查不继续有效。
- 事实：候选 → 已确认；尚无证据可以保持未知，作者也可显式确认为设定。

不能把 `planned → drafted → accepted → canonical` 作为所有对象共用的状态机：大纲接受不代表其中的事情已经发生。

候选事实必须引用原文修订、段落/场景、提取理由；对白中的谎言、角色推测、不可靠叙述不能自动升格为世界真相。区分世界事实、读者已获信息、角色相信的内容和作者秘密。

作者可以否定一次提取，或将含义标为未知、角色信念，而不必删去正文中的梦境、隐喻与留白。例如“她把第二副碗筷收回柜里”不能强制确认“关系破裂”。纠正提取并重新通过完整性检查后，正文可以采用，未经确认的关系事实不变。模型理解不是作者必须接受的事实。

采用时展示正文与关联事实变化。若正文依赖一个被取消选择的事实更新，整个依赖组暂不可采用，必须先修正正文、关联或候选事实，再重新检查；不能任意拆开产生矛盾。语义争议可由作者裁决并记录理由，但解释文字不能绕过引用完整性、版本、锁定或跨作品边界检查。

每个候选绑定项目、来源版本和读取依赖。提交时检查版本；过期候选保留并说明需重新检查，不覆盖后来手工修改。重复接受同一候选返回同一提交结果。

在候选视图上完成检查后，用同一事务提交正文、事件、知识历史、关系变化、版本与受影响标记。索引作为可重建派生数据，按版本更新；索引未同步不能假称最新。

撤销生成一个可追溯的恢复提交。已有后续依赖时，展示影响并要求选择恢复范围或局部纠正，不能无条件覆盖后文。首期保证最近一次且无后续依赖的联合提交可一键撤销。

## 8. Context、规划与质量边界

一个 Context 服务共享查询能力，使用三类信息策略：Planner 读取相关秘密与未来约束；Writer 读取当前表达所需内容与信息边界；Critic 读取候选内容、约束及证据。三者不需要三个独立服务或常驻 Agent。

Context 查询同时包含项目/修订、故事时间、读者阅读位置和视角人物。倒叙与插叙不得只按章节号推断世界时间；同章内可用场景顺序标识知识变化。

优先纳入硬约束、选定章节和衔接，再补相关实体与检索证据；每段来源有版本和用途。超过预算时返回遗漏说明并允许继续调查，不把“截断后的前12条”当完整故事。必须在读取范围内先筛选再限量，不为每次生成加载全书快照。

角色隔离要覆盖模型会话历史：Writer 的本次输入没含秘密，不代表复用 Planner 历史就不会泄露。生成任务使用明确的信息上下文，复用策略须在技术设计中测试。

| 检查 | 性质 | 作者看到的结果 |
| --- | --- | --- |
| 引用、版本、锁定、明确事件前置条件 | 可确定的硬检查 | 错误位置、证据、修正方法；阻止有缺陷的正式提交 |
| 明确知识与揭示边界 | 结构规则 + 正文语义判断 | 区分已证实冲突与疑似泄露；不把提问、试探等同于确认 |
| 动机、节奏、人物主动性、重复、风格 | 软评议 | 原文证据、影响、可选修改；作者可以不采纳 |
| 原文的意外发现 | 创作机会 | 提出与原计划的差异和后续可能性，不自动改全书 |

所有报告带被检查的版本、覆盖范围和结果；缺少材料或检查未运行时显示“未检查/依据不足”，不能显示“通过”。结构检查通过不等于文学质量通过。

领域对象至少包括：CreativeBrief、OutlineNode、ChapterPlan、ScenePlan/Beat、DraftRevision、FactProposal、TemporalStateEvent、Dependency、ReviewBundle、TaskRun。由技术设计决定具体类型与存储，不在本 PRD 固化未经验证的接口。

将现有四步工作流改名或清晰标注为 Execution Plan；新增的 ChapterPlan 必须真正保存本章内容设计。

Agent 通过结构化工具创建/查询/修订产物、提交候选和运行检查。正式应用由主进程绑定作者审阅动作；应用端拒绝越项目、越版本或未经审阅的写入。提示词约束不能替代写入边界。

工具需要覆盖空作品的角色/场景/章节建立，不能仅支持替换已有章节。UI 发送时携带选定作品、章节、任务类型和版本；任务历史与模型会话都按作品关联。

任务记录运行阶段、输入版本、模型配置、输出引用、检查点、取消与重试状态。记录用量，不把整篇原文和秘密无界复制到日志。接模型前可用固定候选验证流程，但发布验收必须包含真实模型生成测试。

保留 Electron/React、Python Runtime、SQLite 和独立 Codex 环境。测试阶段直接替换旧契约，不为旧字段维护双轨业务模型；本地测试数据库与测试作品按当前 schema 重建。

## 12. 评测与发布判断

初始样例集至少覆盖悬疑信息边界、关系变化、世界规则、慢节奏情绪场景、倒叙、多视角；另加空作品和手工导入/修改。事实正确性的固定样例与文学评议分开统计。

同一设想和约束对比“当前简单提示生成”与“规划 + 状态反馈”，记录模型版本、生成长度、调用数、用量与等待时间，避免将模型升级误认为架构收益。

产品指标：从输入到首份可编辑产物的时间、草稿采用率、改稿用时、每章人工纠错次数、后续计划被无谓改写的比例、错误回写/恢复失败次数。采用率按产物类型和是否局部采用分别统计，不把点击接受当质量证明。

文学评议由真实作者在试用阶段盲评：因果、人物主动性、声音一致、信息控制、情绪与阅读意愿，必须引用具体段落；当前 AI 角色讨论不计入真实作者样本。

发布要求：固定数据保障场景全部通过；macOS/Windows 都完成核心旅程；真实模型贯通至少一组新作品样例和一组改稿样例；没有未解释的锁定覆盖、跨作品读取或错误事实提交。质量提升和耗时目标在记录首轮基线后制定，不预先承诺百分比或百万字稳定性。
