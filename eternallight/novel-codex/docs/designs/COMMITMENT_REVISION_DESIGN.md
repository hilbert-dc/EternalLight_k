# 对话调整叙事承诺：任务架构落地

## 决策

复用 WorkTask → WorkStep → Task/Attempt → Candidate → Author Review，不增加提案状态机或模型直写正式内容的通道。

作者明确要求调整一个已建立承诺时，对话任务先检索并读取完整承诺，再登记 `reviseCommitment`。目标冻结为 `{type:"commitment",commitmentId,revisionId}`；不明确的名称必须澄清，不能随机选择。该任务只能修改这一对象，不能创建新承诺、改 ID 或变更不可变的 extractionOrigin。模型输出是候选解释，不是事实、自动确认或文学质量认证。

`read_commitment` 对 advisory 提供作品内单对象只读查询，对 reviseCommitment 仅返回绑定对象的冻结基准；正文与关系检索继续使用现有任务范围。Writer、提取和知识建模任务不获得全局承诺读取权限。返回最多 32KB 内容，不携带作者审批控制。

`submit_commitment_candidate` 仅限根 Agent 的绑定任务；Runtime 从不可变基准恢复 origin，领域层再次校验 ID、origin、证据、目标窗口、活动状态、输入水位和候选 CAS。自己的检查点允许继续，其他作者/任务写入导致输入过期；不得自动换目标或重放过期意图。幂等回执、取消、暂停/恢复、重试、锁及完成证明沿用现有机制。

暂停/恢复沿用现有安全限制：暂停不承诺恢复到模型 token，已经失败且留下部分候选写入的尝试仍标记 `partialOutput`，不自动重发旧意图覆盖新候选。作者先复核已保存候选，再发起新的明确调整。普通任务的既有限制不是本切片新增的无损断点恢复能力。

按用户要求由当前实现者单独推进，以下是自检，不声称独立专家已评审。

- 架构：新增窄领域操作，不复制任务、版本或确认机制，不改上游 Codex 内核。
- 可靠性：任务创建与行动登记事务内检查来源；提交事务内验证 frozen input + CAS；来源不可变。
- 技术：同步领域、HTTP、MCP 与 Electron 操作注册；集成测试覆盖成功、越权、过期和伪造证据。
- 产品：自由讨论不自动修改；候选保存与作者正式采用分开。
- 体验：沿用现有执行过程与承诺候选编辑/确认界面，不新增审批入口。
- 零兼容：直接更新当前 schema，不提供旧数据迁移、旧操作 fallback 或双写。
