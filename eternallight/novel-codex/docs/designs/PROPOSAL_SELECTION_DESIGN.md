# 跨对象提案的作者选择与预检

目标：补齐 S4 已有原子提交的作者工作流，覆盖规划、正文及身份候选，不新增模型执行器或正式写入通道。

## 契约

- 提案操作绑定具体对象、候选修订和 Review；多个章节以对象 ID 区分，不按 `draft` 类型合并。
- Detail 返回该 Review 的事实候选和来源场景 ID，避免使用另一个同修订 Review 的事实列表。正文和身份内容仍来自不可变候选，不允许界面编辑预检证据。
- Preview 接收显式 `selectedOperationIds` 与 `selectionsByOperationId`，复用 Apply 的业务校验及确认事实来源闭包；在同一读快照内执行，不改变 head、Review 或事实。Apply 仍在写事务中终验，不将 Preview 当作一次性授权。
- Draft 的场景选择表示**确认事实的来源范围**，不是部分正文采用。正文操作采用整份候选；不提供会误导作者的“只采用选中场景正文”。事实可保持候选、拒绝或确认；只有明确确认的事实进入正式记录，确认必须选择其来源场景。
- 非正文候选使用空选择；身份采用仍走现有身份校验。未知字段、操作、场景、事实 ID 及非法决定拒绝，不静默忽略。
- 任一选择变化立即撤销旧预检可提交状态；异步旧响应不能覆盖新选择。项目切换、候选变化或作品变更重新读取。依赖缺失、来源过期、脏稿或运行中的任务不允许提交。
- 整组采用和撤销复用现有事务，确认事实及规划影响随组提交/补偿一起改变。后续正式变更仍禁止直接撤销旧组。
- 采用回执从持久化 application members 返回实际 `selectedOperationIds`。部分采用后的详情与撤销历史只标记实际成员，不能从提案原始操作列表推测哪些对象已采用；预检选择映射也只发送选中成员。

## 实施与验收

独立小说领域模块共享选择校验；Runtime/Electron 仅透传 Author 请求；React 面板支持按 Review 选取所有当前候选，逐操作选择来源场景及事实决定，并展示声明依赖。

必须验证：正文+规划或身份成组采用、显式确认/拒绝、来源场景缺失和伪造选择拒绝、预检不产生写入、来源变动后的终验拒绝、原子撤销，以及真实 React/Electron 的选择与过期响应行为。现有规划操作不保留旧 Preview 请求格式，所有调用方同步修改。

实施者按领域权威、事务并发、真实仓储证据、作者决策和交互五个视角自检；遵照用户要求单人实施，不组织独立评审。无旧代码/旧数据兼容层。此切片不证明语义依赖闭包、模型提案生成、反事实正文分支或 S4 整体完成。
