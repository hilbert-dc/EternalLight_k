# 事件条件与效果的来源解释

## 目标及推进顺序

S1 的完整目标仍包含跨来源前提、条件解释和状态演进。本阶段先建立可复用的
来源引用解释器，不以时间顺序冒充因果，也不执行模型提交的效果。随后继续
批准规则下的条件组合、状态迁移及真实语义验收；本阶段不代替它们。

当前 event 前提可引用严格前文章节、效果仍引用本批次非事件主张，统一使用
`{sourceBatchId:null|string,assertionIndex}`。单独 Rust 模块读取授权来源的
完整主张，而不是读取已经按查询时刻过滤过的 entries：否则事件发生时刚刚
结束的前提会被误判为缺失。只解释有来源 typed state 的有限区间；命题观察、
关系及人物认知暂明确标为不支持，不混用世界时间和认知时间。

前提使用事件开始的左侧区间：start < eventTime 且 end 缺省或 end >= eventTime
表示区间适用；start == eventTime 报告 startsAtEvent，不能假定同一刻的微观顺序。
未知事件时间或状态起点均报告 unknownTime，不补零、不做减一运算。
效果起点只分类 beforeEvent/atEvent/afterEvent；早于事件并不直接证明正文矛盾，
可能是维持状态或提取解释不足，交由模型和作者理解。事件结束不截短效果区间。

每条结果仅保留各侧 referenceIndex 和有限时间分类，由父事件引用确定来源，
无重复正文、身份或事实副本。报告标明 sourceBoundTemporalReferences、未推断语义真值、未认证全局
条件、未执行状态改变。适用不等于前提真实、无冲突或已确认；确认事件也不会
确认引用主张。空引用保持未解释，不作为无条件或无效果证明。

解释器同时接入知识投影和 Review 的事件元数据；当前/历史查询继承原来源、
世界时间、Reader/Writer 和预算边界。Review/确认终验复用事件校验，引用的
typed state 损坏必须失败，不能只核对证据形状。UI 显示有限时序说明及非执行
性质，不替代原参与者、来源和逐项事实决策。

序列化 UTF-8 字节；已有事件仍限 8,000 字节。模型可见组合项仍可能超过
1K tokens，列为 P0 实施者检查：复用现有查询/Context Pack 整包硬预算，
不改写历史、不增加工具或供应商执行通道、不追加无限嵌套引用。

测试须覆盖：前提结束恰等于事件开始、起点等于事件、未知/极端时间、效果
早于/等于/晚于事件、未解释与不支持类型、损坏引用状态；查询时刻已过滤前提
仍能显示同源时序；确认只改变被选事件，历史回放及 UI 不伪装执行结果。
无旧接口兼容、迁移、依赖或上游内核修改。文学正确性、跨源条件和全部 S1–S5
完成条件继续独立验证。

## 实现边界与查询成本

## 下一实施边界：批准规则的条件组合与状态演进

### 四值解释实施契约

Author/World 和审核共享只读解释器，读取正式采用的精确规则及身份修订。
独立于返回 entries、模型选中的 preconditions、世界时间查询裁剪收集所有
当前草稿或历史快照来源；按原正文完整验证实体与主张，不信任派生索引。
同一请求只收集一次。最多200批次、8 MiB原始来源，超限或待建模来源使
解释覆盖不足；这是保守全域界限，不能声称超限时召回了所有相关证据。
历史缺失 capture 或精确正文、来源实体种类冲突直接失败，不返回成立。

四值采用独立支持/反驳位：all支持全部/反驳任一，any支持任一/反驳全部，
not交换两位。缺角色不做空集全称成立。single属性可由不同有效值反驳
相等；multiple属性按成员关系解释，相等成员支持eq/反驳ne，其他成员
不证明该成员不存在。实体只按明确合并认定相同、明确distinct认定不同，
多值数值顺序比较没有成员量词，保持未解释，不冒充单值比较。
不把不同拼写的ID当作身份反证。自然语言例外、类型不适配、未知/同刻
起点保留未知，事件开始前采用左区间，不执行效果或自动确认关联主张。

证据结果保留精确批次/主张序号，可回查正文与独立确认；它仅解释来源
主张，不签发世界真相。每事件最多16证据引用、6 KiB报告，每请求最多
100,000次比较；证据/操作/来源缺失不得被截断后认证为满足。报告同时
保留观察到的四值和解释覆盖，只有完整覆盖下才给出最终四值，否则最终
为unknown。受限视角不运行解释器或披露全局报告。该实现不等于状态
迁移、文学正确性、真实供应商或S1–S5全部验收。

实施者五视角自检（非独立评审）：共享来源和规则权威、四值与开放世界、
真实仓储/HTTP及UI、作者对话流程、不伪装真值；不增加兼容层、数据库、
供应商执行器、依赖或上游内核修改。测试覆盖未选反证、规则采用/撤销与
快照、all/any/not、参与者量词、多值/身份、时间/例外/预算/来源损坏。

可检查实现单元：领域来源收集/四值解释及独立逻辑测试；查询/审核适配、
类型/UI及真实HTTP流程测试。二者共用原权威链，不构成两套执行器。
P0形状检查：16条较长Unicode批次引用、较长规则/身份修订及最大来源计数
的报告为3,910 UTF-8字节、2,136安全预算tokens。报告本身硬限6 KiB，
没有原文副本；Context Pack仍整条移除可选知识项并标记裁剪，query_story
继续受原整包界限约束，不通过扩大预算保留报告。完整组合、工具参数与
多会话总预算不由该压力样本认证，仍属原目标待办；不改写模型历史。

### 前序切片：有界规则表达式进入原作者采用链

同一个 `propertyRules.payload` 必须包含 `definitions` 与 `eventRules` 两个
数组，不提供缺省旧字段或格式转发。属性定义仍最多 64 项；事件规则最多
16 项，按 `eventType` 唯一，类型键 80 字节、说明 512 字节、例外最多 8 项
每项 256 字节。每条事件规则为 `eventType / description / exceptions /
condition`。整份 payload 仍限 16 KiB，每条事件规则限 4 KiB。

condition 的有限 AST：`{type:all|any,conditions:[...]}`、
`{type:not,condition:...}` 或 `{type:state,role,subjectKind,predicate,
quantifier:all|any,operator:eq|ne|lt|le|gt|ge,operand}`。深度最多 4（根为 0）、
每规则最多 31 节点、all/any 每组 1–8 项。叶子必须引用本次载荷中已定义的
主体种类/属性，主体种类须符合事件角色；不从名称猜实体。operand 为
`{type:boolean|integer|text,value}` 或 `{type:participant,role,quantifier}`。
数值顺序比较只接受 integer，规则整数 operand 限 JSON/Renderer 可无损表达的
安全整数 ±(2^53−1)，Rust 与前端同限，避免比较常量被隐式舍入；实体比较通过参与者角色参数化，不硬编码
人物 ID，角色与所引用实体种类必须一致。未知字段、空组、脚本和无限嵌套
不进入候选，更不进入采用。文字 operand 是数据，不是程序。

本切片一次同步 Rust 校验/修订载荷、原 Codex/MCP 对话生成、冻结输入分页、
IPC、Renderer、fixture 及真实仓储/HTTP/UI 测试。已有结构规则编辑保留事件
规则，界面展示有界表达式并允许明确移除；新增事件条件默认通过对话生成，
不要求作者手填 AST。采用/撤销仍沿原账本，候选不成为规则权威。

这个切片只提供可校验、可采用的规则语言；当时条件解释标记未执行，
不因规则采用、表达式合法或时序适用签发满足证明。下一切片必须收集同一
快照内必要来源和反证，产生四值解释及只读状态演进，原 S1–S5 目标不变。
这不是另一套阶段计划或缩减完成条件。

该阶段 Author/World 查询披露正式 eventRuleCount 和 declaredNotInterpreted。受限视角
沿原 propertyRulesPolicy=withheldForLimitedPerspective 声明两类规则均未披露，
不返回事件规则计数或重复声明；零不是“不披露”的替代值。这样保持已有
20 KB 上下文预算、权限边界和必需输入，不因重复元数据而拒绝原合法任务。
