# 显式依赖传播规则与预算隔离

目标：落实 S4 类型化、版本化的传播规则。普通关系图不是依赖图，影响分析不得先扫描地点、归属等关系再过滤，否则它们会消耗边、节点和结果预算，挤掉真正的依赖路径。

## 设计

- 小说领域维护固定的、不可由模型执行任意表达式的规则集。首版保持现有八类出向依赖：causes、enables、prevents、motivates、foreshadows、paysOff、reveals、inputDependency；报告携带规则集版本，每条路径边携带规则 ID。
- 关系图实现共享来源、身份、历史快照、时间和认知校验；私有类型化遍历策略区分普通关系与显式依赖。依赖策略在 SQL 邻居召回的 LIMIT 之前过滤类型，非依赖节点不进入下一层 frontier。普通关系 API 的行为不变，不新增第二个图执行器。
- 全部已有路径、节点、字节、结果上限保持有效；独立来源路径不合并。规则只说明某类候选依赖需要复核，不把路径当作新事实，不自动修改正文或正式指针。
- 规则版本绑定本次运行的静态规则集，未来规则改变须改版本并重算报告。当前不允许作者/模型自行修改规则，不承诺语义依赖、反事实全文重算或全书影响完备。

## 验收与自检

使用公开仓储保存正文、创建真实建模任务并发布来源，生成超过邻居上限的非依赖边；真正因果链仍须完整返回且只统计依赖边。验证普通图保留非依赖关系、历史来源冻结、当前源失效、路径截断仍不标为完整，以及 Runtime/真实 Electron 展示规则版本。严格 Clippy、完整回归及格式化。

实施者按架构边界、SQL 与预算、真实仓储证据、作者可理解性、UI 来源展示五方面自检，不召集独立评审。无新依赖、schema、旧格式兼容或上游内核修改。

## 2026-09-26 验收记录

真实生产仓储的集成 fixture 保存 12 章、绑定建模任务并发布 1,080 条地点关系，另含非依赖桥接和真正两跳因果链。普通关系图报告边预算截断；显式影响仍完整找回两个依赖边，仅统计这两个扫描边。来源变更后当前结果撤销，冻结快照仍重放原始链路；一条结果上限如实报告不完整。公开 HTTP 返回与领域结果一致，查询不移动 head。真实 Electron 测试展示规则版本并保持脏稿失效与来源证据。
