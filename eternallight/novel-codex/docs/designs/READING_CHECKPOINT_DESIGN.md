# 任务内长篇阅读检查点

## 决策

将原文阅读的连续进度保存为既有 WorkStep 的有限候选记录，由当前 Codex 根 Agent 显式调用 `checkpoint_reading`；`query_story` 仍是只读，不隐式写日志或改变 Canon。`read_reading_progress` 返回该步骤唯一阅读流及可继续的计划。不新增调度器、供应商 SDK、独立 Agent 生命周期或旧格式兼容。

本检查点解决任务暂停/新 Attempt、进程重启和确认回执丢失后的已知页进度；不提供模型 token 无损续推，不证明模型真正理解了所有原文。子 Agent 继续独立使用原有只读检索，不能推进根 Agent 的检查点。本轮不把持久进度替代文学质量、人工金标、全局知识审计或双平台验证。

## 契约与权限

每个 WorkStep 只有一个阅读流，问题与 QueryStep ID 首次冻结。检查点请求包含单步 literal `passages` 计划、已收到报告的 `reportHash`、`expectedVersion` 和至多 512 UTF-8 字节的候选摘要；问题至多 512 字节。Runtime 在显式写事务中重新执行同一计划，核验完整报告摘要、页完整且未裁剪，以及任务、步骤、来源和权限。模型不能上传自造报告或任意“已读范围”。初始页必须 `cursor:null`，后续页必须精确承接此前下一游标；不能跳到后部再声称连续阅读。POV 缺少原文认知证明时拒绝建立检查点。

模型摘要只是本页判断，不是事实确认或全书摘要。最多 10,000 页，沿同一 WorkStep 的新 Attempt 不重置页上限；模型预算仍归既有 Engine/Task。持久记录只保留最新有限摘要、计数、来源/权限摘要、下一游标及回执，不积累整书正文或无界模型上下文。

读取和保存均核对当前 Attempt 是该 WorkStep 的活动 Attempt，父任务/步骤正在运行，凭证、输入和来源仍有效。恢复只能由现有 WorkTask 控制创建新 Attempt；相同步骤/问题/权限与来源一致时，为当前 Task/Thread 重绑定旧位置。来源变化返回 stale、无摘要/可复用游标；不能以另一任务、另一作品、改变范围或旧凭证取回当前进度。读请求不会授予恢复权、补满预算或自动消费页面。

版本 CAS 串行化并发推进。同一任务的完全相同请求允许回执丢失重试；不同摘要、页、任务或旧版本不得覆盖记录。数据与 Host recovery operation 的提交证明在同一事务，失败一起回滚。显式阅读写入不产生小说产物，因此不触发普通任务的“部分小说输出”阻断，但失败/未知工具回执仍由原恢复账本处理，不自动重发或猜测成功。

## 完成语义

只有从初始页连续确认、直到范围末尾，才显示 `acknowledgedTraversalComplete`；它表示服务端核验了连续页来源，根模型声明已处理，而非语义质量认证。`semanticCompleteness=unknown`、`modelJudgmentVerified=false` 始终保留。阅读检查点不改变 Task 完成条件、正式指针、作者锁定或 Canon。暂停/取消后记录保留，新请求仍受既有状态门禁。

## 实施及验收

Rust Core：独立小模块与当前 schema；共享查询执行拆出事务内内部入口，不允许嵌套读事务承担写入。Runtime：公开能力绑定的显式 GET/POST 入口。MCP：根 Agent 的两个有限工具与恢复元数据；宿主公共提示指导先读取进度、按返回计划继续，完整页收到并分析后才记录。默认环境及类型/fixture 一次同步。

验证覆盖：完整连续链、无跳页、摘要/CAS/回执重放、源/权限/作品/活动 Attempt 隔离、暂停/恢复及重开、裁剪与 POV 拒绝、页预算不重置、原文/正式数据不变、晚期写失败回滚、真实 HTTP 和真实 Codex/MCP/Runtime 回环。UI 进度呈现和真实供应商自主恢复需各自证据，不能由结构测试签发。

依用户要求由实施者单独完成五视角检查，不召集评审：架构保持一个 WorkTask/Engine 任务链；技术 A 核验事务、身份、游标和来源；技术 B 覆盖公开接口、恢复证明和一次性契约切换；产品明确中断可继续与未知范围；UX 不显示假“全书理解”。零兼容门禁通过，无新增上游内核改动或依赖；当前 schema 直接建表，不写旧库升级、回填或双轨逻辑。

## 当前实现与验证记录

Rust Core 的独立 `reading_checkpoint` 模块已落地。查询执行复用事务内私有入口；单个有限最新状态的编码上限为 12KB，摘要与问题分别最多 512 UTF-8 字节。保存重新生成完整报告并核对 contentHash、连续位置和版本；最新状态有完整性摘要，损坏时失败，不猜测修复。Unicode 字符计数复用原文分页的重叠常量，不重复累计交叠范围。达到页上限但未到末尾时返回 budgetExhausted、无 resumePlan，不能靠新 Attempt 重置计数。

公开 Runtime GET/POST 入口为 `/api/projects/{projectId}/tasks/{taskId}/reading-progress`。原生 MCP 已提供 `read_reading_progress`、`checkpoint_reading` 两个根工具；公开 Runtime 也检查工具身份中的根/子 Agent 归属。宿主公共提示包含恢复、保存、裁剪重读和候选摘要说明；只有读取工具进入只读恢复分类，保存仍必须由原账本回执证明提交。未扩大子 Agent 权限、正式内容写权限或模型调用路径。

6 项新 Core 集成测试覆盖连续链、准确字符累计、跳页/伪造报告哈希拒绝、重复回执、冲突 CAS、数据库重开、新 Attempt 恢复、旧凭证拒绝、源变化隐藏进度、摘要 UTF-8 上限、跨 Attempt 页预算、存储损坏及晚期回执失败一起回滚。Runtime 原文测试现为 4 项，新增公开接口完整页、裁剪、任务身份、完整子 Agent 元数据及 POV 拒绝；原生 MCP 现为 9 项，新增根步骤权限测试。

真实 Codex/Engine/MCP/Runtime 受控回环完成原文首段 → 保存检查点 → 读回进度 → 从下一游标读取 → 语义候选重排 → Context Pack；并通过 Author-only 恢复快照确认 checkpoint_reading 的真实 committed 回执、线程身份和请求摘要，读取工具不伪造写入记录。该回环使用可控供应商响应，证明生产工程链路，不证明实际供应商自主理解或恢复能力。

最终 `CARGO_NET_OFFLINE=true npm run verify` 终态退出码 0：构建、两轮完整原生回归、引擎/委派/发布回归、146 项宿主测试和 12 项 UI 测试通过。严格 native 工作区 Clippy 退出码 0。验证过程中同步了新增 MCP 工具清单，并将身份绑定错误测试对齐当前 `400 invalid_request` 契约；未通过放宽权限或保留旧清单解决失败。既有前端约 4.07MB 的大包体警告仍存在。

实施后五视角自检：架构未新增调度/模型执行权威；技术 A 的页链、来源、CAS、字节预算和事务回滚有领域证据；技术 B 的公开接口、真实内核调用和恢复回执有集成证据；产品获得有限阅读进度恢复而不是小说内容自动采用；UX 不宣称全书语义完成，不生成虚假百分比。上述是实施者自检，不代表独立专家评审。
