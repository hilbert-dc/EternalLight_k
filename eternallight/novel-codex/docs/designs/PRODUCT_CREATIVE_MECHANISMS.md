## 1. 产品决策：同时建设质量底线与创作深度

创作下限是作者更稳定地得到符合本次要求、人物行为与前文可理解、可继续修改的作品；还包括不丢稿、不混淆事实与猜想、明确暴露未完成检查。文学上的下限由具体作品诊断，不能由 schema、测试数或模型 PASS 数代替。

创作上限是作者有机会发现有辨识度的情节机制、复杂的人物选择、恰当的信息安排、长期呼应和自己的表达。评审应保护有意识的留白、缓慢、反高潮与陌生方案；文学分歧不应消灭这些选择。我们验证的是在特定任务中提高获得优质结果的机会，不承诺测得作者或模型的绝对上限。

产品允许后台存在多层规划、多角色评审、主动取证与有限修订。作者通过自然语言表达目标、范围和取舍，默认看到作品、重要变化和仍需决定的问题；不承担逐席开会、逐字段填表的负担。作者可从构想、大纲、卷纲、独立片段或已有正文进入，也可以一直不建完整目录。

## 3. 四条端到端作者旅程

### 3.1 同一作品连续三次推进

第一次：作者给出片段，直接获得并编辑工作稿，不要求先定书名、卷数和结局。第二次：“先保留这一版，接着写下一场”，系统保存确切选择后，以选定版本和允许使用的前文启动续写。第三次重新打开，恢复已保存稿件、未决问题和上次继续点，作者修改人物动机后再创作，无需重复讲整本书。

“保留并继续”是一个作者意图、两个有序结果：先保存工作基线决定，再启动生成。保存冲突时不启动；启动失败时保留选择和待续意图。重启只恢复状态，不自动重新调用模型；用户主动继续后检查凭证、许可与剩余预算。界面清楚区分已保留、启动失败、已保存部分稿和结果未知。

### 3.2 在投入长篇正文前审清结构

作者：“审全书大纲和第二卷，保留结局，把第二卷改得更能写。”系统解释本次范围并沿已授权目标执行；宏观阶段不要求补齐每章细节。独立角色检查全书重复、第二卷人物行动、前后卷承接和阅读期待，交付值得保留的设计、关键问题及分歧。修订不超出本次可改范围；超出时保留具体提案供作者决定。

只读 P1 可以在正文尚未产生时成立；不能把“先写出正文”作为审纲前提。P2 可依据已认可作者要求和规划之间的冲突修订规划，不必伪造正文证据。关键机制是否能写成场景，可再由作者选择 AC-2.1 短试写验证。

### 3.3 好创意在扩写中被削弱

作者选中的设计是“女儿用一件旧物试探父亲，父亲的回避进一步破坏信任”。扩写只剩旁白解释人物关系。系统引用原意和确切正文，提出“缺少可观察的试探与回应”的疑点，同时保护作者喜欢的冷淡对白。作者可补写动作、保留原表达，或明确改变原意；不能因为未出现某个关键词而判失败。

### 3.4 跨章关系与长期承诺

“父女信任破裂”关联第一、三、七章的具体片段；第七章准备和解时，系统能取回第三章尚未回应的背叛。它可以提示和解缺少承接，不能自动宣布人物已原谅。作者选择补写、保留突变作为谜团，或修改计划。正文修改后旧关联保留为历史定位，重新确认后才成为新证据。

## 4. F1／F2：可持续的创作依据

### 4.1 作者选定工作版本

Codex 当前已支持目标章的冻结候选来源；缺口主要是前章和跨规划对象仍以正式采用版本取材。F1 增加作者明确选用的工作版本集合，复用现有不可变修订，不能自动以最新 AI 候选替代正式前文。每项标明来源类别、修订、适用范围和作者选择。

同一目标只有一套有效来源解析规则：作者明确指定的本次来源优先于其已选工作版本，未选择的对象按原正式来源处理；所有材料仍须符合任务许可和知情边界。Outline／Plan／正文的依赖必须可解释，不能把互相冲突的“各自最新版”默认为一致。缺少必要关联时明确待核对，不补造正式承诺。

作者编辑已选用工作稿后，保存新修订可推进该对象的工作选择；任务启动时冻结确切修订，正在运行的任务不追随头部变化。选择工作稿不更新正式正文、规划或世界事实；文中角色谎言也不自动成为客观事件。正式采用继续走现有 Review／AcceptanceCommit。

### 4.2 取证与快照

F1 抽出主文档 CreativeInputSnapshot 的共享基础，供试写、规划评审与修订使用。先按用途、POV、阅读位置和当前许可投影，再在一致的版本视图内保存实际输入、引用、摘要哈希、材料类别与遗漏；不能只保存引用并在执行时回读任意最新内容。

F2 加入有界的作品内研究：由明确问题定位原文，例如“第十二章是否已让女儿知道身份”。先得到允许访问的版本目录，再按受限查询读取；每个 SourceReceipt 记录问题、所用索引版本、原文修订与范围、内容摘要、是否截断及许可。索引只是找资料的入口，判断要回到授权原文。未命中、只读到目录或不相关材料不能算完成取证。

时序统一为：固定材料版本视图 → 有界检索 → 封存实际证据包 → 生成或评审。两案实验的研究在共同快照封存前完成；A/B 不能各自从实时作品引入不同新事实。若评审后需要补证，建立有界的新输入修订并明确哪些报告失效，不能悄悄扩充旧快照。检查者必须得到生成者实际使用且其检查用途允许读取的来源；超出其权限的部分明确交由另一有权任务检查，不能伪装覆盖。

为作者约束、确切目标正文和本次必须检查的证据预留容量；可选例子优先省略。硬材料放不下时缩小范围或分批，不能通过删除关键证据显示“全书通过”。Unicode 字符数、UTF-8 字节和模型 token 各自计量；保持当前安全上限，最终请求组装后再次检查，而非以字符数冒充 token。

用途、来源授权或可见范围变化时，撤销相关活跃任务能力，拒绝新增读取、存稿和完成；旧会话不可用于续跑，已保存成果仍可查看。普通作者编辑使结果需要重核，不允许晚到回包覆盖作者的新稿。不能追溯撤回此前合法发送的内容。

### 4.3 知识类别和不确定性

语义性质、认知状态、可见性为正交维度。复用现有 world／reader／character／author-secret 与 unknown／suspected／known／false 及位置规则；增加面向作者的“安排”“假设”“明确未知”说明及其来源。模型可以提出分类建议，未经作者确认不升级为正式事实。不要仅按材料来自正文还是大纲判定真伪；正文叙述也可能是不可靠叙述或人物转述。

规划顾问与当前位置模拟读者使用不同任务用途和输入。全书梗概可用于规划体验审阅，但包含终局的梗概不能用来声称当前读者会产生何种悬念。单个字段的标签不能替代服务端权限投影。

## 5. P1／P2：长篇规划深度评审

### 5.1 启动与层级职责

入口包括作者主动审纲、准备新卷、终局方向变化、关键关系改向、长线承诺兑现及出现跨卷复位线索。系统可提出一次相关建议，不在每次保存后自动开会。短篇、日常片段、无结局作品均可跳过。

| 对象 | 主要评审问题 | 不得强求 |
| --- | --- | --- |
| 全书大纲 | 核心体验、人物长期选择、承诺与终局条件、跨卷差异及因果累积 | 远期每场戏、固定卷数、未确定真相 |
| 卷纲 | 本卷存在理由、入口／出口、谁主动行动、资源与知情渠道、事件后果与邻卷接口 | 每卷升级、反转、不可逆损失或统一长度 |
| 故事单元／近期计划 | 关系或事件如何变化、场景是否能承担选择、依赖是否成立 | 所有单元都按同一冲突模板 |
| 关键场景试写 | 纸面设计是否能成为动作、对白、信息安排和阅读体验 | 逐字遵纲或通过模型文学总分 |

只检查当前阶段已经具备的材料。全书“规划已检查”与全书“正文已读完”是不同声明；每份报告列出实际覆盖对象、未读范围及无法判断项。分批阅读保持同一来源版本；缺一批不能称全书检查完成。

### 5.2 独立角色与分歧

首期评审方案从三类角色选用必要的两类，深度模式可同时启用三类；人数是首轮产品上限，可由后续验证调整，模型不能自行增员。专业题材关注点进入相关角色职责，不默认再增加常驻代理。

- 结构／因果：前提、行动、结果、状态承接、重复和终局所需条件。
- 人物／主题：独立目标、误信、可选行动、关系代价、选择如何体现作品关注的问题。
- 阅读体验：承诺、信息释放、节奏、情绪与回报；明确是全书梗概顾问还是受限位置读者。

第一轮不读取其他评审的报告、生成者自评、预评分或推荐排名；各自读取适合职责的材料投影。独立会话不等于不同模型或真人独立判断，文档和界面不能夸大。综合顾问同样具有独立用途和授权投影；聚合不解除原报告的权限。含作者秘密的诊断可供获准的作者／规划视图使用，不能经综合稿、修订建议、缓存或后续提示反向注入受限读者任务。

检查覆盖与问题数量分开：任务输入冻结本席应检查的对象／作者要求 ID、内容摘要、职责和来源版本。报告逐项返回已检查、无法判断或未检查及依据；Runtime 核对完整 ID 集合、目标修订、来源权限和引文定位。最多六条意见只限制发现数量，不缩减应检清单；漏项、协议错误和截断均标 incomplete，不能折算为通过。超大清单需预先分批并记录未完成批次。

每条意见包含具体证据、观察到的现象、可能原因、影响、建议修法、需保护的有效内容及不确定性。阅读体验角色可只报告症状与证据，原因、修法和保护项允许未知或不适用，不能为字段完整而编造。读者反应先作为症状，诊断顾问再结合合法作者要求分析原因；所谓“作者诊断角色”只能给建议，不取得真实作者决定权。

只对同一证据和同一命题合并重复意见，不能仅因 criterion 或目标字段相同就当作共识。存在证据争议时允许一次定向复核；审美分歧保留为取舍，不通过多数投票、双席 AND 或平均分强制统一。查不到证据的意见标 unknown／不成立，禁止用任意原文开头补造锚点。

### 5.3 有限执行与交付

P1 首期只读：最多三席各一份报告、一份综合建议、至多一次有目的的争议复核。每席最多六条意见，综合视图默认显示最重要三条并允许查看全部；技术错误与关键方向变更独立显示，不被摘要上限隐藏。没有实质问题时允许无意见，不为凑数继续调用。

P2 在明确“审并改”的授权内，最多一轮限定范围修订和一轮影响复查；报告、修订候选与复查结果分别保存。未解决问题、预算不足或改动超过权限时交付已有结果与具体选择，不无限循环到所有角色满意。单独“审一下”不授权改稿。

角色之间可以按当前单活跃任务约束顺序调度；独立阅读不要求并发。未来并发只改变执行方式，不改变共享材料、隔离和总预算。复核预算在开始前预留，生成阶段不能先花完全部预算。结构化协议失败属于检查故障，不能转成作品质量缺陷。

交付包含：原规划与候选差异、值得保留的内容、优先问题、争议及建议取舍、各项处置、覆盖与未完成项。作者可保留原案、选择修改、暂缓或驳回；高风险的好设计不因评审低分从候选列表消失。

### 5.4 与局部改纲和正式采用衔接

P1 的 ReviewFinding 是建议，不能冒充已有 Review／AcceptanceCommit 的正式接受清单。P2 将选定意见编译为 PlanChangeProposal，复用基线版本、锁、候选头 CAS 和采用回执；不得另建一套“评审通过即正式发布”的写入路径。

规划证据、作者要求、已采用正文、未采用正文要分别标记。规划证据可支持“这个安排与另一个安排矛盾”的提案，不证明事件已经发生。正式采用基于未采用正文的变化仍须先采用证据，或使用 AC-2.2b 同次原子提交。依赖未采用规划的提案也必须与该规划同次采用或先使依赖成立。

P2 首期只改已有 Outline／Plan 节点字段，复用 AC-2.2a；跨产物依赖使用 AC-2.2b。可以审查全书范围，但每次修订范围单独冻结；超出当前可改范围的建议保留在报告中。新增／删除／拆并／重排结构以及全书路线重建仅作为提案，不伪装首期已支持，后续单独设计身份与来源映射。

真凶、人物生死、核心关系、关键揭示时机和已保护意图的改变要独立显示并由作者决定；锁定原文须明确解锁。修后复查原问题和实际依赖，不仅看左右邻卷；已知远距依赖也在范围内。未读依赖显示未知，不能只检相邻卷就宣布全局安全。

## 6. 探索、人物与创意兑现

### 6.1 让候选在机制上有实质区别

AC-2.1 仍最多两个短案。差异可来自目标倒置、不同角色的主动选择、信息误读、制度压力、反制或失败后的可继续路径；题材标签和换地名不是充分差异。先描述这个事件为什么依赖本作品的具体关系和规则，再组织场景；不强制先补齐庞大人物百科。

一个方向可保留作者原案，另一个探索较大变化；也可以全部来自作者。高偏差不等于自动改掉硬事实。第一轮比较隐藏生成者标签和预评分，保留具体代价与理由；不按单一加权分自动淘汰。作者可以全部拒绝或手动组合，原案与来源保留可追溯历史，不因落选自动删除；作者删除、撤回来源授权及保留期限按统一策略执行。选择不会自动传播成永久偏好。

### 6.2 人物拥有自己的行动逻辑

人物顾问按当前问题检查：公开目标与私欲是否冲突、人物知道什么、误信什么、拥有哪些筹码、遭遇反制后还有什么选择、缺席后会因什么重新行动。配角和对手可以主动改变局势，不只作为主角资源。系统推测的动机保持假设，不用“未公开需求”之类默认值伪造人物内心。

这些是诊断问题，不是每人必填字段。独处、环境推动、观察性叙事不因行动者不足两名而失败；功能人物不必都有跨卷成长；人物选择可以通过动作、迟疑或拒绝显现，不强求显性心理解释。首期作为 P1／Q2 的限定职责，不建立全员自主模拟系统。

### 6.3 选定意图进入正文

Q2 支持作者明确选定的少量 CreativeIntentAnchor，记录目标机制或体验、来源与版本、适用场景、允许变化和保护强度。锚点可从选择方案时明确保留的要点产生，不把模型整份候选说明自动变成硬约束；不得强制每章都有选择、牺牲和反转。

检查结果为已观察到、部分、未观察到、证据不足，并附原文与解释。“未观察到”需要注明实际阅读范围；截断资料不能证明全文缺失。引用匹配只是定位验证，语义兑现需要独立判断。作者可以保留原文或改变原意，不能被旧模块固定的 hard 标志锁死；涉及既有保护才进入方向变更流程。

修订任务携带问题清单和 PreservationSet：确切原文锁沿现有锁机制执行，需保护的声音、意象、留白属于语义保护意图，不能谎称字节相同就已保护。未点名部分不顺手重写；复查同时检查原问题和亮点是否受损。原证据文字消失只表示锚点变化，不等于问题解决。

## 7. N1／N2：单元、承诺与滚动规划

N1 建立单一故事单元身份。当前 OutlineNode.kind=unit 与章节 primaryNodeId 可复用为起点；目录归属、单元关系和文本证据是不同关系，不能再建一个同名权威实体让两套状态漂移。单元可独立存在，只填标题即可；一个单元关联多章多段，一章服务多个单元。

文本链接包含真实修订、场景／段落身份、精确范围和关联类型，例如展开、回应、完成或引用。编辑新增链接采用显式追加／替换，不能像源工程部分 UI 一样用新选区静默覆盖旧 links。改写、拆分或重排后保留历史定位；重定位须有新旧映射和明确确认，模型不能把相似文本当作同一证据。

N2 在单元或已确认承诺上记录读者具体问题、已给信息、未来计划、可调整的兑现窗口、推迟可能造成的影响及正文证据。计划“第五卷揭晓”不等于已兑现；自动提取只形成建议。作者可确认推进、选择延期、转义或放弃，并说明影响，不因超过一个数字窗口强制制造事件。

当前卷可以细到行动，近卷保留备选路径，远卷只保留功能、前提和出口。卷长服从内容承载量；重复可以是有意识的形式选择。工具的相似度或状态字面差异只能触发核查，不直接判“换皮”或“倒退”。进入新卷、完成关键单元或改动长程方向时再回看前缀；无需每保存一次全书扫描。

N1 的手动关联与历史定位可先交付；N2 的自动建议、兑现诊断和长期观察必须独立验证。全书自动改纲、自由分支模拟和外部发表不属于这两个阶段。

## 8. 工程落点与契约边界

以下为目标领域责任；其中 WorkingBaselineSelection、CreativeInputSnapshot 与 PlanningReviewRun／ReviewFinding 已发布首个闭环，其余名称仍是设计占位。后续继续优先复用已有修订、事实、任务、审阅与回执。

| 对象／责任 | 最小必要信息 | 归属与限制 |
| --- | --- | --- |
| WorkingBaselineSelection | 作者、对象及修订集合、依赖、适用范围、选择版本、后续意图 | Runtime；仅作者选择，不推进正式指针 |
| SourceReceipt／CreativeInputSnapshot | 授权投影、实际文本、查询与来源版本、遗漏、预算、策略与模型配置 | Runtime；检索、生成、检查来源可追溯，保持用途隔离 |
| PlanningReviewRun／ReviewFinding | 层级、范围、材料快照、角色、证据、问题、分歧、覆盖和完成度 | Runtime 独立模块；只写意见，不直接写正文与正式规划 |
| FindingDisposition | 接受建议／驳回／暂缓／需补证、理由、作者或顾问身份、关联提案 | 顾问建议与作者决定严格区分，不伪造共识 |
| CreativeIntentAnchor／PreservationSet | 作者选定意图、来源、范围、保护级别和版本 | 复用保护与锁；不得成为另一套世界事实 |
| NarrativeUnit／EvidenceLink | 单一单元身份、目录关系、多个版本化原文锚点 | 复用规划身份或定义唯一新身份，实施设计消除双权威 |
| DeliveryReceipt | 持久化成果、哪些检查完成、哪些缺失、版本及继续点 | 复用 task outputRefs；unknown 不写成成功或零消耗 |

现有 service.py 负责保存、审阅、采用和上下文，generation.py 负责任务目的、目标与完成，planning_bindings.py 负责章与规划来源绑定，context_limits.py 负责有界组装。新增职责用独立模块承接，提取必要共享校验；不把更大的流程塞进 service.py、Electron main 或主 React 组件，不将小说业务放进 codex-core。

Electron 复用单活跃任务与 handoff；新增窄操作及显式交付类型，保持允许的输入和输出归属。Renderer 复用编辑、差异、未保存保护与错误组件；不将内部角色 ID、协议字段或 token 计算放进作者必经操作。

所有执行计划覆盖角色、综合、补证、修订、复查、失败重试的预算。应用尝试、AppServer turn、工具读取、墙钟与底层模型请求分别计量；一次 turn 可能包含多次推理。当前 Adapter 未完整观测的模型请求数、token 和费用记未知，不宣称已实现底层硬上限；承诺硬上限前必须在执行层可强制。不能将两案各一个任务写成只消耗两次模型调用。新增模型可见材料须有分片与总量硬限；遵守仓库上下文规则，可能超过 1k token 的新单项在实施设计中列为 P0 人工审查项，任何单项不得超过 10k token，不能用总预算替代单项检查。具体上限在阶段设计时冻结，禁止运行中由模型扩大。

协议、schema、类型、fixture 与文档在同一阶段同步调整；测试数据库按当前格式初始化。删除无消费者旧逻辑前核对引用，不引入历史兼容、回填或双轨。产品方案通过不替代各阶段五角色实施设计门禁。

## 9. 验证上限、下限与代价

沿用主文档 Q0 的等预算当前 AC-1 对照、独立保留任务、作者与读者评价，以及真实默认配置成本报告。严格的等模型预算结论需要底层请求与用量可观测；缺少时只能报告应用尝试／turn／时间边界下的结果，明确不能声称等算力。每次只增加一个机制，另做移除单一机制的对照；不能把整套升级的差异归因于多代理。

| 目标 | 主要证据 | 反作用与失败样本 |
| --- | --- | --- |
| 下限：明确要求与叙事连续性 | 独立人工判读的约束违背、知情穿越、无依据行动、断裂接口；故障注入验证不丢稿和完整状态 | 所有预定任务保留分母；检查不足、空交付、过度阻断、错误事实采纳分别报告 |
| 上限：有价值的新发现 | 匿名比较同目标作品，作者指出想保留的新机制、人物选择、呼应或表达；读者给具体片段理由 | 原案被误劝退、陌生方案被磨平、平均拼贴、审美趋同与声音受损 |
| 修订价值 | 独立核查问题是否解决、保留项是否受损、是否产生新问题，记录最终作者选择 | 引文消失、模型改分或反馈关闭次数都不等于修好 |
| 使用代价 | 同书三次推进的重复解释、审阅时间、等待、实际用量和恢复负担 | 只统计成功运行、只报选中最佳稿、隐藏失败成本 |

扩充现有开发与冻结保留任务类型：人物关系、悬疑与知情、安静／非线性、跨卷重复、长线兑现、工作稿跨次续创；各类包含有意非常规且无错误的对照。质量下限同时报告失败尾部及其严重程度，上限报告预先规定选择规则下获得有价值结果的比例与偏好，不使用事后挑出的最高分代表提升。

评审器单独验证：植入已知问题并保留无问题原案，检查漏报、误报、证据与结论不相符、角色间重复和分歧；生成器与评审器不能互相宣布通过。机器判定只用于可靠性和预筛选，真实作者／读者是未执行的研究计划，不以本轮 AI 角色评审替代。

所有扩大默认使用的决定都要求质量与可靠性两类出口满足，并守住作者控制与成本边界。样本不足标证据不足；增加角色没有收益时减少或改换职责，不能无限增加修订次数。
