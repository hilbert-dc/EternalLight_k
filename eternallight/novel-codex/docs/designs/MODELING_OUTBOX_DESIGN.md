# 正文来源新鲜度记录：保存即时、语义理解按需

当前契约：手动保存只持久化正文并更新依赖状态，不创建模型任务。智能体在已授权的对话任务中决定是否需要提取知识，通过 `request_candidate_task` 请求准确绑定已保存正文的 `modelKnowledge` 工作。

## 确定性数据维护

- 每作品/main/正文对象唯一一行；当前选中正文变化与失效记录同事务提交。连续保存合并为最新来源，保留首次和最近编辑时间。
- 跨来源认知依赖失效时，同事务标记受影响对象。未分析的来源保留 `pending`；不把缺失或过期知识当作当前事实。
- 发布知识时，只有匹配当前来源的有效批次能确认该记录。迟到、失败或过期批次不会确认新正文，旧证据仍可追溯。
- Author-only `GET /api/projects/{projectId}/modeling-outbox` 返回有界来源新鲜度记录，`authority` 为 `sourceFreshnessOnly`。分页使用读快照，游标绑定代次水位；变化后旧游标失效。
- 记录不提供 `due`、派发许可或自动任务预算。`originSnapshotId` 仅表示来源出处。

## 语义分析的责任

Electron 不再定时消费正文保存事件；自动建模消费者、派发 API 和专属 domain-task 授权表及分支已删除，没有替代空实现或兼容路由。通用 `setWorkspaceContext` 只向仍需要当前工作区状态的章节结构影响检查传递作品与编辑状态。

智能体根据创作任务选择分析。对话请求记录准确的章节和来源，Host 解析建模批次；子任务继承原工作授权和有限预算。源版本、任务能力、写入范围、预算和暂停/取消仍由程序验证。分析失败或跳过不能声称检查成功；已保存的正文可以继续使用。通用任务恢复重新核对已发布批次的当前来源、发布任务和活动知识头；知识头缺失或过期时禁止把它当作未发布任务继续重试，尚未发布的有效批次仍可按原授权继续。

删章等结构变化后的影响检查仍保留自动触发，这是作者已确认结构操作的反馈责任，不属于保存后强制知识提取。

## 验收范围

- 来源记录测试覆盖同事务保存、回滚、幂等、合并、重开、源变化、发布确认、迟到拒绝、跨作品隔离与游标失效。
- 真实 HTTP 测试覆盖手动改稿后没有新任务、准确的待分析来源，以及对话显式请求分析后的来源约束和原预算继承。
- 通用已提交知识产物恢复测试仍覆盖进程重启、失败回执和不重复消耗预算；测试以作者授权的普通任务创建，不经过已删除的自动派发。
- 工程直接使用当前 schema；不提供旧数据库升级、回填或旧 IPC 兼容。
