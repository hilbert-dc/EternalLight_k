# 有界创作策略

## 目标与非目标

把 EternalLight 的优秀创作方法落在本工程现有 Codex/MCP/候选/作者采用链路中，不另建 Agent OS、强制角色流水线、文学总分或自动发布权。以作者意图为边界，探索机制差异，检验原文证据，保留审美取舍和未完成项。

参考：EternalLight 的 creative-direction、theme-ethics、serial-architecture、audience-modeling 技法，creative_ceiling_engine、whole_book_quality_loop，以及 creative-strategy-r4-2026-09-08/report.md。R4 没有证明浅动态优于固定准备，两组有效交付均为0/8；因此本方案不默认加深规划、不宣称提升质量已经实证。

## 方案

1. 单一 JSON 策略目录，声明适用条件、不适用条件、输入、步骤、交付、止损。包含机制探索、上限挑战、主题张力、长篇续航、读者审阅、定向修订、质量比较七类。默认直接完成明确小任务，发现真实分歧/风险再选择策略。
2. 原生 MCP `read_creative_strategy` 提供 catalog 或单项。静态只读，无作品查询、网络、副作用或权限授予；复用身份校验、操作白名单、参数校验和完成门禁。调用事件自然进入现有执行记录。返回仅是方法，不能作为读过原文/通过质量检查的证据。
3. 根智能体只收到目录和使用边界，正文按需读取；子角色可使用同一只读方法工具。角色职责与策略独立，同一角色可用多种策略，无强制人数或候选数。
4. 必需事实/作者约束与审美建议分开；后者不自动阻断、不自动修改已采用内容。比较保留机制、优势、牺牲、证据和未完成事项，不求和成单一文学分数，不把所有方案平均拼接。
5. 修订前先读完整所需原文，定位根因，只改授权范围，修订后复核保留项和回归。没有新证据或明确新修法时停止，不重复同提示词消耗预算；在预算中保留成稿与最终核验空间。
6. 读者观察与作者诊断分开报告。当前原生子任务未提供可证明的上下文隔离，故只能称读者视角审阅；不得将 fork_turns=none 或新角色名当作盲读证明。真正盲读需要另行实现材料投影与工具权限隔离，未在本次承诺中伪造。
7. 比较协议使用同题同约束、保存完整候选及失败、匿名随机顺序、分别记录规格/事实/偏好/成本。策略质量状态保持 unvalidated，需真实评测后才能声称有效。

## 五视角实施前评审（同一执行者）

- 架构 APPROVE：一个策略事实源，MCP编译内置，根指令与角色权限同步；不重建任务系统。
- 技术A APPROVE WITH CONDITIONS：验证静态工具不能扩大作品访问，错误身份/操作/参数拒绝，发布完成后关闭；禁止用户路径输入。
- 技术B APPROVE WITH CONDITIONS：验证catalog与单项、角色生成一致性、调用链、工具schema和发布资源；原生构建与前端回归。
- 产品 APPROVE：作者明确目标优先，复杂度自适应，不用试验结果承诺文学上限。
- UI/UX APPROVE：延用简洁执行记录，无角色管理面板，无强制选择策略。

## 验收边界

工程保证方法来源、可读取、身份/操作边界及工具配置一致；模型负责选择方法、执行文学判断和语义验收。本次不实现每次委派文本的强制结构化契约、不声称策略总会被调用或真实读者满意度提高。
