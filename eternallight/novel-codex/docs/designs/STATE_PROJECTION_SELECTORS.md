# 全局状态投影：先筛选来源，再限制返回

状态：有限结构化查询已落地；不代表 S2 全局语义检索或完整状态推理完成。

## 决策与实现

Reader 原路径先截取最近 100 章，Author/World 先截取前 100 个对象，再检查断言；这会把早期证据或后期相关事实静默遗漏。现在四类投影共用 `story-core::state_sources`，从权威来源筛选后才限制返回，不保留旧来源读取分支。

`KnowledgeStateQuery` 和 Author-only 状态 HTTP 查询增加可选 `entityId`、`predicate`：实体选择匹配 subject、target 或认知持有者，谓词精确匹配。实体选择先根据当前/冻结身份决定展开到原始 ID；不是名称模糊匹配或自然语言意图识别。Character 的 `ownerId` 仍是必填，不能由实体选择替代。

来源召回同时约束作品、当前选中正文修订、已发布且 ready 的知识批次、视角、读者位置和时间。Reader/Character 的章界限在来源筛选前执行；Author/World 不以读者位置限制。World 只包含世界/因果关系及非认知断言；类别来自唯一 `relation_types` 注册表，不另维护 SQL 关系分类。

历史查询只重放所请求 main 快照捕获的正文、知识与身份版本。在筛选相关来源前检查完整冻结来源清单；即使损坏发生在不相关章节，也不以最新批次补齐缺失捕获。未知时间和不合法认知区间不会被当作可靠状态；不合法认知区间进入权威校验并拒绝查询，避免 SQL 提前排除后返回虚假的空结果。

SQL 在已发布 `assertions_json` 上进行来源匹配，不把可重建索引升级为事实权威。最多加载 200 个匹配的已建模来源、返回 200 条投影条目；另显示最多 100 个待建模来源 ID。待建模来源可能与任意选择相关，不能因没有断言而假设无关。失配知识头只返回 `model_pending` 元数据，不再经宽松批次读取恢复为 ready。

`coverage` 保留来源、条目、时间、冲突与命题来源缺口，增加待建模总数、ID 截断、匹配/未排除来源总数和实际处理来源数。`matchingSourcesCount` 包含无法判断是否相关的待建模来源；`scannedSourcesCount` 是装载并处理的来源数，不是数据库扫描行数。`complete` 仅表示当前显式选择的结构化覆盖，`semanticCompleteness` 固定为 `unknown`。

## 回归证据

- 231 章生产 fixture：Reader 取回第 1 章证据，Author/Character 取回第 231 章知识；Reader 位于第 230 章时不能读取第 231 章来源。
- World 时间选择排除其他时间位置；宽范围 231 个来源超过 200 上限时明确报告截断与不完整。
- 修改正文使当前知识失效，冻结快照仍重放旧知识；冻结清单缺少不相关章节捕获时拒绝查询。
- 损坏认知区间拒绝查询；跨对象失配 ready 头不能将候选断言重新带入投影。
- Runtime 公开 HTTP 回归覆盖实体/谓词/时间/快照选择、空选择拒绝和 Candidate 凭证无权访问 Author 路由。

测试位于 `state_selector_tests.rs` 和 `state_selector_http_tests.rs`。最终代码的串行 `npm run verify` 已通过，包含 Rust 文档测试、引擎及真实 Codex 回环、Agent 与 UI 回归；`cargo clippy --workspace --all-targets -- -D warnings` 已通过。首次并行验证在 rustdoc 阶段出现依赖加载错误，串行全流程复跑没有复现，未据此修改产品逻辑。

本次按用户要求由当前执行者直接实施，没有组织独立专家评审；没有修改 Codex 上游内核、添加兼容路径或删除作者数据。

## 边界与后续

来源排序目前按章节与对象稳定排序，不是语义相关性排序。未选择实体/谓词时仍可能截断，不能证明远章事实全部召回。局部命题仍保持批次限定身份，不以同名 ID 自动跨章合并。

后续需要自然语言 Query Planner、相关证据排序与可检验的覆盖策略、承诺和硬约束建模、完整世界/人物状态演进、模型与人工金标评估以及 Windows 测量。当前选择器不能替代这些能力，也未扩大 Agent 工具权限。
