# 授权原文分页的长篇规模验证

状态：S2/S5 的工程读取证据；模型语义质量与持久扫描恢复另行验收。

## 方法

在 novel-codex 执行 `CARGO_NET_OFFLINE=true npm run bench:passages -- --locked --offline`。独立 release example 复用 `long_work_fixture`，通过生产作品/修订/建模/任务边界构建 512 章、百万汉字、1,024 场景、50,176 断言，实际规模从临时 SQLite 原始修订及就绪批次读取并核验。没有直接写入业务表制造规模，没有调用供应商、读取测试密钥或触碰作者数据库；退出后临时目录清理。

基准创建一个冻结来源的 advisory Task，调用生产 `query_task_plan`，包含授权、输入/水位检查、只读快照、查询执行、证据归一化、排序及 9 KB 整包预算。每页最多两个 160 字符片段；测量时间包含解析原修订、核对版本/对象/字段和 Unicode 锚点的额外成本，不仅是 SQL 耗时。

每组先测首查询，再测 30 次热态查询，P95 用最近秩。三组分别测首章第一页、连续页及第 512 章内字符位置 1,500 的页面。后部游标是任务范围内的显式定位，不被当作之前页面已消费的证明。首查询在构建作品、读取规模之后执行，不是系统冷启动测试。

另外对 512 章逐章读取一页并校验 1,024 个锚点，再从 `cursor:null` 连续读取至范围末尾：各章的已覆盖字符位置只能向前增长，下一片段不得跳过已覆盖末尾，最终必须等于实际正文长度。重叠 32 字符不重复计入完整覆盖。机械遍历不执行模型判断，响应仍保持 `fullScanCertified=false` 与语义未知；不得由此认证全书理解。

## 实现边界

原路径在授权范围展开正文/场景 JSON，再排序选字段。现实现先按章节/对象顺序取得一个授权源修订，只解码当前来源；空/已读完来源逐个前进。字符截取只读取到当前片段末尾并检查剩余字符，不为每个片段计数全文。它不依赖派生索引，不新增模型执行器、缓存权威、旧格式兼容或数据库迁移。

源清单核验仍随作品对象数增长；JSON 解码与按字符位置跳过前缀仍随当前修订大小增长。空来源较多时需要逐个检查。因此本基准的短章数字不代表接近字段上限的单章、大量空章节、所有视角或任意规模均有固定时延。没有声称 O(1) 随机访问。

## 验收边界

本机工程指标需与真实供应商成本/时延、人工金标召回与影响集合、持久扫描账本、模型自主全书阅读及 Windows 分开。原文分页性能达标也不能宣告 S1–S5 全部完成。普通任务取消、范围、来源失效和预算裁剪仍沿现有门禁；本基准不构成持久语义审计证书。

## 本机结果

机器为 macOS Darwin 25.5.0、Apple M5 Pro、aarch64、24 GiB 内存，release 构建；未与其他测试/基准并行运行，但未关闭其他桌面应用。数据实际为 512 章、1,024,000 汉字、1,024 场景及 50,176 就绪模型断言；这些断言是确定性 fixture 输出，不是模型质量认证。构建耗时 51.57 秒，编译时间不计入查询。

| 路径 | 首查询 ms | 热态 P50 ms | 热态 P95 ms | 热态最大 ms |
| --- | ---: | ---: | ---: | ---: |
| 首章第一页 | 1.17 | 1.00 | 1.08 | 1.08 |
| 连续原文页 | 1.06 | 1.00 | 1.08 | 1.08 |
| 第 512 章内定位 | 1.10 | 1.08 | 1.12 | 1.13 |

从初始游标到范围末尾的机械遍历耗时 4,351.81 毫秒，共 4,096 页、8,192 个来源片段；排除重叠后逐章覆盖 1,027,584 个实际正文字符，包含 1,024,000 汉字和分隔符。所有页检查预算、页完整标记及来源锚点，所有章节累计末尾等于实际正文长度。另行逐章的一页校验验证了 1,024 个锚点，不冒充逐页语义评价。

优化前使用相同生产合成构建链及页面大小，热态 P95 为首章 6.62 ms、连续页 12.01 ms、后部定位 6.69 ms。两轮不是隔离实验室中的统计比较，首查询的预热也有不同：最终基准额外读取真实规模。仅据此记录当前访问路径的改善，不保证固定加速倍数；原路径也未超过本机初始 1 秒目标。本机当前三条有限读取路径达标，不将这一结论扩展为所有查询、模型扫描或全部 S5 达标。

输出明确保持 `allCharactersRead=true`、`fullScanCertified=false` 和 `semanticQualityVerified=false`：第一项是基准程序的机械字符对照结果，后两项表示领域/模型未被签发全局语义认证。

验证记录：新增空来源/场景遍历与单来源解码两项 Core 回归，原 HTTP 原文三项回归继续通过；完整 `npm run verify` 退出码 0，包括两轮 native、180 项引擎、146 项宿主、真实 Codex 原文工具回环及 12 项 UI 测试。严格 native `cargo clippy --workspace --all-targets --locked --offline -- -D warnings` 通过。存在既有前端大包体警告；未进行真实供应商语义质量或 Windows 认证。
