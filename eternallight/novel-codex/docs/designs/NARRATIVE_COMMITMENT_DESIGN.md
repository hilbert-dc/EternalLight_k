# 叙事承诺：版本与证据契约

最新执行入口进展：已有承诺的显式对话调整已接通 `reviseCommitment`，精确 ID/修订冻结、根 Agent 候选提交和完成验证复用任务链；不可变提案来源、正文证据、锁及作者正式确认边界保持不变。`read_commitment` 不向 Writer 泄露全局承诺。下文各切片的“对话调整未实现”描述其当时边界；当前技术契约及验证见 [对话调整承诺](COMMITMENT_REVISION_DESIGN.md)，真实模型旅程和自动创作派发不因此通过验收。

目标：落实 S3 的叙事承诺数据基础，而不是在计划、Canon 和 UI 中分别维护伏笔状态。每个承诺是现有修订体系中的独立 `commitment` 对象，使用稳定 ID、不可变修订、候选/确认指针、快照、Review、采纳与补偿撤销；不新增写入账本。

## 决策与当前交付边界

- kind 为伏笔、悬念、人物转变、目标或关键场面；正文不是每个细节都必须兑现，开放窗口合法。
- setupEvidenceRefs 和 fulfillmentEvidenceRefs 引用同作品不可变 draft 修订的 Unicode 字符锚点。每次保存和正式采纳在同一事务复核来源仍是 main 快照选中修订；跨作品、伪造摘录、失效来源拒绝。历史读取只按指定快照成员解释来源，后来的改稿不抹去旧证据。
- status 为 open / partiallyFulfilled / fulfilled / abandoned。部分/全部兑现必须有兑现证据；放弃必须有显式作者理由。证据匹配仅证明引用有效，不证明文学意义已兑现。当前仅 Author 可保存及创建 Review；模型不能借此关闭伏笔或写 Canon。
- 放弃可以保留已有的部分兑现证据，不把 abandoned 解释成“从未推进”。这些证据仍需核验，不能因放弃跳过来源约束；旧版本及作者理由继续保留。
- targetWindow 为 open 或稳定 chapterId 范围。保存时核验两端属于当前作品且顺序有效；读取根据所查版本的正文章序计算窗口，无法确定时返回 unknown，不用当前目录冒充历史顺序。
- relatedEntityIds、plotThreadId、characterArcId 只是有限关联声明，不把未解析关联升级为正式世界身份或自动依赖。状态只在承诺自身保存，不在 PlotThread/CharacterArc 重复维护。
- Author HTTP 提供单对象保存、当前/历史读取和专用 Review 创建；采纳及撤销复用现有接口。领域保存及采纳不能绕过证据契约；锁与 CAS 继续复用既有权威。更新正文后读取标注 sourceCurrent=false，不自动把承诺改成 open 或偷偷重写它。
- 本切片尚不提供模型自动抽取、Writer 上下文排序、自然语言承诺调整、作者 UI 或质量认证。这些仍是完整 S3 的必需后续，不能以本切片验收替代三章创作与作者评价。

## 实施前五方面自检

由实现者独立自检，不组织评审会议：架构复用版本/提交服务；技术 A 在保存/采纳事务核验来源并封闭候选权限；技术 B 真实仓储及 HTTP 测试验证失败回滚、历史、锁与撤销；产品保留开放结局与显式放弃；UX 返回实际来源状态，不伪装模型文学判断。无旧数据升级、兼容分支或第二权威，同步当前接口、测试及文档。

## 当前接口与来源解释

- `POST /api/projects/{projectId}/commitments/{id}`：`payload` 为承诺，另含 `baseSnapshotId`、`expectedRevision`、`expectedCandidateRevisionId`、`idempotencyKey`。保存产生既有候选回执；同键同输入不重复写入。
- `GET /api/projects/{projectId}/commitments/{id}?snapshotId=...`：省略快照读取 main；返回冻结正文证据、来源适用性、按所查快照重放的确认状态和窗口章序。不存在及其他作品快照均返回未找到，不能从错误差异确认快照存在。
- `POST /api/projects/{projectId}/commitments/{id}/reviews`：指定 `revisionId` 与 `idempotencyKey`，创建无事实提案的作者审阅。随后使用现有 Review accept 和 commit undo；采纳在事务中再次核验来源，不能靠空 checks 绕过。

每对象最多 32 KB，setup/fulfillment 各最多 8 个引用，每段引用最多 2,000 字符，关联实体最多 16 个。引用当前限定 `/body`，不伪装支持尚未实现的任意块定位。窗口支持已有正文中的稳定 chapterId 或 open，尚未支持尚无正文的未来规划窗口、相对事件窗口或 overdue 推理。当前仅有单对象 API，无列表/方法 UI；不会为了接口存在就宣称作者已能通过对话完成承诺调整。

当前与历史确认状态从该快照祖先的采纳/撤销记录推导，不套用现时 accepted 指针。承诺仍可在旧源上保持历史状态；`sourceCurrent=false` 表示对所查询版本需复核，不代表系统已经撤销作者决定。来源失效不会自动删除正文或独立承诺。正文、意图和作者直接决定之间的完整来源建模、自动抽取与 Writer 受限证据装配仍待实施。

## 专项验收

专项验证覆盖状态证据要求、伪造/重复/跨作品来源拒绝、失败快照不变、开放结局、确认/撤销的历史重放、前文编辑后的拒绝采纳、版本窗口及旧记录保存；HTTP 包含候选读写/审阅拒绝、幂等、重开持久化、完整 Review accept/undo 和无效请求不改变数据。另有锁定确认承诺后拒绝替换的真实仓储场景；锁与普通候选 CAS 继续由已有仓储路径提供。

## 可分开审阅的实施段

第一段是 Rust 契约、修订写入/采纳门禁与真实仓储测试，是最小独立领域交付；第二段为依赖第一段的 Author HTTP 路由和端到端测试。本轮完成这两段，不把模型工具与 UI 混入同一大修改。下一段应围绕原有 Codex 任务与受限来源契约接通候选生成/读取，再完成作者对话与 Writer 上下文；不能另立状态机或直接调用供应商接口。

## 任务上下文接入设计（后续实施切片）

将 `ContextPack.relevantCommitments` 的空占位替换为核心仓储的任务受限投影，复用持久化 TaskQueryScope；不新增模型调用、任务类型、状态机或写权限。读取重新加载任务并校验活跃、未撤销及输入版本，整次投影使用同一读快照。运行时保留现有 capability/到期检查及上下文前后来源栅栏。

引用必须全部属于当前快照且处于任务正文范围；先过滤章节和来源，再按 open、partial、closed 的稳定顺序流式选择，场景范围继续核验引用结束位置不超过已授权正文前缀。不能只删未来引用而保留完整承诺。最多 16 条、12 KB；单条超预算整体略过，不截断证据，仍继续寻找可容纳的后续条目。

非 POV 任务读取的是作者叙事意图/分析，不是角色知识或世界事实。受限投影不带未解析实体关联、窗口和放弃理由等未绑定披露范围的元数据。POV 尚无摘要与标准的披露证明，返回固定空集和不完整覆盖，不暴露隐藏条数；这是待补齐的安全边界，不宣称 POV 承诺检索完成。未绑定任务同样明确不提供投影。

每项保留承诺修订、来源引用、候选/作者确认标记与 candidateNarrativeInterpretation 权威标签。来源失效不改变状态，只使当前任务不再消费；空集不代表不存在伏笔，也不证明文学兑现。覆盖报告区分预算截断、披露限制与语义未知。承诺与正文共享 Context Pack 总预算，最低优先级承诺按整项移除，随后更新覆盖与 contentHash。

共享预算先移除低优先级承诺，剩余最高优先级的一条与其他可选素材竞争，只有其余可选素材都无法继续裁剪时才移除它；不让初始大包体直接吃掉所有承诺。这个选择不是额外保留预算或必需输入豁免，冻结目标、必要源文和事实仍不可被承诺挤走。

实施前五方面独立自检：架构复用现有任务/修订/快照；技术 A 检查任务伪造、撤销、来源与范围；技术 B 真实仓储及 HTTP 回归、预算哈希；产品支持规划/写作读取而不冒充自动抽取；UX 返回诚实覆盖而不新增虚假 UI。按用户要求不组织评审会议。无兼容层、旧数据迁移或上游内核修改。

可独立审阅的顺序为核心受限投影及仓储测试，随后是 Runtime Context Pack/预算与 HTTP 回归；不混入模型候选生成和 UI。SQL 在条数限制前过滤来源与章节，应用层流式过滤场景并有限装配；数据库仍需枚举和排序承诺，当前专项覆盖超过选择上限的隐藏记录，不冒充大规模承诺库性能认证。后续若增加索引，只能作为可重建派生物，不能另立状态权威。

## 后续提取执行切片

来源冻结的候选抽取现已沿既有任务链接通，详见 [正文绑定的叙事承诺提案提取](COMMITMENT_EXTRACTION_DESIGN.md)。extractCommitments 的产物是不可变提案批次，不是独立 commitment；批次内 ID 不承担长期故事身份。显式对话请求可登记并执行提取步骤，根任务经原生 MCP 提交，有效输出才能完成；Author 可读取报告及来源适用性。
