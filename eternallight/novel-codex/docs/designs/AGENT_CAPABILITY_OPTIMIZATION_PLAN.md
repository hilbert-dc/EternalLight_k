# Novel Codex Agent 能力与执行效率优化方案

日期：2026年10月10日。状态：主要结构切片已实施，相关工程回归及代表性真实模型闭环通过；成本压力目标、完整Native覆盖尚未全部通过。人工读者评分按作者指示延后。

首要目标是提高作品质量，忠实实现作者意图并保留作品的独特性。在作者授权及资源约束内，优先投入对创作有价值的阅读、构思、比较、修订和核验；在质量达到要求后，再减少无效协议工作、等待、费用与返工。模型负责理解、创作和判断，工程负责可靠执行与真实反馈。总token减少不是首要目标，也不要求提高“正文输出token占比”。

本方案承接[理想架构](../../IDEAL_ARCHITECTURE.md)和[演进路线](CODEX_CREATIVE_EVOLUTION_ROADMAP.md)，细化小说 Agent 的近期优化切片。它不替代[架构规则 B01 至 B10](../../../ARCHITECTURE_RULES.md)、[任务管理合同](TASK_MANAGEMENT_ARCHITECTURE.md)或现行工具契约；方案中的目标接口不代表已经实现。小说是首个验证场景，共用改进可用于漫画和动画，但不以小说步骤规定其他媒介的创作流程。

## 1 主要决策

1. **先建立质量基线与质量门槛。** 按作者目标判断指令遵循、因果连续性、人物声音、节奏和语言效果。代码回归及模型自评分不能独自证明文学质量；有质量退步时，成本收益不能抵消。
2. **优先消除无效协议工作，保留有效创作投入。** 最新单场景交接与前后决策占79.95%的已知累计token，是诊断信号而非压缩配额。身份绑定、版本引用、定位和恢复可交工程处理；必要阅读、构思、备选方案与评审不因非正文输出而被删除。
3. **保留现有 Work 和执行循环，收敛重复权威。** 围绕 Work、带操作类型的 Step、Attempt 审查重复状态，不另建通用工作流引擎，不按概念数量删除领域对象。
4. **按优先级验收。** 先满足作者要求、作品保护与可靠交付，再判断创作质量，最后比较同等质量下的成本和时间。质量明显提升且在授权范围内时，允许增加token与必要步骤。
5. **按质量收益扩展协作、知识建模和模型路由。** 有质量收益的机制即使增加成本也可保留；只有质量相当时才按效率取舍，不以便宜、短提示词或少Agent作为默认优越性。

### 1.1 质量优先的决策规则

质量按具体作品和作者目标判断，不压成一个可与价格加权抵消的总分。明确保留项、人物基本动机和关键因果等约束不能被更流畅的语言掩盖；实验性写法、刻意留白和不可靠叙述不能被机械判为需要修正。

| 对照结果 | 决策 |
| --- | --- |
| 明确要求、保护范围或必需交付失败 | 不接受为优化，无论节省多少 |
| 质量下降，成本下降 | 不接受为默认方案，不用经济收益抵消质量损失 |
| 质量相当，成本或等待减少 | 接受为效率优化；质量相当须有对应任务证据 |
| 质量提升，成本增加 | 在现有授权、作者选择和资源约束内优先考虑，不因token增长淘汰 |
| 质量提升，成本下降 | 优先采用，仍验证可靠性与任务适用范围 |
| 质量证据不足或评审分歧未解决 | 保留原质量义务，补评测；不能标为已证明无损或全量替换默认策略 |

质量优先不意味着无限生成、固定多Agent团队或每个标点都强制独立审稿。模型按问题选择投入，工程保留必要上下文、合法工具和继续改进的能力；达到作者目标时可以直接交付，同条件无进展时诚实停止，不循环刷评分。

### 2.1 协调与技术资料阅读已经构成重点问题

对最新真实任务账本和工具轨迹的只读归因，确认“创作外围开销很大”在具体样本中成立。更准确的表述是：**大量用量发生在交接、行动选择、工具说明和状态协调阶段；尚不能将这些用量全部归为搜索文档或无效浪费。**

同一次空作品约100字开场任务的完整阶段用量如下：

| 阶段 | 供应商请求数 | 已知累计 tokens | 占本场景比例 |
| --- | ---: | ---: | ---: |
| 初始讨论与生成交接 | 7 | 224995 | 21.28% |
| 生成前决策 | 5 | 250503 | 23.69% |
| 正文写作任务 | 8 | 212053 | 20.05% |
| 保存后的接续决策 | 10 | 369999 | 34.99% |
| 合计 | 30 | 1057550 | 100% |

交接及前后决策合计845497 tokens，占79.95%。最终保存95字候选，独立核验未执行，执行额度耗尽。写作任务本身也包含阅读与工具调用；决策阶段可能包含有用的创作判断，所以20.05%不是“纯创作token占比”，79.95%也不是“可直接省掉的成本”。比例四舍五入可能有尾差。

这组任务保留下来的四个会话共75次工具调用，按实际返回文本块各计一次、使用cl100k_base本地分词，得到下表。工具调用数不同于供应商请求数；该轨迹不是全部供应商出站提示捕获，不能将表中token直接除以上面的供应商用量。

| 工具 | 调用次数 | 返回文本的本地 tokens | 解释 |
| --- | ---: | ---: | --- |
| read_context | 9 | 33860 | 混合作者要求、目录、绑定、状态和协议文本 |
| read_tool_guide | 16 | 12411 | 技术工具说明与参数定义，含分页和重复首段 |
| discover_creative_capabilities | 10 | 6587 | 能力发现与目录 |
| read_work_status | 8 | 5432 | 工作状态与下一步行动信息 |
| read_source_content | 13 | 5287 | 包括原文、作者要求及工作区视图，不能全部归为技术开销 |
| 其余工具 | 19 | 10911 | 任务登记、完成、交接及一次正文保存等 |
| 合计 | 75 | 74488 | 不含后续历史重放、完整schema、模型输出及缓存计费 |

前四类合计43次调用，返回58290个本地tokens，占这份轨迹全部工具返回文本的78.25%。其中read_context并非纯协议，故这一比例只表示返回内容集中在哪里，不表示78.25%可删除。

另有两个可定位的机制值得优先处理：

- 8份成功解析的read_context结果均带同一份方法文本。仅从这8份JSON删除selectedMethods中的text字段进行差分分词，就减少13000个本地tokens，约占这8份上下文结果的38.56%。这证明重复传输实际存在；首次注入、不同独立线程和压缩后的恢复仍可能需要规则，不能把全文全部删除。
- request_work_action指南在该运行中长17822个字符，轨迹出现首段重复读取及cursor为4000、8000、12000的续读。当前[指南实现](../../native/story-mcp/src/tool_guidance.rs)将完整工具定义序列化后按最多4000 UTF-8字节分块，而不只返回简短用法。这使按需说明本身产生多轮模型往返；只缩短初始说明并不足以保证端到端节省。

实测还包含插问期间TaskNotWritable被解释为不能修改、原编辑目标未接续的生命周期缺口，以及传输失败后的工具纠错。它们会增加协调请求，必须与文档载荷一起解决，不能仅靠删提示词掩盖。原作阅读和必要核验是有效创作成本，不应和反复学习工具协议一起压缩。

结论分级：协调用量占比高、指南多轮阅读和相同协议文本重复传输已有证据；它们对完整账单各贡献多少、能安全省去多少、在正常成功任务中是否普遍如此，仍需出站请求归因及同条件对照。最终稿字数或保存正文的token只能衡量可见产出，不能代替创作思考与质量投入。本文不设置“创作token至少占多少”或“协调token必须低于多少”的目标；提高正文占比可能只是删掉必要阅读和评审，不能作为收益证据。

证据：[真实任务复测与阶段结果](../../design-reviews/2026-10-10-task-live221.md)、[原始账本](../../design-reviews/evidence/2026-10-10-task-live221-222-ledgers.json)、[真实工具轨迹](../../design-reviews/evidence/2026-10-10-task-live221-222-tool-trace.json)、[本次归因结果与源文件摘要](../../design-reviews/evidence/2026-10-10-agent-overhead-attribution.json)。本次归因只读取现有证据，没有新增模型请求。

## 3 目标职责与执行结构

### 3.1 每层只拥有一类权威

| 层 | 优化后的职责 | 直接落点 |
| --- | --- | --- |
| 主模型 | 理解目标、选择相关原文、构思修改、提出后续行动、判断语义与解释结果 | 当前模型上下文、方法和角色资源 |
| Codex Core 与 Agent Engine | 通用模型与工具循环、上下文、协作身份、协议传输、实际请求用量与执行恢复 | 现有 Core 与 Engine 公开合同 |
| Host | 绑定进程与会话、消费持久事件、派发已准入任务、暂停取消及执行健康投影 | electron 中现有执行和生命周期模块 |
| MCP 与 Runtime API | 同源工具声明、受信身份传递、简明业务参数、结构化结果与错误 | story-mcp 与 story-runtime |
| Story Core 与 Authoring | Core 保有作品、授权、版本、事务、幂等、Work额度和交付事实；Authoring 构造冻结输入与任务契约 | 现有领域用例与任务输入构造 |
| Renderer | 展示正文、差异、已保存成果、真实阻塞与可执行控制 | 当前对话、编辑器与工作区组件 |

“下沉到 Runtime”在本方案中指由以上工程层按责任处理，不是把所有逻辑堆进 Runtime API 或 MCP。模型不读取领域数据库，Host 不根据自由文本选择文学流程，Engine 不认识小说章节业务。

### 3.2 保留 Work Step Attempt 的层次

```text
Work  作者目标、原始要求、授权范围、累计预算及交付事实
 └─ Step  一项明确类型的行动、输入来源、依赖和必需输出
     └─ Attempt  一次执行身份、执行状态、错误及用量关联

GenerationRun  连续写作的领域范围和逐章交付约束
Artifact       正文、报告、设定等不可变产物及修订
Permit         作者授权事实
```

Step 已有 operation 字段，先在现有操作注册与类型定义中统一输入、输出、准入及完成规则；有真实消费方时再补类型，不创建万能 Operation 表。GenerationRun 保留连续写作特有约束，通用暂停、派发和接续复用现有 Work 路径。Permit、Proposal、Commitment 等对象按其领域含义保留，不混成执行状态。

状态收敛以三个问题为判断依据：同一事实是否有两个写入者；同一状态是否存在两套不一致转换；同一故障是否需要多个入口各自修复。只有确认重复，才在一个切片内指定唯一权威、同步调用方并删除被替代分支。任务执行结束、产物保存、用量结算和目标交付继续独立表达。

## 4 模型接口与簿记下沉

### 4.1 用版本绑定引用承载编辑条件

目标是让模型表达“修改这个已读片段为这些文字”，而不计算偏移或重新拼装身份。优先扩展现有 editAnchor 和来源引用；只有确实减少参数错误与上下文开销时，才引入短引用表示。

下面是目标业务参数示意，不是当前可调用 API：

```json
{
  "targetRef": "读取结果返回的版本绑定引用",
  "replacement": "修改后的文字"
}
```

引用由 Story Core 基于授权来源签发或解析，包含可校验的目标对象、来源修订、候选比较条件、范围及摘要。它是定位依据，不是授权凭证；每次保存仍校验当前执行身份、范围、锁定、撤销和生命周期。优先使用可从持久来源确定解析的表示，避免引入新的内存真相或独立引用数据库。

版本只从模型实际读取的来源、作者选区或本任务已有检查点取得。提交时发现目标已变化，返回明确冲突及受影响范围，交由模型重新阅读和判断；禁止自动填入最新版本后继续写入，也不自动把旧引文匹配到新稿。

精确引文必须在声明的对象和版本内解析。零匹配、多匹配、跨组修改分别返回可处理结果；不能默认选中第一次出现的位置。模型选择目标，工程计算 Unicode scalar 偏移、校验 oldText 和修改重叠，复用现有候选保存事务。

### 4.2 幂等绑定逻辑操作

Engine 的 callId 标识一次调用，不能独自定义跨模型重发的同一逻辑操作。网络重传、模型纠错、新的创作修改也不能混为一类。

目标是由现有持久操作账本保存逻辑操作引用及请求摘要：首次派发前确定身份；同一调用重传复用原身份；模型重发时引用已返回的操作回执。相同操作引用而目标、版本或内容变化须拒绝；修改后的新意图形成新操作。不能按文本相似度或时间窗口猜测重复。

未知保存结果先按原操作查询。确证未写入且允许纠错时才再提交；已有保存回执直接返回事实，不重新生成正文。若短引用方案需要额外准备调用，必须计入全流程对照，证明收益后再采用。目标是减少手工协议，不增加每次写入的固定握手。

### 4.3 精简常用工具并保留完整能力

以当前任务实际需要组织工具：定位与阅读、编辑与保存、行动接续、问题与报告、状态与控制。基础上下文直接提供目标对象、作者要求引用及必要读入口，避免每个小任务先浏览整个目录。

常用操作直接可见，较少使用的分析和方法按需发现；工具名、简短说明、schema、指南和错误示例来自同一契约。复杂写入使用可被实际供应商路径支持的判别联合与互斥约束，并在真正执行前保持最终校验。不能为了减少工具数把所有行动塞进一个巨大通用参数对象。

衡量实际初始 schema token、首次选对工具比例、发现往返数、参数纠错次数和端到端结果。约15个核心工具可作为对照候选，不能成为全产品固定数量门禁。

针对第2.1节已观察到的指南开销，优先把“完整schema传输”与“简短操作指南”分开：实际调用所需schema沿合法工具发现机制加载；指南同源生成最小用法、关键前置及当前操作示例，必要时按字段或主题展开。避免模型为了查一个字段从头分页读取整份JSON。必需约束仍在schema和执行校验中，未加载的工具也不能因看过指南而自动获得调用权。

### 4.4 错误携带能决定下一步的事实

沿现有结构化错误合同补齐消费缺口，至少保留阶段、稳定原因、字段或目标、是否派发、写入是否已知及合法下一步。错误内容有界、脱敏，并经过真实 HTTP、MCP、Engine 和 UI 消费链验证。

| 情况 | 工程确定的行为 | 模型或作者下一步 |
| --- | --- | --- |
| 参数类型或互斥错误，确证未派发 | 指明字段与允许形状，不消耗新的业务写入 | 模型在原权限内纠正 |
| 领域允许但 schema 未加载 | 提供当前合法发现入口，不标为无权限 | 模型加载后继续 |
| 来源或候选版本过期 | 保留原稿，返回冲突对象和版本关系 | 模型重新读取并决定改法 |
| 保存结果未知 | 先查原操作回执，不生成新写入键绕过 | 核对后继续或准确说明阻塞 |
| 费用未知 | 保留原账本，按当前是否有限额度及结算状态准入 | 不清零，不误报已耗尽 |
| 缺少作者授权 | 返回缺少的具体对象、动作和范围 | 仅请求缺少的决定 |
| 同条件反复无进展 | 按可信条件与实际进展判断是否停止 | 展示保留成果和恢复条件 |

## 5 授权接续与交付闭环

作者在同一对话中从讨论转向修改，模型可通过现有任务请求入口表达明确行动。Native 根据真实作者要求、当前对象、范围和累计预算准入；Host 执行已准入任务并把结果带回同一 Work。不存在权限缺口时，不要求作者重复批准同一范围。

有些新作品生成路径当前通过批准后的 GenerationRun Work 执行。目标是把授权来源、父目标关联、预算扣减和结果返回明确贯通，防止重复发根预算；不为消除“两个 Work”这一表面现象直接删除既有生成契约。是否合并持久容器须由重复权威和实际故障证明。

每类操作明确最小完成契约：

| 操作 | 必需输入 | 必需完成证据 | 可选增强 |
| --- | --- | --- | --- |
| 局部润色 | 原文、作者要求、选区与保护范围、适用读取义务 | 当前候选回执、范围外内容保持、要求对应检查及可打开差异 | 风格对照、独立读者 |
| 单章续写 | 必要前文、当前设定和本章要求 | 正文持久化、必要连续性检查、适用评审与交付回执 | 多种开篇、角色分析、额外建模 |
| 一致性检查 | 明确检查问题、授权来源及覆盖范围 | 可定位的发现与来源；无发现时如实声明覆盖 | 关系索引、持久语义查询 |

独立评审是否必需由作者要求及操作合同决定。简单修改不新增固定团队流程，已要求的独立核验也不能为了省 token 被自检代替。工程检查字数、锁定和版本，模型判断意图、语言与连续性，作者满意另行记录。

暂停、重启、插问返回、变更要求、迟到回执和保存后断流纳入同一切片的相邻状态测试。恢复使用原 Work、累计用量和持久结果；作者改要求时显式更新意图与来源，旧结果只保留为历史，不覆盖新稿。已保存但未完成、已完成但展示读取失败必须分别呈现，展示刷新不得再次执行模型。

## 6 上下文与成本治理

### 6.1 先建立可归因的请求记录

复用 Engine 用量和现有评测脚本，增加可关联的观测投影，不建立第二套收费账本。每次请求关联 Work、Step、Attempt、模型配置和执行阶段，记录：

- 实际输入、输出、供应商明确提供的缓存用量与计费信息；缺失字段保持未知。
- 系统提示、工具声明、历史、原文与工具结果的本地分词估算，标明分词器与是否包含封装。
- 定位、有效阅读、重复读取、编辑、检查、纠错、恢复等可观测阶段；分类不收集私有推理文本。
- 首次失败与当前阻塞、是否发送、保存回执、延迟、人工干预及清理结果。

累计 tokens 是每次请求用量之和，包含重复上下文。供应商缓存 tokens 通常是输入的子集，按实际协议归一化，禁止重复加总。估算 token 不能冒充实报；只有具备可信费率版本与完整用量时才能计算金额，否则只报告已知项和缺口。

### 6.2 减少无效阅读与重复上下文

先区分四类投入：理解原作和作者要求；构思、试写和修订；质量核验与必要证据；技术协议与机械协调。前三类以质量效果判断是否需要，不能按调用次数或文本重复率直接删除。重读同一段原文可能是有价值的语言比较、连续性核对或修订后复查；“同版本同范围重复”只触发分析，不自动触发截断、去重或禁止读取。

稳定的规则和工具声明保持确定顺序，动态项目、目标与状态放在独立后缀，缓存收益以供应商回执或对照为准。详细方法和角色按需注入，共同规则从单一资源生成，避免多处独立维护。

对同一有效执行上下文，执行合同在受信指令入口绑定固定版本；普通read_context返回方法标识、摘要和必要状态，不重复携带未变化的全文。完整冻结文本继续由原领域事实保存并可按需读取。新独立线程或压缩后规则不在有效上下文时，由上下文构造合同恢复必要指令；不能把“进程曾加载”当成“模型本轮仍可见”，也不能只删除工具结果而漏掉实际指令注入。

读取沿冻结来源复用已经取得的片段，缓存键包括项目、执行可见范围、来源修订、视图、查询、游标和覆盖信息。运行时可解析续读引用并返回有界页面；不能静默把全章塞进每轮请求，也不能把缓存存在视为模型已经读过。

状态读取优先由提交回执携带当前有效投影，Host 使用现有持久事件接续，减少模型为等待而反复调用 read_work_status。压缩后提供目标、当前产物、未决问题和恢复引用，不重放全部操作日志，不用摘要替代决定性原文证据。

局部保存后，工程可确定验证范围外内容保持，模型按目标核验改动及必要上下文。当前要求完整原作或保护范围阅读的路径继续执行；若要缩小读取义务，须按 B10 同步变更创建、准入、读取、报告、终验与恢复，并验证等效保护，不单靠改提示词取消要求。

### 6.3 区分效率目标与执行额度

当前工程明确规定正常创作默认计量，不要求作者填写请求、token 或时长上限。本方案保持这一产品约定，不将“局部修改5万 tokens”变成所有生产任务的静默硬限制。

评测每次显式冻结请求、token 和时间额度，耗尽保留失败与成果，不追加额度挑选成功样本。现有真实工具评测示例的每样本10请求、50000 tokens、90秒可作为短文本编辑的初始实验配置；续写与跨章检查按输入规模另定，不能机械沿用。

生产提供可选的费用或执行额度设置，具体限制由作者选择或已授权策略给出，继承到子任务、重试和模型切换。无上限时也持续计量、允许停止并实施有事实依据的无进展保护。若未来决定改变默认预算政策，须先明确产品取舍并同步修改现行规则，不能通过本方案暗改默认值。

节省的技术开销可以用于更充分的原作理解、备选方案比较和有效评审；不强制自动花完，也不强制转化为账单下降。评测触及预定额度但尚未达标时记录未完成，不能削减质量标准使其通过；如需扩大实验额度，另记新的预定批次，不追溯改写原样本。

## 7 质量评测与能力增强

### 7.1 建立固定任务与对照

质量样本在涉及模型可见信息、阅读策略、方法、评审或模型路由的优化实施前冻结，与成本基线同时建立，不留到效率改造结束后补测。首批覆盖短局部修改、长章局部修改、单章续写及跨章一致性，包含重复引文、锁定片段、Unicode、矛盾线索和信息不足样本。对客观约束建立可重复断言；对文学质量保存参考片段和评分准则，不把唯一参考写法当作唯一正确答案。

工程基线与优化方案使用相同初始作品、作者输入、权限、读取义务和交付标准。在隔离环境运行不同冻结源码版本，保留全部失败，不在生产维护双轨兼容。模型版本、推理配置、温度、缓存条件和运行顺序可追溯，配对顺序交替或随机化。

端到端场景从应用公开入口给出一句目标，不向模型补工具步骤、故障答案或手工修改正文。工具回放单独衡量接口，不能替代此类自主闭环。

### 7.2 分开判断约束与文学效果

| 层次 | 检查内容 | 判断方式 |
| --- | --- | --- |
| 确定性正确性 | 保存、来源、范围外保持、锁定、重复写入、字数等明确要求 | 真实领域回读与合同断言 |
| 语义质量 | 指令遵循、事实连续性、人物动机、遗漏、因果和叙事视角 | 带原文证据的独立评审及争议复核 |
| 文学体验 | 语言、节奏、情绪、人物声音、悬念与阅读意愿 | 隐藏方案身份的配对人评，允许平局 |
| 作者收益 | 接受或进一步修改、返工、达到满意稿的人工时间 | 作者试用记录，和模型评分分开 |

同模型隔离线程可降低当前对话锚定，但仍共享模型偏差；跨模型评审也不自动成为客观真值。LLM 评审用于扩充观察和筛查，人评用于校准争议及最终质量取舍。首批沿用路线建议，至少形成8个达到满意稿的有效配对，同时报告全部任务的成功、失败和人工投入；小样本只作继续投入依据，不宣称普适提升。

每个任务预先记录质量维度、必须保留的特征和判定理由。候选隐去方案、模型和成本标签，随机左右顺序，允许“各有优劣”和“无法判断”。局部改稿既评目标段落，也检查必要前后文是否失去人物声音、铺垫或节奏；续写和跨章任务检查必要全章与跨章依赖。不能通过片段评分证明长篇质量。

重大遗漏、人物或因果破坏、违背作者明确风格约束须单列，不允许总体均分抵消。评审分歧保留原判断和原文依据，必要时追加独立复核；没有真实人评时标为待人评，不由Agent填写人类意见。八个配对未发现退步只构成初步证据，不能声称已统计证明质量等价。

### 7.3 方法 协作与持久语义按收益启用

方法资源补充适用问题、必要输入、简短示例、反例和退出条件。角色描述围绕可隔离问题，不靠增加公共协议段落证明专业性。比较零子任务与针对性子任务的结果，将派发、重复阅读、整合和评审成本一并计入。

委派的目标状态是由受信子线程创建事件和 Native 授权合同绑定父子关系，减少模型报告 UUID 再人工式握手的往返。只在父任务已有委派权限和明确范围时派生授权；子任务仍保存隔离候选，父任务按不可变引用整合，不能自动覆盖共享稿件或冒充父任务阅读。

原文加基础索引与按需持久语义进行消融：两组都能正常理解原作，均保留作者已确认设定、来源和制作结构。计入首次提取、更新、过期修复和错误纠正。先判断是否减少连续性错误、遗漏和人物失真，再比较达到相同质量的总投入；不能仅因短任务维护成本偏高就取消在复杂长篇中有质量收益的机制。相同质量下无效率收益才考虑简化默认使用范围。

### 7.4 模型接入先可验证再分工

先完善现有模型的工具、上下文、错误与恢复路径；导航、偏移、格式和版本校验尽量由确定性工具完成，不为这些工作新增便宜模型调用。

模型路由作为后续对照变量：在作者允许的模型策略和已验证连接内，先验证不同模型承担写作或评审能否满足对应质量要求，再比较成本与成功率。不能仅按任务短、篇幅少或价格低自动降级创作模型。切换保持原授权、来源、累计预算及真实模型记录，不静默改变作者指定模型，也不因低价模型失败就无限升级重试。

资格与构建指纹继续有效。先将失效原因做成可定位诊断并自动运行受影响的资格验证；只有明确证据依赖关系后才考虑细化失效范围，不能把内核变化一律视为无关并复用旧认证。

## 8 结构 启动与文档治理

### 8.1 随切片拆分热点文件

| 热点 | 目标边界 | 验证重点 |
| --- | --- | --- |
| electron/main.mjs | 保留组合入口，按既有领域拆 IPC 注册与生命周期依赖 | IPC调用方、授权及退出清理；复用已拆模块 |
| src/App.tsx | 作品与对话容器、编辑会话、执行状态 hooks | 切换、迟到结果、未保存草稿、控制互斥 |
| src/CreativeWorkspaceView.tsx | 正文与差异、任务、资料等有独立职责的面板 | 阅读位置、跨章切换、真实状态与错误展示 |
| native/story-runtime/src/server.rs | 认证公共层与按资源组织的路由模块 | 实际HTTP形状、认证、结构化错误和领域调用 |
| native/story-core/src/sqlite_repository.rs | 按聚合拆实现，事务留在拥有完整不变量的用例内 | 原子性、并发冲突、重复提交及恢复 |

拆分跟随行为改进，不先进行全仓文件搬家。衡量跨模块改动范围、依赖方向和重复逻辑，不以单文件行数作为唯一完成指标。结构整理和语义变更尽量分成可独立审阅的改动。

### 8.2 启动按阶段观测

记录 Host 启动、Runtime 就绪、数据库初始化、Engine进程、Core握手、MCP初始化、工具加载、资格核对及首次模型请求的时间。区分源码构建锁、二进制启动、服务握手和模型网络等待，形成冷启动与热启动分布。

先修复实际慢阶段，再比较生命周期复用或预热。任务绑定的 MCP 不能跨任务直接复用旧 capability；可复用的进程资源与必须重新验证的执行绑定分开设计。测试使用隔离数据库、端口和有界并发；超时保留阶段证据并清理本次进程，不通过整体拉长超时掩盖问题。

### 8.3 设计 证据和状态分开维护

总体目标继续放在 IDEAL_ARCHITECTURE，工作包和进度继续放在演进路线。本方案只维护跨切片的优化决策与退出标准；已实现行为回写现有专题合同，实施日志进入对应 design-reviews，原始证据进入已有 evidence 或 CI 产物存储。

证据记录运行身份、源码与二进制摘要、配置、样本清单、阶段结果、失败与证明范围。报告原子落盘，CI 无论成功失败都上传已有产物；/tmp 只作为运行暂存，不成为最终证据唯一地址。只归档脱敏诊断和隔离样本，不把密钥或真实作者全文加入仓库。

发布目录先核实构建脚本和当前使用方，再统一产物位置与清理政策。磁盘占用先区分源码、依赖、缓存和可再生成产物，不按目录大小直接删除。

评审按现有模板缩短内容：文档与简单展示改动使用精简记录，权限、保存、恢复和跨层合同保留完整相关反例。五视角可由同一执行者自审，不默认五个额外模型；不把本方案解释为免除当前门禁。

## 9 实施工作包与退出标准

工作包按依赖推进，不预设日历工期。每包交付可运行的纵向结果，接口、schema、类型、提示、测试和文档一次性同步；删除被替代分支，不引入历史兼容或长期双轨。真实作者资料仍按原授权保护。

| 工作包 | 责任与范围 | 完成证据 | 扩大投入前的条件 |
| --- | --- | --- | --- |
| A 质量与开销共同基线 | 质量样本、Engine观测、现有评测脚本、三类小说任务 | 冻结质量维度与基线稿；复用第2.1节证据，补指南、重复协议、状态往返、出站历史与缓存的贡献 | 有可比质量标准；区分必要创作投入与技术开销，未知项不伪报成功 |
| B 局部编辑闭环 | Core来源与保存、MCP参数、Runtime接口、Host接续 | 从一句请求到差异、保存、必要核验和交付；含冲突与断流恢复 | 保护断言全部通过；实际模型对照有收益，不能只看patch大小 |
| C 授权与恢复衔接 | Work准入、Host持久事件、Engine结算、UI投影 | 讨论转修改、保存后中断、插问返回、改要求、暂停重启 | 无重复写入/根预算；已保存事实不丢失；拒绝原因能决定下一步 |
| D 续写与跨章质量验证 | Authoring输入、完成契约、质量评测 | 扩展A的质量样本；同条件续写及一致性检查、盲评和人工返工记录 | 明确要求通过，无已确认的关键质量退步；分歧和样本局限保留 |
| E 能力质量收益实验 | 方法、委派、知识消融、可选模型策略 | 单变量或可解释的小组对照，全成本计入 | 按第1.1节优先保留质量收益，质量相当时再比较效率 |
| F 结构与运行治理 | 各热点责任模块、启动与证据存储 | 随相关切片完成拆分；阶段启动数据与持久证据 | 原公开行为保持，未增加第二调度器或事实权威 |

A先行并包含质量基线；B的模型可见信息改动须使用A的质量样本验收；C中的目标丢失与交付阻断优先修复；D复用B/C并扩展质量覆盖；E依赖可靠质量对照；F随所涉及切片推进。确定性身份绑定、观测和无语义变化的整理可先进行，但不能把工程回归通过标为文学质量验收完成。

A/B优先处理已观察到的三个放大因素：完整指南分页、上下文重复携带方法全文、缺少有效进展的状态与行动往返。每项比较包含所有新增发现或恢复调用后的总开销，保留同等保存、核验和权限要求；不可通过让模型少读必要原文，或不再完成独立检查制造节省。

### 9.1 指标口径与初始目标

| 指标 | 口径 | 门槛或决策方式 |
| --- | --- | --- |
| 保护与一致性 | 已执行用例中的越权写入、范围外变化、重复副作用 | 相关确定性回归全部通过；任何实际破坏阻断扩大 |
| 创作质量 | 预定任务的意图、连续性、人物声音、语言与节奏；盲评及作者反馈 | 先于成本判断；关键退步阻断，分歧未决或样本不足不得声称质量无损 |
| 端到端交付 | 达到冻结完成条件的样本数除以已启动样本数 | 与同条件基线比较；环境未启动另报，失败和超时留在分母 |
| 首次工具正确率 | 不经参数修正的有效业务调用除以全部有效业务调用 | 与故意错误用例分开；报告纠错次数和错误类型 |
| 全流程开销 | 每个预定任务所有尝试的已知tokens、费用、耗时及未知项 | 报告全部样本总量与成功配对分布，不能只比较成功样本掩盖失败成本 |
| 重复阅读 | 相同版本与范围的重复请求及返回token | 区分核验必需与无进展重复；优先消除后者 |
| 协议与协调负担 | 每次完整交付的指南/发现往返、重复合同文本、状态读取、各执行阶段用量 | 以第2.1节作为具体故障样本，补正常成功样本；降低总成本而不牺牲必要阅读与交付 |
| 作者投入 | 达到满意稿前的干预次数、人工时间和返工 | 与独立人评及全部任务交付率一起判断 |

首个切片的必需退出条件是作者要求与保护全部满足、真实交付成立，并获得与影响范围相符的质量证据。原“已知token中位数至少下降30%”降为质量可比后观察的探索指标，不作为交付门槛或默认策略选择依据。高质量方案即使没有节省30%、甚至使用更多token，也可按第1.1节采用；节省更多但质量较差的方案不得采用。A阶段预先冻结样本、评价方式和费用统计，不能根据结果事后改评分规则。

p50和p95只在有足够样本时作为稳定分布报告；小样本同时列出逐样本值。至少8个满意稿配对是初步产品判断门槛，不是统计显著性承诺。自动CI先检查确定性保护、样本完整性及现有工具效率门禁；外部模型与人评按有明确范围和额度的批次运行。

### 9.2 首个可执行切片

选取已有长章中的一个明确段落，要求增强悬念并保持其余正文。使用隔离作品和当前生产应用入口，建立以下交付：

1. 冻结作者目标、必须保留的特征和质量评价方式；保存当前实现的完整基线，包括一句输入、全部请求、正文前后版本、费用和最终状态。
2. 同源工具声明与上下文构成报告，定位主要重复读取或纠错原因。
3. 在现有 patch 路径上优先修复一个已证实瓶颈；确有必要再实现版本绑定引用，保持同一保存事务。
4. 重复引文、过期版本、锁定片段、Unicode、保存回执丢失与作者暂停的相关合同回归。
5. 相同输入和标准下的真实模型对照，读回整份候选验证保护，人工盲评目标段落及必要上下文。
6. 将实际收益、剩余故障和下一切片写入原工作包记录；未交付或受阻也保留，不自动扩大运行额度。

## 11 文档评审与核对

本次范围仅为专项方案及演进路线入口，不改变生产代码、权限、默认预算或运行行为。事实基线包含当前未提交工作区，提交HEAD仅用于定位仓库，不代表全部源码状态：`307c541801fe9cfaad9ad80dfb1c7d8d9bf016a8`。后续实测必须另存当次源码及构建身份。

前审由同一执行者按五视角自审：架构保留既有循环与事实权威；技术A要求来源绑定、幂等及未知结果明确；技术B要求区分历史、当前实现和目标接口；产品以作者目标、创作质量及可靠交付为优先，再比较投入；UI/UX保留同对话接续和可理解的真实状态。五项均为有条件通过，条件是成文后完成引用、规则一致性和范围检查。该结论不等于代码实施批准或五名独立评审者认证。

文档后审仍由同一执行者完成，结论只覆盖方案质量与规则一致性：

| 视角 | 后审结论 | 核对依据 |
| --- | --- | --- |
| 架构 | APPROVE | 第3至5节保留现有事实权威、执行循环和领域边界；未建立第二调度器 |
| 技术A | APPROVE | 第4至6节明确版本冲突、逻辑幂等、未知结果、暂停与预算，不自动推进来源 |
| 技术B | APPROVE | 第2节区分证据层级；第9节规定逐切片同步与真实边界验收；目标接口明确为示意 |

| UI/UX | APPROVE | 第5节要求同对话接续、可打开成果、真实阻塞及展示失败与执行失败分离 |

## 13 全量验收后的根因分层与结构调整（2026-10-10）

[真实验收](../../design-reviews/2026-10-10-agent-full-acceptance.md)未通过。以下是依据失败证据修订的目标设计，不代表这些结构已经全部实现。创作质量仍为优先目标，原质量与授权标准不降级。

### 13.1 先判断属于哪一类

| 现象/证据 | 根因分类 | 责任与修复方式 |
| --- | --- | --- |
| 稿件未变，direct verification仅因生产Task失败而stale | 已确认的设计耦合，落实于状态过滤代码 | Story Core分离证据有效性与执行生命周期；来源/标准变化仍失效，任务失败仍阻止执行 |
| 小改字与100字写作多轮读取、保存后仍不闭环 | 协作/交付合同复杂性；需按轨迹定位每个额外回合 | 收敛模型可见交付动作，Runtime绑定来源/回执和计算机械完成条件；不要求模型搬运CAS或多份状态 |
| 约98.3%已知tokens为输入、上下文/状态重复回传 | 已确认的成本现象；不能直接等同无效推理 | 按版本及已实际送达内容生成必要上下文，方法全文保留恢复入口；精确统计缓存与重复，不删必要原文 |
| 空段组首尾拼接与整章body.trim比较不一致 | 具体实现/数据合同不一致 | 统一规范化合同并验证空段与Unicode、锁定组；保留原始组内容，不为通过样本改原作 |
| 并发改稿后恢复拒绝 | 安全拒绝本身合理，恢复产品合同仍欠完整 | Native返回来源变更差异和受影响义务；模型决定如何修订，原授权内可重新绑定的新执行由Runtime判定；不得强行继续旧CAS |
| 自动化37项失败 | 测试合同、实现缺陷、时序等混合，尚未逐项归因 | 不通过改断言批量消绿；分别核对真实合同、生产故障及环境负载，保留失败列表 |
| 文学质量缺乏有效A/B与真人评分 | 评测设计/证据缺口 | 冻结可运行基线与同条件样本，真实盲评；单侧稿件与模型自评只能作为材料 |

### 13.2 交付权威分成三个独立维度

1. **产物/证据有效性**：已事务保存的稿件、核验和引用属于持久事实；由当前稿件修订、作者标准、来源依赖与身份关联决定是否仍有效。生产Attempt结束或失败不是单独的失效依据。明确的证据撤销/篡改/换源仍须判无效。
2. **执行可用性**：权限、暂停、预算、未结算费用、执行代次决定是否允许新操作。有效旧证据不授予任何新执行权限，也不自动解锁未知写入。
3. **交付状态**：Native根据原作者目标、当前有效产物、模型提交的创作判断与完整核验、未解决问题及账本计算。已保存不等于完成，任务失败也不应抹掉真实已保存成果。

Host/Renderer分别呈现三个维度；不从一句模型“完成了”推断状态，不把“Task失败”显示成“作品或证据不存在”。保留原失败事件和费用。无需为此另建第二套Work事实表。

### 13.3 模型表达判断，Runtime完成机械交付

目标中的模型输入应直接区分：原始作者要求、用于比较的冻结原稿、当前待核验候选、仍未满足的义务、已知保存回执。每个引用由Runtime给出当前任务作用域内的稳定标识；模型不负责猜测“latest”或同步版本号。只有内容真正送达模型后才记录读取覆盖，不能由预加载或目录出现冒充阅读。

模型可以选择继续写、修订、核验、提出有依据的问题或申请完成；这些动作不固定文学步骤或专家数量。对“申请完成”，模型提交语义判断、必要引文与未解决项，Runtime在既有事务边界内解析引用、核对当前版本/保护范围/必需输出/费用结算，并登记交付；无变化的版本核对、幂等重放、分页续读不再要求模型往返完成。

这是目标合同，不是允许Runtime替模型判断悬念、人物声音或因果。需要独立审阅的作者要求仍需满足；模型发现不足可以主动重写。幂等写入与未知结果核对仍以Runtime账本为准。优先在既有Work决策和交付路径中收敛动作，避免另建Host调度器、固定关键词路由或“写作专用第二循环”。

### 13.4 落地顺序与退出条件

先修已确认的证据/生命周期耦合，使用同一原失败和反例复验；再设计保存→核验→交付的统一语义动作，同步Core、Authoring、MCP、Host与UI消费合同。随后处理上下文重复和恢复所需增量；最后用同条件真实样本比较总请求及token，完成质量盲评。每步保留源代码身份与真实失败证据。

验收要求包括：保存后的生产Task失败不作废同源有效证据；真实换稿/改标准会作废证据；暂停、取消和未知费用仍阻止执行；不重写受保护正文；未完成不冒充已交付；同源缓存不漏掉作者新要求。文学质量单独验收，成本下降不能补偿质量退化。当前不存在“增加预算后跑通即完成”的退出条件。

### 13.5 全部改动重新审查，不以局部补丁代表整体完成

当前优化改动整体重新进入设计审查。已经验证的保护机制和观测成果保留，依赖旧职责分配的实现按新合同重构，测试和文档一起更新。工作区同时存在其他改动，[工作区清单](../../design-reviews/evidence/2026-10-10-agent-change-review-inventory.json)用于识别范围，不代表所有文件均属于本轮，也不代表逐行审查已完成；不得直接清空或批量回滚。

| 审查面 | 处理原则 | 必须重新证明 |
| --- | --- | --- |
| Story Core身份、CAS、幂等、保存事务、账本 | 保留事实权威，核查是否混入文学决策或错误生命周期耦合 | 越权拒绝、重复写、未知结果、并发修改与原文保护 |
| Work/Attempt/Operation及交付 | 重新设计模型可见合同，删除重复机械确认；逐条追踪现有状态的必要性 | 同一作者目标贯穿保存、核验、恢复及终验；真实失败可恢复且不伪造完成 |
