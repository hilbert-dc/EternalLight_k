# 智能体交付自检

## 前置设计评审

目标：最终协调收尾前，智能体核对作者目标、真实保存成果、检查范围与遗留决定，并将自评绑定当前 Work 版本与来源。普通 worker 和选择下一行动的协调任务不承担最终自检。

非目标：不认证文学质量，不新增作者维护面板，不扩展写入授权，不自动采用、删除或发布。

- 架构专家：APPROVE WITH CONDITIONS。原 complete_task 原子事务内保存自评与完成状态；无兼容 wrapper。自评不是权限证书。
- 技术专家 A：APPROVE WITH CONDITIONS。验证当前版本/digest，引用必须来自当前 Work 的真实输出；当前有效正文产物不能遗漏。
- 技术专家 B：APPROVE WITH CONDITIONS。结构与语义边界在 Runtime 再验证，非法请求不写入；completed 幂等重试不覆盖已有自评。
- 产品经理：APPROVE WITH CONDITIONS。保留已完成与未完成的真实区分；无产物讨论允许空引用，不制造额外分析任务。
- UI/UX：APPROVE WITH CONDITIONS。在对话 summary 说明成果、覆盖范围、未完成与待作者决定；不增技术检查表。

当前 schema 直接新增交付记录表；API/MCP/调用方与测试一次切换，不迁移、回填、双写或保留旧契约。

验收：缺自评、过期版本/来源、外部或遗漏正文引用拒绝；真实局部检查可完成且不追加建模；partial/needsAuthorDecision不得标称目标全部完成；分页可获取全部回执；普通worker继续原职责。

## 实施后复核

- 完成任务契约新增 deliveryReview；Runtime 验证当前 Work 版本、来源摘要、真实产物归属与全部当前正文与规划等修订成果覆盖，在原完成事务内持久化。
- 最终连续创作章使用同一机制；中间 worker/协调不提交最终自评，避免逐章重复全篇检查。
- agent 自评与程序保存证据分开。partial/needsAuthorDecision 保留具体遗留事项，已有任务状态仅给中文提示，不新增维护面板。
- 最终对话遵守作者语言/篇幅，不披露内部绑定/hash/版本字段。
- 旧 API 原位切换；Rust 方法签名与调用同步，不新增兼容 wrapper。当前 schema 直接创建新记录表。
- 自检的可信边界：证明引用属于实际保存成果及当前来源；不证明文学质量、不证明模型逐字阅读。实际检查与局限由智能体负责说明。
- 测试结果由主任务统一记录；新增专项覆盖缺失/过期/伪造/遗漏证据、目标状态矛盾、部分完成及零产物讨论。

### 真实模型验收后的语义修正

发现：模型已明确说明第2章不存在、跨章检查未执行，却把目标状态填写为 fulfilled。结构合法不代表语义正确。

修正：最终协调明确区分“实质创作/检查目标完成”和“如实说明无法完成”。缺来源/能力/预算导致未执行的目标必须列为 partial + unresolved；checkedScope 不能成为隐藏未完成目标的位置。真正的作者选择才使用 needsAuthorDecision，明确排除的检查不作为未完成目标。没有关键词扫描、额外模型裁判或 schema 扩张。

agent-followup-policy 契约测试 2/2 通过。它只验证生产提示词注入与规则保留，真实 DeepSeek 行为仍由主任务复验，不以提示词测试代替模型验收。
