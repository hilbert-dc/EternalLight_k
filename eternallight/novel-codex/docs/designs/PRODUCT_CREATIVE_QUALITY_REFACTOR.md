## 1. 产品决策

目标是让作者更容易发现值得保留的写法、维持自己的表达，并把正文中的好发现发展成可持续的长篇。可观察的成功是“作者愿意留下且读者有反应的具体作品变化”，不是系统自称更有创造力。

下一阶段同时建设**质量下限和创作深度**：Q0 建立质量对照，F1/F2 完善工作版本、固定输入与按问题取证，随后开展隔离短试写和独立的长篇规划深审，再接局部修订与组合采用。故事单元手动关联可独立交付；声音、创意兑现和长期承诺诊断分批验证。连续多章、完整世界模拟与跨卷分支仍在之后。

深审可以包含多个专业角色和有限修订；不把后台创作能力简化成一次泛化点评。作者默认看到作品、证据和关键取舍，已明确委托的范围内不逐席重复确认。只读审纲不要求先写正文，也不要求作者先确定全书结局。

作者方向明确时直接写作；方向不确定时才探索。规划可以暂定，结局可以未知，卷与单元可跳过；软件不要求作者先填完结构再创作。保留意图、保留安排、锁定原文继续分别处理。

### 本轮目标与非目标

| 要改善 | 产品机制 | 必须观察的反作用 |
| --- | --- | --- |
| 关键场景只有一个平庸首稿 | 一个问题、两个实质不同的短试写 | 锚定、方案同质、比较负担 |
| 好正文偏离了原安排却难以继续 | 有证据和范围的局部改纲提案 | 自动改向、影响遗漏、反复审阅 |
| 大纲完整却无法持续写，卷间重复或复位 | 分层专业评审、承诺与人物行动检查、定向修订 | 从众、错误否决非常规设计、阶段细节过度约束 |
| 跨次创作使用错误版本或遗漏远处依据 | 作者选定工作版本、版本化取证和覆盖清单 | 最新 AI 候选擅自成为基线、资料过期或越权 |
| 扩写丢失创意，修稿磨平有效表达 | 创意兑现与亮点保护、修后影响复查 | 锚点模板化、旧引文消失被当成问题已解决 |
| 作者表达被默认模型声音覆盖 | 作者选定的样段和可编辑理由 | 偏好僵化、上下文串用 |
| 修改只围绕事实错误 | 有证据的读者体验反馈 | 审美误报、过度解释和磨平留白 |
| 功能越来越多但作品是否变好未知 | 固定基线、成对盲评和作者试用 | 指标替代创作、挑选成功样本 |

不承诺提高每位作者的文学最高水平，不提供统一文学分、热度预测或自动出版。首期不引入跨作品自动学习、作者身份模仿、全书自动改写、自动决定生死／真凶、无限代理讨论或无人裁决正式内容。

## 2. 论文依据与迁移边界

下表的“工程取舍”是产品假设，不能表述为论文已经验证本系统或中文长篇创作。

| 原始来源 | 可以借鉴的证据或机制 | 工程取舍与局限 |
| --- | --- | --- |
| [Re3，EMNLP 2022](https://aclanthology.org/2022.emnlp-main.296/)；[DOC，ACL 2023](https://aclanthology.org/2023.acl-long.190/) | 规划、状态、候选比较和修订共同参与生成；详细大纲控制改善实验中的数千词故事评价 | 复用现有规划链；检验近期安排是否兑现。大纲遵循不能单独代表文学质量 |
| [DOME，NAACL 2025](https://aclanthology.org/2025.naacl-long.63/) | 动态分层大纲和时间知识图谱帮助处理写作中的变化 | 借鉴动态规划与按事件取回记忆；论文限制报告约 200 次调用、4 小时生成约 7,000 词，不能原样搬入交互路径 |
| [Agents’ Room，ICLR 2025](https://arxiv.org/abs/2410.02603) | 专门的规划、写作子任务在其自动故事实验中得到专家偏好 | 先明确任务职责、共享依据和停止条件；不据此推断代理越多越好、已验证长篇共创 |
| [Wordcraft 专业作者研究，2022](https://arxiv.org/abs/2211.05030) | 13 位专业作者、八周使用发现构思辅助价值，也指出声音、套路化和控制问题 | 保留作者样段、修改理由和不同工作方式；这是定性研究，不是我们的质量提升效应量 |
| [Doshi 与 Hauser，2024](https://arxiv.org/abs/2312.00506) | AI 创意辅助改善部分短故事评价，同时增加作品之间相似性 | 作者原始材料先保留，两案必须有实际分歧；同时考察新发现与同质化，不只考察平均偏好 |
| [LitBench，2025 预印本](https://arxiv.org/abs/2507.00769) | 成对偏好可用于评估创作评价器 | 借鉴盲评与偏差控制；其 Reddit 故事偏好一致率不能当作中文小说文学裁判准确率 |
| [LitVISTA，ACL 2026](https://aclanthology.org/2026.acl-long.1024/) | 对叙事结构、功能与关系的诊断揭示模型的全局理解缺口 | 关注铺垫、呼应、节奏；主要实验有给定事件锚点，语料为英文文学，诊断成绩不是生成质量证明 |

论文不能替代真实作者试用。低层可靠性、交互效率、文学体验分别验证；自动评价只能辅助定位与筛查，不能独立宣布“提高创作上限”。

本轮对 EternalLight 的机制研究是另一个证据来源，详见[源码证据清单](ETERNALLIGHT_MECHANISM_EVIDENCE.md)。其中有历史真实模型评审，也有当前未接入和启发式模块；不能把源工程文件数或调用次数当作效果证明。

## 4. AC-2.1：关键问题与两个短试写

### 4.1 作者旅程

1. 作者在构想、章或具体片段处提出一个问题，例如“这场晚餐怎样表现父女疏离？”；也可以直接给两个方向。
2. 系统整理一张可编辑问题卡：本次要比较什么、哪些意图保持、可改变什么、两个方向有何不同。已有明确意图时不重复确认；问题不清楚时只澄清会影响本次写作的一项，不自动补全全书。
3. 作者选择“试两个方向”。A、B 共用同一批准输入，每案默认约 500～1,000 中文字；长度是试用初值，实际按声明的预算限制。
4. 中央并排或切换显示“原稿／方案 A／方案 B”，先看关键差异、可能后果和片段；模型不能把推测后果显示成必然结论，不默认按文学分排名。
5. 作者可带回一案、都不选、保留原稿，或手动组合成实验内的派生编辑修订，保留 A/B 来源但不新增第三个生成方案槽。只有明确选择“带回章节”才写普通候选。理由可选，也可稍后补；不以填理由作为继续写作条件。
6. “带回章节”产生一个普通待采用候选，之后沿用现有审阅和正式采用。选择方案不等于正式采用。

没有章节时也能建立独立实验。实验本身不物化两个章节；只有作者带回时，才选择现有章节或明确创建一个独立章节。新章物化与候选写入必须原子完成，失败不留空章。

### 4.2 隔离与状态

每实验最多两个方案槽；每槽允许不可变修订。重试只更新该槽，成功稿不被另一案失败抹掉。发起新问题建立新实验，旧实验可读和归档，不无限自动生成更多选项。

状态彼此独立：

| 层级 | 状态与作者看到的含义 |
| --- | --- |
| 实验 | 待确认问题、可执行、已有结果、已决定、已归档；版本变化另显“带回前需复核” |
| 单案任务 | 等待、运行、已有部分稿、已交付、失败、取消、外部结果未知；只据持久化输出报告交付 |
| 作者决定 | 未决定、选择 A／B、手动组合、都不选、沿用原稿；决定独立于正式内容状态 |
| 带回 | 未带回、已写普通候选、冲突待处理；记录不可变来源与幂等回执 |

停止后保留已经保存的内容；取消 A 不伪装 B 也完成，停止整个实验不得启动排队的下一案。只有一案完成时允许比较、带回该案或单案重试。部分稿可带回继续编辑，但不得升级为“完整交付”。

### 4.3 输入与领域契约

下表为目标领域责任，名称不是当前已发布 API。CreativeInputSnapshot 的共用底座归属 F1，实验隔离归属 AC-2.1a；实施设计需据此一次性确定数据库、JSON 与类型契约。

| 对象 | 必须包含与约束 |
| --- | --- |
| Experiment | 作品、问题、目标范围、批准意图、共同输入快照、两案方向、保护与可变范围、预算及作者决定 |
| CreativeInputSnapshot | 事务内取得的权限投影内容、来源修订／场景位置、内容 hash、投影和权限策略版本、模型配置、预算与遗漏清单；保存后不可变 |
| TrialVariant / TrialRevision | 所属实验与槽、独立候选头、父修订、正文／场景、完整度、局部假设、任务来源；不成为正式事实来源 |
| TrialSelectionRevision | 作者手工组合的实验内不可变编辑修订、A/B 来源、选定文本及编辑版本；仅作者可写，不移动普通候选头 |
| PromotionReceipt | 选择的确切修订、目标章节、预期作品与普通候选版本、来源映射、幂等请求及结果；带回组合稿产生新的普通候选和新审阅 |

首期目标仅支持 `existingScene` 与 `standaloneFragment`：前者绑定 `chapterId/baseDraftRevisionId/sceneGroupId` 及已有 `sceneId`，后者由 Runtime 分配独立片段身份；都冻结阅读边界、POV、故事时间。首期两案固定相同 POV 与阅读边界；跨 POV 比较需要另行设计权限投影。场景内任意选区、自动插入与重排留后续，不能把现有 `throughScene` 前缀权限当作单场景权限。

共同快照先完成权限过滤，再保存可供任务读取的实际文本，不能只保存引用。A、B 不读取对方正文、假设、点评或聊天历史；每案只能加入自己的批准方向和局部假设。任务按自己的快照版本读，不从变化后的实时工作区补取来源。

快照内容不是新权威 Canon。任务创建、续跑、读取、存稿和完成均重新检查当前许可；权限收紧或来源被撤销授权时撤销相关活跃 capability、停止新增调用并拒绝新写入和完成，有关快照不可用于续跑，旧会话与派生摘要隔离。已保存稿可供作者查看；迟到回包不能恢复任务或改变可交付状态。作品普通编辑使结果需要重新带回核对，但不悄悄改变 A、B 的共同输入。不能追溯撤回此前已经获准发送的模型输入。

隔离试写按固定快照、实验／方案头与当前许可校验，允许普通作品版本在此期间前进；由试写专属校验实现，不放松普通生成任务的当前版本检查。带回时再校验当前作品版本、普通候选头和目标身份。

`generateTrial` 只写自己实验中的单案产物；不能写普通章节候选、另一方案、正式事实或规划。模型提交的事实只能留作该案假设。正式事实需从带回后的正文证据重新确认，不能直接将假设转为事实。

带回使用 author 权限，校验目标位置、锁、完整度、场景身份和当前候选 CAS。既有场景保留身份；新增场景分配新身份并记录映射。局部替换只覆盖作者选定范围，保留未选正文；不能把不可见尾部移动到更早阅读位置。

普通候选或作品版本已变化时，保留试写和本地编辑，展示旧依据、当前稿、试写稿；作者明确重新核对后建立新的带回请求，不自动换基线。重试原请求返回原回执。正式采用继续沿用 Review/AcceptanceCommit；撤销带回只在没有后继修改时恢复前一普通候选头，否则保留版本并说明冲突。

## 5. AC-2.2：带证据的局部改纲

AC-2.2a 先支持已存在的 Outline 或 Plan 节点字段修改，不自动新增、删除或重排结构树；AC-2.2b 再支持跨产物组合审阅与提交。两者是明确的实施边界，不能把单产物采用称为全部改纲能力完成。

正文驱动入口是作者选“保留这个发展”，或在现有反馈中选“提出局部改纲”；P2 另可从规划专项评审的具体意见进入。两种入口共用提案与采用边界，分别标注正文、规划和作者要求来源。不在每次保存后自动生成建议。

改纲卡包含：原文证据及位置、旧安排、建议安排、改变理由、明确依赖、可能影响、未检查范围与保护冲突。作者可维持安排、回正文修改、驳回疑点或选择计划差异；全文改写不是默认操作。

目标对象 `PlanChangeProposal` 至少冻结证据类别及来源修订／场景或规划字段范围、目标 Outline/Plan 基线、逐项旧新值、依赖组、保护变更、来源评审意见／任务和作者决定。模型仅能提交提案，不能直接推进正式规划或解除锁。

正文驱动默认限当前单元、相关章纲和最多三个近期章节；P2 可以审全书，但修订范围须按本次委托单独冻结，不能继承只读权限修改全书。涉及未授权节点时先显示具体扩大范围；已有明确授权不重复询问。数量是首轮交互上限，不可通过截断隐藏必需依赖；超出时缩小目标或拆成依赖完整的提案。

提案可以以普通候选正文作为探索证据，但必须标为未采用证据；正式采用计划变化时，证据须已正式采用，或与本次选中的正文在同一提交内成立。后者归属 AC-2.2b；AC-2.2a 可以探索和编辑此类提案，但只有证据已采用且修改在单种规划内依赖闭合时才能正式提交。不能先改纲成功、再采用正文失败。

P2 的纯规划提案可用已认可作者要求和规划之间的证据，不要求先存在正文；计划中的事件仍不成为已发生事实。若依赖另一个未采用规划修订，该依赖须先成立或随 AC-2.2b 同次提交。全书大纲拆并、增删节点与重排不属于 AC-2.2a／P2 首期，评审可提出建议，不能假装结构编辑已实现。

作者选用提案先形成普通规划候选和冻结审阅，校验每个受影响普通候选头的 CAS，不覆盖尚未采用的作者修改；作者编辑后，提案检查与审阅清单重新核对。

AC-2.2b 新增 `ChangeSetReview`，冻结所选正文／Outline／Plan 修订、证据、各候选头、包内引用、保护决定和依赖。候选构造必须支持包内 Plan→Outline 引用，不能沿用普通保存时强制替换成当前正式 Outline 的行为；其读取与正式提交不得混淆。不能通过顺序调用两次现有 `accept_review` 冒充原子采用。

部分选择必须依赖闭合。例如计划引用了新 Outline 修订，系统列出必须共同采用的 Outline 修改及原因，由作者一并选择或取消；不自动勾选隐藏改变。跨产物的所选差异、正式指针、反馈处理与作品版本一次事务提交或全部回滚。

涉及保护意图、人物生死、真凶、关系和关键揭示时机的变化使用独立方向变更卡。精确原文锁须先通过作者明确解锁流程，不得靠提案绕过；已发表内容不得静默覆盖。

提案状态为待审、需重核、已采用、已拒绝或已撤回；证据正文、目标基线或权限变化使相关检查失效。只有正式采用成功后，关联 impact 才可标记 updated；拒绝或失效不等于已解决。组合回执记录全部前后指针、事实事件与反馈变化；首期只支持无后继修改时整体撤销，存在后继时保留版本和冲突说明，不覆盖后来的作者修改，也不宣称当前单产物撤销接口已支持组合提交。

## 6. 后续增量：声音依据与文学反馈

### 6.1 作者声音依据

作者主动选一个样段，或明确要求记住写作偏好，才创建 `VoiceReference`：来源修订／片段、作者理由、可编辑规则、适用作品与情境、启停状态、有效范围和版本。接受一次修改不会自动变成永久偏好。依据需区分叙述者、POV 与具体说话人，不能把多人对白混成同一声音；人物关系变化导致的有意表达改变可作为本次例外，不因句长或问句率偏离自动纠正。

例如“这段争吵靠动作表现，不直接解释心理”可以仅适用于本作品的一类场景。条目可以矛盾或暂时例外，系统展示冲突供作者处理，不套用统一文风标签。首期不跨作品推断或共享。

原文和提炼出的规则都继承来源权限。任务清单列明本次实际使用的依据；删除、停用、到期和权限收紧影响未来任务并使相关快照／派生缓存失效。没有获准依据时仍可写作，不能伪造作者偏好。

### 6.2 文学反馈

作者选择本轮关注点，例如人物可信度、情绪递进、潜台词或阅读期待。正文 Q2 首期一次只启用一个反馈任务；独立的规划深审 P1 按机制文档第 5 节可启用多个互补角色。默认呈现最多三条高价值意见，可展开全部，也允许没有意见。真实权限、版本或数据错误单独展示，不受三条限制。

每条 `NarrativeFeedback` 包含正文证据锚点、阅读位置、检查范围、可能读感、解释、可选修改及不确定性。作者可选择修改、保留原样或不采纳；审美分歧不阻断保存与采用。修改后旧锚点和结论标为过期。

模拟读者只接收该阅读位置已公开的信息；创作顾问仅在另一个明确许可的任务中读取允许的幕后材料，两者的会话、反馈与检索不得混用。不把模型想象的读者反应当作真人反馈。

反馈不能强制每章冲突、反转、悬崖结尾或显性心理解释。正文角色扩展逐个验证增益、成本与相互冲突；规划 P1 已单独定义有限多角色协议，不受正文单关注点限制。

Q2 同时支持作者选定的创意兑现检查与修稿亮点保护，见机制文档第 6 节。锚点只承载作者明确选择的意图，不要求每章都出现反转、代价或成长；原文证据匹配不等于语义成立，删除旧引文也不等于问题修好。

## 7. 预算、恢复与界面统一要求

- 预算覆盖共同规划、取证、两案生成、专业评审、综合、修订、复查和失败重试；各模式只执行自己授权的步骤。执行前可见调用数、目标篇幅、墙钟上限及可靠的费用估计；无法估计费用时明确未知，不能显示零。
- AC-2.1 首期默认两案各一次生成任务；重试由作者触发并显示剩余预算。P2 的“审并改”可在既有授权内执行一轮修订和一轮影响复查，不无限循环。沿用当前作者输入与组装消息硬预算、Unicode 分片和上下文遗漏说明；两案不能绕过单任务限制。
- 应用尝试数、AppServer turn 数、工具读取量与墙钟分别设限；一次 turn 内可能有多次模型请求，不能把两个方案写成确定两次模型调用。底层模型请求数、实际 token 和费用按可信事件观测；当前 Adapter 尚无完整汇总时记未知。若产品声称某项硬上限，必须在实际执行层可强制，不能用估算替代。
- 应用文本预算与 provider 实际用量分别记录。外部请求结果未知时保留请求／turn 身份，先核实持久化产物；无法确认后再次生成算新尝试，不承诺模型执行或计费 exactly-once。
- 应用重启不自动续花预算。显示已保存片段、原输入版本和上次状态；作者选择继续时重新检查权限、凭证、预算与来源。
- 未保存正文、方案编辑和改纲编辑使用一致的保存／放弃／留在此处规则。切页、切章、关闭和晚到回包不得丢稿或覆盖当前编辑。
- 窄屏可切换 A/B，宽屏可并列；原稿可随时查看。键盘能到达切换、选择、关闭与错误，焦点可恢复；不只靠颜色区分方案或状态。
- 方案 ID、修订号、模型角色、依赖键和 hash 位于可展开的依据详情，主流程使用作者语言。
- 修正文案中“必须先固定方向／结局”的暗示，保留“待定并探索”。当前 Brief 文案优化与新领域逻辑分开提交。

## 8. 创作质量基线与研究方案

### 8.1 两类对照

离线机制比较优先以 B「当前 AC-1」对 C「B 加一个新机制」；工作基线、主动取证、双试写、规划深审与局部改纲分别增加和验证；规划深审另比较去掉某一席或修订步骤后的结果。A「同模型直接写作」作参考，不能只选弱基线证明复杂流程有效。

冻结作品输入、模型配置、采样设置、最终篇幅、总输入／输出预算上限、调用数和时长上限，包含规划、比较、批评与失败重试。C 有两案选择时，B 也有同预算的生成或修订机会。分别报告等预算与真实默认配置结果；保留选择方法和所有产物，不事后挑最好种子。逐请求记录实际用量，不为凑齐预算强制增加调用。严格等模型预算比较需可观测底层请求与用量；未接通时只报告应用尝试／turn／时间边界，不宣称等算力，详见机制方案第 8～9 节。

建议准备 12 个开发任务与 12 个冻结保留任务，覆盖悬疑信息安排、人物关系、日常慢节奏；每类包含方向明确、真实分歧、正文偏离和表达要求。长篇机制另外加入跨卷重复、承诺兑现、独立人物行动和同书三次续创任务，并包含刻意安静、非线性且没有缺陷的对照。扩充后的样本规模在 pilot 后预登记，不能把原短场景样本当作长篇结论。保留任务每条件做三次独立运行。先用开发集 pilot 校准预算与可收集性，再冻结配置和门槛；这只是小规模研发证据，不能外推所有作者。

### 8.2 评价与退出条件

| 维度 | 采集方式 | 不能替代它的指标 |
| --- | --- | --- |
| 可靠性 | 隔离、权限、版本、恢复、预算的确定性回归 | 文学评分、生成完成文案 |
| 作者价值 | 作者判断是否符合意图、属于自己的表达、有值得保留的新发现、愿意继续；记录具体片段与理由 | 一次采用、少修改、字数 |
| 读者体验 | 同意图成品匿名、随机左右位置的成对盲评；主要问题为更愿意继续阅读，另报人物可信、情绪、语言与新意 | 模型自评分、固定文学总分 |
| 使用成本 | 包含规划、等待、比较、审阅和修改的时间；调用和实际用量、未知用量、失败率 | 候选保存到采用的墙钟代理 |
| 多样性 | 同题与跨题材的方案差异、套路和重复检查，辅以人类片段解释 | 单一嵌入距离或词汇丰富度 |

每对成品计划至少三名读者，允许平手、不适用和无法判断；读者仅获当前位置公开背景。作者知道操作方式，不能将其操作体验称为盲化。统计按任务／作者聚类，报告平局、分歧、失败、置信区间与题材差异，不能把每次投票当独立样本扩大显著性。分别报告全部预定运行的完成率，以及双方有可评成品时的条件偏好；未完成、取消和超预算案例保留在总体分母中，不能仅展示成功样本偏好并推导整体效果。

作者可用性沿用现有产品计划的 8～12 位中文作者交叉体验，顺序平衡、任务难度相近但不重复；仅有真实分歧的 4～6 位作者参与探索功能初测。此为招募计划，尚无真人参与。

pilot 后、查看保留集前登记：主要读者偏好指标、作者意图／控制感的非劣界限、允许的等待与审阅成本、预算上限和分析方法。不得把论文百分比直接作为本产品门槛，也不得事后改变门槛。区间或样本不足以支持结论时，标为证据不足，保留实验入口而不默认扩展。

任何秘密越权、正式态污染或丢稿立即暂停对应机制。连续两轮预先冻结的验证仍无实用增益或超出成本门槛时，停止增加代理与修订轮次，重做假设；再次评估使用新保留任务，避免在同一保留集上调参。只有可靠性与创作价值两类出口都满足，才考虑默认开放和扩大规模。

### 8.3 研究材料与匿名指标分开

31 项本地 metrics 继续保持固定匿名聚合。质量研究另有作者明确参与的 `QualityStudyPackage`，包括匿名案例号、材料授权、冻结配置、逐请求成本、作品修订、盲评映射、评价及片段理由；它可能含正文，不能称为无内容匿名统计。

研究包默认本地、与生产作品及聚合指标分开保存；导出前逐份预览范围。联系作者、录制、上传、外发或作为训练数据另行取得明确授权。退出可删除研究副本，不删除作者作品。首次真实调用前确定模型和预算，首次外部研究前落实材料范围、人员、期限及删除方式；本轮没有执行这些操作。

| Q1 声音依据 | 作者样段／理由、说话人归属、有意变化、权限与版本 | 验证更符合作者表达；未选样段不自动成为永久偏好 |
| Q2 文学反馈与创意兑现 | 单关注点反馈、选定意图锚点、亮点保护、作者驳回和过期处理 | 依赖 F1；远距证据用 F2。修订沿已有候选边界，不新建正式权威 |
| 后续 AG | 连续多章、跨卷分支、人物模拟、结构树调整和更长篇观察 | 独立设计身份、依赖、来源映射与验收，不阻塞 P1/P2 现有节点能力 |

建议推进顺序：在已完成的 F1 与 P1 只读闭环上，Q0 建立质量基线 → F2 补证与 AC-2.1 探索分别交付 → AC-2.2a／P2 → AC-2.2b。N1 可独立排期，N2、Q1、Q2 按作者试用结果推进。作者声音与正文反馈仍不是 AC-2.1 首批出口；P1 当前结果也不能被误称为已完成 P2 修订或已经提高文学质量。

每阶段按数据契约／Runtime 行为／IPC 调度／UI 旅程分成可审阅的小变更，单次落地必须保持可运行闭环；必要的接口、类型与 fixture 同批切换。代码实施前仍须按 [设计模板](../../DESIGN_REVIEW_TEMPLATE.md) 完成该阶段五角色设计审查，不用本文替代数据库与协议细节评审。

## 10. 关键验收场景

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| Q01 | 无结局、无卷纲，仅给一场晚餐 | 可直接写或建立实验，不强制补全规划 |
| Q02 | A 假设父亲知情，B 假设父亲不知情 | 独立任务和假设；两案未带回时普通候选、正式正文／事实／规划不变 |
| Q03 | A 后作者修改普通章节，再运行 B | 仍读批准共同快照；带回要求重新核对，无实时材料混入 |
| Q04 | A 完成、B 失败、随后重启 | A 原文保留；显示 B 边界；仅显式重试 B，不重复收费式盲重跑 A |
| Q05 | 生成中收紧样段或故事材料权限 | 相关任务停止新增读取／调用，旧会话不可用于重试；不能宣称撤回已发送内容 |
| Q06 | 选择 B、都不选、手动组合 | 选择不等于采用；组合先存实验内派生修订；明确带回才建普通候选并重新审阅；都不选不改变作品 |
| Q07 | 试写替换中间场景、原尾部含秘密 | 锁和场景身份保持，未选尾部不被泄露、删除或前移 |
| Q08 | 无章节的实验带回新独立章时写盘失败 | 新章和候选全部回滚，无空章或假成功 |
| Q09 | 带回响应丢失、重复点击、旧请求重试 | 一次普通候选结果；不覆盖后续作者编辑；可查原回执 |
| Q10 | 候选正文引出的改纲提案 | 标明未正式证据；正式提交须证据已采用或随正文原子提交 |
| Q11 | 只选依赖新 Outline 的 Plan 差异 | 明示必要依赖，不自动夹带；不闭合不能提交，闭合后全部成功或回滚 |
| Q12 | 保护真凶／关系／揭示时机被改变 | 独立方向变更卡；未批准保护变化不得进入正式内容 |
| Q13 | 证据变更、提案拒绝、撤销后有下游修改 | 旧检查失效，impact 不假装解决；拒绝／撤销不覆盖新作品 |
| Q14 | 作者仅接受一句话或停用声音依据 | 不自动学习；停用项和派生规则不得进入未来任务 |
| Q15 | 安静场景、含混对白、反馈被驳回 | 不因缺反转或模型偏好阻断采用；意见引用确切文本并可过期 |
| Q16 | 两案总预算已耗尽且外部用量未知 | 不继续自动发起；未知不写零；保留全部已存稿 |
| Q17 | 切页、关闭、窄屏和键盘操作 | 编辑不丢失、状态可读、错误可定位、焦点可恢复 |
| Q18 | 读者盲评与研究导出 | 读者包不含作者秘密，随机顺序和失败记录完整；外发需明确授权 |

阶段映射：Q01～Q09 属 AC-2.1（Q02～Q05 隔离基础，其他为完整旅程）；Q10 的已采用证据与 Q12～Q13 属 AC-2.2a，Q10 的正文同次采用、Q11 及组合撤销属 AC-2.2b；Q14 属 Q1，Q15 属 Q2；Q16～Q17 为各新增交互通用要求，Q18 属 Q0。后续条目不计入 AC-2.1 首批出口。

新增 M-A01～M-A22 及其 F/P/N/Q 阶段映射见[机制方案第 10 节](PRODUCT_CREATIVE_MECHANISMS.md#10-增量验收与阶段映射)，与本表共同验收。全书规划检查、正文阅读覆盖和正式采用完成分别报告。

Runtime 负责事务、权限和故障注入；Agent 测试通过真实 handler/Adapter 验证操作与交付；真实 React/Electron 回归覆盖作者旅程；固定模型端到端验证实际提示、工具调用和保存。macOS、Windows 桌面与 Linux Runtime 的适用行为分别记录证据。既有功能回归继续执行，但本轮文档不报告新测试通过。

## 11. 实施前必须具体化的事项

产品方向与边界由本文固定。进入各阶段实施设计时确定具体 schema／IPC 名称、公共校验模块的抽取顺序、事务与错误码、快照删除和许可撤销索引、场景／单元唯一身份与映射、工作版本依赖、来源回执与补证失效、评审发现合并规则、AppServer 可观测性、上下文及研究包大小上限。数值预算由开发集 pilot 校准并在正式比较前冻结，不能在运行中由模型自行放宽。
