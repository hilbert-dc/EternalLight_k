# 长篇创作执行可靠性设计与评审

日期：2026-10-07。依据：实际应用《万城灯火》100章体验、保存回执、任务记录和模型请求记录。本记录由同一实施者按五个角色独立审视；不冒充独立人员评审。

## 目标与边界

目标：新章创作通过明确章数的 GenerationRun 执行；候选链顺序推进时读取新冻结输入；最终交付由模型提交可验证自检；上下文在桥接输入硬限制前压缩，超限不得重试同一请求。总字数是全书规划目标，100章是本次生成任务目标，两者分开保存。完成只以实际章回执及最终审核为依据。

非目标：自动采用、发布候选；用主机编造模型自检；通过自然语言关键词自行扩大权限；历史兼容、升级、迁移、双读双写。保持现有作者确认范围和预算的生成入口。

影响模块：Electron 同租约执行及 advisory prompt；Native 候选动作输入校验；Agent Engine 上下文目录与桥接错误；真实 Runtime 协调测试、当前 schema 测试与应用验收。

## 目标架构与实施

1. 新章与批量章节优先走 request_generation_handoff，使用真实目标章数、作者意图和当前来源。已有 GenerationRun 持久记录章回执、任务次数、预算和检查点；不能以普通对话 canFinish 替代生成目标。将这一分流置于 ordinary advisory 的前部，避免被资料修改提示淹没。
2. Native 对候选链只认可同 Work、同原始 advisory、已完成且有实际保存回执的孩子改变 candidate head。accepted head、working baseline、作者意图及工作区版本必须仍相同；其他工作和手工写入仍拒绝。旧任务的冻结来源不更新；下一 worker 重新冻结当前输入。
3. Work 决策有最终自检要求而模型仅返回文字时，Host 在原任务、线程、执行租约和预算内发出最多两次协议纠正，要求模型读取最新 read_work_status、提交 complete_task。Host 不构造 deliveryReview；仍未完成则明确协议失败，保存内容保留。普通 worker 和只选下一动作的协调不新增自检要求。
4. 模型目录的压缩阈值使用保守输入预算的60%，保留 tokenizer 差异、工具协议及下一轮任务注入空间。桥接精确输入硬限保留；该超限具有固定诊断码、400终止状态及 retryable=false，不重复请求耗空时间。自动压缩仍由 Core 在原线程执行，不创建新工作或额度。
5. 既有构建身份和策略一致性门禁保留，源代码验收使用重新构建的当前 Runtime/Engine；打包应用不是源码热更新。

## 验收标准

- 三项同源候选顺序批准并执行，后续 worker 看到实际前序候选；手工、其他 Work、采用或基线改变仍拒绝。
- 真实 Runtime + 生产 Host：模型遗漏 complete_task 时同任务纠正成功；不生成额外预算，不伪造审核；连续遗漏有界失败。
- 全100章生成目标不能在99章满足；既有生成检查点和恢复测试通过。
- 上下文输入硬限拒绝必须非重试；模型目录阈值低于硬限并有余量。
- 当前源码构建与必要回归通过；实际应用验证明确记录所用构建、操作及保存结果，不能用模拟测试声称100章实际生成成功。

## 测试阶段零兼容门禁

- [x] 不因旧调用方、旧数据降低目标架构。
- [x] 当前生产代码、fixture、测试与文档一起更新；不改变历史格式。
- [x] 集成测试重建当前 schema 测试作品。
- [x] 数据一致性、并发授权、错误恢复及安全门禁必须验证。
- [x] 无兼容实现；无需兼容例外授权。

## 五角色实施前评审

- 架构专家：APPROVE。Native 负责来源与完成权，Host 负责协议履行，Engine 负责输入预算；不把模型提示当作唯一完成校验。不得更新旧快照。
- 技术专家 A：APPROVE WITH CONDITIONS。候选变更必须有同源已完成回执；外部修改负例和原租约额度验证是发布前阻断检查。
- 技术专家 B：APPROVE WITH CONDITIONS。协议纠正不得在租约关闭后重建任务；最多两次。真实 Runtime 测试必须覆盖自然回复而漏工具的路径。
- 产品经理：APPROVE。作者看到实际保存数量、部分完成及可继续状态；100章目标经生成入口明确确认，不以创建第一章代替目标。
- UI/UX：APPROVE。保留当前明确章数与预算的确认界面；协议错误说明已保存成果保留，不能要求作者手工处理内部技术字段。

综合结论：APPROVE WITH CONDITIONS，上述负例与集成测试通过后方可宣称修复通过。获授权兼容例外：无。

## 上下文恢复补充评审（实施前）

已超限的线程也要能在原线程压缩恢复。桥接的400终止响应携带 context_input_budget_exceeded 与 retryable=false；Codex API 只把这个结构化输入超限映射成 ContextWindowExceeded，普通400保持 InvalidRequest。Core既有压缩逻辑在压缩请求超限时裁掉最旧历史项后重新构造请求；不重复相同失败请求，也不重置任务额度。

影响新增：codex-rs/codex-api 的 HTTP 错误分类及测试。五角色复审：架构 APPROVE（错误语义一致）；技术 A APPROVE WITH CONDITIONS（严格诊断码，非重试标记）；技术 B APPROVE WITH CONDITIONS（正例与普通400负例测试）；产品 APPROVE（现有超长对话可恢复）；UI/UX APPROVE（无需作者手工缩短技术上下文）。零兼容门禁 PASS；未增加历史格式处理。条件：当前 CLI 必须重新构建及更新构建身份，不能跳过门禁。

## 长范围来源校验补充评审（实施前）

真实 Runtime 范围回归发现：生成入口接受100章，但 generation_author_source::history 仍把 end-start 限制为2，导致超过3章的作者来源在启动事务内被拒绝。统一使用 MAX_GENERATION_CHAPTERS 检查范围，保留所有来源、历史文本预算和原子事务校验。100章启动及101章拒绝的真实HTTP测试作为阻断验收；不增加兼容路径。

五角色复审：架构 APPROVE（唯一范围常量）；技术 A APPROVE WITH CONDITIONS（100章原子启动回归）；技术 B APPROVE（保留来源和历史预算）；产品 APPROVE（界面承诺与启动边界一致）；UI/UX APPROVE（不向作者暴露内部来源字段）。零兼容门禁 PASS。另一个回归测试沿用409断言，但当前接口对未发出的 intentRevision 有明确400参数纠正说明；按当前契约修正该断言，不改变生产校验。

## 长正文保存回执补充评审（实施前）

实际源码应用已在当前 schema 环境批准第2—100章的99章范围。第2章真实正文已保存；随后 Runtime 保存 DTO 同时回传 body 和 sceneGroups 的全文，MCP 原样送回模型，约28KB的重复中文内容触发单项10K token限制。正文输入本身只有一份且已通过限制。根因是把供作者界面展示的数据模型直接当作模型的写入回执。

目标：MCP 成功保存只返回绑定到实际存储结果的 chapterId、checkpointId、revisionId、version；完整正文及分组继续由 Native 保存并供读取。非目标：提高输入上限、截断稿件、伪造完成审核、重新生成已保存的第2章、重置范围或预算。影响模块：MCP 保存成功输出契约与说明、当前 fixture、真实 Core/Bridge/MCP/Runtime 集成测试。Native HTTP 作者 DTO 保持完整。

验收：长中文稿只产生一份写入，后续模型回合收到有界回执并成功继续；Native 读回正文、分组、版本与回执完全一致；成功回执目标不符或关键字段缺失必须拒绝，失败 HTTP 错误原样保留。实际应用从既有保存成果与原范围恢复。

五角色评审（同一实施者按角色审视）：架构 APPROVE（分离作者数据与模型写入回执）；技术 A APPROVE WITH CONDITIONS（校验实际回执绑定，保留原 CAS 与错误）；技术 B APPROVE WITH CONDITIONS（真实全链路长正文、完整读回及负例）；产品 APPROVE（已保存稿件可恢复，范围和完成依据不变）；UI/UX APPROVE（无需作者缩短正文或处理技术字段）。综合 APPROVE WITH CONDITIONS，集成测试及实际恢复为阻断项。

零兼容六项门禁 PASS：不新增版本探测、fallback、迁移或双轨；不以旧行为降低架构；生产契约、说明、fixture 与测试一起更新；使用当前 schema；保留一致性、权限及故障恢复验证；兼容例外无。

## 当前生成故障恢复补充评审（实施前）

真实保存后失败还暴露两个当前版本问题：决策协调的局部 save 只更新 GenerationRun，不更新 Work 的列表索引状态，导致 blocked/running 不一致而任务列表拒绝读取；普通重试把已完整保存的 writer 重新排入写作队列。目标：GenerationRun 是生成状态唯一权威，生成 Work 的读取状态从经过现有来源校验的 Run 投影，局部写事务同步列表索引；作者继续原运行时，在同一事务使用既有 recoverable_output 核验当前完整稿件，且没有未决工具写入，恢复 failed writer 的产物完成状态，保留原错误与用量，然后交由模型决定章节交付。只有真实当前完整产物可恢复，不生成模型自检，不修改稿件、范围、历史回执或额度；partial、无产物、变化来源及未决写入不可走该恢复。

影响：Core 的生成状态投影、决策写事务和作者重试事务；当前 HTTP 故障/重启/继续测试。验收：blocked 任务列表可读，重启后作者继续不产生第二个 writer 或第二份稿件，预算不变，模型仍需选 finishChapter 并提交最终审核；partial 仍为原范围内实际重试。

五角色评审：架构 APPROVE（Run 权威，列表状态仅索引）；技术 A APPROVE WITH CONDITIONS（当前回执、来源、未决写与结算门禁，同事务恢复）；技术 B APPROVE WITH CONDITIONS（真实 HTTP 正例、partial 负例与重启）；产品 APPROVE（继续保留既有稿件与范围）；UI/UX APPROVE（原任务恢复入口可用，无技术操作）。综合 APPROVE WITH CONDITIONS。零兼容六项门禁 PASS，当前故障恢复不增加历史数据处理或迁移；兼容例外无。

## 长正文回执与恢复实施后复核

实际变更：MCP 成功保存校验原生回执的目标及必要字段，只输出四个保存字段；完整 HTTP DTO 与存储正文保持不变，错误原样保留。生成 Work 状态从经过现有来源校验的 Run 投影，决策事务同步列表索引。作者继续原运行的事务复用既有 recoverable_output，完整当前稿件恢复为产物完成状态，保留原错误、原任务、已结算额度及原范围；未决工具写入阻断事务，partial 仍需实际 writer 继续。最终章节交付仍由模型选择，最后一章仍须模型提交交付审核。

验证证据：MCP 全52项通过；真实 Core/Bridge/MCP/Runtime 集成以4500汉字稿件复现旧全文回执会超过单项10K限制，单份正文请求约6770保守 token获准，精简回执低于500 token，随后模型回合成功；完整正文与原分组读回一致，一次写入、原任务三次请求、原授权不变。当前 HTTP 恢复8项通过：完整稿件不重写、不新增 writer 或额度；partial 不冒充完整；未决写入拒绝且事务无变更；状态索引不作为第二生成权威且只读不改库；既有暂停、重启、取消及重规划均通过。Electron 离线恢复6项通过。定向差异检查和当前 Native 构建通过。

实际应用：当前 schema 环境通过 CUA 创建《万城灯火》，原第1章3421字符精确保留。真实模型在第2—100章的已批准99章范围内保存了第2章4533字符。用户亲自更换工程密钥后，源码应用重启，并在模型选择器完成真实 DeepSeek / deepseek-flash 连接验证，界面显示“模型连接已就绪”。随后在原对话通过“继续任务”恢复原生成运行。尚未宣称100章完成；以后续实际章节回执为准。

五角色实施后复核：架构 APPROVE（作者数据、模型回执及 Run 权威清晰）；技术 A APPROVE（完整回执、原错误与结算保留，未决写拒绝）；技术 B APPROVE（全链路长稿、完整读回、当前故障与负例通过）；产品 APPROVE WITH CONDITIONS（真实长跑100章仍待完成）；UI/UX APPROVE（已保存正文及原任务继续入口通过实际应用验证）。零兼容门禁 PASS，无兼容例外或迁移工作。与方案无语义偏差；实际100章长跑是唯一未完成的目标验收。


## 单项模型输出超限补充评审（实施前）

实际应用第5章 writer 在桥接出口被拒绝：`provider_output_item_limit`，function_call 的参数 30,891 UTF-8 字节、保守计量 14,000 token，超过原有 10,000 上限。该调用未交付 MCP，正文未保存。现有 `executeManagedTurn` 把任何回合失败都视为进程损坏，杀死健康 App Server 并丢弃线程身份，导致模型无法在原能力、租约和预算内更正自己的格式/篇幅错误。现有 MCP 的互斥正文校验在工具调用入场后才发生，不能处理此前的输出入场拒绝。
