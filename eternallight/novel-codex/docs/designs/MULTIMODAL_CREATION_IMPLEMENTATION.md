# 多媒介创作完整实施契约

日期：2026年10月8日

状态：实施进行中。用户已授权按[理想架构](MULTIMODAL_CREATION_ARCHITECTURE.md)全部落地；功能是否完成以本记录中的实际证据为准。

## 共同实施边界

沿用现有单仓库、单应用、Agent Engine 与 Rust 领域 Runtime。当前工作区已有其他创作与可靠性改动，不能覆盖、撤销或用空实现替代。

三个媒介均可以独立创建。项目身份 API 与 Edition API 分离；漫画、动画内容不进入虚拟章稿，不在调用小说 API 时以空小说投影伪装完成。共同版本以既有 story revisions、snapshots 和 receipts 为权威，新增作用域明确映射到对应分支。

共享 TypeScript 契约为 [multimedia-types.ts](../../shared/multimedia-types.ts)。Rust 使用同样的 camelCase 字段、封闭类型与校验；fixture、HTTP、IPC 和模型工具同步核对该契约。该文件不含凭据、任意文件路径或模型可伪造的执行身份。

## 当前 HTTP 和 IPC 目标

- 创建项目登记标题、简介、medium 与幂等键，返回真实 project、editions、activeEditionId。
- editions 的创建与列出依附于项目，明确 medium、scopeId 与 branchId。
- 漫画和动画 workspace 返回 edition、headSnapshotId、revisionId、typed document、保存原字节 documentEncoding、assets 和 sources；小说继续使用其已绑定 Edition 的小说投影。
- 保存绑定 expectedRevisionId、typed document、idempotencyKey、readSet 和 sources。读取依赖区分 pinned 与 mustBeCurrent，不能隐式改用最新资料。
- 素材导入先登记操作，受控导入、文件归档后事务登记；预览由可信应用素材引用提供。
- 模型工具以真实任务能力调用，不能使用作者 token 绕过目标和预算。
- 媒体操作引用当前 Work/Attempt。执行状态与费用由 Engine 权威存储负责；领域库保存目标绑定与素材回执，不另建调度和预算体系。

## 2026-10-08 本轮补齐

本轮继续共同底座，未改为另一套漫画/动画引擎。以下是当前工程能力，不能替代真实供应商或完整作品质量验收。

- **图片消息**：媒体对话可以只发送图片，作者原文保持空串。真实素材编号贯穿 Host、任务冻结、模型请求、失败重试和重启历史；没有图片的空消息仍会拒绝。小说对话仅图片发送不在本切片范围。
- **图片资格**：作者显式点击“验证当前模型的图片输入”，才向当前连接发送两张随机像素测试图。答案不写入提示；两次观测证据独立于文字工具证据，绑定当前凭据作用域、协议、构建指纹和有效期。识别失败会撤销识图资格，文字资格保持；认证或账户访问失败仍按原连接门禁处理。本批全部为受控传输，没有真实外部或付费请求。
- **局部编辑**：`patch_media_document` 的封闭操作覆盖页、格、对白、镜头、轨道和片段。稳定 ID 与分页避免整篇重写；单事务保持未读子节点、锁、来源关联及读依赖。整批无效即无写入；真实保存回执才显示成果。
- **共同设定**：新增人物、世界、规则、时间线和风格编辑。保存以及作品“使用最新设定”均由作者明确操作；采用创建新的作品修订，模型不能替作者采用。每个文档修订固定共同设定及素材库集合，历史导出和旧任务不被后来更新污染。
- **来源变化**：比较实际引用的段落、画格、镜头和片段。无关兄弟节点更新不误报；选区失效/移除分别提示，不覆盖当前改编。入口位于编辑器“设定与来源”，默认折叠，不增加对话底部日志、重复任务按钮或永久模式。
- **离线交付**：可编辑项目包含保存原字节、固定共同设定、真实素材及完整摘要清单；路径、文件集、大小和摘要严格验证。恢复只写入新目录，不覆盖作者数据。外部原作来源仍是显式引用，这不是全项目历史数据库备份。
- **发布资源**：FFmpeg、FFprobe、字幕字体和许可证进入固定清单；检查真实目标架构、依赖闭包、签名后摘要和空 PATH 渲染。缺失或伪造组件直接阻止发布。本机 Homebrew 组件有外部依赖，未伪装为便携发布包。后续字幕实现改为固定字体的 Electron 光栅化与 FFmpeg 合成，不再依赖 `drawtext`。
- **跨版素材**：宿主只读取原 Domain 操作明确授权的素材修订。同项目其他 Edition 的真实引用可复用，未授权或任意项目素材仍被拒绝。

验收入口已经加入 `npm run test:multimedia` 和常规 `verify`。需要真实开发编解码组件的 `npm run test:multimedia-media` 要求显式指定 FFmpeg、FFprobe 和字体，缺配置即失败，不能用跳过测试伪装为实际渲染通过。

### 实际字幕预览与成片

动画字幕使用明确配置的固定字体。预览和导出共用字形覆盖检查、字幕布局和时间边界；缺字体、缺字形或超出版面明确失败，原字幕文本保留。空白字幕不要求字体。私有 Electron session 从内存提供唯一随机页面，拒绝外部页面、文件、脚本、权限及新窗口；大中文字体不会再受 data URL 长度限制。

成片先合成视频画面，再叠加透明字幕 PNG。帧边界按有理数运算并使用半开区间，避免相邻字幕多出一帧；同时出现的字幕有稳定的布局和资源限制。字体识别依据是 Chromium 实际使用的 custom font 与字形数量，结合字体文件摘要、PNG 透明度及成片像素验证。MP4 清单保存真实 renderer 的 `subtitleEvidence`，包含字体摘要、实际字体字形及对应帧区间；不把系统字体替换或空结果登记为成功。可编辑作品包不包含本机字体文件。

发布门禁在空 PATH 下启动当前构建版本的真实 Electron，调用正式字幕链生成 H.264/AAC，再由 FFprobe 和字幕前/中/后三帧回读。固定组件清单中的字体摘要、实际 custom font、帧区间和当前 Electron 版本都必须匹配。开发机成功不能替代有许可证、依赖闭包和签名证据的便携安装资源。

### 固定修订上的长文本

对白、画格说明、镜头说明和字幕的结构页返回稳定身份与 `textFields`。模型调用 `read_media_workspace` 或 `read_media_source` 的 `section: text`，以独立的 `charOffset`、`charLimit` 分页；不把全文塞入结构页，也不默默截断。每页最多 8000 Unicode scalar，实际序列化输出最多 64 KiB，包含确切修订、全文及切片摘要和实际返回范围的来源引用。共同设定 statement 也可读取，但模型不能写入；其来源用 `canonSources(entryId)` 另行分页。

`startChar`、`endChar` 是 Unicode scalar 半开区间 `[start,end)`，不是 JavaScript UTF-16 下标。`charOffset` 相对当前授权文本窗口，`returnedSource` 中的范围是原字段绝对坐标。`textDigest` 是 UTF-8 全文 SHA-256，`sliceDigest` 是返回片段 SHA-256；文档 `source.digest` 仍是保存的 `content_json` 原字节摘要，不能相互替代。

`replaceTextRanges` 在同一字段上接受 1–32 个基于原文本坐标的非重叠替换，同时校验全文、切片摘要、版本、锁和任务授权。每批同一字段只有一个该操作；所有修改、来源关联和读取依赖原子提交，无效批次不产生修订。重复请求沿用真实幂等回执。固定来源不能扩展到兄弟节点、其他字符范围或未授权作品，也不会因为任务已经保存新稿就改读 HEAD。

来源区域保留原有折叠结构，显示“对白／画格说明／镜头说明／片段字幕／共同设定”、字符范围与短摘录。语言意图继续交给模型；工程只校验实际身份、授权、摘要、资源上限和提交结果。
