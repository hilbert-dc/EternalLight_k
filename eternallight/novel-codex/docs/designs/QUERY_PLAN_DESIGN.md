# 任务绑定的证据查询计划

状态：已落地，S2 的受限查询执行切片；不是完整语义召回验收。

当前排序协议：计划必须显式给出 `ranking`，初次使用 `literal`；Codex 可对该报告的全部结果提交来源摘要绑定的 `modelSemantic` 判断。Rust 在原任务授权读快照内重建基准，拒绝旧摘要、缺项、重复或未知结果，再按候选分数重排并执行原整包预算裁剪。重排只评价已返回的授权候选，不改变证据或确认状态，也不认证模型推理质量。旧的缺省 ranking 格式已移除。详见 [语义判断与来源绑定重排](SEMANTIC_QUERY_RANKING_DESIGN.md)。

当前召回扩展：`passages` 无需关键词即可逐页读取授权源正文，再由 Codex 按含义找证据和评分；原文游标绑定任务、问题、步骤、政策与源水位，不依赖派生索引。每页有硬字符/数量/字节预算，POV 缺少认知证明时原文保持隐藏，裁剪不得跳过未返回片段。页完整、范围末尾与全局语义认证明确区分。见 [无关键词原文召回](PASSAGE_RECALL_DESIGN.md)。

范围更新：新增 extractCommitments 后，当前开放九类模型任务。下文八类为此前协议切片和测试记录；新增任务复用同一只读入口，正文固定当前选中 sourceRevisionId，结构范围不晚于源章，Context Pack 不注入全书规划。绑定源文是必需输入，预算不足明确拒绝。详见 [提案提取契约](COMMITMENT_EXTRACTION_DESIGN.md)。

## 决策

由当前 Codex Agent 将作者问题转成有限 `StoryQueryPlan`，不新增直接调用模型的分类器或任意 SQL 接口。Rust 校验、执行和报告覆盖；模型负责提出检索词、识别问题和依据证据作答，不能以规划自签完整性。

生产入口 `query_story` 对当前九类模型任务开放，复用任务能力、源水位和取消机制。正文、精确名称候选、时间状态、关系扩展均在同一 SQLite 读快照内执行，权限与任务输入在该快照再次核验。范围统一由 `TaskQueryScope` 推导，Writer/POV 不能通过此入口变成作者全局视角。只读子 Agent 可使用根任务相同范围，不能自选其他作品或历史快照。

计划含问题、最多四个具名步骤和 4,000–9,000 字节整包预算。有限操作为 text、passages、resolveEntity、state、relations。步骤不执行表达式、不依靠名称自动合并身份；多个同名身份返回候选，Agent 须据证据选择明确 ID 后再查询，不把第一项默认为正确身份。关系最多三跳，状态区分世界时间和认知时间。

报告包含计划、快照、任务、来源水位、分通道覆盖、有来源的结果、缺口和内容哈希。不把多跳路径升级为事实。超过预算整条移除可选结果/发现并明确标记，绝不截断 JSON 或原文引用；装不下必需报告时拒绝。结构化覆盖与语义完备不同，语义完整性始终未知。

## 证据打包与排序

报告使用共享 `evidence` 字典，结果通过 `evidenceRef` 引用。去重键包含对象、不可变 revision、字段路径、原文 quote 和 start/end 字符位置；相同文字但不同章节、revision 或字段不合并。同一来源的不同断言、正反主张、身份候选和确认状态也不合并。认知结束证据保留独立 `epistemicUntilEvidenceRef`。来源引用保持完整，不保留重复的旧内联引用格式。

结果具有稳定 `resultId`，冲突 findings 使用结果 ID 和共享证据引用，不再依赖排序前的数组下标。初次排序采用问题和操作检索词的可解释字面词/中文双字重叠分数；它本身不是语义重排。可选第二阶段使用 Codex 模型的相关性候选分数，保留 `literalRelevanceScore` 和候选理由，且不能改变来源/冲突/确认。两阶段均不是可信度、事实确认或模型质量评分；相同分数保留原顺序。

整包最多保留 40 个不同证据片段，并遵守原字节预算。裁剪优先从仍有多条结果的通道删除最低分整条结果，再处理只剩单条的通道；同分优先移除更大的结果。通道保底是预算允许时的优先策略，不保证所有通道永远能装下。移除后清理孤立引用并使对应通道与整包 coverage 不完整；清空受影响通道的冲突发现，撤除可能跳过遗漏证据的游标，要求重新查询。所有保留引用必须能在共享字典中解析。

预算裁剪后，原正文游标若已越过被移除的结果会被撤除，并要求以更小范围/limit 重新查询，不能跳过未返回证据。状态后端的统计记录原通道覆盖；`originalReturnedItems` 与 `returnedItems` 单独区分报告实际保留量。移除结果后清空可能引用它们的 findings，不能保留失去证据的冲突结论。

## 验证与边界

### 全任务范围统一

由 `story-core` 根据已授权 TaskRecord 推导唯一查询范围，不接受模型自签范围：advisory、Brief、Outline、非滚动 Plan 和规划评估允许项目级证据；滚动 Plan 只读 `planFromChapter` 之前的正文及原始知识；Writer 保留已有章节/场景/POV/时间边界；建模和场景评估的正文只读绑定章及源修订，结构化证据最多到该章。第一章滚动规划的前文范围为空，不退回全作品。范围受限的结构知识不读取后续身份决议或作者确认。

`query_story` 和 `read_context(queryPlan)` 对当前九类模型任务开放；未知操作、缺失绑定、过期输入、取消及跨作品仍拒绝。普通 `search_story` 复用同一正文范围，不能成为联合查询门禁的旁路。组合读取保留初始/最终全局来源一致性检查，并核对报告自己的有效范围水位；`queryScope` 进入 Context Pack 的策略哈希，即使没有联合计划也明确报告有效范围。建模源和场景评估源重新匹配当前选中修订，政策中带具体 `sourceRevisionId`。

建模 Context 的实体目录也在 SQL 选取上限之前按章节筛选，并保留原始 ID，不携带后续作者身份决议。滚动规划、Writer 和场景评估的 `workingKnowledge` 复用同一原始来源投影；`stateFacts` 是按范围过滤的独立作者确认记录，不能把它的确认状态倒灌进原始工作知识。第一章滚动规划没有正文或结构知识输入；完整 Brief/Outline/Plan 仍属于明确标为计划的创作输入，不当作事件。

实体目录预算先扣除联合报告空间，最终整包仍可完整移除可选实体条目并清除可能悬空的歧义组，设置 `ambiguityScanComplete=false` 和 `entityCatalog` 覆盖缺口。目标正文、建模源正文、冻结计划及联合报告必须保留，合计装不下则明确拒绝。当前版本同步替换原禁止路径及 fixture，不增加兼容分支。单人实施，不组织独立评审。

当前定向验证：三个 `query_scope_tests` HTTP 场景覆盖 Brief/Outline/Plan、首章与后续滚动规划、普通检索旁路、取消、绑定建模源、目录隔离和不足预算；六个 `authoring_run_tests` 包含真实三章领域阶段中的四通道场景评估；二十个 `runtime_http_tests` 包含真实规划席位的组合查询，以及 Author 确认与 Writer 原始知识分离；MCP 三个测试对八种操作的根/可信子 Agent 逐一执行只读转发。

### Context Pack 融合

`read_context` 可带类型化 `queryPlan`。MCP 只将计划编码为 Runtime 查询参数；模型不能上传自制报告。Runtime 用当前任务凭证执行同一核心查询，核对报告的快照及来源水位与初始 Context 读取一致，再将完整报告放入 `queryReport`。最终原有来源/快照检查仍执行，混合版本拒绝。

查询报告是该次请求的必需输入，不能因外层预算被静默清空；基础包的可选正文/元数据/知识仍按既有预算规则裁剪。两部分共同受最终 UTF-8 预算，装不下则拒绝；内层保留自己的来源引用、哈希及不完整覆盖，外层哈希覆盖整个组合。内层检索不完整时，外层也报告 `queryRetrieval` 缺口；内层完整不能覆盖基础包的其他缺口。计划绑定外层 policy digest。

组合入口允许全部九类模型任务，无任务凭证的 Author 不开放。Runtime 执行计划并核对有效范围水位；基础包及查询报告共同受整包预算。这是协议及任务范围的融合，不等于所有任务的语义 Context Pack 已验收；统一语义选择、相关性去重及金标质量评估仍待完成。

### Writer 有效范围

- 正文：目标章及之前，目标章受场景前缀约束；POV 任务不返回未证明人物已知的正文命中。
- 身份：使用前文原始来源声明，不读取后续作者身份合并或确认结果；POV 名称候选目录保守隐藏。同名多 ID 保持歧义。
- 状态：复用状态来源筛选与投影，但 SQL 在来源上限之前强制目标章之前的范围，身份为原始 ID、确认状态为 candidate。拒绝 author 视角；POV 只允许 character，继承绑定 owner 和 storyTime。绑定时间不能被请求替换，指定阅读位置必须等于目标位置，内部结构知识仍限于前章。
- 关系：复用现有 Writer/POV 图门禁；多跳不产生新事实，未绑定时间的 POV 查询保守隐藏。
- 水位与策略：报告使用范围内对象/知识水位和明确的 `policy`，策略摘要涵盖章节、场景、POV、时间及身份/确认规则。POV 状态覆盖不暴露被隐藏主张的数量或缺失来源诊断，并始终不宣称证据完备。

本轮为两个 Writer HTTP 全链路场景及 MCP 根/可信子任务转发补充回归：四通道组合、前文来源、目标场景正文、未来章和场景后缀隔离、作者视角/换 owner/换时间/换阅读位置拒绝、POV 隐藏正文与名称、组合包水位与整包预算。后续身份决议/作者确认及百万字带计划组合的专项验证仍需补充；已有源码边界不能代替其集成证据。

集成验证覆盖联合来源、名称歧义、时间筛选、来源失效、任务取消/绑定、未授权任务禁止、坏计划、整包预算和子 Agent 工具白名单。本轮仅新增测试断言依赖 `pretty_assertions`，无新生产运行依赖、无 schema/旧数据升级、无上游内核改动。按用户要求单人实施，不组织独立评审。

既有五个 `query_plan_tests` HTTP 场景与两个 `query_writer_tests` 场景已通过。MCP 的三项本地 TCP/权限回归覆盖八类任务的根任务与可信子 Agent 只读转发、组合计划的 URI 编码，以及未知操作和子 Agent 写入拒绝。Electron 真实 sidecar 另验证 Outline 工具列表及带 bearer/task capability 的联合查询转发。技能说明已按 skill-creator 校验通过。这些是工程和确定性协议证据，不是供应商真实模型自主规划质量认证。

Writer 阶段完整验证：`CARGO_NET_OFFLINE=true npm run verify` 退出码 0，覆盖仓库边界、TypeScript/Vite 构建、领域与 Runtime 测试、引擎及委派集成、发布门禁、Agent 与 Electron UI 回归；严格 Clippy 通过。`just bazel-lock-update` 已成功结束，上游锁文件无变更。上述验证不包含供应商真实模型认证或 Windows 真机验收；全任务扩展另行记录本轮验证。

全任务扩展完整验证：`CARGO_NET_OFFLINE=true npm run verify` 退出码 0，包含所有 native 领域与 Runtime 回归、179 项引擎测试、2 项真实 Codex 委派集成、7 项发布门禁、131 项 Agent 测试和 8 项 Electron UI 测试；独立 native 工作区严格 Clippy 通过。回归发现的两处旧断言（建模正文的章节范围、Outline 的 MCP 工具列表）已按新契约更新，保留未来知识隔离、只读授权和真实鉴权转发验证。真实 Codex 测试使用受控模型端点，不能据此认证供应商模型或宣称连续创作质量达标。当前 macOS 验证不替代 Windows 实机证据。

证据打包另有五项行为测试：不同来源/字段/位置不误合并，同源矛盾主张保持独立，排序后冲突引用仍指向正确结果，结束证据独立保留，低预算不优先清空后续通道、不会保留孤立引用，40 片段上限和内容哈希确定性。公开 HTTP 联合查询还验证状态与图对同一原文共享引用，且场景字段引用不被改写为全文路径。该轮完整工程验证包含 131 项 Agent 回归及 8 项 Electron UI 回归通过。

当前已接通模型候选语义重排的协议和 Rust 执行；仍需真实供应商自主规划/打分的质量评估、全书语义召回、所有任务的语义 Context Pack 验收、金标召回和 Windows 验证。精确来源去重、协议融合及候选重排不等于语义召回或全局推理完成；既有回归结果不自动覆盖新排序协议，当前验证另记于重排设计文档。
