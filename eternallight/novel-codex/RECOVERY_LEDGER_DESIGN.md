# 权威工具操作恢复账本

## 目标与边界

恢复依据来自领域事务，不来自模型文本、HTTP 成功码或 Host 日记猜测。复用现有 Task、候选回执、动作、知识发布与任务完成记录，不建立第二任务状态机，不改上游 Codex 内核。作者操作不是模型工具调用，不伪造调用身份。没有工具身份的直接领域调用不冒充 Host 操作；已派发但尚未产生权威证明的请求仍由 Host 保持未知。

## 实施设计

- 原生 MCP 将规范 JSON 的工具/原始参数摘要传入 Runtime；元数据不暴露给模型参数 schema。
- 两个独立 Rust 工作区启用精确浮点解析。MCP 对跨 JavaScript 边界的参数统一规范化后再验证、转发和计算摘要：整数形式的浮点数及负零收敛到整数；超过 ±(2^53−1) 的整数明确拒绝并要求用字符串，不能静默舍入后当成另一个请求。原文字符串不被改写。这是当前统一协议，不是按模型配置的补丁。
- Runtime 在已有 Candidate 能力认证后绑定根线程、Task、turn、call、工具名及摘要。子 Agent 不获写入权。绑定先持久化 accepted，重复调用身份不能换参数或工具。
- 仓储的候选保存、行动登记、知识发布、评审报告、任务完成在业务提交的同一事务内关联具体证明；回滚不产生 committed。重放已有候选回执同样绑定到原产物，而非新 UUID。
- 存储只包含身份、SHA-256 摘要、状态、时间及领域回执引用；不存工具参数、正文、摘要回复或 bearer/capability。候选确认与正式 Canon 权限不变。
- 恢复分页在 SQLite 同一事务冻结任务状态与操作元数据，fence 绑定作品、排序后的 Task 集合和页长，后续页读不可变成员。限制任务数、每任务调用数、总快照行数和 fence 寿命；未知/过期 fence 拒绝，不重建另一份快照冒充原分页。
- 没有业务证明的 accepted 保持 outcome-unknown；未知工具和提交前中断不猜为成功或失败，不自动重发写入。

## 实施者自检

按用户要求单人实施，以下不声称独立评审已通过：架构复用领域权威；技术 A 检查事务、身份与幂等；技术 B 检查真实 HTTP/持久化/分页测试；产品保留明确核对；UX 沿用现有恢复入口。无旧 schema 升级、双轨或兼容逻辑。

## 验证要求

真实仓储重开验证提交前未知、提交后回执丢失、幂等重放、事务回滚、跨作品/任务、身份冲突、来源变化及固定分页；HTTP 验证 Candidate 身份与 Author-only 恢复查询。MCP 验证摘要传输。进程级断点测试须覆盖 Host 未观察到成功的实际持久化写入。供应商真实模型与 Windows 实机验证另行报告，不以本机自动化代替。

## 实施状态

权威元数据表、同事务回执关联、固定分页、根身份绑定及 Host 摘要核对已实现；没有新增上游内核修改或第三方 crate，MCP 复用当前 SHA-256 依赖。报告重放返回与首次保存一致的对象和 ID。

专项验证：5 项领域测试、1 项 HTTP 测试、10 项恢复集成测试通过。其中真实 Runtime + MCP 重启用例同时验证 `1.0` 的参数规范化、Host 未观察成功的候选写入，以及完全未进入 Host 日记的任务完成调用；两者均从真实数据库找回原回执。数值边界与 header 注入测试通过，独立引擎的 IEEE-754 往返测试通过。

最终完整 `CARGO_NET_OFFLINE=true npm run verify` 通过：构建、两轮原生 Rust 测试、180 项引擎测试、2 项真实 Codex 委派集成、7 项发布门禁、143 项 Agent 测试、11 项 Electron UI 测试。产品原生工作区与独立 `eternallight-engine-core` 的严格 Clippy（`-D warnings`）均通过。证据来自当前 macOS 和受控模型端点，不是供应商真实模型认证。构建仍有现存的大体积前端分包警告，不影响这次测试结果。执行 `just bazel-lock-update` 后根 Bazel 锁文件没有漂移。

剩余边界：未进入领域绑定、尚未到达 Runtime、或无法识别的调用仍人工核对。拒绝/执行前取消尚无全入口持久化证明，不能据空结果自动重发；无损模型 token 恢复、供应商连续创作、Windows 实机和全部 S1–S5 完成尚未证明。
