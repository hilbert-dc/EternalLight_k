# 对话 Markdown 渲染设计评审

版本：1.0 · 2026-09-19 · 状态：实施后复核通过

## 变更概览

- 目标：让 Novel Engine 回复使用完整、安全的 GitHub Flavored Markdown 渲染，支持标题、段落、粗体、斜体、删除线、引用、表格、链接、行内代码、代码块和嵌套列表。
- 非目标：执行回复中的 HTML、脚本或事件属性；改变 Agent 事件协议；为旧的自定义 Markdown 解析器保留双轨。
- 影响模块：Renderer Markdown 组件、对话样式、前端依赖、UI 测试。
- 当前版本验收标准：GFM 表格与行内格式正确生成语义化 DOM；原始 HTML 不执行；代码块可读且可复制；亮色与暗色主题均可读；构建和 UI 测试通过。

## 测试阶段零兼容门禁

- [x] 不涉及数据库或 IPC schema。

## 角色评审

### 架构专家

- 结论：`APPROVE`
- 模块边界与依赖方向：Markdown 解析封装为独立纯 Renderer 组件；App 只传入受长度限制的文本，不把解析职责继续堆入主组件。
- 是否存在无授权兼容层：否。

### 技术专家 A

- 结论：`APPROVE WITH CONDITIONS`
- 可靠性、安全、并发与性能：使用 `react-markdown` 的 React AST 渲染，不启用 `rehype-raw`，因此模型文本中的 HTML 不进入可执行 DOM；流式文本允许中间态逐次安全解析。
- 条件：增加恶意 HTML 与危险链接测试；禁止 `dangerouslySetInnerHTML`。
- 是否把当前版本可靠性误写成历史兼容：否。

### 技术专家 B

- 结论：`APPROVE WITH CONDITIONS`
- 实现、测试与一次性切换完整性：移除 `splitConversationBlocks` 与手写解析器；锁定依赖版本；为 GFM 表格、引用、嵌套列表和代码路径增加组件测试。
- 条件：构建、UI 测试、依赖审计与 diff 检查通过。
- 是否遗留双轨、fallback 或半迁移状态：否。

### 产品经理

- 结论：`APPROVE`
- 用户价值与范围：Agent 输出的结构层级、重点、表格和代码能够被快速扫读，解决“模型已输出 Markdown 但界面像原始日志”的核心问题。
- 是否把旧行为保护误列为产品需求：否。

### UI/UX 设计师

- 结论：`APPROVE WITH CONDITIONS`
- 流程、状态、错误与可访问性：保持 Codex 风格的低噪声正文；表格横向溢出而不撑破右栏；引用、行内代码和链接有轻量视觉区分；标题层级不应压过工作区主标题。
- 条件：亮/暗主题都使用现有 token，表格保留语义标签和键盘可访问链接。
- 是否保留无价值的旧交互双轨：否。

## 综合决策

- 最终结论：`APPROVE WITH CONDITIONS`
- P0/P1 阻断项：不执行原始 HTML；完整 GFM；删除旧解析器；关键 DOM 与安全测试。
- 获得明确授权的兼容例外：无。
- 实施范围：独立 Markdown 组件、样式、依赖、测试与实施后复核。

## 实施后复核

- 实际变更：新增独立 `MarkdownContent` 组件，以 `react-markdown` + `remark-gfm` 渲染回复；删除旧手写分块与格式解析；补齐标题、段落、强调、删除线、引用、链接、行内代码、代码块、任务/嵌套列表和表格样式；代码块保留复制操作，表格支持键盘聚焦和横向滚动。
- 与方案的偏差：无。危险协议链接降级为不可交互文本；原始 HTML 通过 `skipHtml` 丢弃，未启用 `rehype-raw` 或 `dangerouslySetInnerHTML`。

- 五方复核：架构专家确认组件边界独立；技术专家 A 确认无 HTML 执行路径；技术专家 B 确认构建、回归、安全测试与依赖审计通过；产品经理确认模型结构化回复恢复可扫读性；UI/UX 设计师确认视觉截图中的标题、引用、嵌套列表、表格、代码与链接层级清晰，亮暗主题沿用现有设计 token。
- 剩余项：无阻断项。Vite 仍提示现有主 bundle 超过 500 kB，属于后续性能拆包范围，不影响本次 Markdown 正确性与安全性。
