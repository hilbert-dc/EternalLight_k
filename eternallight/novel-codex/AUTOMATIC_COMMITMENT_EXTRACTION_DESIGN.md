# 连续创作中的叙事承诺提取

## 目标与实施边界

补齐 S3 连续工作稿循环：Draft → Extract（知识）→ Commitments（承诺提案）→ Assess → Check。每章的承诺提取是已有 `extractCommitments` 模型任务，不新建执行器、状态机或正式写入链。只有作者可将提案建立为独立承诺、调整或确认；自动提取不宣称识别全部隐含伏笔、文学质量或兑现判断。

## 方案

- Rust authoring 在知识就绪后冻结本章当前正文修订，返回带运行版本、步骤令牌、意图代次、章节及源修订的提取任务。
- Task/Step/Attempt 领取事务核验阶段及章节；任务创建及候选提交沿现有来源、CAS、能力、幂等和恢复账本链。子 Agent 仍只读。
- 运行中的提取报告必须声明连续覆盖整章字符范围；普通独立提取仍可声明局部范围。覆盖是模型声明的处理范围，不是语义召回证明。没有发现候选可提交空 candidates，但不能用空报告跳过本章处理。
- 提取阶段计入模型调用预算，失败及重试仍消耗调用。最低预算改为每章五次加初始 Brief/Outline；单次许可上限为 32。反馈重写及当前章调整均需预留重写一次、知识提取一次、承诺提取一次、评估一次，加后续每章五次，不把剩余预算重置。Check 是确定性阶段，不额外消耗模型任务名额。
- 当前 `usedTaskAttempts` / `maxTaskAttempts` 的计数单位是模型任务尝试名额；另有跨任务供应商请求/token 总账，两者均不是实际费用。一项 Codex 任务可包含多次推理或工具回环。宿主默认保留最低所需名额之外的四项反馈修复额度，不承诺失败后自动补充额度。
- Electron 使用现有引擎通道执行提取并等待权威完成后推进；三章的确定性宿主步数上限同步增加，不因新增必需阶段在末章前中断。
- 阶段 UI 显示“提取叙事承诺提案”，任务详情及候选面板复用现有交互。

## 实施者五视角自检

按用户要求单人实施，不召集或冒充独立评审。架构：唯一运行权威与执行端口；技术 A：原事务绑定与失效门禁；技术 B：真实 Runtime 三章、重写、预算和恢复测试；产品：默认自动处理而非要求逐章按钮；UX：明确候选提案、阶段和失败，不伪装正式承诺。无升级、双轨或历史兼容路径。

## 验收

真实 HTTP 三章及第四章续作经过提取阶段，输出绑定具体源正文；不完整处理范围拒绝且不能完成任务；暂停后重开恢复已提交报告而不再次消耗模型调用；每次重写重新提取当前正文。检查最低预算、反馈预算及错误目标领取回滚。Host 验证真实阶段路由，UI 验证阶段文案。执行完整 verify、严格 Clippy、最终格式化和差异检查后记录结果。

专项实施证据：7 项真实 Runtime 生成测试通过，包含三章、第四章续作、重写后新来源、空/部分处理范围拒绝、错误章节领取不消耗预算，以及提交后暂停/恢复不重复提取。宿主阶段路由与既有任务交接共 8 项测试通过。

最终验证：`CARGO_NET_OFFLINE=true npm run verify` 通过，包含构建、两轮 Rust 工作区测试、180 项引擎测试、2 项真实 Codex 委派集成测试、7 项发布门禁测试、144 项 Agent/宿主测试与 11 项 UI 测试；严格 Clippy（工作区全部 targets，`-D warnings`）通过；独立工程严格边界检查 `strictReady=true`。构建仍有既有前端大体积 chunk 警告。模型回环采用受控端点，此记录不构成真实供应商文学质量或 Windows 实机认证。

字符范围回归另复现并修复 SQLite length 在 NUL 处提前终止的问题；运行报告的处理范围统一按 Rust Unicode 字符数校验，与正文证据锚点一致。第四章真实提交、建模、提取和完成用例覆盖中文、NUL 与补充平面字符。新增阶段的主要逻辑位于私有 `commitments.rs`，已有较大 authoring 编排模块只增加阶段胶水，不新增平行状态机。

边界：这次完成自动提案阶段；后续的规划受限装配现由 [规划提案上下文](COMMITMENT_PLANNING_CONTEXT_DESIGN.md) 继续实现，其证据独立记录。承诺演进/兑现判定及依赖反馈不借自动提取或装配冒称实现。真实供应商连续创作、金标承诺召回、Windows 实机及全部 S1–S5 验收仍未证明。
