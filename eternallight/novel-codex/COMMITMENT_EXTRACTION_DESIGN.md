# 正文绑定的叙事承诺提案提取

## 目标与边界

新增 `extractCommitments` 任务，复用现有 Codex 执行、Task/WorkStep/Attempt、能力凭证、冻结方法、候选修订、幂等与恢复。每次绑定一个当前正文源，模型可提出零到十六项开放承诺候选；不建立供应商直连、第二调度器或自动 Canon 写入。

提取结果是不可变 `commitmentExtraction` 候选报告，而非已经建立或确认的独立承诺。报告中的 ID 是批次内提案 ID；作者选择建立独立承诺时再赋予长期身份，避免模型抽取改动覆盖作者自己的承诺。这一边界需要后续逐项审阅/建立接口和 UI 接通，不能把保存报告冒充完整 S3。

## 契约

- target 固定 chapterId、chapterNumber、sourceRevisionId，创建任务事务核验其是同作品 main 当前选中的 draft。输出对象固定为 `commitment-extraction-{chapterId}`；输出 CAS 冻结于 inputManifest。
- payload 固定 chapterId、sourceRevisionId、examinedRanges 和 candidates。范围使用原文 Unicode 字符偏移，排序且不重叠；仅表示模型声明读过的范围，不证明语义完整。每个候选 setup 引用必须精确匹配绑定源并位于某个声明范围内。批次内 ID 不重复，报告最多 40 KB。
- 候选暂只允许 open、无兑现引用、无放弃理由与开放窗口。模型不能以提取任务关闭已有伏笔，也不能伪造作者决定。正文承诺证据复用现有严格校验器。
- Context Pack、普通检索与查询计划都只读取绑定正文范围及相应有界状态；不注入全书规划。绑定源文是必需输入，放不下则明确拒绝，不能只留下“本次分析完成”的空上下文。
- 根任务唯一写工具 `submit_commitment_extraction`；子 Agent 仍只能检索，不允许提交。Author-only 可重读报告及其 sourceCurrent/覆盖说明；报告本身禁止作为 Canon 或正式故事承诺采纳。
- 有效输出仍可完成任务、记录回执及在重启时恢复；来源变动阻断旧任务。空候选合法，不能解释为本章绝无伏笔。

## 五方面实施前自检

按用户要求由实现者自检，不召集评审：架构沿用现有引擎与单一修订权威；技术 A 核验源、范围、根/子权限与撤销；技术 B 真实仓储、HTTP 和 MCP 回环；产品支持批量候选且不强迫兑现；UX 区分提案与已建立承诺，空结果和未扫描范围不伪装为全局通过。无旧字段 fallback、双写、迁移、供应商专属逻辑或上游内核修改。

## 可独立审阅的实施顺序

先落核心任务、输出校验与真实仓储测试，再接 Runtime/MCP/Host、对话请求与回归。作者明确要求“提取并保存候选”时，advisory 可登记 extractCommitments 步骤，创建请求事务再次检查来源与原任务输入；Host 仍通过既有候选工作流执行，WorkStep 认领/恢复/结束沿原权威。普通提问、预测不能自动登记持久任务。

当前建库定义同步扩展候选任务请求的 operation 约束；当前 schema 测试从空数据库运行，不为旧测试库增写 migration。后续再完成作者逐项建立独立承诺、自动创作循环派发及 UI；各段使用同一契约，不留兼容入口。确定性测试不替代真实供应商的文学质量、作者体验与 Windows 实机验收。

## 已实现的任务管理闭环

候选提取沿同一个持久化 WorkTask → WorkStep → Task/Attempt 执行。对话登记请求和认领任务时分别检查当前来源；输出对象、章节、源修订和 CAS 都不能由模型临时替换。完成必须有合法持久化报告，重复提交返回同一回执；取消、输入失效与终态禁止迟到写入。重启只依据真实输出恢复，不根据模型文字判断成功。

报告读取与独立承诺建立刻意分开：报告标为 candidateProposalBatch，旧正文报告仍可阅读但 sourceCurrent=false。报告不能直接进入正式采纳，零候选不意味着无伏笔。绑定正文超过上下文预算时明确失败，不静默丢弃源文。

新增验证分层包括真实 SQLite 的四项任务/证据场景、真实 Runtime HTTP 的对话请求—认领—提交—完成回环、原生 MCP 根/子写入权限、Host 冻结指令，以及实际 Codex app-server 通过原生 MCP 的读取—提交—完成调用。最后一项使用受控模型和 HTTP fixture；它证明协议执行，不是供应商语义质量或生产 Runtime 的单进程端到端认证。

## 作者逐项建立设计（领域与桌面契约已实现）

Author-only `POST /chapters/{chapterId}/commitment-extractions/establish` 接收 reportRevisionId、proposalId、baseSnapshotId、expectedRevision、idempotencyKey。领域从指定快照中读取选中的报告，选择一个提案；由作品/报告修订/提案 ID 的确定性摘要生成长期 commitment ID。同一提案不会因为换请求键创建重复对象，重试沿既有候选回执返回同一结果。

独立承诺内容保留 extractionOrigin（chapterId、reportRevisionId、proposalId），来源不可删除或改绑。第一次建立在候选保存事务内再次核验报告当前选中、提案与正文证据；只允许原提案内容加上长期 ID。后续作者可正常修改状态、摘要、窗口与证据，但保持原始来源可回看；报告后来被替换不撤销已经建立的作者对象。建立不是正式确认，继续使用已有 Review accept/undo，不新增接受路径或第二状态机。手工承诺 origin 为 null；来源信息不注入受限模型投影。

实施者五方面自检：架构复用 save_candidate/不可变修订；技术 A 校验同作品快照、事务 CAS、当前报告和来源不可变；技术 B 仓储重试/并发失效与 HTTP 权限回归；产品逐项建立且默认候选；UX 显示提案来源与未确认状态，拒绝过期操作而不默默采用新报告。按用户要求不召开评审或使用编码子 Agent。无兼容、旧库迁移、自动确认与供应商分支。

实施顺序为领域建立与来源不变量、Author HTTP 完整回环，随后同步 Electron 独立 IPC 模块/preload/TypeScript 契约。报告在同一读快照返回 snapshotId 与 projectRevision，作者必须提交看见的版本，不能自动重绑最新报告。桌面接口已支持读取、建立、保存来源、专用 Review；作者可见面板及完整对话调整仍是后续范围。建立请求仅创建一个对象，正式采用仍需单独明确操作。

## 作者可见面板设计（当前实施）


章节页以折叠“叙事承诺”面板呈现提案，按需读取，不在作者写作时自动抢占正文。显示模型声明的阅读范围、不可变原文证据和语义覆盖未知；未生成、空提案、来源失效与接口失败分别展示。建立只提交当前看到的报告/快照/版本；未知结果保留同一幂等请求供重试，不自动重绑新报告。报告读接口增加当前快照内已建立的提案身份，刷新和重开面板后不会重复建立。

打开独立承诺后显示 candidate/confirmed、状态、兑现标准、来源和证据，支持明确确认与撤销当前确认，不合并建立和确认。内容编辑必须统一接入全局未保存提示、保存/放弃与导航保护，本轮不加会丢失输入的局部编辑器；摘要、状态、窗口与原文锚点的完整编辑留给后续统一编辑能力。正文未保存或 Agent 在运行时禁写，来源失效禁止建立和确认；切换作品/章节/来源立即隐藏旧数据并拒绝迟到响应，包括 A→B→A 切换。确认与撤销仅调用现有 Author Review 流程。读取同一快照的确认提交身份、作品版本和 undoAvailable；只允许现有内核规定的当前最新、非组成员确认被撤销，后续正文或其他提交使撤销不可用，界面解释限制，提交事务仍是最终门禁。不能绕过快照约束撤销历史确认。

实施者五方面自检：架构只加领域投影与 React 展示，不新增权威；技术 A 冻结 CAS、幂等、来源失效与异步隔离；技术 B 真实仓储/HTTP、真实 Electron React 与视觉检查；产品区分建立与确认；UX 低干扰、键盘操作、证据和空状态明确。依用户要求不召开评审，不新增兼容、迁移、自动确认、供应商分支或模型写权。窗口/证据完整编辑、旧报告独立对象全局列表、完整对话调整与自动派发仍须后续完成。

独立承诺返回的 authorControls 与历史故事投影分离：当前读取返回同一读事务中的 projectRevision/undoAvailable，指定历史 snapshotId 时 authorControls 固定为 null。确认身份、来源和内容仍按指定快照重放。历史内容不能带上后来作品版本或后来撤销可用性，历史读取不能被当作实时操作依据。真实 HTTP 回归比较撤销前后同一历史读取的完整对象，并核对其与当时故事投影一致。
