# 百万字长篇基准与索引恢复验证

状态：S5 的有限规模验证，不是理想架构全部验收。

## 设计与边界

本次针对长篇数据规模下的读取和派生索引恢复建立可复现证据，不修改模型供应商适配、不增加旧接口/旧数据兼容，也不以合成文字替代文学质量评估。按用户要求由当前执行者直接实现与复核，未组织独立专家评审。

基准通过生产 `SqliteStoryRepository` 的创建作品、保存候选、创建任务、发布建模批次及完成任务接口生成数据。SQL 仅用于读取实际规模；没有直接写表伪造生产发布链。数据在临时目录内生成，正常退出后清理，不触碰作者作品、密钥或真实模型。

运行入口：在 `eternallight/novel-codex` 执行 `npm run bench:long-work`。它以 release profile 编译并运行 `native/story-core/examples/long_work_benchmark.rs`，标准输出提供 JSON 报告，标准错误显示进度。该较重基准不加入普通单元测试；运行环境变化后需重新测量，不能把本机数字作为所有机器的保证。

## 数据集 long-work-literal-v1

- 512 章，每章 2,000 汉字、2 个场景；实际持久化正文共 1,024,000 汉字、1,024 场景。
- 每章 49 条关系及 49 条人物认知，共 50,176 条断言；人物在章节间复用，命题按来源批次限定。
- 每章有唯一的字面检索标记；其余正文是确定性的汉字填充，不是自然语言小说。
- 场景正文及正文分隔符来自同一内容；关系、实体和认知证据均在发布时核验字符锚点。
- 保留逐章保存形成的历史快照；最后再保存一次，使最后发布的知识也被明确捕获。

每类查询先测一次首查询，再测 30 次热态查询，P95 使用排序后的最近秩。首查询发生在数据构建之后，不是操作系统冷启动。字面检索覆盖均匀分布的 31 章标记，要求返回目标修订并核验所有返回证据的来源字段和 Unicode 字符区间。该时延包含正确性检查开销。

当前/历史人物查询分别核验 200 来源上限及截断标记；Writer POV 关系查询核验其有界覆盖。这些查询刻意保留不完整标记，不能把上限内结果称为人物的全部知识。

## 索引优化与恢复约束

规模验证定位到搜索索引核对的访问路径缺口：原分词主键按 `(project_id, gram, doc_id)` 排列，逐文档核对按作品和 `doc_id` 查找时缺少适配的前缀，可能重复扫描作品的大量分词行。

当前 schema 增加 `(doc_id, project_id, gram)` 覆盖索引，同时支持文档外键级联删除的定位。没有强制 `INDEXED BY`、第二套索引权威或旧 schema 迁移逻辑。查询计划回归验证使用两个作品的真实保存数据，要求按文档与作品执行覆盖查找且不为 gram 排序建立临时 B-tree；已有损坏恢复、跨作品隔离及坏源回滚测试继续保留。该索引增加存储和发布写入成本，构建与重建耗时分别报告。

基准在重建前核对搜索、实体、断言、人物认知和关系五类派生索引，再逐类通过生产事务重建并要求返回完整核对结果。重建前后比较代表性人物投影、关系图和检索结果；搜索只比较结果而非整个响应，因为重建应递增索引代次并使旧游标失效。该对照并非所有状态、所有查询或编辑序列的等价性证明。

## 本机实测

本次机器：macOS（Darwin 25.5.0）、Apple M5 Pro、arm64、15 逻辑 CPU、24 GiB 内存；Rust 1.98.1，release profile。以下为最终一轮测量，没有与旧访问路径基准或项目验证并行运行；未关闭其他桌面应用，不是隔离实验室测试。编译时间不纳入数据构建或查询耗时。

| 查询 | 首查询 ms | 热态 P50 ms | 热态 P95 ms | 热态最大 ms |
| --- | ---: | ---: | ---: | ---: |
| 字面证据检索 | 64.00 | 43.28 | 45.80 | 47.85 |
| 当前人物知识 | 156.60 | 141.41 | 143.79 | 144.53 |
| 历史人物知识 | 147.24 | 143.39 | 148.95 | 152.85 |
| 当前关系图 | 22.32 | 2.36 | 2.70 | 2.78 |
| Writer POV 关系门禁 | 386.53 | 259.28 | 264.08 | 268.55 |

31/31 合成字面查询在前 20 结果中取得预期证据，所有返回锚点验证通过。上述五类路径的本机热态 P95 低于初始 1 秒目标，但不扩展该承诺至未测查询。

数据构建 51.88 秒；重建搜索索引 18.56 秒、实体索引 0.80 秒、断言索引 0.81 秒、人物认知索引 0.51 秒、关系索引 0.46 秒。重建时长包含重建事务内部的核对。搜索索引实际有 2,049 个字段文档、2,300,305 条 gram，五类报告的缺失/多余/变化或孤立计数均为零。代表性人物投影、关系图和检索结果重建前后相同。

旧访问路径的同规模测量曾报告搜索重建 168.89 秒，增加覆盖索引后的另一轮为 23.76 秒；这两轮期间存在并行运行负载，不计算固定加速倍数。最终一轮 18.56 秒用于当前实现的记录，而非所有机器的承诺。

验证：`npm run verify` 全流程通过（包含新查询计划回归、Runtime、引擎、委托、Agent 与 UI），`cargo clippy --workspace --all-targets -- -D warnings` 通过；最新基准独立运行退出成功，合成字面金标遗漏会触发断言失败。

## 尚未覆盖的验收

后续独立 `bench:passages` 已补同规模的有限原文查询与全书机械字符对照：首章/连续/后部页本机热态 P95 约 1.08–1.12 ms，4,096 页覆盖实际正文全部字符。该入口不调用模型、不认证模型消费页面，不替代语义质量、持久语义扫描恢复或 Windows；详见 [授权原文分页的规模验证](PASSAGE_READ_BENCHMARK.md)。

后续已补充独立 `evaluate:story` 入口，使用外部标注与生产查询核验 evidence Recall@20、显式路径/正文对象影响召回及逐类遗漏，冻结一致副本而不写原作品。它不复用本基准的合成标记生成金标，也不把工程样本声明为人工评审；当前基线仍为字面检索与显式影响，语义通道与真实 Query Planner 的端到端效果另行验收。实现、输入形状及验证见 [小说检索与影响集合评估](STORY_RETRIEVAL_EVALUATION_DESIGN.md)。以下未覆盖项仍然成立，新增工具不等于已有合格数据和达标结果。

本基准不证明语义 evidence Recall@20、影响集合 recall、二十四类人工金标、Context Pack P95、真实模型三章生成旅程、Windows 产品旅程、作者文学质量评价或全量世界状态重建。独立的 `bench:context` 已补 Writer/POV Context Pack 的同规模范围测量，详见 [预算设计与基准](CONTEXT_PACK_BUDGET_DESIGN.md)，并非其他任务类型或语义质量验收。索引核对通过仅说明派生结构与保存的建模输出一致，不说明模型提取真实、小说信息完备或任意模型均具备所有能力。
