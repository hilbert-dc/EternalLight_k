## 阶段 2 当前实施契约

事件前提和效果统一为 `{sourceBatchId:null|string, assertionIndex:整数}`，两个
字段必须同时存在；null 显式表示本批次，不接受旧数字或省略字段。前提可
引用同作品、当前有效的严格前文章节；效果仅引用同批次。每侧最多 16 项，
同一来源/序号不可重复或跨两侧复用，序号小于 100，批次 ID 最多 160 字节。
源状态主体必须是当前事件参与者的精确身份，不做字符串名称合并。

本地引用仍核对事件范围内的原文及结束证据；跨源前提使用来源绑定的独立
原文，不要求前文锚点落进本章偏移。Current、Snapshot 和审计的 Published
均沿阶段 1 的唯一来源读取，历史范围不使用当前知识头。发布、审阅生成/
确认、原始批次读取、差异与断言审计检查外源契约。状态区间解释仍是只读
候选，不认证因果真值，不执行效果，不自动确认引用来源。

时序报告使用各侧 `referenceIndex` 指向父事件引用列表，避免重复长批次 ID
及证据；维持 3 KB 派生报告、8 KB 事件及现有整包预算。新增组合内容仍按
P0 检查，不以裁剪过的查询 entries 判断前提存在性。

通用来源依赖索引从已发布载荷派生，统一收录跨章命题与事件前提；正文
改稿沿同一有界任务/outbox 链传递失效，不再只沿认知索引。索引损坏可核对
及事务重建，不改权威源或冻结历史；读取和确认仍校验原始来源，不仅相信
依赖索引。实现分为机械契约切换、来源/失效链及真实场景测试三个可检查
部分，不组织专家会议；五视角由实施者自检，不声称独立评审。

此阶段目标是跨来源引用闭环，不代替批准规则条件组合、完整世界状态机、
语义真值与全部 S1–S5 验收。新增测试必须覆盖合法前文状态、错误来源/序号/
主体、外源效果拒绝、损坏源、原子失败、当前/历史时序、改稿传递失效及
依赖索引修复；UI 同步显示来源，所有 fixture 一次性切到当前契约。

## 目标与实施依赖

### 后续条件推理前的实体类型一致性门禁

跨源参与者不能仅以相同 ID 被视为同一种实体。当前事件和被引用原文的
实体声明须在相同身份处保持种类一致；校验直接读取已验证的源载荷，不能
由缺失、残留或伪造的实体索引授权。发布使用本次候选实体，历史查询使用
同快照捕获的事件实体，不重新选择当前目录或当前头。比较所有共有身份，
以免关系目标等间接引用绕过主体检查；不同名称或别名不做自动合并。

实施者五视角自检（非独立评审）：架构继续复用唯一来源读取；技术 A 用
真实 SQLite 损坏注入证明索引不影响类型门禁；技术 B 同步发布、查询、
审核、快照、差异和审计调用方；产品不增加作者手工建模步骤；UX 类型
不一致显示原有错误/不足，不伪造成立报告。本项不新增模型内容、表、
依赖、兼容逻辑或上游修改。先复现缺口，再修复和验证；不是完整状态机。

同一门禁还须核对事件所属批次的完整实体/主张原文证据，不能只检查外源
证据和本地引用形状。凡解释事件的发布、当前读取、历史、审核、差异与
审计，均按其精确绑定正文调用发布校验；不把外源正确当成本章已验证。
只影响事件解释链，本项不认证其他投影的完整语义。坏源不自动修复，
失败不消耗审核或确认幂等回执，显式恢复测试注入后同一请求可重试。

实施证据：新增真实 SQLite 故障测试在修复前失败，来源将共享物品身份改
成角色后 resolver 仍返回成功；新增仓储审核故障在修复前同样失败，篡改
实体原文摘录后仍保存了 `invalid-review-4`。两项都是可复现缺口，不是
推测的供应商限制。现在外源 resolver 接收调用方的本批实体，与已验证外源
的全部共有身份比较种类；本章事件批次调用同一 `validate_payload` 核对绑定
原文、全部实体和主张。queued 发布使用本次候选，不读取存储中的空数组。
当前/历史查询、发布、审核、差异及全量/分片审计调用方一次同步。

四项外源核心场景当前通过，增加缺失索引仍拒绝类型冲突、源恢复后不依赖
索引修复、伪造索引不改变合法源、非主体的共有身份冲突，以及当前/历史/
审计范围检查。扩展 HTTP 场景验证发布失败保持 queued/空载荷、本地证据与

1. 来源底座：当前/历史/已发布范围采用同一来源选择及原始载荷校验，来源

   判定事实存在。发布、知识查询、Review 终验与索引审计复用此门禁。
2. 事件扩展：统一来源限定的主张引用，前提可引用授权前文，效果保留事件
   原文中的独立证据；接通依赖失效、历史重放、条件解释及作者展示。后续
   条件组合与状态机继续建设，不将事件确认视为效果执行。

阶段 1 是必要的来源可信性修复，不表示阶段 2 已完成。旧接口、数据和
索引格式不增加兼容分支，不新增另一条 Agent 执行链或上游内核接口。
Runtime 仅增加工作区已有 `rusqlite` 的 dev-dependency 用于真实 HTTP
故障注入，不增加生产依赖或新的第三方版本；锁文件同步当前依赖关系。

## 来源范围与语义

Current 必须有同作品的有效知识头，正文选中修订与建模源相等；Snapshot
必须捕获该精确批次、正文成员及修订，允许当时有效、如今 stale 的批次。
Published 仅用于原始历史索引核对，不提供当前查询权限，也不冒充快照。
不存在或范围不可见返回不足；范围可见但载荷/证据损坏返回 CorruptState。

统一来源读取须解析有界实体与主张，复用当前实体/断言/事件 schema、身份
唯一性和精确 Unicode 证据校验。索引删错不允许制造不存在的命题；仍有
权威源声明时，不把丢失派生索引当作命题已消失。正文以绑定的不可变修订
核对，不做同名重绑定、当前源回填历史或自动修复源载荷。

此门禁验证源的局部结构与证据，不证明语义真值、完整依赖图或全局一致。
不会递归将一份有界返回膨胀成全书内容，也不把正文复制到模型结果。

## 故障复现与当前实现

修复前，真实 SQLite 测试移除源命题声明后，旧入口返回 `Ok(true)`；
期望的损坏拒绝测试失败，证明问题可复现，而非只依据代码推测。

复用 `modeling::validate_payload`，命题门禁从校验过的实体声明判断。

已扩展原有跨章 HTTP 场景：残留索引不能放行损坏源，后章仍为 queued
且两个候选载荷保持空；仅修复测试注入的源后，删除派生命题行，合法发布

门禁只校验该源局部声明及证据，尚未对所有跨源引用递归签发全局完整性。
重复引用同一大型源的实际查询成本须按长篇数据继续测量，不宣称 P95 优化。
