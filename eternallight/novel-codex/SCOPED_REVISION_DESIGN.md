# 持续创作首个实施单元：版本绑定的局部改稿

2026-09-27 · 对应 C03/C04 的基础切片；不等同于完整联合旅程通过。

## 设计与实施者自检（非独立评审）

当前对话动作 API 把章节目标重建为 wholeChapter，丢失模型提出的局部范围。
本单元保留 generateChapter / WorkTask / Step / Attempt 及原有候选写入、建模
待办机制，不新增调度器、模型通道、任务类别或兼容分支。

- 对话可以提出 `scope={type:"selectedScenes",sourceRevisionId,groupIds}`。
  groupIds 是正文 sceneGroups 的稳定 id，不是规划 sceneId，最多 16 个。
- 范围是模型对作者请求的结构化解释，并非模型自身能够证明作者授权。
  模型须先读正文、核对来源和范围；歧义需询问，不得将讨论解释为写入。
- Rust 在动作登记及尝试创建事务中核对章节身份、当前原稿、唯一场景 ID、
  锁定状态。未知、重复、空目标或过期来源拒绝，不放大为整章任务。
- 本范围允许读取目标章全文及既有 Writer 授权内容，不扩大到未来章节。
  写入整份候选，但只允许目标场景 body 改动；其他场景、顺序、场景元数据、
  标题及规划引用必须等于冻结原稿。正文须由全部场景正确拼接。
- 每次检查点均与冻结原稿比较范围外内容；自己的后续检查点不改变范围。
  原有 CAS 和任务输入水位仍阻止外部新稿被覆盖。失败事务不留下部分修改。
- 完成后复用原有 modelKnowledge 后续动作和源修订失效机制；新批次就绪
  前不得称建模完成。候选不自动采用，不自动确认 Canon。

无 schema、依赖、上游内核或 UI 布局修改；无数据删除和旧格式兼容。
边界校验放在领域层，HTTP 仅规范化目标；接口、模型指令与测试同步更新。

## 验证计划

真实 Runtime HTTP 链覆盖：已有正文 → 对话登记局部动作 → 绑定执行尝试 →
拒绝范围外写入 → 正确候选 → 完成回执 → 新原稿建模后续；确认原稿、无关
内容与正式采用状态保留。补充锁定、重复/未知 ID、过期基线与再次检查点。
模型指令测试验证范围随 handoff 保留，指令不引导扩大权限。

本单元不宣称自然语言范围识别质量、任意字符级修订、跨章自动影响闭包、
暂停后关联重规划或“修改后自动续写新章”已实现；这些继续按持续创作验收
计划推进。下一单元需要把目标/许可及重规划绑定到现有任务链，而非绕过
过期门禁恢复旧尝试。
