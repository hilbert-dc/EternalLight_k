## 2. 目标链路

```text
源修订/建模批次 → 分片验证原始来源 → 同代次密封的来源与索引证明
                                  ↓
事件 + 已批准规则 + 身份决议 → 有界查询相关状态 → 四值解释
                                  ↓ 超出交互预算
                          可暂停/恢复的完整范围求值
```

来源证明只证明结构与出处，不证明模型理解正确，更不将候选升为 Canon。
所有模型工作继续经既有 Codex 引擎；确定性校验、扫描及求值在领域 Rust 中运行。

## 3. 完整来源证明

采用一个来源校验责任边界，不拼接多个语义不等价的“审计已通过”布尔值。
扩展现有持久审计机制，增加明确的来源验证结果；旧索引审计的 complete
仍只能用于其声明的检查范围。开发阶段直接更新当前 schema/契约，无双读兼容。

每个发布来源分片必须校验：

1. 精确 project/object/revision/batch 归属、发布状态及原始正文存在。
2. 原始 entities/assertions 对正文字符范围与 quote 的完整校验；复用
   `model_sources::validated_source`，不从待核对索引恢复原始来源。
3. 事件跨源引用、typed state schema、本地实体声明和引用闭包。
4. 抽取实体/断言与对应派生索引逐条一致，包括缺项、多项、错项及孤立项。
5. 页内结果和 next cursor 同一事务提交；失败不能跨过该来源。

证明绑定来源集合代次、正文代次、索引代次、验证算法版本。
发布、撤回、源内容/摘要故障、索引变更、快照捕获变化都必须撤销依赖证明。
代次溢出整笔回滚；同值写入不制造失效。数据库触发器是故障检测，
不是允许原位编辑不可变修订，也不是抵抗任意数据库管理员篡改的安全认证。

当前范围仍由当前正文 head 与有效知识 head 的联合约束确定；历史范围仍使用
快照显式捕获，不用后来知识填补 NULL 捕获。完整发布集校验可支撑范围内索引
查询，但不能绕过 pending_sources、视角授权或快照归属检查。
在同一 SQLite 读事务中验证证明与执行查询，避免校验后读取新代次索引。

## 4. 相关证据选择与求值

从已批准规则 AST 推导叶条件的角色、属性、类型、比较操作和量词；
从具体事件绑定参与者及事件时间，从已批准身份决议解析 canonical IDs。
不得使用模型挑选的 preconditions 列表作为全体反证范围。

在具有有效完整性证明的索引上按上述键过滤，再使用稳定的
`(batch_id, assertion_index)` 分页；过滤必须先于 LIMIT。
未知时间、类型不匹配和互相矛盾的声明必须进入检查，不能为了命中率删去。
同一 canonical 实体在授权范围内的类型冲突需显式失败或未决，不能取首行。

交互预算区分：来源验证工作量、匹配证据读取量、比较次数、返回引用及
最终序列化 bytes。作品有 500 章而某属性只有 3 条来源，不应因为总章数大
就固定 unknown；某属性真的有大量来源时必须返回可继续检查的状态。

完整范围任务冻结作品范围、事件源、规则修订、身份修订及源/索引证明。
按叶条件、参与者、操作数持久化四值累积状态和有限代表证据；
只有对应完整范围扫描结束才执行“没有发现支持”的最终判定。
all/any/not 组合在叶条件完成后计算，不把单页 unknown 当作全局 unknown。
输入变化后旧任务为 stale；历史冻结任务只能沿原范围恢复，不能拼入新规则。

最终区分：

- evaluationComplete：所声明条件与来源范围已计算完毕，所有缺口明确处理。
- sourceClaimsTruncated：完整计算所用引用未全部展示。
- result：supported/refuted/both/unknown，始终只是来源主张下的解释。
- worldTruthCertified=false、stateChangesExecuted=false：本流程不提交新事实。

引用展示需为不同叶条件与支持/反对结果保留代表来源；如果有限说明预算不能
表达整条规则的解释，返回摘要及独立受权分页详情，不能展示“完整证明”文案。
模型单项继续遵守 9,000 bytes 总包装上限；不得注入无限证据或重写历史上下文。

## 7. 完整来源验证接入（B 的前置实现）

同步断言审计、断言索引重建、持久知识审计共用 `validated_assertions`，
从精确已发布正文修订读取原始 entities/assertions，调用
`model_sources::validated_source` 的全 payload/quote/字符范围校验，
再验证事件跨来源引用。不再只对两个相同 JSON 宣称来源可靠。
即便损坏的原始断言被原样复制进派生索引，原文校验也必须拒绝。

持久作业每批通过后才推进检查点；无效来源使作业 failed，
verifiedConsistent 不得为 true。索引重建仍在事务内拒绝损坏来源，
不覆盖原文、不推进作品版本、不“修复”为自洽但虚假的证据。

分片预算现包含精确正文 content_json 的 UTF-8 bytes，加上实体及断言。
保持最多 25 批次/通常 250 KB；单个超出通常预算的来源独占一轮并继续推进，
不因过大而永远卡在同一检查点。此处是分片工作量策略，不是全部来源的
硬内存证明：单个来源绝对大小、外部引用递归读取和总 CPU 仍须后续独立限额。

当前测试 fixture 按当前发布契约补齐正文、声明与证据，不保留空正文或缺证据的
历史兼容路径。新增原文损坏、索引同步损坏、重建原子拒绝、持久检查点不越过失败
以及大正文分片测试。HTTP 测试经真实发布、Author 审计路由与 worker 验证：
正文故障撤销旧报告，重新审计失败，候选身份不能读取维护报告。

边界：知识审计增加了原始证据验证，但尚未统一实体索引证明、规则/身份范围
与可复用密封凭据。不要仅因为本次审计通过就将 C 接到它上面。
200 来源收集器、引用展示与求值完整性耦合、可恢复完整条件求值仍未替换。

本轮验证：核心库 141 项、Runtime HTTP 20 项、状态属性 HTTP 8 项（含新故障
测试）、事件 HTTP 4 项均通过；整个 native workspace/all-targets 严格 Clippy
通过。最初 fixture 不完整导致的 9 项失败已通过补齐当前发布契约解决；新增
HTTP 测试的宏导入编译错误已改为显式导入。以上是最终成功运行结果，未以

## 9. 联合审计的写入失效闭包

实体代次以外，断言、认知、知识头、来源依赖与对象 head 也必须在每次实质
写入时更新知识代次；不能仅依赖业务函数主动调用 bump。索引 INSERT/DELETE/
实质 UPDATE 现使用同一触发器生成器。依赖表原有仅更新新作品代次的触发器
已替换；跨作品 UPDATE 使旧、新作品同时失效，同值写入不失效。

已发布批次的归属、源修订、发布状态变化也更新知识代次，避免 COUNT/MAX 不变
掩盖来源变化；未发布批次的变更不影响发布来源证明。原文与提取 JSON 的变更
仍使用原有多类审计代次门禁。此机制是损坏检测，不授予修改不可变来源的权限。

触发器先确认作品仍存在：作品删除的级联清理不得给已删除作品重新创建代次行。
这不是跳过活跃作品的校验，删除后也没有可复用的作品审计结果。

新增故障注入回归覆盖完成报告和运行中检查点同时失效、两个作品的归属移动、
同值写入不误报、其他作品不受影响及发布状态变化。现有删除/重建作品回归
用于验证级联清理；首轮曾发现外键失败，已补作品存在门禁。

实施者自检（非独立评审）：统一失效责任，不新增调度器或模型请求；
事务失效保持失败原子性；当前测试库重建，不做旧触发器迁移或兼容；
作者继续看到既有 stale 提示，无 UI 契约变化。
仍需完成验证算法/范围绑定与受权证明读取，再切换长篇条件收集器。

本轮最终回归：144 项核心测试、20 项 Runtime HTTP、8 项状态属性 HTTP 通过；
native workspace/all-targets 严格 Clippy 通过。
新测试包含 10 类实际 SQL 变更，观察真实持久作业的旧报告和运行中作业失效，
没有只测试触发器文本或静态配置值。作品级联删除使用既有删除/重建水位测试。
本轮无 UI、模型上下文或依赖变化；未运行真实模型、长篇性能或 Windows 验收。

## 10. 同快照证明与条件来源筛选

作业记录必填 validation_version；读取、恢复与继续推进时拒绝不同算法版本。
条件查询只接受当前知识/实体代次均相同、来源 COUNT/MAX 相同、全部检查类别
完成数量等于来源总数且无差异的 completed 作业。证明检查强制要求调用方已在
读事务中，随后索引选择和原文读取复用该事务；模型不能传入一个自制“通过”标志。

两个执行层是资源策略，不是旧代码兼容：

- 无证明且范围不超过 200 来源时，直接验证全部范围原文；8 MiB 读取预算仍生效。
- 无证明且范围超过 200 时，明确未完成，不再重复读取任意排序前缀。
- 有证明时，从已批准事件规则 AST 提取属性，SQL 在 LIMIT 前选出包含这些
  state 的来源；不使用模型挑选的前提列表排除反证。选中来源仍重新校验原文。

原文、历史快照及 pending_sources 的授权和完整性门禁不变；证明覆盖的是索引

## 18. 后台分片调度与失败隔离

复用当前 Runtime 进程，在领域层选择 queued/running 作业，每个 tick 只推进一个
来源。持久单调调度序号用于轮转，避免长任务或持续新请求饿死其他作品；选择
与登记序号同事务，页提交仍以版本校验防重复。新请求从当前最大序号入队，
不会不断插到旧请求前面；索引支持队首选择和最大序号读取。无需持有跨 tick
内存状态。进程在选中后退出只改变轮转位置，不丢失待执行页。
paused/cancelled/stale/completed/failed 不进入调度。执行错误回滚该页后，仅能以
原版本将仍可运行的作业标记 failed；若另一执行器或作者已改变版本，不覆盖它。
失败保留最后已提交检查点，不自动重试；作者显式重新开始会创建新作业。
数据库暂不可写时不能伪称已记录失败，返回错误并由 Runtime 退避。

实施者自检（非独立评审）：不新增模型执行通道或兼容表；测试需覆盖 worker
真实完成、暂停重开、失败后不重试、失败不阻塞其他作业与新请求不会抢占旧任务。
本节不包含公开请求权限、解释分页或 UI；failed 当前只表达执行未完成，不声称
已提供细分故障诊断或自动修复。

## 19. 作者权限 HTTP 入口

  请求体，返回 201 和作业；同绑定请求可返回已存在作业，不隐式恢复暂停。

invalid_request；未知 JSON 字段/命令由严格反序列化拒绝（422）。所有状态都
