# 有证据的多参与者事件模型

## 目标与边界

推进 S1 的 StoryEvent 数据基础：事件有独立事件实体身份、类型、世界时间、
角色化参与者，以及来源限定的前提和本批次效果主张引用。删除 event 任意布尔/字符串值的
生产契约，不保留兼容分支；普通观察仍用 assertion，不把观察改名为事件。
正文、知识批次、作者确认及快照仍使用现有权威链，不增加事件数据库或执行器。

事件 value 固定为 participants、preconditions、effects、untilExclusive 四字段。
participants 最多 16 项，角色为 actor/recipient/affected/location/instrument/item/
witness/beneficiary；实体种类由代码校验，同角色同实体不可重复。subjectId 必须
指向同批次 event 实体，predicate 是非空事件类型；storyTime 必填整数或 null。
untilExclusive 是整数或 null，已知结束必须晚于已知开始。事件结束只描述事件
持续时间，不使其发生记录消失，也不自动终止效果主张。

preconditions/effects 各最多 16 个 `{sourceBatchId:null|string,assertionIndex}`，
两字段必填，null 表示本批次；序号小于 100，来源 ID 不超过 160 UTF-8 字节。
前提可引用同作品当前有效的严格前文章节，效果仅限本批次；引用非 event 主张，
同一来源/序号不能重复或跨两侧复用。空数组是未解释，不证明无前提/无影响。
引用主体/认知持有者必须精确匹配参与者。本批次关联证据及结束证据须落在事件
原文锚点内；跨源前提独立核对来源正文，不混用跨章偏移。来源选择、历史重放
及依赖失效详见 [跨来源条件设计](CROSS_SOURCE_CONDITION_DESIGN.md)。
完整状态迁移和批准规则条件组合仍按总架构继续实施。

事件模型描述候选解释，不执行世界变更。确认事件不确认其引用主张；各主张
仍独立审阅、确认、撤销。未知时间不补为零，时间顺序不自动推出因果，duration
不等于属性有效期。状态冲突继续保留独立来源，不实施 latest-wins。
确认事件不注入通用 stateFacts，覆盖报告标明 typedEventFacts；模型经类型化
状态查询保留批次/来源/序号后解释引用，避免游离编号被当成全局已确认状态。

## 接入与验收

Rust 单独 event 模块拥有形状、角色类型、引用和证据范围校验；发布事务在
写索引/知识头前检查，错误不能留下半发布。当前/历史知识读取和断言审计拒绝
损坏事件载荷。StateSelector 在来源限额之前召回参与者相关事件，原时间/POV/
章节门禁不扩张。Chapter Diff 的受影响实体纳入参与者，但不推断必须改写。

读时校验针对实际读取的批次，不宣称每次选择性查询都审计了未选源；查询的
complete 也不代替全量源/索引审计或语义完整性。事件对象的合法形状与原文
锚点存在，不证明模型提取的参与角色、时间或因果解释在文学上正确。
断言派生索引全量/分片审计与重建、审阅生成/确认终验、候选差异现在与发布
和实际批次读取复用同一联合契约：同一快照或事务读取实体声明，核对事件
身份、参与角色和引用，不允许同 ID 后一声明覆盖前一声明。损坏源使重建
原子失败，旧索引和正式作品保留；不是自动修复源载荷或文学语义认证。

Codex 原建模 handoff 描述新契约。Author Review 和跨对象提案显示参与者、
前提/效果编号及候选性质，沿原采用和撤销路径执行。测试更新当前 fixture，
真实 Runtime 验证发布、权限、查询、确认、历史回放、失效和回滚；界面回归
验证说明和参与者展示。完整 S1–S5 和真实供应商/文学/Windows 验收不由此签发。

validate_links，未核对源批次 entities 的事件身份与角色种类。改为在同一个

validate_batch；不建立另一套事件校验。分片作业已有实体载荷和字节预算，

不能通过最后一条声明覆盖同 ID 的不同种类来满足角色校验。
进一步核对确认：现有审计来源签名只包含已发布数量/最大 rowid，未覆盖同
批次 payload 修改。当前 schema 为已发布 assertions_json/entities_json 变更
增加触发器，在同一事务递增已有知识、实体及关系审计代次，同时覆盖历史
捕获审计代次。不增加平行状态表或版本探测，代次仍
是无业务意义的围栏，不能将旧报告拿来证明新源。正常 API 不修改已发布载荷，
该门禁另覆盖测试故障注入及损坏源修复，不提供自动修复权威载荷的入口。

验收：合法已发布事件的增量索引与全量重建等价；损坏 actor/entity、事件
身份、缺失实体及重复声明导致同步审计/重建失败；重建保留原索引、源载荷、
作品 head 与其他作品。持久作业报告 failed 而非 completed/true，重开后仍
保留失败证据；修改实体声明使已完成结果失效。公开仓储审阅/采用入口及候选
差异拒绝同样的源损坏，真实 Runtime 合法事件生命周期仍通过。新测试只验证当前契约，
不保留旧 event 标量或修复历史数据。五视角自检沿本节边界执行；无独立评审。
这一步不承担文学语义证明、跨源条件或完整状态机的完成声明。

架构：事件是源批次中的类型化主张，不建立第二真相源。技术 A：有限载荷、
实体角色与同源引用、发布事务、披露边界、读时损坏拒绝。技术 B：真实接口和
查询证据优先，不用模型回复证明世界变化。产品：作者无需手填模型；可以通过
对话自动提取并逐项裁决。UX：原审批链显示事件解释边界，确认不级联。

零兼容门禁：生产、提示、fixture、类型和文档一次切换；无旧值 fallback、
迁移或双轨。按以上条件实施。完整条件解释、跨源前提、状态机及推理评估仍
是原目标的剩余工作，不被本切片替代。
