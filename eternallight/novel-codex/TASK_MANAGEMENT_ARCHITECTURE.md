# 创作任务管理目标架构

目标修订：2026-09-27。服务于“对话驱动、可控迭代的持续创作系统”。
本次新增的是任务选择与重规划目标，不表示以下所有行为已实现；历史 A–D
完成记录仅证明其原有范围。统一门禁见 [持续创作验收计划](CONTINUOUS_CREATION_ACCEPTANCE.md)。

当前读取与控制的并发优化见 [任务管理优化：读取与控制一致性](TASK_MANAGEMENT_OPTIMIZATION.md)。
任务列表读模型从工作区组件抽离；读取失败保留最后成功结果并禁用旧状态控制，
显式重试不会创建任务。首屏、分页和控制后刷新共享读取队列；迟到响应按作品
生命周期隔离。运行中的持久任务不依赖当前 Agent 标志才能刷新。控制及撤销共用
同步互斥，并阻止跨作品的旧回执污染新界面。恢复请求另保留长执行等待槽，
期间仍可暂停或取消；短控制不能相互重叠，也不能重复恢复或撤销。
取消结果仅覆盖同任务恢复的退出提示，不隐藏另一任务的错误。
错误提示记录请求归属；另一任务控制开始或成功时不会清除先到的执行失败。
不改变 Rust 的状态与恢复权威。

### 已保存产物恢复与模型执行分离（2026-10-01）

WorkTask 的当前契约新增 `resumeMode`：`recoverSavedResult`、
`continueExecution` 或 `null`，由 Rust 在读取事务中计算，不由 UI 猜测。
仅暂停/阻塞且通过恢复安全检查的任务提供动作；存在当前尝试拥有、来源仍有效、
发布回执与活动知识头均已核验的失败建模产物时，优先提供本地恢复。
未知写入、输入变化、未确认部分产物仍拒绝恢复。

作者点击“核验并恢复”走版本条件的 `control: recoverSavedResult`。
Renderer 通过独立 `agent:recover-work-task` IPC 传递这个明确意图；读取到的
动作若已变化，Host 拒绝本次操作，不能把离线核验悄悄升级为付费模型执行。
Rust 在写事务中重新验证证据，只恢复可证明已保存的步骤，保留原失败记录；
不创建新 Attempt、不重复发布、不伪造最终回答。全部执行步骤结束则更新终态；
存在原有或新生成的后续步骤则保持作者暂停，之后另行选择“继续任务”。
本地恢复不代表创作目标已达成。

Electron 可先核对既有用量，但不会申请新预算、启动模型或扩展执行范围。
模型不可用时仍允许本地核验；需要执行模型的恢复先检查配置，缺失时不把任务
改为运行中、不弹出预算确认。Renderer 保留读取失败、未保存编辑、并发执行
和版本安全门禁，同时直接显示禁用原因。本轮不扩大 GenerationRun 的离线能力。

状态：A/B/C/D 基础链路已在当前测试版落地；状态驱动的通用编排、多入口与中途调整仍需独立实施和验收，以具体证据为准。

## 执行终态与实际交付（2026-09-30）

`WorkTask.status` 是现有步骤调度/控制的执行状态，不是自然语言目标的满意度
证书。删除“status=completed 就直接 ready_for_review”的推断，新增必填
`deliveryReport`，在列表/单项/Attempt 所属工作读取的同一 SQLite 快照中派生：

- 修订证据来自真实 `story_task_outputs_v2`、本项目不可变修订与冻结输出对象，
  不信任 `output_refs_json` 展示元数据；整章还须满足 chapterComplete。
- 知识证据来自实际目标批次、来源项目版本与 publisher Attempt；记录必须已发布。
  当前知识头与当前候选/正式选择一致且批次 ready，才可作当前依赖；过期批次
  保留历史引用，但显示 superseded，不伪造依赖已就绪。
- 普通候选被后续版本替换也保留历史证据，但不再显示为当前待审阅候选。
- 尚未执行的 proposed Action 和未结算的 Provider grant 分别返回原 ID；不会
  创建新 Step、补授权或扩容预算。执行结束但未结算时 UI 继续只读轮询，结算
  后停止；暂停/取消/恢复仍由原控制权威处理。
- 所有有效步骤实际完成、当前必需产物有证据、提案和用量均已闭合时，结构
  产物才可显示 ready_for_review；否则为 partial/pending，不覆盖执行终态。
- 纯讨论完成单列 discussion_ended，不强制生成正文。`complete_task(summary)`
  只登记 completionReport，不是保存最终 Agent 回复的证据，也不证明回答质量。

界面使用“执行结束”“候选产物待审阅”“讨论已结束”，并提示核对作者目标，
不把模型的完成声明当成领域终验。报告不复制正文、不存私有推理，不增设第二
调度器或旧接口 fallback；已被替代的普通交付推断删除。

这补齐的是结构交付可见性与真实证据，不等于通用作者目标闭环。任意自然语言
目标的冻结完成条件、受保护对象/全局影响判定、最终回复交付回执及作者质量
评价仍需独立落地；GenerationRun 的逐章事务交付门禁仍是其原执行权威。
Generation Work 读取在同一快照复用原 Run/来源/逐章历史证据校验，不能用临时
滚动规划是否仍为当前头来否定已交付章节，也不能绕过 Run 校验伪造完成。

本切片验证记录（重复运行不重复计数）：Core lib 159、新交付回归 5、原任务

## 目标与边界

作者通过对话提出目标，领域系统负责产物、版本、执行状态和恢复；Codex
负责模型、工具和子 Agent 调度。领域步骤不是工具调用的镜像。
不增加分布式队列，不建设历史数据或接口兼容层。

当前对话接续使用同一 Work 的决策任务。Agent 通过 `read_work_status` 读取
已保存产物、必要缺口和合法动作，再用 `request_work_action` 选择下一步。
Runtime 从持久状态推导目标与来源，核对原授权、输入版本、预算和幂等性；
Electron 仅派发已准入步骤并把结果送回原对话，不维护固定的后续操作表。

默认预算仅计量，未设置的请求、token、尝试次数或期限不伪装成固定上限。
明确设置的限制仍严格执行。同一来源、同一动作没有进展的重复失败会停止；
暂停、待核对写入、失效来源及未结算消耗不能靠另开任务跳过。模型说“完成”
不能替代真实产物和必要检查。纯讨论没有产物动作时可以直接结束。

Agent 在同一执行中接收工具校验错误并决定如何纠正参数。正文保存工具仅
接受 body 或完整 sceneGroups 中的一种表示；场景组的规范全文由 MCP 派生，
作者权限和场景保护由 Runtime 校验。明确发生在写入前的正文校验拒绝会结束
本次操作日志，允许同一任务提交修正后的新操作；未知写入结果仍须先核对回执。
若尝试已终止，父对话只能通过 Runtime admission 创建原授权范围内的后继步骤。

任务围绕作者的可核验结果建立，不把一次消息、一个模型回合或固定章数直接
当作目标。纯讨论和询问进度不新增修改任务；同一目标可跨多轮对话，新的
实质修改要求须明确绑定原目标还是建立后继目标。Brief/Outline/Plan/Chapter
是可用操作，不是所有任务固定串行的四个阶段。

## 状态与意图驱动的编排契约

1. **确定目标与依据。** 从创意、规划、正文或局部问题进入；引用源消息、
   生效意图修订、选中内容和快照，记录范围、预期产物与完成条件。作者要求、
   系统假设和待决选择分开，系统补全不得获得新的许可。
2. **按缺口提出动作。** 模型可以建议检索、分析、补充设定、规划、生成、
   修改或检查；必须说明该动作服务的目标和依赖。能复用的有效产物不重做，
   信息足够时直接执行合适的局部任务，不机械补齐整套结构。
3. **领域层准入。** 对动作验证受支持操作、输入版本、来源范围、受保护对象、
   依赖就绪、输出契约和剩余预算，再在原领取事务绑定 Step/Attempt。
   决策依据应能从持久输入与回执解释，不保存模型私有思维，不增加第二调度器。
4. **有界自主推进。** 已获许可内的普通动作可自动继续；动态追加步骤
   必须无依赖环且有实际进展，重规划计入同一预算账本。越界、关键方向冲突、保护项或预算
   不足时才请求作者决定，不把每个工具调用变成人工审批。
5. **处理反馈与失效。** 新意图区分补充、替代和冲突，计算受影响依赖闭包。
   已失效步骤停止领取，迟到输出隔离；有效且独立的产物保留。未知影响保守
   阻断相关接续并说明，不假装已穷尽全书影响。
6. **产物驱动完成。** 完成由冻结的目标条件、候选产物、必要检查和建模水位
   判定。已生成正文但依赖知识未就绪属于部分交付；分析任务则不强制生成正文。
   模型说“完成”或达到三章数量都不能替代领域终验。

### 连续写作与恢复的职责

GenerationRun 负责连续写作的授权范围、章节检查点和预算，实际操作仍由
同 Work 的决策 Agent 选择。WorkTask 负责统一用户目标与可发现性，非连续
写作任务不被强行塞入 GenerationRun。新章节范围先通过类型化提案呈现在
原对话，作者确认一次后才能建立运行；模型不能自己创建新的执行许可。

`read_context` 交付冻结来源目录；`read_task_source` 按不透明 sourceId 和游标
读取有界页面。选择、保护与评估所需原文必须完整读到，普通问题按需检索。
分页不扩大事实视角、写权限或预算，未读部分不等于不存在。任务自身保存后，
仍从创建时冻结的来源读取，不能悄悄改用最新正文。

“继续执行”和“调整后继续”必须区分：前者校验原输入及回执后恢复；后者在
新意图/新输入下重新规划受影响步骤。不得将已完成/取消的旧 Attempt 重新打开，
不得修改已冻结的尝试输入。必要时建立显式关联的后继 Task/Step，引用仍有效
产物并绑定新依据；有部分写入先核对回执。新的预算只能来自作者授权，不能靠
创建新任务或新 GenerationRun 洗掉已消耗成本。

这是目标行为，不覆盖现行的安全拒绝：当前输入失效时，旧恢复入口仍应拒绝，
直到关联重规划路径有真实测试证明可以安全接续，UI 不能提前承诺“无缝恢复”。

## 领域结构

- Conversation：交流上下文，与用户任务一对多关联，不拥有执行状态。
- Task：用户目标、完成标准、项目、取消意图、整体状态和版本号。
- Step：依赖、输入版本、预期产物和检查点。支持有界动态追加；默认串行。
- Attempt：一次实际执行，关联 Codex thread/turn、错误、时间和重试次数。
- Artifact/ChangeSet：不可变候选修订、来源 Attempt、接受记录和撤销依据。

现有 TaskRecord 承担 Attempt 职责；GenerationRun 是长篇领域流程。
两者已关联至持久化 WorkTask/WorkStep/WorkAttempt。GenerationRun 本身仍是其长篇流程的唯一状态权威，WorkTask 同步呈现状态，不复制调度算法。
已有候选修订及提交记录继续作为产物和变更权威，避免复制正文存储。

## 不变量

1. 只有校验产物的专用完成路径可完成 Attempt；终态不可重新打开。
2. 重试创建新 Attempt，不改写旧尝试；重复终态请求不改写原始证据。
3. Step 的领取、Attempt 关联和状态改变在一个 SQLite 事务中完成。
4. Task 取消意图持久化后，任何后续 Step 都不能被领取。
5. 不在持有数据库事务时等待模型或网络。跨进程写入使用版本条件更新。
6. 重启将失去执行器的尝试识别为中断，再核对写入回执；不得盲目重放写入。
7. 恢复必须校验输入版本、预算和依赖；不承诺恢复模型到某个 token。
8. Task 完成须满足全部必需步骤与产物标准；草稿已生成但建模失败应显示部分交付。
9. 作者实质调整不能让旧尝试获得新范围；纯提问不推进意图代次或重启执行。
10. 重规划不丢弃独立有效产物、不重置消耗、不绕过作者采用/撤销事务。

## 控制语义

- 暂停：禁止领取后续步骤，当前尝试可在安全点结束；立即中断是独立选项。
- 恢复：从有效检查点继续；输入变化时重新规划，而非继续使用失效上下文。
- 取消：记录用户意图，阻断后继步骤，同时请求执行器中断。
- 撤销：依据 ChangeSet 生成反向变更，检查后续依赖和当前头版本；不是取消模型调用。
- 接受：候选转为正式修订，事务中记录接受前后版本及操作者。

## 实施顺序与验收

### A：执行尝试状态边界（已实施）

收紧现有 update_task：禁止通用更新完成、禁止终态回退、重复更新不改写证据。
专用 complete_task 支持绑定一致的重复完成。测试覆盖无产物完成拒绝、
失败/取消后恢复拒绝、重复取消与完成的幂等性、产物完成校验。

### B：持久化 Task/Step 与候选队列（已实施）

建立任务、步骤、尝试关联；动作领取时原子记录 Attempt ID。
用版本条件更新防止重复领取；启动时对照产物回执修复步骤结果。
将对话、按钮、GenerationRun 统一接入，删除 Electron 内存状态作为调度权威的逻辑。
验收：完成后落库前崩溃、重复领取、第一项失败后剩余项恢复。

### C：全链路控制（已实施）

取消、暂停、恢复使用任务级接口；每次领取检查持久化控制意图。
取消不能被建模错误捕获后吞掉。恢复创建新尝试并关联旧检查点。
验收：步骤间取消、建模期间取消、多候选取消、重启恢复、输入版本变化。

### D：产物/变更与交互（已实施）

任务详情关联候选和接受记录，提供可解释的部分交付、待处理、阻塞状态。
统一恢复入口；按真实能力显示控制按钮。撤销检查冲突，不静默覆盖后续修改。
验收：部分产物、重复接受、接受后再次修改再撤销、跨任务依赖冲突。

## 设计检查

本次由主实现者按五角色关注点自检，不表示召集了独立专家评审。
架构：状态权威归 Rust，Electron 只保存当前执行句柄和并发保护；技术 A：领取、Attempt 关联、取消与恢复均在持久化事务内校验；技术 B：重复领取、崩溃恢复、版本冲突和失败重试可测试；产品：候选产物与正式采用分离，部分交付不显示为完整交付；UX：仅在可用状态显示暂停、继续、取消和有前置版本条件的撤销。
未新增兼容层，未改动 Codex 内核。五角色均为实现者按模板的检查视角，不是独立人员签署。

## 2026-09-24 幂等重试边界

复核发现动作请求已持久化后，如果源对话转为完成或作品版本推进，领域层原实现会先检查当前可写状态并拒绝相同幂等键的重试。现在领域层先在所属项目和源任务内核对已保存动作的操作、目标、指令与输入版本；完全相同的重试返回原记录（包括其最新执行状态），不同载荷仍拒绝。HTTP 层每次生成新的内部动作 ID，所以同键重试不要求该 ID 相同。只有首次创建才受源任务进行中和作品版本门禁约束；入站动作不得伪造非排队状态或执行结果。Rust 回归测试覆盖源任务完成且作品版本已变化后的领域层重复请求，以及同键换指令的拒绝。候选 HTTP 入口仍要求有效的运行中任务能力凭证；凭证被撤销后不能据此重新访问动作，作者应通过任务详情/动作读取入口查看结果。此修正不改变执行、取消或恢复语义。

## 2026-09-26 任务视图一致性

## 收尾检查发现的生产恢复缺口

此前检查发现 Rust Runtime 的 `recovery_snapshot` / `recovery_operations` 返回空 operations，不能用 Electron mock 的恢复测试通过证明真实生产账本完备。已验证的 Task 输出、候选修订、幂等回执及重启完成恢复，与“每个 Host 工具请求都有可核对的权威操作结果”是两种不同保证。

下一优先级是补齐恢复投影，不增加第二候选/确认状态机：

1. 保存受任务身份绑定的操作元数据（调用身份、工具名、内容摘要、幂等键摘要及领域回执引用），不持久化模型正文、工具参数原文或秘密。
2. 候选写入与回执关联必须在同一领域事务提交；不能先记录 committed 再执行，也不能根据模型消息或仅有 HTTP 成功码伪造领域回执。
3. 非候选写入分别使用真实的动作登记、知识发布和完成记录作证明；未知写入保持人工核对，不能统一猜测为成功或失败。
4. 恢复读取用同一数据库快照及冻结分页 fence，并按作品/Task/调用身份限制；读操作显式分类，不产生写入核对噪声。
5. 使用真实 HTTP 与进程重启验证“提交前崩溃、提交后回执丢失、Host 未记录写入、来源变化、重复核对、跨作品/任务请求”，不能只依赖 mock。

下面的实施进展更新了该缺口，不以单轮完整 verify 通过宣布整体理想架构目标达成。

## 权威操作回执与冻结恢复分页

原生 MCP 为工具与原始参数计算规范 SHA-256 摘要；已认证的 Runtime 根调用绑定 Task、线程、turn、call 与工具名。操作元数据只存摘要和身份，不存参数、正文或令牌。候选保存、动作登记、知识发布、规划评估报告、任务完成在同一领域事务写入具体回执关联；证明校验失败时业务写入一起回滚，候选重放与非候选重放指向原产物。

恢复查询不再返回空占位列表：同一 SQLite 事务冻结任务状态与操作元数据，fence 绑定作品/任务集合/页长，重开数据库后的续页仍读原状态；超预算、过期、跨范围拒绝。Host 消费时核对请求摘要、幂等摘要及已提供的线程身份，committed 必须有真实回执引用，不生成虚构兜底回执。

五项领域集成测试覆盖候选、动作、知识、报告、完成、回滚、重放和冻结分页；真实 HTTP 验证根身份、Author-only 查询与失败保持未知；真实 Runtime + MCP 进程重启验证 Host 未记录成功时恢复原候选 revision。详见 [权威恢复账本](RECOVERY_LEDGER_DESIGN.md)。进入领域绑定之前被拒绝、未到达 Runtime 或未知工具的请求仍保留人工核对；不据“没有记录”猜测未执行，不提供模型 token 无损恢复或自动重发旧意图。真实供应商连续创作、Windows 实机及其他 S1–S5 门槛仍需各自验证。

## 规划引用与工作区任务保护

generatePlan 的每个预期效果显式绑定有界 commitmentRefs，沿原 WorkStep / Attempt 候选事务核验精确修订、来源和各目标章节前文范围。错误、过期、未来来源与已建立对象的旧提案不能生成有效产物；失败不留下候选或任务输出。assessSceneOutcome 已按冻结引用和标准逐项保存 commitmentAssessments，证据只能来自该效果已校验的场景事件；矛盾/不足复用原 Check、resolve-feedback 及重写任务，候选历史的来源失效可检测。没有第二任务调度器，任务完成或作者接受现稿都不自动确认承诺。真实供应商与文学验收仍需独立进行，详见 [承诺推进反馈链](COMMITMENT_PROGRESS_FEEDBACK_DESIGN.md)。

整体验证同时发现 Renderer 接线缺口：App 要求可拒绝的 boolean 放弃回调，工作区却仍返回 void，且承诺编辑器未注册统一保存会话。已补齐当前版本契约，保存中拒绝放弃和重复保存，刷新保留编辑器与输入，显式放弃仅清除本地输入。任务控制与撤销在补充编辑期间不可触发；任务分页水位失效重新读取第一页，不将过期列表拼入当前列表。知识、历史快照和确认事实校验入口复用现有有界校验任务。

自动创作新增的承诺提取阶段使用可理解的阶段标签，重写预算显示与 Rust 当前契约一致（当前章四次模型任务、后续章每章五次）。最终构建与验证结果见反馈链文档的验证记录，不把 Mock、合法引用或通过机械测试当作全部理想目标已完成。

## 作者工作区诊断与任务状态展示

六类确定性校验继续使用已有 Rust 持久任务和版本控制，Renderer 只负责统一折叠展示，不创建平行调度器或修复权威内容的通道。折叠不会停止运行中轮询，摘要分别报告运行、暂停和需要处理；没有报告与完成但未经核验不冒充一致。读取错误与操作错误分别保留，成功读取不能掩盖失败操作，只读重试不启动新任务。

## 长篇分析的 WorkStep 阅读检查点

阅读进度现在归既有 WorkStep，而非某次临时 Task/Attempt。根 Agent 可显式保存一页连续 literal 原文报告；Runtime 在同一写事务重新查询、验证报告摘要和前一游标，记录有限候选摘要、页计数及恢复回执。只保存最新检查点，不生成小说产物、不推进正式指针、不建立平行任务管理器。

暂停按现有协作式任务控制执行：父任务暂停后立即拒绝检查点读写；当前尝试终止进入 blocked 后，由既有恢复控制重新排队并创建新 Attempt。来源与范围仍一致时，重新核验权限并给当前 Task/Thread 签发游标，不沿用旧凭证。重复提交同一请求返回原结果，CAS 冲突、跳页、来源变化与旧 Attempt 被拒绝。页预算按 WorkStep 保留，耗尽不给不可执行的续读计划。

连续确认到范围末尾只表示可核验的原文页链及模型阅读声明；不证明模型理解、不确认 Canon、不改变任务完成条件。作者面板现已增加有界阅读投影；真实供应商自主恢复认证仍未完成。实现边界和验证见 [任务内长篇阅读检查点](READING_CHECKPOINT_DESIGN.md)。

### 作者阅读进度与执行状态分离

WorkStep 的当前契约包含必需的 `readingProgress`：无记录为 null，来源有效时仅返回检查点版本、页数、去重字符数和遍历状态；来源失效为 stale，完整性或归属不可核验为 unavailable。模型摘要、查询计划、游标、凭证和回执不进入该投影。列表、详情及控制回执在原事务读取，不以读取进度修改 WorkTask CAS 版本或任务状态；数据库错误仍报错。

作者可查看暂停、终止或完成后的有效历史进度，根 Agent 的恢复接口仍要求有效运行中任务能力。UI 复用原有恢复阻断原因，阅读状态不重新决定能否继续。运行中第一页轮询每 1.5 秒且不重叠；历史分页用 epoch 排除迟到响应，作品切换先清理旧任务。没有全书理解百分比，也不以达到当前阅读范围末尾宣称任务完成。具体范围和验证见 [作者阅读进度](READING_PROGRESS_UI_DESIGN.md)。

## 2026-09-30 最终回复回执：收到回答不等于目标达成

`WorkTask.status` 表示执行状态，`deliveryReport` 表示结构交付，Task 的完成
summary 是模型或宿主的完成说明；三者均不能代替真正收到的公开最终回复。
本切片增加独立的回复证据，不新增任务调度、领域产物、正式采用或目标认证通道。

### 契约与权威边界

- Adapter 只选择同一 thread/turn 的已完成公开 `agentMessage`；显式
  `final_answer` 优先于未标 phase 的最终消息。流式 delta、commentary、reasoning
  及未完成消息不作为持久最终答案。宿主仅在回合成功 completed 后登记。
- Author-only `GET/POST /api/projects/{projectId}/tasks/{taskId}/final-reply`
  接受线程、实际 turn、已交付最新意图代次、公开 item ID、文本和截断标记。
  Candidate/MCP 的 `complete_task` 没有登记或查询权；没有新增模型工具。
- SQLite 写事务核验真实 Task/作品/turn 和作者来源，按 Task 保存唯一不可变
  回执。首次写入检查当前执行权威；历史读取及精确重放不重新授予执行权，
  也不因之后的领域失败或作品修订而清除已有回复。冻结输入/目标/模型及已交付
  作者追加记录形成来源摘要，身份与正文形成回执摘要；读取重新核验完整性。
- 并发不同正文只允许一个提交；相同请求重放返回原时间与原回执，不覆盖内容。
  登记后拒绝追加旧 Task 的作者要求，避免回合结束后才送达的要求冒充本轮输入。
  原 Task 的失败/取消仍如实显示，不因回复存在变成成功。
- 文本最多 65,536 UTF-8 字节，宿主按 Unicode 码点截断。`recorded`、
  `truncated`、`absent` 分别表示已保存、部分文本、成功回合没有公开最终消息；
  GET 为 null 则表示没有持久回执，不能把四种状态混为完整交付。
- HTTP 写入结果未知时，只读核对完整请求绑定；不重新发起模型回合、不猜测
  已保存、不新增费用。新 schema 直接创建回执表，没有旧摘要回填或兼容兜底。

## 作者局部改稿结果契约（本轮实施设计）

首个结果核验限定已存在章节的 `selectedScenes` 改稿。模型可以在候选动作的
target 中提出 `desiredOutcomes`：最多四项，每项具有稳定 ID、最多 500 字的
criterion 和非空 groupIds，必须是该动作选中正文场景的子集。现有单项批准或
有限范围预览显示这些条件，作者批准完整动作 target 才冻结；模型不得在执行
或评估阶段替换条件。没有预期结果的讨论或任务不强制建造语义评估。

沿原 WorkTask/Step/Attempt 推进写稿与建模；真实源绑定知识发布并完成后，
同事务追加 `assessRevisionOutcome` 步骤，复用原次数/费用/期限及暂停恢复门禁。
其目标由仓储派生，绑定 writerTaskId、原稿、新稿及知识批次，宿主不能另建
无来源的评估根。只读输入按章节/原选中场景裁剪，原/新稿片段有字节硬上限
及覆盖缺口，不授予任意历史来源或未来章读取权。

`submit_revision_outcome` 只供这个根任务提交 `revisionOutcome` 候选分析修订。
每个条件恰好一次判断 supported / unmet / insufficientEvidence，理由与证据
均有上限；前两者至少给一条实际新稿内、属于该条件授权且正文实际改动场景的 Unicode 原文
锚点。Rust 只核验来源、身份、范围、完整性与证据引用，不声称自然语言判断
客观正确。提交、任务输出和恢复回执沿已有候选事务，重复请求不能制造新产物。

作者只读查询按原 Writer Task 定位不可变候选，随后原文/知识变化标为 stale，
不删除历史或升级为 Canon。UI 区分执行状态、结构交付、回复与候选结果判断，
默认折叠且只读重试，作品/任务切换隔离旧响应。此阶段不自动按评估结果采用
正文，不增加第二套调度器；结果驱动的作者决定和“调整后接续”持久关系仍是
后续切片，不能把本阶段评估保存当作任意作者目标闭环全部完成。

## 作者决定与后继创作来源契约（2026-09-30）

本切片是上一轮结果核验的独立可审阅阶段：Core 决定事务、Runtime/Host
接线、UI 和集成测试分别落地，避免在大编排模块内堆积新的调度器。实现
由三个编码子 Agent 并行处理不相交范围，主 Agent 负责事务及关键路径；
按用户要求不组织专家评审会议。

### 决定不是正式采用或执行许可

作者对完整且来源当前的 `revisionOutcome` 可选择 `acceptRevision`（作为
后继依据）、`repairDraft`（还需改稿）、`defer`（暂缓），附最多 1000 字备注。
三种决定都不会修改正文、确认 Canon、创建任务或增加旧预算。备注是作者
对这次判断的记录，不被偷偷改写成新任务的根意图。

Author-only POST `revision-outcomes/{writerTaskId}/decisions` 接收严格请求：
`decisionId`、`expectedAssessmentRevisionId`、`expectedDecisionId`（首个为
null）、`choice`、`note`。Core 使用 Immediate 事务，核验实际完成的 critic
产物、Writer/场景来源、新稿和已发布知识批次；比较最新决定和当前报告头。
决定 ID 为 1–128 字节 ASCII 字母/数字/连字符；冲突 ID 及过期 CAS 拒绝。
同 ID、同作品/Writer、完全相同请求的重试返回原记录，先于当前性检查；
因此丢失回执后的重读不制造重复决定，也不复活已失效的执行权。

`story_revision_decisions_v1` 追加不可变决定与严格请求，记录绑定报告修订、
实际新稿、知识批次及服务端时间。GET 报告附带最多 20 条倒序历史，历史决定
保留，但只有匹配当前报告和来源的最新接受决定能准备后继创作。Candidate
不具备此 Author 写入口，模型支持/未达成的结论也不能替作者作决定。

### 来源关联不是预算继承

接受后，界面仅打开原有连续创作确认流程：作者再次核对根意图、1–3 章范围、
当前作品修订/快照/摘要、费用/尝试上限和期限。请求可带严格的
`revisionPredecessor = {writerTaskId, assessmentRevisionId, decisionId}`；普通
生成无此可选关系。后继运行仍有独立作者消息、WorkTask 和预算账户。

Run 状态与 `story_generation_revision_sources_v1` 同事务冻结这一来源边；
创建时检查其属于同一作品、决定确为最新接受、实际完成判断仍绑定当前
正文和知识。首次领取模型任务时再次核验，阻止确认后决定变化的竞态。
之后 Run 自身演进不使历史来源失效：只校验原边和实际不可变来源，保持
既有快照摘要检查、任务围栏、累计费用/尝试和暂停/取消规则。状态更新、
重规划或恢复不得替换/删除关联，不产生第二套控制权威。

UI 显示最新决定、备注及有界历史，保存期间禁止重复操作；写失败提供重试
及只读刷新。跨作品/任务的迟到响应隔离，过期报告不提供新决定或后继入口。
准备后的最终确认再次读当前报告和最新决定，Rust 事务仍是最终权威。

## “还需改稿”到新讨论的来源契约（2026-09-30）

本切片复用已有 WorkTask / WorkStep / Attempt、对话、候选动作审批、
Writer → modelKnowledge → assessRevisionOutcome，不新增调度器或费用账户类型。
作者决定仍只保存决定，点击“讨论下一次改稿”只准备可编辑的对话。
作者明确发送后，宿主建立新讨论的有限预算，不重复弹窗确认；不能给旧 Writer 自动补额度。

### 权威与来源

- 新 advisory 的 target 为 `type: project` 和 `revisionRepairSource`，来源复用
  `RevisionPredecessor` 的三个必填字段：writerTaskId、assessmentRevisionId、decisionId。
  它是追溯边，不是 sourceTaskId / resumeStepId 派生执行，也不继承原作者消息。
- Core 在创建任务的同一写事务核验同一工程内真实完成的报告、原 Writer、
  正文修订、已发布知识批次及最新 `repairDraft` 决定。任一来源变化拒绝创建，
  Work、作者消息、预算、Attempt 不得部分落库。
- manifest 冻结 typed `revisionRepairInput`：来源、作者决定、章节、原批准场景、
  完整预期结果和评估的 id/status/reason。不复制原文引句，不当作 Canon 或作者原话。
  不允许调用者自报冻结包；后续根据实际同 Work 前序 Attempt 追溯来源。
- 新作者消息只来自这次可编辑、明确发送的文本。决定备注只作为可见编辑建议，
  不能暗中变成新要求；模型诊断与原作者意图保持分离。

### 新写作许可与接续

当前入口有意限定为局部再改稿：候选只允许 `generateChapter`，章节不变，
`selectedScenes.sourceRevisionId` 必须是本次决定绑定的当前正文，场景集合是
原获批集合的非空子集；不带旧修订继续写，也不从修复入口扩到其他章节。
候选必须提出非空、场景内的新 `desiredOutcomes`，作者可重新批准细化后的目标。
更广的规划或修订应另开普通讨论并取得相应授权，本入口不能借此扩权。

提出候选、批准候选和新 Writer 领取前均核验来源仍有效，原审批不代替新审批。
Writer 已领取后使用这次冻结的写许可；它自己的候选稿让旧报告过期是正常结果。
后续 Writer 输出、知识发布和新结果评估核验历史来源及各自当前输入，不要求
旧报告继续“当前”，避免自身写入导致接续死锁。新报告仍是 candidateAnalysis，
需要作者决定；正文和 Canon 继续独立采纳，不自动循环到下一次写作。

### 有界上下文与故障行为

冻结包编码上限为 8,000 UTF-8 字节，完整准入，不静默截断目标、备注或判断理由。
超过上限拒绝这个专用入口，作者可转为普通讨论；不能删掉部分来源假装完整。
本轮人工核对了可能超过 1k token 的新增包：8,000 字节硬上限、只含候选数据、
无新增系统指令或私有推理；来源 ID、真实归属及字段完整性均由 Core 核验。
read_context 将此包作为 mandatory operationContext，移除返回 manifest 中的重复副本；
只压缩可选上下文，最终重算字节数与 hash，过小 byteBudget 必须显式失败。

UI 准备和发送前重新读取来源，切换作品、取消、运行中或未保存正文不自动消费
准备来源；迟到异步结果不得恢复旧入口。Host 再做预检，最终 Core 事务仍是权威。
运行中追加对话与新修复根互斥，不得丢掉来源而转为 steer 或普通聊天。

### 暂停写入栅栏与取消后用量结算（2026-09-30）

领域 Task 的自身 active 状态不等于仍有执行权。校验同时查询所属 Work：
paused、blocked、cancelled、completed 都拒绝迟到工具能力、检查点与完成写入。
暂停前已完成的任务仍能按原回执结算，再由作者恢复；暂停后不能以旧 capability
绕过 Work 控制。脚本任务完成与停机时序需明确，测试不能依赖暂停后仍写入。

取消先撤销活动尝试并保留历史，然后允许原已授权终态任务核对真实预算回执。
这种更新只增加既有账户的已发生用量，不能改运行状态、目标、来源、期限、
剩余许可或尝试谱系，不能恢复/重规划。重复结算和重开仓储不再消费额度；
不能为了让账本结算成功而恢复已取消任务。

Engine Runtime 唯一写正常 completed/failed/cancelled 预算终态，Bridge 正常
释放只解绑；worker 丢失保守记录 outcome-unknown。连接 ID 路由与供应商
模型名分离。生产主进程窗口销毁回调保存 WebContents 引用，不重复访问销毁对象。

本机恢复 4/4 与既有创作/检查点/重规划 16 项最终共 20/20 通过；权限/预算
42/42，重建后二次改稿接续 14/14、真实 preload/主进程只读讨论 1/1 通过。
测试优先沿实际仓储、HTTP、Codex/MCP 和 Electron 边界验证；脚本供应商、
候选载荷和 API 调用边界如实记录，未升级为完整 UI/真实模型验收。
完整验证与失败记录见 [持续创作验收第 13 节](CONTINUOUS_CREATION_ACCEPTANCE.md#13-生产桌面入口与恢复验收补齐)。

### 创建与恢复会话的启动所有权（2026-10-01）

作者启动、恢复或停止任务时，会话的就绪等待也是受控生命周期，不能只在
模型 turn 已开始后处理并发。Adapter 用一个当前启动记录承载目标与共享
Promise，`ensureSession` 可以加入进行中的创建或恢复；同目标恢复只发一个
RPC，不同恢复目标或 detach 在就绪等待中拒绝，避免悄悄切换作者选定会话。

握手后的继续执行及会话结果发布均验证子进程身份。任务重新绑定或停止后，
旧结果不能写入新的 thread id、发出 ready、清除新启动记录或关闭新进程。
启动记录的清理必须验证它仍是当前记录，不按“最后返回的请求”夺取所有权。

创建或恢复失败，关闭当前进程并拒绝待处理请求，状态明确为 error；保留
本次执行租约和任务能力凭证，交由已有任务终态及结束操作撤销，不让错误
处理扩大授权。作者重试会重新握手并等待必需 MCP，不自动重试模型，不
继承一个失败线程，也不绕过原有预算校验。

本轮不改变 Work/Attempt schema、暂停写入栅栏、恢复回执或模型额度。真实
生产桌面已覆盖同一应用、同一作品中 MCP 失败后重试：失败阶段没有请求、
审批或 Attempt，重试正常完成。故障边界与证据见持续创作验收第 22 节。

### 对话回合所有权与界面重试（2026-10-01）

会话启动共享不等于允许共享一个模型回合。对话、内核审阅和上下文压缩
统一通过 `engine-turn-lifecycle.mjs` 执行；在第一个异步准备步骤之前，
同步取得独立 `turnOperation` 所有权，并覆盖会话准备、模型回合、命名等
后续 RPC 和最终结果返回。另一调用明确拒绝，不覆盖原 completion，也
不登记一个等待执行的新模型任务。

`turnWaiter` 只负责关联流事件，流结束可以释放它，但不能提前释放完整
操作所有权。操作每次从 await 继续时验证记录及子进程身份；完成通知先于
启动 RPC 返回时，不能把已完成 turn id 重新设为活动状态。停止或关闭会
撤销操作记录，迟到成功或失败只能结束旧调用；finally 只清理自己的计时器
和仍属于自己的 waiter/操作记录。

回合失败或超时清理当前进程，并显示 error，避免重试复用可能仍在执行的
旧轮次。保持现有十分钟回合期限、预算、未知写入核验和租约回收规则；
没有自动重发模型任务、重新保存产物或提高额度。

Renderer 的根提交使用同步 ref 防止 React 尚未提交状态时连续 Enter 发出
两次 IPC。已进入 running 的指令仍走原有 steer，不被根提交锁替代。
暂时的连接/执行错误不是“未配置模型”：配置存在时允许作者明确重试，
缺失配置仍阻止发送；宿主在每次执行前继续验证实际凭据、能力、范围和预算。
旧调用的 finally 不清掉新提交记录，切换作品后旧结果仍不能覆盖当前对话。

上述为当前版本并发和恢复约束，没有旧接口兼容分支。真实 React App 的
键盘和重试按钮回归以及内核/桌面证据见持续创作验收第 23 节。

### 对话执行与工作区读取分离（2026-10-01）

一次对话执行成功不因后续 Renderer 读取失败而改判失败。模型执行结果与
工作区同步分别呈现：保留回复，提供明确的 Runtime 只读刷新；只读刷新不
重启模型任务、不重写产物，不增加模型费用，重复点击在同步边界拒绝。
失败或因编辑推迟读取时，顶部不能显示“工作区已同步”。该约束本轮覆盖
日常对话完成路径，不代表生成、保存、采用等所有产品操作已完成同样收敛。

自动刷新和手动刷新发布结果前核对当前作品、提交 scope 与实时 dirty
状态；期间开始编辑时不发布旧读取结果，也不触发中央工作区刷新。作者先
保存或明确放弃修改，再只读刷新。切换作品和卸载使旧对话 scope 失效。

重试操作消费失败轮次的原指令，不消费当前输入框草稿。运行中追加用独立
同步锁防重，确认成功只清除未变化的已提交输入；迟到追加回执只能更新仍
运行且 thread/turn 身份一致的回合，不能把已完成回合重新变成 running。
所有执行仍通过既有宿主的权限、范围、凭据与预算检查。

### 发送即执行（2026-10-01）

明确的发送、生成和手动继续操作直接进入执行，不再重复弹出初始预算
确认。主进程 `task-budget-grant.mjs` 绑定当前作品快照、源摘要和独立作者
消息，Runtime 与引擎继续持久化及校验执行授权和用量。默认授权不设模型
请求数、累计 token 或任务耗时上限。后台消费不能自行授权，恢复、
重试及后继步骤必须继承同一归属。正式采用、知识确认、候选动作范围
及危险工具审批仍为独立决定，发送不等于授权这些决定。

真实桌面与回归证据见 [持续创作验收第 27 节](CONTINUOUS_CREATION_ACCEPTANCE.md#27-发送即执行移除重复预算弹窗2026-10-01)。

实际 App 键盘、按钮、中央编辑器及快照证据见持续创作验收第 24 节。

### 执行授权与用量计量分离（2026-10-01）

本轮由单一实现者完成技术、产品和安全边界检查，不组织外部专家评审。

默认创作采用 metering-only：`maxRequests`、`maxTokens`、`deadlineAt`
显式为 null。请求字段缺失、授权不存在和归属不匹配仍拒绝执行，不能把
未知状态解释为无上限。自动生成的 `maxTaskAttempts` 也为 null；章节目标
和作者确认的精确修改范围继续约束内容，而不是限制模型工作量。

1. 作者发送绑定 source digest、snapshot、author message 和 work owner。
2. Rust Runtime 原子创建授权、工作账本、当前 attempt 的持久 grant。
3. 引擎按调用预留、按终态结算已知/未知用量。无上限时继续计量，不触发
   quota exhausted；明确限额的认证测试仍可使用有界计量策略。
4. 后继步骤和重试继承 owner；未结算的 attempt 不允许并发重领授权。
5. 作者停止仍撤销 epoch、终止调用并核账。内容采用与执行授权保持分离。

删除默认 16 次 / 200,000 token / 15 分钟额度、每 attempt 的 64 次 /
1,000,000 token 隐式分配上限、32 条结算记录导致的执行阻断，以及普通
回合 10 分钟和引擎租约 30 分钟的额外默认时长截断。无时长额度用 null
贯穿进程桥，不用巨大数字或重新补充额度模拟无限执行。

不删除单次请求/启动超时、错误重试策略、模型上下文与输出窗口、供应商
限流、任务 capability 有效期及 SessionPlan 认证有效期。当前 task capability
仍每次最多续至当前时间后的 30 分钟；主进程在有效期内通过 author-only
接口续期，绑定原作者、作品、线程、任务、来源、模型、operation、target
及原有效期。来源变化、暂停、撤销、终态或过期均拒绝，执行账本不重置。
引擎 SessionPlan 续期重新解析可信且仍有效的能力证据，保持同一执行
scope、lease identity、epoch 和预算；认证证据不足时明确停止并要求验证。
这使正常长任务不因单份凭证期限中断，但不承诺供应商、证据或失效授权
下的无限执行。不能通过取消权限检查或扩大用量上限代替续期协议。

变更局限于 `eternallight/agent-engine` 与小说领域层，不修改 `codex-rs`
内核、模型调度或供应商协议；默认计量策略对所有已支持模型通用。
