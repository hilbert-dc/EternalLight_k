# 小说协作角色库

## 目标与范围

在已有结构、一致性、通用检索角色之上增加人物、文风、读者体验。角色是可复用能力模板，不是固定出场团队或并发配额。同角色可有多个不同范围的实例。保持现有 Codex 生命周期、预算、只读工具与淡雅状态行，不新增调度系统或作者管理面板。

EternalLight 只读参考：config/product_agents.md、config/agent_harness_notes.md、config/agent_skills/{character-craft,style-craft,audience-modeling}/SKILL.md。采用人物开放变化、可验证语言特征、逐段读者认知及假设标记；不移植 Python Agent OS、阶段 DAG、发布网关、固定角色数量或旧数据结构。来源文件仅作设计参考，不安装为本工程执行技能。

## 实施前五视角评审（同一执行者）

- 架构 APPROVE：角色目录集中定义，生成原生 TOML；安装前一致性校验，配置错误不破坏现有目录。既有主智能体仍负责协调。
- 技术A APPROVE WITH CONDITIONS：角色只读、工具白名单统一，禁止角色配置扩大权限；角色定义及安装逻辑进入资格摘要。
- 技术B APPROVE WITH CONDITIONS：验证完整角色集合、生成配置一致、缺失/篡改拒绝及安装失败保留当前配置；测试生产指令和构建。
- 产品 APPROVE：五个专业角色加通用角色按需选择，不以角色名承诺能力或真实读者评测。
- UI/UX APPROVE：沿用每子任务一行状态，不加选择名单；任务名仍描述本轮工作而非展示所有可用角色。

## 任务约定与验收

根角色委派必须说明目标、范围、冻结上下文/准确引用、排除项、交付物、验收标准。子角色报告检查覆盖、发现及证据、不确定性、未完成项；主角色核对关键引用、处理冲突，必要任务缺失不能宣布全体完成。

这些自然语言任务约定和语义验收由模型执行；本次工程硬校验的是角色集合、配置一致性和只读权限配置，不声称对每次 spawn 内容作结构化拦截或证明文学质量。既有最终交付自检机制保持不变。

## 零兼容门禁

PASS：无版本适配、回填、迁移、双读双写或旧字段兜底。当前源配置、安装入口、资格摘要、测试一次更新；无数据库改动。当前可靠性、权限、文件发布完整性继续验证。兼容例外无。综合结论 APPROVE WITH CONDITIONS，条件为上述定向测试。

## 实施后复核

五个专业角色加三个通用角色已集中定义，八份原生TOML与生成器严格一致。安装前检查完整集合与配置，错误/缺失不替换当前目录；新增只读静态方法工具不扩大作品读写权。角色配置、拒绝篡改/缺失、根策略注入4项测试通过，发布资源2项通过，八份TOML解析通过。关联策略与MCP验证见 CREATIVE_STRATEGY_DESIGN.md。

同一执行者五视角均APPROVE，零兼容门禁PASS。报告语义和任务匹配仍需模型执行，不能凭角色名称承诺创作质量。未修改参考工程EternalLight。
