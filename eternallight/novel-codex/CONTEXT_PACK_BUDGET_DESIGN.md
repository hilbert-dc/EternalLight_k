# Context Pack 有界来源与整包预算

状态：当前实现及有限规模验证；不是完整语义 Context Pack 验收。

## 问题与决策

原上下文路径先调用整批建模知识读取，再对 Candidate/POV 把实体和断言清空；无谓反序列化长篇模型输出，Author 路径还可能把原始候选数组挤入上下文。正文、事实、知识各自估算预算，最后包装、来源元数据和覆盖信息可能使整包超额。目标正文单独超过预算时，旧路径可能跳过该正文而返回一个不具备目标输入的成功包。

现在采取同一当前版本协议，不保留旧上下文组装分支：

1. `story-core::context_sources` 只读取最多 100 个当前来源元数据，报告所请求范围的真实来源总数，不反序列化 `entities_json`/`assertions_json`。活动批次必须与作品、对象、选中正文修订、发布时间和 ready 状态匹配；匹配不到则 `model_pending`。元数据不是候选断言或事实，不携带 `entities`/`assertions`。
2. 范围先于召回：Writer 按冻结目标章限定，滚动规划/场景评估限定至其已完成位置；Project 范围仅用于有权读取的调用。正文、实体目录、工作知识仍由各自任务范围读取，不把该元数据 API 当作权限或语义查询规划器。
3. 先沿用正文、事实、知识的有界选取，再在实际 JSON 包装预算内裁剪可选内容。已有 Scene 链接预算先处理；随后依序移除非目标正文、来源元数据、实体目录条目、工作知识尾部条目。建模实体目录先预留联合报告空间；删条目时清除可能悬空的歧义组并标记扫描不完整。
4. 保留冻结任务目标、作者意图、规划、已选择的确认事实、目标章正文及指定建模源正文；它们本身超过预算时明确拒绝。没有截取半个正文、半条证据或半个 JSON，也不会用摘要替换必须保留的输入。
5. 裁剪同步 `coverage.complete=false`、去重后的 `missingScope`/`truncationReasons`、实际 included 数量。工作知识删项后清空可能不再成立的 findings，并重算候选/确认条数；原来源水位和请求范围不伪装成变小后的全范围。
6. 最终裁剪之后计算实际 UTF-8 字节数、内容哈希与包 ID，Runtime 再检查硬上限和任务输入/快照/来源水位。失败不产生写入、任务完成或权限扩大。

本次由当前执行者按用户要求直接设计、实施与复核，未组织独立专家评审。没有修改 Codex 上游内核、接口兼容分支、旧数据迁移或数据库双权威。

## 回归与规模证据

`context_budget_tests` 用真实生产保存和发布路径构建四章，再经公开 Runtime HTTP 路由创建 Writer 任务。16 KB 预算下核对目标源保留、第四章隔离、整包裁剪说明、工作知识条数、实际字节及哈希；8 KB 放不下目标正文时要求 422，修改冻结目标位置时要求拒绝。

`context_sources_tests` 经公开仓储接口验证来源章界限、改稿后从 ready 转为 `model_pending`、批次指针撤除及跨作品隔离。`npm run verify` 全流程和 `cargo clippy --workspace --all-targets -- -D warnings` 已通过；新增 fixture 由基准与集成测试共享，不增加生产测试专用 API。

`npm run bench:context` 复用 `long-work-literal-v1` 的 512 章、1,024,000 汉字、1,024 场景、50,176 断言生产 fixture。它创建带有效任务凭证的普通/POV Writer，经公开 HTTP 路由读取，每类首查询加 30 热态样本；检查目标正文、预算、覆盖、来源元数据形状及重复读取的哈希稳定性。不发起模型请求、不访问作者数据、不绑定 TCP 端口。

本次基准机同 [百万字长篇基准](LONG_WORK_BENCHMARK.md)：Apple M5 Pro、24 GiB、arm64 macOS、Rust 1.98.1，release profile。以下为统一状态来源筛选落地后的串行复测；数据构建 53.74 秒（另计，不含编译）。数字包含路由认证、SQLite 打开、领域查询、包装与响应解析，不包含后续基准断言检查。

| Writer | 176.68 | 121.38 | 127.12 | 140.38 | 52,838 |

两类范围的本机热态 P95 低于 2 秒初始目标，且包均不超过 60,000 字节；两者均诚实报告不完整覆盖。首查询发生在构建之后，不是操作系统冷启动。此前 Writer P95 为 58.09 ms、POV 为 183.51 ms；统一来源筛选扩大了 Reader 来源查询范围，Writer 本次变慢，不能把此改动称为全面性能提升。

2026-09-29 复测先发现一次真实契约不一致：章节计划和任务创建允许
`povCharacterId`/`storyTime` 显式为 `null`（表示未指定），原文与关系读取也接受，
但任务绑定 Query Plan 将它们当成非法值，使无 POV Writer 的 Context Pack 返回
`TaskBindingInvalid`。现已统一该读取契约，并由 `query_writer_tests` 覆盖显式
`null` 的任务查询、同任务 Context Pack 和未来章节隔离。修复后的同一 release
基准（512 章、30 热态样本/类型）构建 46.90 秒；Writer 首查询 220.60 ms、
P50 208.37 ms、P95 213.13 ms、最大 216.33 ms、58,035 字节；POV Writer
分别为 162.82/162.67/167.47/169.04 ms、59,471 字节。两者仍低于 2 秒，
但较上表 Writer 更慢，需持续观察。此为本机进程内 HTTP 路由与有界且不完整
的知识覆盖，不证明真实桌面、语义完整、Windows 或文学验收。

## 仍未完成

全部八类模型任务的 `read_context` 已能携带类型化 `queryPlan`，由 Runtime 重执行并核对同一任务、快照与有效范围来源水位，完整报告纳入基础包及整包预算。`queryScope` 明示由 Rust 推导的范围并进入策略哈希；正文普通检索复用相同范围。报告不能作为可选字段被裁剪，装不下拒绝；报告的检索缺口传入外层 coverage，外层内容哈希覆盖内层报告。实现及验证边界见 [任务绑定查询计划](QUERY_PLAN_DESIGN.md)。基础包与报告之间的全面语义去重及所有任务的质量验收仍缺；不能将两种 Writer 的既有时延数字作为扩展组合入口的测量证据。

预算裁剪目前是确定性优先级，不是完整语义相关性排序；Reader 工作知识仍有来源/条数上限，不能据此证明远章事实全部召回。首个有限 Query Planner 已接通，但完整自然语言消歧与召回、承诺与硬约束的全面建模、所有任务类型的 Context Pack 语义验收、人工金标、真实模型创作旅程及 Windows 测量仍按 S1–S5 推进。分支/历史任意 Context Pack 也不能由当前主分支的结果推断完成。
