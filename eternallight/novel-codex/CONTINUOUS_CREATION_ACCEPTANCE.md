## 1. 目标与文档职责

**对话驱动、可控迭代的持续创作系统。** 作者可以从创意、大纲、已有正文或
局部问题进入，通过对话获得内容、调整作品，并在调整后可靠继续。

本文是 [理想架构](IDEAL_ARCHITECTURE.md) 的统一用户旅程与验收索引，不建立
与 S0–S5 平行的阶段或第二份任务状态权威。[故事系统架构](STORY_SYSTEM_ARCHITECTURE.md)
负责领域与数据契约，[任务管理架构](TASK_MANAGEMENT_ARCHITECTURE.md) 负责
Task/Step/Attempt、控制、依赖和恢复。前半部分维护当前目标及验收标准，保留
S0–S5、C01–C10和既有安全质量门槛；后续执行记录保留实际实现、失败与最终
复验结果，不把目标调整预先标成已实现，也不改写历史结果。

保留既有独立 Codex 引擎、Rust 领域、SQLite、候选/正式隔离、知识建模、
检索、提案及采纳撤销链。开发测试阶段直接替换不合适实现，不建设旧接口或
旧数据兼容。本文不授权删除实际作品或取消无关运行。

语义能力按本次问题使用，不要求创作前完成全书建模。当前任务的交付由冻结
作者目标、必需产物、必要检查和真实依赖判定；知识批次只有属于该目标的必需
产物或后续操作真实依赖时，才是对应门槛。非必需分析失败须如实保留，独立
已保存产物仍有效；必需分析未就绪时，依赖操作继续阻断。不得通过删掉已登记
必需步骤、降低标准或清零消耗使失败转为通过。

现行具体链路仍强制知识批次、提取或评估的地方，在同步完成创建、准入、交付
报告、收尾/恢复及相应类型、fixture、测试之前，继续按真实实现报告结果。
本次只调整目标，不授权绕过当前安全检查或靠 UI 隐藏必需任务；新建测试样本
直接使用当前契约，不增加旧格式适配。漫画和动画的编辑制作结构与可选语义
分析也遵循此区分，具体媒介验收继续归多媒介实施记录。

## 2. 什么算产品价值

- 作者无需维护技术表单，但可以查看并调整系统提出的假设与结构。
- 输出可能是回答、设定、规划、场景、章节或跨对象修订；以作者目标判断价值。
- 同一作品可反复生成、讨论、修改、检查和接续；不要求每次从零搭建规划。
- 允许授权范围内自主工作，不需要逐步批准，也不允许模型自行扩大范围。
- 作者始终能知道内容依据、实际修改、影响范围、剩余问题和下一步。

“一句创意生成三章”保留为连续性、上下文传递和自动执行测试。它不能单独
证明意图理解、调整质量、建模正确性、恢复可靠性或文学效果，也不是默认
每次生成三章的产品策略。数量仅在作者明确选择的生成范围中生效。

## 4. 证据与完成门禁

每个用例的记录至少包含：代码版本、平台/运行环境、输入作品与来源版本、
原始作者请求和授权、实际动作及产物、预期与实际差异、测试或演示日志、
未覆盖项。任务 ID、回执、来源摘要和检查点用于核验；不收集密钥或私有推理。

每轮另记录冻结目标的必需产物、实际依赖及语义步骤的必要性依据。直接读取
原文完成的任务与确有语义依赖的任务都须覆盖，不能仅挑其中一类。验证必需
分析失败时相关操作被阻断、非必需分析失败不被写成成功且独立已保存成果可读、
模型试图删除必需步骤以过关时被拒绝；合法重规划保留依据、旧失败及累计费用。
知识陈旧、未读范围或未评估质量继续如实显示，不把“没有语义门槛”解释成
“不需要核对原文、授权和版本”。语义开/关的质量、返工和费用对照作为收益
证据，不用结构数量或建模完成率替代创作收益。

证据分层报告，不相互替代：

1. **领域确定性验证：** 固定模型输出下检验权限、版本、事务、依赖、预算、
   幂等、取消与故障恢复；不得用正常路径掩盖异常路径。
2. **真实执行链验证：** 生产 UI/IPC、Runtime、Codex/MCP 和数据库连通，验证
   同一操作及回执；使用 fixture main 或受控供应商时明确标注替换边界。
3. **真实模型验证：** 记录供应商/模型、实际费用、失败与重试，验证目标理解、
   工具使用、反馈调整和跨轮接续。接入认证不代替小说任务表现。
4. **作者质量验证：** 使用获授权作品，由作者评价可读性、人物一致性、调整
   符合度和返工负担；预先确定样本及合格标准，不以模型自评代替人评。
5. **规模与平台验证：** 沿用故事系统第 13 节的百万字/场景/断言规模、P95、
   Recall@20 与影响召回目标、二十四类领域场景及 macOS/Windows 门槛。

S3 最小闭环必须覆盖 C01–C08 的相关功能及 C09 连续性回归，包含真实模型
调整接续证据和作者评价；C10 的全部规模/双平台门槛归 S5。阶段验收不能删除
原有对应安全约束。整体完成仍要求原 S0–S5 全部门槛，不能仅用本表替代。

不使用代码行数、测试数量、生成章数或主观百分比作为完成证据。按需求项
分别记录“未实现／局部实现／待联合验证／已验证／受阻”，附可复查证据，
而不是把未测试项计入完成率。当前已有局部实现记录仍在各专题文档中，尚未
形成足以证明上述联合旅程全部完成的证据集合。

## 5. 下一步实施顺序（沿原 S0–S5）

1. **先补目标与范围契约。** 对齐作者意图、系统假设、任务完成条件、许可和
   原消息/版本绑定；列明现有字段能表达什么、缺什么，不新增平行状态机。
2. **打通“已有正文→局部调整→可靠继续”。** 以 C03/C04/C05 为首个联合
   实施单元，覆盖直接读取原文的实际改稿、确有必要时的语义依赖屏障、迟到
   结果、预算及作者可见反馈。同步任务创建、准入、交付报告、收尾与 fixture
   测试后验证新完成条件；不必等待全部知识系统完善，但缺失范围必须明确。
3. **扩展状态驱动的多入口编排。** 模型建议下一步，Rust 准入与完成终验；
   复用原 WorkTask/Step/Attempt，保留连续写作 GenerationRun 的唯一状态权威。
   校验动态步骤上限、依赖环、停止条件及恢复后的成本归属。
4. **将 UI 围绕创作决策收敛。** 中央内容、右侧对话默认显示目标、修改、影响
   和待决事项；技术过程折叠可查。不要以新增更多诊断面板替代联合创作旅程。
5. **补质量、规模与双平台证据。** 在链路稳定后完成真实供应商/作者样本评估、
   故障矩阵与长篇性能；失败项进入对应 S 阶段修复，不能换一批容易通过的场景。

局部可靠性修复继续进行，但只有影响上述主旅程或明确安全门槛时占据主优先级，
避免长期完善某个子系统而不检验产品闭环。此顺序不引入第二套供应商接入、
Agent 调度或正式写入通道，仍保持后续同步合入上游 Codex 的边界。

## 17. 真实建模失败修复与复验（2026-10-01）

### 17.1 根因与实现

此前三次真实失败分别暴露了两条不同路径：供应商发送 failed/incomplete
终止事件，被 StreamGuard 转成无原因的通用错误；以及发布成功后模型继续
改写并重复发布不可变批次，产生冲突并耗尽预算。不能把前一种历史失败
直接认定为输出上限：当时没有保存供应商的具体终止原因。

独立 Rust Bridge 现在先识别安全的终止原因，保存供应商已报告用量，再拒绝
失败流的可执行输出。输出上限、内容过滤、上下文上限等不会按断流自动重播；
明确的服务端/限流错误仍走 Codex 已有的有界重试。未知原因归入固定错误码，

不再把完整 entities/assertions 回送给模型。成功后的批次不可修改；精确重放
仍幂等，改变内容仍拒绝。改变内容的重复发布与 rejected 恢复操作记录在同一
事务中提交，避免 rejected 写入停留在 accepted。冲突响应明确要求完成任务，
而非继续修改发布参数。MCP 描述及任务指令同步该协议；可省略 aliases，

## 19. 主链稳定性与失败恢复（2026-10-01）

### 19.1 启动与执行隔离

## 22. 可用性：启动停止、恢复并发与失败重试（2026-10-01）

### 22.1 本轮方案与故障证据

- 恢复会话没有共享启动记录，并发两次恢复及一次 `ensureSession` 会发出

- 已收到但尚未发布的旧创建/恢复响应，在任务重新绑定后仍可覆盖新线程；

- 创建/恢复 RPC 失败没有让 Adapter 进入 error 或清理失败进程，查询状态

## 24. 可用性：保护输入，区分执行与读取失败（2026-10-01）

### 24.1 范围与问题

继续按作者此前授权直接实施，不组织专家评审。本轮只修改日常对话的
Renderer 交互及回归测试，不改变模型接入、任务 schema、权限或预算。

- 点击失败轮次的“重试”调用原指令，但原实现无条件清空输入框，丢失作者
  新写、尚未发送的另一条指令。
- 追加指令在等待 IPC 回执时，作者仍可输入。成功回执无条件清空输入框，
  会删除等待期间的新草稿；React 尚未提交状态时连续 Enter 可重复追加。
- 回合成功后的 `getState` 和模型执行共用外层 catch。工作区读取失败会

- 对话提交时捕获的 dirty 状态不能代表刷新回执到达时的编辑状态。迟到
  追加回执若仍投递 `agent/steer`，该 reducer 还会复活已完成的回合。

### 24.2 当前版本约束

原指令重试不消费输入框；普通发送仍消费明确提交的指令。追加使用独立

和 turn 身份一致，才能投递运行中的 steer 状态更新；迟到回执不复活终态。

按钮只读 Runtime，不启动模型、不保存新产物，不自动重试或提高预算。

自动刷新和明确的只读刷新在发布状态前检查当前作品、提交 scope 与最新
dirty 状态。读取等待期间开始编辑则不发布回执、不递增工作区 refresh
token，保留中央编辑内容并提示先保存或放弃修改；dirty 时刷新按钮禁用。
本轮针对对话完成后的同步路径，不声称已经统一所有生成、采用、保存操作

## 25. 真实使用：启动故障、稳定入口与首次作品（2026-10-01）

### 25.1 实际发现与方案

本轮启动项目真实 Electron 客户端，而不是仅运行临时测试环境。第一次
启动在创建窗口前退出，日志为 `evidence dependencies must be an object`：
严格的 Rust 认证校验拒绝了实际数据目录中的缓存，但启动流程把认证缓存
当作整台客户端的前置条件。因此既有干净环境回归不能复现这个故障。

方案保持内核严格校验不变，将模型授权与本地工作区可用性分开。无效缓存
不能启用模型，也不能阻止打开窗口、读取或手动创建作品；模型目录显示
待重新验证。仅在明确重新认证时，把原缓存保存为 `.rejected-<UUID>`
备份，重新生成当前证据，不转换旧字段、不移植旧报告、不自动放行能力。
验证前仍检查所选模型和凭据；无效的选择不触发缓存退役。

另发现开发 Renderer 每次随机分配端口。作者身份、会话和布局存于
localStorage，随机 origin 会把每次运行呈现为新的站点。开发入口改为
固定 `127.0.0.1:5173`，或明确指定 `NOVEL_CODEX_DEV_PORT`；端口占用时
报错，不自动换端口。本轮不迁移其他 origin 下的旧作者数据。

实际首次打开还会读取不存在的默认作品。空作品库现在呈现明确的新建
入口，禁止无作品对话及无所属历史读取；已有作品但当前选择已失效时，
选择列表中的有效作品，不把选择问题误报为 Runtime 离线。
