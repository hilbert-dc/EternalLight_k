# 连续创作的供应商请求与 token 总预算

状态：终态回执、跨任务 Rust 总账、桌面执行接线与启动前额度确认已有本地实现；故障矩阵、真实供应商核账和可调整额度授权尚未验收。

## 要解决的问题

`GenerationRun.usedTaskAttempts` 是已认领模型任务的保守尝试计数，不是供应商
请求数。每个 Attempt 创建独立的 Agent Engine `PersistentTaskBudget`，默认最多
64 次请求、100 万 token；失败重试、重规划或下一章都新建预算。已实现的
`deadlineAt` 会限制新任务和每次引擎租约，但不能代替跨任务的请求/token 总账。
租约同时接收相对时长与原许可的绝对毫秒截止上限；通用 Agent Engine 在签发时
取两者及 SessionPlan 到期时间的最早值，避免跨进程启动耗时使租约晚于作者许可。
模型调用可能成功、未知、超额、部分完成或在回执写入前崩溃；不能按“Agent
回复完成”推算费用，也不能在重试时隐式补预算。

## 最终契约

1. 作者许可分列任务尝试、供应商请求、供应商 token、截止时间及明确作品/
   章节/保护范围。现用 `maxTaskAttempts` / `usedTaskAttempts` 表达任务尝试，
   不保留旧字段兼容。请求/token 总额在 Rust 运行许可中冻结；启动前按同一
   额度计算规则展示上限并要求作者确认。独立的额度调整授权仍待实现。
2. Agent Engine 的持久预算记录是供应商请求用量原始证据。每个任务 Attempt
   使用唯一 run ID；完成、失败、取消均将未决 reservation 按未知用量计入，
   崩溃则先恢复孤儿预算再读取终态回执。活动预算不是可扣费回执。
3. 回执只返回有界的状态、请求数、实际 token、未知 token、额度与超额标记；
   不返回请求正文、凭据或无界 settlement 映射。缺失、活动、损坏或来源不符
   时阻断下一模型步骤，不按零用量放行。
4. Story Runtime 按 `runId + attemptId + budgetId` 幂等登记同一回执摘要，在一
   个事务里推进该运行的请求/token 余额；同一 Attempt 的不同回执拒绝。正式
   创作产物与供应商用量是两个证据通道，不把计费数据写成 Story Canon。
5. 下一个模型任务创建预算时取原运行剩余额度与单任务上限的较小值，真正的
   供应商请求在 Agent Engine `reserve` 前被拒绝。Rust `advance-task` 必须核对
   前一模型任务的终态计费回执；失败任务也须结算后才能显式重试。作者增加
   额度须独立授权与版本化，不得由模型或重规划隐式增加。
6. 进程恢复先查询 Host 操作结果和引擎预算记录：活动所有者继续等待；孤儿
   reservation 记未知并封存；回执重复提交幂等。未知用量按预留上限保守收费，
   不因后来 HTTP 结果不明而自动退款。费用金额仅在有可验证供应商价格和
   usage 时展示；未知计费不能伪装成精确花费。

## 实施与验收顺序

1. **终态回执读取（已实现）：** Agent Engine 从原持久预算 SQLite 以只读连接
   读取有界终态摘要；活动、缺失、损坏或预算 ID 不符时拒绝。Node 薄封装与
   Rust/Node 回归覆盖失败、孤儿恢复与重复读取；回执只包含用量、额度和状态，
   不包含正文、凭据或 settlement 映射。此步不提供总预算门禁。
2. **运行总账（已实现，待扩大故障验证）：** Rust GenerationRun/Task/Attempt 添加不可变预算许可、终态
   扣费记录及严格前置检查；`advance-task` 与 retry 不得越过未结算 Attempt。
   不接受客户端自报的供应商用量代替引擎回执。
3. **生产调度接线（已实现，待完整故障矩阵）：** Electron 对每次子任务以原运行剩余值创建持久预算，
   终态后读取引擎回执并提交 Rust；崩溃时先恢复引擎记录再重放登记。
   重规划 UI 区分尝试数、请求数、实际/未知 token 和剩余额度；启动入口先
   展示本轮上限和工作稿范围，确认后才创建运行。当前上限是固定策略，尚不支持
   作者选择额度或按供应商价格预估费用。
   真实 SQLite/Runtime 集成测试已覆盖活动模型请求预留后宿主退出：恢复把未决
   token 记为未知用量，孤儿任务失败；未登记回执不得重试，登记后可重试但原运行
   请求/token 总额不回补。它不替代所有崩溃点、并发认领或真实供应商核账。
   重新打开作品时，桌面端会对有界运行列表中的未扣账终态任务尝试恢复登记：
   终态回执仍不可读时保留运行记录并标记“待核账”，不开放继续、重试或重规划；
   运行列表读取失败时也不允许再启动一轮。作者可显式重新读取/核账，重复成功读取
   不会再次扣费。主进程与 UI 故障用例已覆盖该路径，但仍不代表完整崩溃矩阵。
   启动许可窗口允许作者选择本轮 1–3 章，默认一章；选项直接决定同一份任务尝试、
   请求和 token 上限及实际运行范围，不再将三章测试场景当作产品默认值。
4. **故障与真实验证：** 用受控供应商制造多次工具回环、usage 缺失、超额、
   重试、暂停、重规划、进程崩溃、回执重复/篡改及并发认领。证明所有路径
   消耗同一总额度，不出现部分正式提交或未经授权的补预算。随后做真实供应商
   小样本核账、成本记录和作者确认；本机脚本模型不能证明供应商计费准确。

本设计复用 Agent Engine 的预算与 Story Runtime 的 GenerationRun/Attempt，
不引入第二个执行调度器。阶段 1–3 的局部测试不能写成阶段 4 已通过；S3/S5
整体仍受 [持续创作验收计划](CONTINUOUS_CREATION_ACCEPTANCE.md) 约束。
