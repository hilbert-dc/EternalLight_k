# 按需创作任务编排

## 目标与边界

作者提出创作目标，智能体选择所需任务及检查范围；Runtime 校验原授权、当前来源、写入边界、执行额度与保存回执。手动保存正文仅更新数据与资料失效状态，不自动启动付费语义分析。删章后的影响检查继续自动触发，这是作者此前明确要求的产品行为。

## 当前版本实施方案

1. 移除手动保存后的自动建模消费者、派发接口及专属自动任务授权分支。保留当前来源的失效标记、检索覆盖信息；对话可按需发起准确绑定已保存正文的知识提取。
2. `request_work_action` 支持现有合法行动键或智能体提出的 operation/target 二选一。新提议通过同一事务的当前任务、来源、授权范围、额度与幂等校验，再变成同一 Work 的步骤。原目标未授权的正文、整章扩展、删除、发布与正式设定确认均不能借提议执行。
3. 连续创作中的当前章允许提出限定场景的修订，保留未选中及锁定内容。评估问题先交由智能体判断并在原授权内修复，不把有问题直接等同于必须让作者操作。已有未解决问题不能被收尾按钮隐瞒；超出授权或实质情节选择仍回到作者。
4. 规划评审允许 1–3 个具体视角，由智能体根据目标选择；高级手动入口显示对应视角，作者明确要求的视角不得省略。宿主按持久化安排执行，不以并行共享会话破坏隔离。
5. 删章后保持自动只读检查；取消固定一次查询、固定排名与固定查询预算模板，交由智能体按证据缺口选择检索；仍明确未读范围，不自动改其他章节。

## 五角色实施前评审

- 架构专家：APPROVE WITH CONDITIONS。提议与执行权分离，原 Work/授权/预算不重置；领域校验集中在 Runtime。
- 技术专家 A：APPROVE WITH CONDITIONS。移除自动派发而保留资料新鲜度；手动保存不产生模型任务，对话提取仍可执行。
- 技术专家 B：APPROVE WITH CONDITIONS。选择角色不等于任意授权；现有来源绑定与串行隔离保留，角色范围与调用方同步。
- 产品经理：APPROVE WITH CONDITIONS。减少不必要分析与技术接管；作者明确目标和重要选择保留，已授权局部工作自主完成。
- UI/UX 设计师：APPROVE WITH CONDITIONS。不增加维护面板；任务与结果沿原对话呈现，单一评审视角可用，错误与未覆盖范围诚实显示。

## 零兼容门禁

不新增历史格式适配、迁移、回填、双读双写或无效旧接口；当前类型、调用方、fixture 与测试一起切换。接口安全、持久性、并发和真实来源校验属于当前正确性，必须保留。

## 验收

必须验证手动保存零自动任务、对话仍可按需提取；原授权内提议成功、越权及过期提议失败；局部修复保留未选内容；单视角评审与非法角色拒绝；删章检查可自主检索但不可写入。实施后记录自动化测试及真实应用验证，不以打包成功代替完整验收。

## 当前接口与责任分工

`request_work_action` 必须且只能提供 `actionKey` 或 `proposal`。提议格式为 `{operation, target}`，target 只允许 `chapterId`、`sourceTaskId`、`scope`。当前正文、原作者范围、执行权限、Work 与额度由 Native 派生，不接受模型填入运行编号、授权、预算或任意对象路径。提议的稳定标识用于幂等重放；失败次数直接查询真实历史，不能靠换提议标识清零。

正文修订沿用原章节与范围；选中场景只能缩小，必须保留未选中内容及作者指定效果。连续创作只能修订正在执行的当前章。规划和其他已授权资料的再修订定位同一 Work 的来源任务；确认设定、删除、发布、新增未授权章节均不在提议能力内。

手动保存后的资料待更新状态只表示检索覆盖限制，不是一张自动付费任务单。系统继续负责索引、事务一致性、来源失效、幂等、锁定和保存核对。智能体负责判断何时分析、选择检索范围、如何改稿以及是否需要追加检查；重要故事取舍与权限扩展由作者决定。

规划检查可选择一个必要视角，或多个互补视角。宿主按已保存安排串行执行；执行调度与权限验证仍由程序负责。删章后自动创建只读影响检查，智能体自由选择相关材料和检索方式，结果回到对话。

## 联调补强

删除自动派发时，发现该路径原本顺带维护了“知识批次已经发布，但活动知识头已失效”的恢复检查。已将检查移到通用任务恢复逻辑，所有来源的建模任务都核对准确来源、实际发布任务和当前活动知识头。已发布但失效的结果不能被伪装成未发布重试；保留真正未发布任务的纠错能力。此项属于 Runtime 数据一致性职责，不交给模型猜测。

修稿后的已知负面场景报告保留为待复查证据。只在真实当前来源的新检查或作者有效决定后解除，不以旧报告失效代表质量通过。没有报告时不强行增加一套评审流程。

## 真实应用验收发现与修正

- 新测试作品手动保存正文成功，任务数为 0，确认保存不再自动触发语义任务。
- DeepSeek 实际对话曾把作品修订号误当作者指令代次。上下文现在提供 `authorIntentState.expectedIntentRevision` 与可执行状态，工具要求准确读取；不存在的较高代次返回可纠正参数错误，真实作者追加指令或旧来源仍被阻止。
- `request_candidate_task` 的确定性拒绝现在在事务回滚后结算为已拒绝，避免误显示保存未知；存储或通信未知仍保留恢复阻断。
- 真实 HTTP 恢复测试发现无章纲写作仍被保存接口强制要求章纲。保存现与 Agent 选择保持一致：无绑定时不能伪造规划来源，有绑定时核对真实章纲及其位置，原来源和写入范围保护保留。

这些修正属于当前契约的可执行性与数据一致性，不新增旧数据适配。最终验收需同时核对自动化回归和更新应用中的真实保存结果。
