# 作者承诺编辑与统一离开保护

## 目标与边界

上一轮完成可见建立/确认面板和版本一致性验证，属于实际进展。本轮完成作者对独立承诺当前候选的结构化调整，并接入现有工作区的保存、放弃、离开与 App 关闭保护。模型任务、跨旧报告全局列表、自动创作循环派发和文学质量验证仍须继续实现，不能用编辑表单代替对话优先的完整 S3。

不新增 Rust 写入权威、任务调度器、供应商分支或上游内核修改；复用 Author-only saveCommitment 与现有不可变修订/Review。保存仍是候选，不自动确认；extractionOrigin、对象身份不可修改。

## 编辑契约

- 编辑独立承诺的种类、摘要、兑现标准、状态/理由、实体关联、线索/人物弧关联、章范围与原文锚点。范围来自当前章目录，证据选择当前已保存正文源，字符位置按 Unicode 计算；历史证据不会被悄悄改绑，作者明确选择新正文版本重新锚定。
- 编辑器冻结初始 detail、snapshotId、projectRevision 和 expectedCandidateRevisionId；自动刷新不会覆盖本地输入。领域仍验证来源、状态/证据、锁和 CAS。
- 补充编辑会话只拥有 Renderer 未保存状态与 save/discard 回调。接入工作区现有 App 保护，不建立第二领域状态机。打开承诺编辑时锁定正文及其他正式写入；正文或审阅已有脏输入时不能打开承诺编辑，防止两种编辑互相推进基线。
- 收起面板保留编辑会话；选章节/作品、切换视图、关闭应用继续走统一离开提示。保存失败返回 false，保留输入；放弃仅丢弃本地编辑，不能称为撤回可能已经落库的候选。
- 保存回执未知时保存请求保留原幂等键、来源和完整正文。重试先重放原请求；若作者已继续编辑，原回执核对后新输入仍未保存，需再次明确保存。作者也可显式读取当前版本作为新基线并保留输入；读取失败不更新基线，之后仍由事务 CAS 拒绝并发变更，绝不自动重绑。
- 实时 Author 控制信息必须存在；历史只读 detail 不可进入可写编辑器。

## 五方面实施前自检

依用户要求，由实现者自检，不召集评审或编码子 Agent。架构：只新增组件和 UI 会话桥接，复用唯一 Author 保存服务。技术 A：冻结 CAS、原幂等重试、来源锚点与锁保护；技术 B：真实 HTTP 作者修订和 Electron UI/navigation 回归；产品：保存和确认分离，所有状态可解释；UX：结构化字段、明确重锚定、失败保留输入与一致离开保护。

零兼容门禁：不新增旧字段 fallback、双写、升级迁移、版本探测或旧接口。生产类型、组件、fixture 和现行文档同轮同步。

## 验证与实施顺序

先落补充编辑会话桥接与结构化编辑器，最小接入既有工作区；随后验证真实 HTTP 的来源保留与状态/窗口修订、Electron 的原请求重试/新输入保留/显式新基线，以及实际工作区的保存与放弃导航。最后构建、全套验证、严格 Clippy、截图和格式检查。大文件只增加必要委派，不将编辑逻辑塞入 CreativeWorkspaceView。

当前阶段必须证明上述编辑保护；全局列表、对话修改、自动派发、Windows 实机和文学质量属于原目标未完成项，不改写总体完成条件。
