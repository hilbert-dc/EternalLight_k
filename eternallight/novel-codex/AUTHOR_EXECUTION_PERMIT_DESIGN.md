# 作者有限许可与自主接续实施契约

2026-09-30 · S3/S5、C01–C09 · 单项、精确范围与有界后继分析已接入；完整自主创作与交付终验尚未完成。

## 已完成接线：规划检查断点恢复

在开放通用范围许可前，补齐既有规划检查 WorkTask 的恢复路径：恢复入口按领域
步骤识别原检查运行，而不是把 `reviewPlanningSeat` 发送到普通候选生成器。
用精确 ID 读取运行（不依赖最近十项列表），仅执行仍排队的席位；已完成席位和
已持久报告不得重跑。无产物失败的席位在原 WorkTask、原步骤、原冻结来源及
原累计预算内创建新 Attempt，旧回执必须已结算。更换席位绑定与领取事务一起
提交，失败不留下新绑定、额度或 Attempt。

执行/核账错误保留可恢复的原运行，不自动取消其他未执行席位；只有作者取消
才撤销整轮。中断后存在部分报告的失败不在本单元自动重跑，继续沿用现有
`partialOutput` 门禁要求作者决定。汇总完成必须同时核验无活动 Attempt、无
未结算额度及所属 WorkTask 未暂停/取消，拒绝时运行和工作步骤一起回滚。
本单元不增加余额，不扩大作品修改权限，也不替代通用范围许可的后续实施。

验证采用本地 HTTP/SQLite/真实持久预算回执及生产主进程恢复入口；不调用外部
供应商。重点覆盖未结算拒绝、重开后同席重试、已完成席位跳过、错误保留状态、
跨归属与终止状态拒绝，以及读取模型权限边界。

## 目标与现有边界

### 当前实施：有界后继分析与精确许可传递

范围请求增加必填 `maxAdvisoryRounds`（0–3），由作者在冻结预览中明确确认；
0 表示不安排后继分析。后继分析也消耗原累计 Attempt/request/token 和绝对
截止时间，不能单独建立根消息或成本授权。每个已完成的范围内候选动作最多
触发一个后继分析步骤；重试沿原步骤，不能重新获得轮数。

Author-only 的原 WorkTask 接续入口只在原步骤完成、候选实际产物存在、所有
费用结算、输入仍当前且范围有效时排入 advisory。步骤持久绑定原许可、原作者
来源和触发动作，复用 WorkStep 依赖与领取事务，不增加调度器。新分析冻结
当前作品输入，作者要求从原消息及已交付意图重建，客户端提示不能替换它。

后继分析的候选请求只有操作与规范目标仍精确匹配原模板时才能沿同一许可
排队；不自动改写 sourceRevisionId 或扩展章节/场景集合。正式采用、锁定修改、
新章权限及 GenerationRun 合流仍各自受门禁，不从分析权限推导。新意图撤销
本 WorkTask 旧范围；历史读取仍保留许可来源，不视为可执行权。

验证包括真实 Router/SQLite 的来源、共享账目、重放、轮数/尝试上限、未结算、
暂停取消、外部改稿、伪造来源和晚期事务回滚；宿主复用原步骤推进并验证不再
弹新根额度确认。生产 UI 展示后继分析轮数并让修改上限失效旧预览。此单元
不是文学交付条件或完整 S1–S5 的完成声明。

### 已接入领域入口：有界操作/目标许可

先把当前单项批准与有限范围覆盖收敛到同一动作领取/写入路径。Author 预览从
同一对话已验证的模型提案选取最多3个操作/精确目标模板，并确认最多3项动作
和2–16次累计 WorkTask 尝试（包括已执行的分析、失败及派生任务）。
预览冻结真实作者消息、当前意图代次、工作版本、作品 revision/snapshot/digest
及原账户剩余额度；确认提交必须匹配完整预览摘要。模型不提供“已授权”字段。
同源后续提案只有操作和规范目标均在模板内、原许可有效且有剩余动作名额时才
自动进入现有 WorkStep；范围外或名额耗尽保持 proposed，不发新额度。已有提案
的排队、许可记录和范围确认一起提交。重放不重新排队或重置名额。

这不是整份范围许可的最终产品形态：仅支持原 advisory 或经持久后继步骤证明
的 advisory 使用精确模板，不推断自然语言授权，不开放任意跨章/新建章规则。
锁定场景、候选隔离、前置产物和领域来源校验仍由原写入事务执行。Author 改变
意图会使本工作内的范围记录失效；桌面预览/原步骤推进已接入，但意图改变后
的新许可恢复、统一完成条件、GenerationRun 合流仍须后续完成。

本单元集成验证须覆盖 Author-only、预览过期、重复确认、覆盖内排队/覆盖外
提案、名额耗尽、篡改/旧意图/暂停取消拒绝、预算不重置及晚期事务回滚。

### 当前实施单元：根作者消息身份

普通根任务的宿主确认同时产生独立 `authorMessageId`（不同于额度授权 ID）。
Rust 创建事务将作品、原线程、作者原话、根 Task 与 WorkTask 作为不可变来源
记录；消息、任务和额度一起提交，失败一起回滚，精确重放不追加消息。缺少身份
的根额度请求直接拒绝，不为旧库补身份。作者原话不是模型输出或派生指令。

后续单项许可返回同一消息身份，意图重建从此来源及已交付追加要求计算；
恢复形成的意图绑定必须回到同一 WorkTask 的较早 Attempt，有界递归核验，不能
用后来被改写的 manifest 冒充作者来源。追加要求仍由既有 TaskIntent 控制，
本单元仅建立原始消息身份，不宣称已完成每条追加消息的独立身份或范围许可。
底层无额度状态构造仍不是作者消息证据；未来范围确认必须取得真实持久来源。

验证涵盖原子回滚、重放、跨归属/身份复用拒绝、消息或 manifest 损坏拒绝，
模型只能获得执行所需的既有上下文，不能创建或批准作者身份。各功能 fixture
显式同步当前契约，不添加默认身份或旧接口兼容分支。

作者通过对话提出目标，确认一次可理解的修改范围和成本上限；模型在该范围内
选择步骤、生成候选、建模、检查及继续。只有扩大范围、改变保护规则或增加预算
才再次请求决定。纯问答不能因模型建议而获得修改许可，候选保存不等于正式采纳。

当前 `task_actions.rs::record_task_action` 对无覆盖许可的动作保存 proposed；同源
精确范围覆盖且仍有名额的动作通过共享队列事务创建 WorkStep。`approve_task_action`
保留作者精确单项确认能力，使用同一队列与证据模块；`task_action_binding.rs`
和任务领取事务再次验证目标。
GenerationRun 另有连续写作范围、来源与累计预算。保留这些已验证的不变量，
替换逐项审批作为唯一授权方式的限制；不创建新调度器、第二份作品状态或供应商路径。

## 权威数据与生命周期

许可是既有 WorkTask 的版本化作者输入，不是独立运行状态机。新增不可变许可记录，
由 WorkTask 指向当前许可；Attempt 冻结许可 ID/代次及来源。许可只由 Author API
确认，模型只能提交解释提案。许可不接受客户端声明的“已通过”“已消费”或余额。

每份许可必须包含：

- 同一作品、WorkTask、原作者消息 ID、原话摘要、当前意图代次；消息身份由宿主
  持久保存并核验，不以模型引用或本地 UI 临时时间戳证明作者来源。
- 目标说明、结构化交付条件及来源三元组：正式 revision、工作 snapshot、sourceDigest。
- 有界操作/目标集合：现有对象的精确 ID，或创建后续章节的明确数量与起始位置。
  场景使用稳定 ID 集合，不能把“第二章”字符串当作对象权限。
- 不可修改对象/场景集合及依据修订。锁定场景始终受既有事务校验；更换许可不能
  偷偷解锁，正式 Canon/Review 采纳也不属于默认候选写入许可。
- 累计任务尝试、供应商请求/token 上限与绝对截止时间，绑定唯一预算账户。
  修改意图、重规划、切模型、进程重启或新 Attempt 都不创建免费余额。
- 允许的衍生动作规则：例如修改目标章后仅对其实际新修订建模、提取承诺及评估。
  衍生目标由领域根据已持久输出推导，不允许模型以“依赖”为由任意扩章。

读取权限与写入许可分别计算。为分析影响读取其他章节不意味着能够改写；Writer
的 POV、场景范围和前文遮蔽不能被较大的项目级问答权限覆盖。

终止/撤销通过既有 WorkTask 控制事务撤销执行权，保留许可、余额与产物证据。
新许可替代旧许可时递增意图代次，失效未领取动作；活动写入的撤销与能力凭证
撤销同事务完成。已提交回执可读取，但旧许可不能生成新的写入。

## 模型解释到执行的闭环

1. advisory 读取作品并提出有界解释：目标、精确对象、拟修改内容、保留项、交付
   条件及必要歧义。解释默认没有执行权限，不因自然语言出现“修改”自动批准。
2. Author 预览显示可核验的范围、保护项、候选性质和预算。一次确认建立许可；
   来源在预览后变化时拒绝确认，重新展示差异，不自动吸收新来源。
3. 模型仍调用现有候选动作工具。Rust 在登记事务校验当前许可、意图、来源、目标
   与剩余预算；覆盖内动作原子创建 WorkStep，覆盖外动作只形成待决定提案，
   不占可执行步骤或预留模型额度。纯分析只有只读工具权限。
4. 领取事务再次校验同一许可与输入。前置自产结果通过已提交回执推进可用依据，
   外部编辑不能冒充自己的输出。预算预留、Attempt 绑定及步骤领取不可部分提交。
5. Host 仅执行已领取步骤。模型请求使用该 WorkTask/GenerationRun 的累计剩余
   预算，并通过现有 Engine 持久回执结算；未知用量先保守扣账，不能先重试后核账。
6. 产物事务执行原有作用域、锁定场景、来源 CAS 和候选隔离检查。后继依赖以
   实际产物修订和建模水位为准，不能以模型“完成”文本放行。
7. 领域完成判定核对交付条件：目标候选存在、范围外内容不变、必需建模/检查已有
   当前来源证明、未决依赖与预算已结算。文学质量仍需独立作者评价；失败可以是
   部分交付或等待决定，不能仅凭计划步骤耗尽宣布目标完成。

## 作者调整后的分析接续与重新授权

执行范围失效不能同时抹除分析任务的历史来源。作者追加要求后，旧范围记录导致
失效的真实作者消息；消息未交付时禁止继续，交付后同一步骤的分析 Attempt 可以
读取当前上下文、提出候选动作、预览新许可。恢复必须验证消息来源、步骤归属、
完整已交付历史、当前输入及原截止时间，不能仅凭 `superseded` 状态恢复。

旧范围仍永久失效，旧写入任务不能恢复权限。新动作保持 proposed，作者通过现有
预览与确认流程重新授权；确认沿用同一个 WorkTask 的剩余预算和截止时间。
分析重试从同一步骤的上一真实 Attempt 冻结完整要求，不退回最初指令。
没有新的有效许可时，历史许可的累计 Attempt 上限仍约束重试，不能借失效绕过。

本地验收使用真实 Runtime 路由、SQLite、来源链与预算结算证据，覆盖待交付阻断、
交付后分析、重新授权、重试、伪造来源和事务回滚；不依赖真实模型调用。

当前实现将失效原因登记为共享作者消息表的外键，消息与失效状态同事务保存。
接续来源必须是首次许可指定根，或同一步骤的紧邻上一Attempt；不能用相同文本
的其他步骤代替。分析恢复核验失效消息已交付、实际归属及冻结历史包含该代次；
候选写入仍使用原active许可校验。范围确认仍走既有接口和桌面入口，没有第二
许可账本、匿名来源回退或旧schema兼容。专项集成测试位于
`native/story-runtime/tests/execution_scope/intent_adjustment_tests.rs`，覆盖真实
候选大纲保存与完成、原额度逐次递减、两次追加后的重试、失效后累计尝试上限、
有效外部工作消息冒充原因、遗漏冻结代次及事务末端版本故障回滚。

本单元最终验证：40项Runtime（范围10、作者来源5、Context12、额度13），
30项Core（账户5、动作绑定11、作者历史3、任务11），11项MCP，共81项
定向Rust通过；25项Host通过。生产Runtime/MCP、TypeScript/Vite、全目标
严格Clippy、上游边界和差异空白检查通过；既存4.1MB前端bundle警告保留。
全程没有调用外部模型，测试以本机macOS、真实临时SQLite和本地MCP回环
为边界；Host测试不代表完整真实Electron/模型旅程或Windows验收。

初次回归在旧实现复现交付后Context返回409，修复后通过；新增测试首次编译
因未引入Digest trait及未使用导入失败，已修正测试导入，没有放宽生产来源、
预算或期限门禁。最终重编译复验覆盖同文不同步骤来源、有效外部工作消息、
遗漏历史、累计尝试上限及实际大纲候选输出。先前混合全量结束exit101，唯一
失败目标是沙箱中的MCP回环绑定PermissionDenied；单独允许本机回环后11项
通过。混合基线不能被追加专项结果改称为当前源码纯全量通过。仍须推进
GenerationRun共享范围许可、结构化交付、冷启动和S1–S5整体完成条件。
最后native Cargo格式化和仓库`just fmt`均完成exit0；后者首次因uv缓存沙箱
权限失败，允许本机缓存访问后原命令通过。最终差异空白检查通过，没有
上游`codex-rs`工作区变更；格式化后没有再启动测试。

## GenerationRun 的统一方式

### 当前实施：章节交付由仓储事务核验

通用运行更新不能仅凭 `status=completed` 或 `completedChapters` 声明完成。
每次章计数增长必须从真实 Check 阶段推进一章，在同一 Immediate 写事务中
重用现有知识查询、场景评估及章节绑定校验，核验当前正文、规划、建模批次、
本运行承诺提取和评估任务的实际产物、作者反馈决定及已结算账户。通过后由
Core 生成有界的 `chapterDeliveries` 记录；调用方只能保留既有前缀，不能追加、
改写或伪造交付证明。完成状态要求冻结范围全部交付且无活动任务或未结算费用。

交付记录是执行证据而非 Canon、正式采纳或文学质量证明；历史记录不因后来
修订变成新的执行许可。不增加第二套任务状态、模型调用、旧字段默认或回填。
必要验证：空输出/跳章/直接完成/伪造证明拒绝且全部回滚；真实三章 Runtime
流程逐章保存正确来源，阻塞与作者反馈继续沿原流程；晚期事务故障不留下证明；
恢复及重规划不改历史证明或预算，最终费用用尽但已交付时不要求新的模型额度。

实现沿用现有运行行及任务账目，不新增交付状态机：只允许 Check 精确推进一章，
证明由 Core 生成，包含本章正文/规划/提取/评估修订、建模批次、评估 Task、
检查快照/来源摘要/运行版本及可空的作者继续决定。读取还核验真实工作归属、
历史修订和快照成员；过去章证据使用冻结正文的章号，不用后来目录编号改写
历史。新的章计数不能回退或跳章，终态不能重新变为运行；账户全部 Attempt
必须终态、已结算，真实次数与费用回执数一致。Core/Authoring/TS 当前契约及
fixture 同步增加必填 `chapterDeliveries`，没有旧字段默认或数据回填。

新增空运行拒绝用例覆盖直接完成、跳章及伪造证明；两条原三章 HTTP/SQLite
流程增加证明前缀、实际来源、重开一致及缺失快照拒绝断言。已批准继续后，
晚期 WorkTask 写入故障使运行、交付证明及工作一起回滚，正常重试可继续。
费用耗尽用例通过本地 Engine 持久预算预留最后评估的全部剩余请求额度，
不能伪造费用数或把许可扩大；最终交付不再申请模型任务。

本轮首次编译发现 ID 错误转换缺失，已显式映射现有错误类型。检查点回归发现
两项 fixture 在工作类型已被 SQL 损坏时仍期待读取成功；现先核验精确拒绝、
原始运行行不变，再恢复正确归属并验证重绑定，不放松许可验证。额度耗尽
fixture 首次重复创建同一个 Engine 预算而违反唯一键，现直接消费已创建预算
的真实终态回执，不改账目或生产逻辑。这些初次失败不计为通过。

### 共享预算领域收敛

GenerationRun 的回执解析、累计用量、未知 token 保守扣账、耗尽判断及回执幂等
现统一迁入 story-core 的 `ProviderBudget`。生产 AuthoringService 直接调用同一
实现，自己保留作品/活动 Attempt/终态核验和运行版本 CAS；删除原生成专用累计
算法，不增加第二张用量表或双份余额。同一账户拒绝将同一 Engine budgetId
记到不同 Attempt；累计溢出在改变任何字段之前拒绝。超支后的迟到终态仍记账，
执行准入与记账分离，不能以账户已经耗尽为由丢弃真实成本。

这仅完成通用账务算法接入既有生产路径，不等于普通 WorkTask 已获共享账户。

### 账目级未结算互斥

执行领取记录增加 `settled`，并以 WorkTask ID 建立 `settled=0` 的部分唯一索引。
除 GenerationRun 活动任务门禁外，共享 reserve 入口也拒绝已有未结算记录的
账户；即使其他数据库写入方绕过该入口，也不能插入第二份活动额度。
只有通过任务归属与预算身份核验的终态回执，才在同一账目/运行事务中将记录
标为已结算。后续 ledger UPDATE 或运行更新失败会同时回滚此标记，不能先释放
额度再丢失消费记录。暂停、失败和取消本身都不释放额度，仍须核对终态成本。

这一约束下沉到共享存储，但产品执行入口仍限现有 GenerationRun；不是普通
WorkTask 已接通，更不是并发多份余额分配。普通目标的初始 Author 额度契约、
账户创建与宿主全路径接线仍是后续必需交付。

互斥验证：19 项针对性 Rust 回归通过，领域用例同时证明 service 拒绝第二次
领取与数据库 UNIQUE 约束拒绝旁路插入；HTTP 故障注入确认账目写入失败时
settled 仍为 0，成功结算才变为 1。严格 Clippy 通过。重建 Runtime 后本地

### 普通任务后续额度确认：实施边界
