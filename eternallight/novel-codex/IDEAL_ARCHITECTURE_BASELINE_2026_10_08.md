## 1. 总体目标

**建设对话驱动、可控迭代的持续创作系统：作者表达方向与调整，系统理解作品现状，在授权范围内生成、修订和可靠接续。**

底层不是单纯存储文本的数据库，上层也不是一组专家提示词。系统需要完整连接：版本化故事模型 → 知识检索与推理 → 创作方法 → 意图与依赖驱动的创作编排 → 作者交互。继续围绕现有独立 Agent Engine 建设小说领域，不重写通用执行内核。

成功标准是“理解已有内容、接受调整，并在调整后可靠继续”，不是一次生成的章节数量。
自动生成是持续创作的一种执行模式，不再是所有任务必经的固定流水线。
“一句创意生成三章”保留为连续性和自动执行测试，不再作为 S3 或产品整体成功的充分条件。
任务结构与控制见 [任务管理架构](TASK_MANAGEMENT_ARCHITECTURE.md)，统一验收及下一步顺序见
[持续创作验收计划](CONTINUOUS_CREATION_ACCEPTANCE.md)。既有 S0–S5、安全和质量门槛不降低。

“理想架构”是本产品目标的名称，不表示已验证最优，也不表示全部能力已经落地。数据建模不替代小说原文；专业角色不保证文学质量；引擎认证不替代产品验收。

有限许可当前切片：精确操作/目标模板已接通 Rust 预览/确认、候选动作排队、
领取围栏、桌面确认卡及原 WorkStep 推进；作者可确认0–3轮后继分析。真实候选
完成并结算后，领域层在原工作中建立有来源证明的 advisory，继续精确模板内
的候选操作；累计尝试、原账户和绝对时限均不重置，不自动替换源修订或扩章。
作者可返回原执行过程控制运行，历史许可不冒充当前执行权或正式采用。
同一步骤的已交付意图调整已允许分析接续与原预算下的新范围确认；旧写许可不
恢复，重试冻结全部已交付要求，历史累计尝试上限仍生效。GenerationRun 已与

显式区分真实 Task 与真实 Run，不创建虚构 Task 或第二账户。任意领域动作的

规划、建模、承诺提取、评估、反馈决定和费用结算，追加有界交付记录；直接
改完成状态、跳章或调用方伪造证明均不能代替交付。历史证据与后来修订分开，

### 文档体系

S1 属性状态切片使用明确的 `kind=state`、有限值类型与 single/multiple 声明，复用原建模任务、源修订、审阅、身份与索引。SQL 在来源截断前过滤世界时间，冲突保留独立证据并区分值冲突、规则分歧与未知时间；结束只撤销适用性，不生成反值。确认有源主张不授予全局 schema 权威，带区间的确认状态不进入通用 `stateFacts`，必须经类型化状态查询消费。审阅 UI 显示区间、类型及模型声明性质。见 [属性状态契约](STATE_PROPERTY_DESIGN.md)。

S1 正式结构规则新增独立 `propertyRules` 修订：Author Gateway 保存只形成候选，原 Review/Acceptance 事务采用后才成为规则权威，撤销及历史快照沿同一账本还原。无位置限制的 Author/World 投影使用批准的主体种类、属性值类型和基数，不重写原模型主张，也不自动确认值；类型不符及未解释的自然语言例外报告覆盖不足。Reader、Character 和 Writer 受限查询不读取全局规则正文或修订。未增加表、兼容层或模型执行通道。作者规则 UI 已接入“世界与规则”，支持可选有限编辑、纯规则审阅、采用及账本撤销；冻结保存请求、未知结果核对和统一离开保护沿当前协议执行。对话规则提案现沿原 WorkTask/Step/Attempt 和 Codex/MCP 生成，保留模型来源与冻结基线描述，根任务经有界 read_property_rules 页面重组完整规则，不授予采用权；见 [对话规则提案](PROPERTY_RULE_PROPOSAL_DESIGN.md)。条件解释、事件状态机与 S1–S5 整体验收仍未完成；见 [作者属性规则](PROPERTY_RULES_DESIGN.md) 与 [规则工作区](PROPERTY_RULES_UI_DESIGN.md)。

S2/S5 原文召回扩展：新增任务范围内的 `passages` 游标通道，不要求关键词命中，直接读取选中不可变正文而非派生索引。Codex 可逐页按含义寻找证据，再使用来源绑定重排；字符锚点、跨片重叠、源水位、Writer 场景与 POV 过滤、整包预算及裁剪后重读由 Rust 管理。它增加可遍历全书的授权原文通道，但页面末尾不认证全书已被模型理解；真实供应商、持久语义审计、成本/规模、人工金标与双平台验收仍待完成。见 [无关键词原文召回](PASSAGE_RECALL_DESIGN.md)。

该原文路径现先定位一个授权源修订再解码，避免每页展开整书 JSON。新增 `bench:passages` 以生产仓储构建百万汉字/50,176 断言，验证全书机械字符覆盖：4,096 页/8,192 片段覆盖含分隔符的 1,027,584 字符，本机耗时约 4.35 秒；首章、连续及后部页热态 P95 约 1.08–1.12 ms。此为有限 Rust 仓储读取规模证据，不含模型/HTTP 时延，不证明语义质量、持久扫描恢复或双平台验收。详见 [原文读取基准](PASSAGE_READ_BENCHMARK.md)；全局语义任务的持久检查点仍需继续实施。

S2 当前新增 Codex 语义候选判断重排：沿原 Task/MCP 查询链，以 literal 报告摘要绑定全部结果，Rust 同快照校验后重排；模型不能新增来源、扩权、确认事实或隐藏裁剪缺口。Writer/POV、来源水位和整包预算仍由领域层控制。它不是全书语义召回或真实模型质量已通过；外部召回评估入口仍测字面基线。见 [语义判断与来源绑定重排](SEMANTIC_QUERY_RANKING_DESIGN.md)。

S2/S4/S5 现有独立小说领域召回评估入口 `evaluate:story`：冻结原库的只读一致副本，按外部标注执行生产字面证据与显式影响查询，核对作品/当前或历史来源及 Unicode 锚点，报告数据摘要、逐类召回、遗漏、错误和截断。未测通道不计满分，总分达标不能掩盖单类失败；人工标注来源只是声明，整体架构认证始终不由该入口签发。新增六项真实仓储/文件回归纳入默认 Rust 验证，完整 native、严格 Clippy、边界与构建通过。它补齐基线评估工具，不是语义通道、人工金标或文学验收已完成。见 [小说检索与影响集合评估](STORY_RETRIEVAL_EVALUATION_DESIGN.md)。

S5 作者工作区已将六项局部校验收进默认折叠的系统诊断入口；运行、暂停、过期与读取/操作异常仍可见，折叠不停止已有运行中轮询。重复操作、刷新突发、跨作品迟到响应与只读恢复已加门禁及真实 Electron 回归。它是展示和客户端可靠性切片，不新增调度器，也不把六项结果当作全局一致或文学认证。构建及全部 12 项 UI 测试通过，真实供应商、语义/影响召回、人工金标与 Windows 验收仍需独立完成。见 [作者工作区诊断分层](WORKSPACE_DIAGNOSTICS_DESIGN.md)。

承诺反馈链已补入规划引用与逐效果候选判断：每个 expectedEffect 显式携带 `commitmentRefs`，以独立承诺修订或报告/提案/正文三元身份定位。候选保存事务检查当前选择、来源和各目标章节的前文上限。场景评估只读取原计划明确引用的冻结标准，逐项给出推进、兑现、矛盾或不足及场景内事件证据；失效引用不得重绑。矛盾/不足复用原 Check 与作者接受/修稿门禁，已保存评估来源失效时保留历史并标为 stale；任何候选判断都不自动改变正式承诺或 Canon。真实供应商、文学语义和全部 S1–S5 验收仍未完成。见 [承诺推进反馈链](COMMITMENT_PROGRESS_FEEDBACK_DESIGN.md)。

## 2. 五层小说架构与横向执行基础设施

| 从底向上的层次 | 回答的问题 | 唯一职责 | 不负责 |
| --- | --- | --- | --- |
| L1 故事数据与版本 | 作品是什么，依据来自哪里？ | 正文、对象、关系、事件、意图、计划、证据、不可变修订、快照与原子提交 | 选择模型、评判审美、执行 Agent |
| L2 故事知识服务 | 当前知道什么，改变一处影响哪里？ | 检索、认知/世界状态、演进查询、Context Pack、增量建模、影响分析与检查 | 自行批准改稿、另建事实权威 |
| L3 创作能力 | 怎样写、怎样分析和修订？ | 人物、场景、文风、信息控制、长篇兑现等方法；绑定所需上下文和输出契约 | 永久专家进程、直接写数据库、动态扩大权限 |
| L4 创作编排 | 为达成作者目标，当前应该做什么？ | 意图与假设管理、有限许可、按状态和依赖选择动作、生成/修订/检查/重规划、暂停恢复与交付 | 重写通用调度器、持有第二套故事状态、无条件启动全书流水线 |
| L5 作者交互 | 作者想要什么，结果怎样呈现？ | 对话、中央正文、进度、证据、差异、采纳与撤销入口 | 推导权威任务状态、执行 SQL、持有供应商密钥 |

这五层是逻辑边界，不是五个网络服务，也不是每次读写都必须穿过五次代理。简单阅读走领域查询，作者采纳走 Author Gateway 和提交服务；创作任务由 L4 组织 L2/L3，再通过执行适配器调用现有引擎。

### 2.1 独立 Agent Engine 的位置

`eternallight/agent-engine` 是横向执行基础设施，继续拥有协议适配、会话、工具执行、子 Agent 通信/等待、预算、取消与恢复。其通用 Rust 核心经现有 Node/Electron 薄封装接入，使用私有 Codex App Server；它既不是故事数据库，也不包含人物、章节或伏笔语义。

- L4 发出受限执行请求，由现有 Host 接入引擎。
- L2 需要模型分析时，提交有快照/范围/输出 schema 的分析任务，经同一执行通道处理，不另用供应商 SDK。
- 模型通过 candidate-only 领域工具读取获准上下文、保存候选或提交报告。
- Author Gateway 代表作者执行采用/撤销；模型及其子 Agent 不获得该权限。
- 领域的“下一章需要先完成上一章”是创作依赖；引擎的进程、RPC、租约和取消是执行机制，两者不重复实现。

### 2.2 依赖方向

领域契约和模型不导入供应商协议、Electron 或 Codex 内核实现。L2 使用 L1 的查询/变更接口；L3 使用领域契约描述方法；L4 组合知识服务、能力注册表和抽象执行端口。Electron 适配器实现执行端口并调用现有引擎。

现有 MCP/HTTP 是传输边界，不是小说业务规则的存放位置。领域内可使用直接函数调用，不为逻辑分层增加本地网络跳数。模型输出进入校验与候选流程，不能反向绕过 L1 的唯一提交服务。

## 3. 数据、知识和创作的核心闭环

### 3.1 数据建模范围

L1 统一保存三类模型，均使用稳定身份、来源和版本：

- 故事世界：实体、关系、命题、事件、时间及人物认知。
- 叙事设计：主题、视角、弧线、Scene/Beat、信息披露与叙事承诺。
- 创作演进：作者意图、计划修订、工作稿、偏差评估、分支及采纳决定。

计划、工作稿、作者确认内容相互关联但保持类型/可见性隔离。世界演进、叙事进度和编辑历史也不得合并为一条含糊时间线。L2 计算的状态、摘要、图视图和检索索引均可重建，不另立真相源。

### 3.2 持续创作主循环

对话表达意图 → 读取作品现状与依据 → 确定目标/范围/完成标准 → 提出下一步动作
→ Rust 校验依赖、版本、权限和预算 → 引擎执行 → 保存候选与检查点
→ 更新建模、解释结果与影响 → 在许可内继续或请求必要决策。

- 入口可以是一句创意、已有大纲、已有正文或一个局部问题，不要求先建立完整 Brief/Outline/Plan。
- 先复用有效内容；补充结构是满足具体任务依赖的手段，不为走齐阶段而重写已有作品。
- 模型提出创作动作和方法，领域层决定该动作是否可执行及何时算完成，不让模型自授权限。
- 作者明确要求、系统提出的假设和待决选择分开保存；假设必须可解释、可替换，不能进入作者要求或 Canon。
- 缺项不是一律追问：可逆、局部且在许可内的选择允许系统标注假设后推进；方向冲突、保护对象或越界须暂停确认。
- 纯讨论/询问进度不创建修改任务。任务可交付分析、设定、规划、场景、章节或跨对象修订，不强制落到章节数量。

### 3.2.1 自动生成执行模式

作者提供方向与范围 → L4 建立任务和有限许可 → L2 准备当前状态与证据 → L3 选择方法 → 引擎执行 → 保存真实工作稿 → 提取候选知识、比较计划与实际 → 通过相关建模屏障后继续。

自动推进工作稿不要求逐场景人工确认，但不等于作者已确认，也不能覆盖锁定内容。下一章基于前章实际生成的检查点，不读取尚未落实的计划作为既成事实。
GenerationRun 保留为授权连续写作流程；它不是所有创作行为的父状态机。已有任务/步骤承接其他动作，不能新增第二套调度或提交权威。

对话后的新章续写现有显式作者入口：最近一轮 advisory 的原始作者要求与冻结
作品来源三元组（正式修订、工作快照 ID、来源摘要）可带入可编辑的 GenerationRun
许可确认。模型回复不替代授权；范围与预算由作者确认，宿主与 Rust 领域层
均重新核验三元组，故候选稿或知识头在正式修订不变时发生变化也不能复用旧许可。
新章由领域运行建章。它补齐人工占位之外的
界面路径，但并未实现模型自主动作识别或真实供应商的完整调整接续验收。

可重复的离线跨进程测试现从受限局部改稿、来源知识重建，经过同一作品的
GenerationRun 规划、领域建章、续写、再次建模、承诺提取与场景评估直至运行
完成；Codex App Server、Agent Engine 桥、Novel MCP、Story Runtime 和 SQLite
均为真实组件，供应商模型由脚本替代。它证明这条执行/状态链可以闭合，不证明
生产 UI/IPC 全链、真实模型意图判断、创作质量或双平台门槛；详见
[持续创作验收计划](CONTINUOUS_CREATION_ACCEPTANCE.md)。

### 3.3 对话调整

“第二章让女主更主动” → 更新有明确范围的 CreativeIntent → 分析影响 → 冻结/取消受影响旧任务 → 加载人物和改稿方法 → 生成修订 → 显示差异、更新工作稿与候选知识 → 在剩余许可内继续。

迟到结果不能覆盖新意图或新 head；纯进度提问不改变指令代次。需要修改已确认/锁定内容时转成作者授权提案，不静默扩大范围。
已经终止的任务不会因新要求重新打开。旧输入失效时先保留产物和操作证据，再生成关联的新步骤或后继任务；只有依赖与许可仍有效才继续。范围扩展和预算补充均需授权，重规划不重置已消耗预算。

### 3.4 实时建模

正文保存与知识理解异步分离：持久化新版本及失效范围 → 合并分析任务 → 绑定快照提取候选 → 校验与 CAS 发布 → 更新派生物水位。分析结果默认只改变候选理解和建议，只有明确许可才能触发正文修订，避免无限自激改写。

## 4. 当前实现与目标差距

以下是本次设计所依据的已检查代码位置，不是一次全面功能审计：

| 当前模块 | 已有基础 | 目标处置 |
| --- | --- | --- |
| `src/` | 中央作品、右侧对话、编辑/审阅组件 | 保留产品结构，补自动生成与建模状态；UI 不持有权威状态 |
| `electron/main.mjs` 等 | 进程/授权/引擎接入及部分任务编排 | 保留宿主职责，逐步抽出小说生成决策到领域 authoring |

| `native/story-runtime` | 本机 Author/Candidate HTTP 边界、查询投影与有界上下文 | 保持薄宿主；领域状态转换继续下沉到 `story-core` |

## 5. 工程落位与语言选择

技术栈为 Electron/React + 独立 Rust Agent Engine + 独立 Rust Story Core + SQLite。Rust Story Core 是小说领域核心，不属于通用 agent-engine，也不修改上游 codex-rs。原 Python Creative Runtime 已在生产切换和契约验证后删除，当前不存在 Python/Rust 双轨权威。

目标 Rust workspace 位于 `native/`：

| 层/边界 | 目录职责 |
| --- | --- |
| 共享契约 | `story-core` 内部模块：类型、错误、标识与受限关系类型 |
| L1 | `story-core`：sources、knowledge、narrative、persistence、changes |
| L2 | `story-core`：timeline、queries、modeling、reasoning、impacts；规模需要时再拆 crate |
| L3 | `story-core` 的能力绑定契约；方法文本仍在产品 skills 目录 |
| L4 | 独立 `story-authoring` crate：目标、滚动创作状态机与本地域务检查点 |
| L5 与宿主适配 | `src/` 与 `electron/`：显示、授权及引擎执行端口适配 |

目录与逻辑层不是机械一一对应：knowledge/narrative 拥有数据语义，查询投影由 L2 计算；changes 服务同时供作者采纳和受限工作稿检查点调用，但权限与正式/候选指针分开。

进程边界只暴露稳定的领域命令与事件；SQLite 访问、事务和权威状态留在 Rust。不能为了“全 Rust”把小说语义塞进通用 engine 或上游 codex-core。

## 6. 重构原则与切换方式

1. 以可运行纵向切片推进，不先拆出一堆空目录或一次重写全部产品。
2. 当前处于开发测试阶段：代码修改直接实现理想架构，不考虑旧代码、旧数据和旧接口兼容。每个切片同时更新生产调用方、类型、fixture、测试与现行文档；删除被替代实现，不保留双读双写、旧入口转发或历史数据升级层。
3. 保留候选隔离、幂等回执、版本 CAS、作者权限和失败恢复等有效机制；“不兼容旧代码”不是丢弃正确性约束。
4. 小说数据及方法目录仅在产品内变化，保持 Codex 上游同步边界；默认不改 `codex-rs/`。
5. 保持快照内读取一致；数据更新必须能说明来源和影响，派生结果不能冒充正式事实。
6. 子 Agent 是可选执行方式；方法加载不提升权限，单 Agent 自查不冒充独立审查。
7. 已有无关 UI/功能改动不因重构被覆盖；涉及本地作品删除须单独确认精确范围。

## 7. 实施主线：复用现有 S0–S5，不再建立平行计划

S1 正式事件规则现接入共享四值解释器：Author/World 和 Review 独立于查询
entries及模型选定前提收集精确正文来源，保留支持、反驳、冲突与未知。
来源、证据或操作预算缺口不签发满足；自然语言例外、同刻起点与身份未决
保留未知。候选规则不生效，撤销及历史沿原作者账本，事实确认不级联。
受限视角不读取全局解释。该切片是来源主张解释，不认证世界真相、不执行
效果，不表示完整状态机或S1–S5已验收；见[事件条件设计](EVENT_CONDITION_DESIGN.md)。

S1 多参与者事件已切换为独立 event 实体与严格类型化解释：参与者角色、世界时间、同源前提/效果主张序号受限且在发布事务内校验。当前/历史读取、审阅及候选差异拒绝损坏引用；参与者进入来源截断前的状态召回与变更实体列表。全量/分片断言审计、重建、审阅生成/确认终验及候选差异现在联合同批实体声明，复用发布的事件契约，拒绝重复身份声明和角色类型损坏。已发布载荷改变即在同一事务撤销四类相关审计的有效代次，不靠来源数量不变继续宣布通过；故障源不能被重建自动修改。作者审阅显示角色和同批次编号，事件确认不级联确认其他主张，不执行状态变化。已确认事件不进入游离的通用 stateFacts，覆盖标记 typedEventFacts，需沿带批次/来源/序号的类型化查询消费。见 [有证据的多参与者事件模型](STORY_EVENT_MODEL_DESIGN.md)。它完成事件数据基础，不替代跨源前提、完整状态机、语义因果推理或 S1–S5 整体验收。

S1 条件解释底座新增同源时序报告：知识投影和审阅从完整源批次解释 typed state 前提的事件前区间，以及效果起点相对事件的顺序；查询时刻裁掉前提并不使其变成缺失。相等边界、未知时钟与不支持类型明确分类，不推出前提真值、无冲突或因果，不执行状态改变。事件校验同时拒绝被引用的损坏 typed state，确认终验不可绕过。见 [事件条件与效果解释](EVENT_CONDITION_DESIGN.md)。这不是完整条件组合、跨源引用或状态机；完整 S1–S5 门槛保持不变。

S2 长篇结构化任务检索补强：Writer 的 `search_story(entityName=...)` 不再先读取最近 100 个建模来源。所有断言在发布事务中写入通用端点索引；名称候选和选定实体的断言均在 SQL 中按作品、目标章之前的章节、当前正文修订与活动批次约束，旧章证据不会因后续 100 章挤出。独立核对/事务重建覆盖全部已发布批次；源修订失效不返回旧断言。候选 ID 最多 100、名称声明最多 300/12 KB、匹配结果最多请求上限/20 KB，完整响应硬限 32 KB；截断与未建模来源进入覆盖报告。声明预算截断时仍可显式选择已找到的 ID 检索，但覆盖不能标为完整。该查询仍需显式名称及 ID 消歧；不能代替自然语言规划、语义召回、完整人物/读者披露策略或百万字性能认证。

S2 检索一致性：Author 联合检索与 Writer 的正文/结构知识、关系图检索现从同一个 SQLite 只读快照完成任务能力验证、输入水位检查、范围计算和证据召回。知识状态及世界/叙事/创作演进投影也在单次快照内读取身份决议、来源和确认记录。并发写入不会让一次响应拼接不同版本的任务状态、正文与知识；WAL 并发回归验证快照内两次读取保持一致，快照结束后可见新修订。读事务只能确保本次读一致，不使缺失索引自动完整，也不把取得快照后取消的任务转为可写许可。

S2 Writer POV 查询收紧：绑定 `povCharacterId` 的任务不再从 `search_story` 返回无法证明该人物已知的原文命中或候选身份详情；结构知识只返回同 POV 且获知时间不晚于任务绑定 `storyTime` 的认知态度，或命题在该时间已知、关系在该时间有效的主张。任务未绑定时间时，相关结构知识保守隐藏。其他断言/事件仍需更细的认知与披露锚点，故保守隐藏并把覆盖标为不完整。非 POV Writer 仍按原前文章节范围检索。`read_context` 的 POV Writer 现在只保留当前授权目标稿，不再直接下发前文原文、未经认知证明的世界事实或建模实体/断言；已确认的人物事实须归属当前 POV 且有不晚于任务时间的认知锚点，知识投影改用该人物视角，覆盖明确标记证据不足。当前目标稿及本章计划仍可能包含人物尚未知晓的作者信息，故这只是保守收敛，不等于 S2 全局视角隔离验收；后续需为普通事实、事件、文本片段和计划建立可检验的披露锚点。

S2 POV 候选元数据门禁：结构化名称检索在 POV 范围内隐藏重名消歧、候选目录截断与隐藏命中截断信号；显式选择一个未经证实的隐藏身份，和选择一个根本不在该名称目录的身份返回同类空结果，而不是用不同错误或候选数量侧信道暴露其存在。无 POV Writer 保留显式 ID 消歧与无效 ID 错误。此收敛尚未证明完整侧信道隔离，查询耗时、其他覆盖元数据与所有下游上下文仍需审计。

S4 显式依赖影响切片：Author-only `impact-analysis` 以当前或冻结快照中的一个实体为变更起点，复用源修订绑定的关系索引，在单个 SQLite 读快照内沿 `causes/enables/prevents/motivates/foreshadows/paysOff/reveals/inputDependency` 出向边生成有界、逐边可追溯的可能影响路径；多条独立证据保留为不同路径。其他关系不作为依赖传播，候选关系不自动变为 Canon。另从同一来源范围内该实体已建模的名称/别名进行有界正文索引检索，返回 `literalMentionNeedsReview` 候选；未建模但字面提及该名称的章节可以被找出，命中不等于需要修改。名称、正文候选和索引覆盖各自报告截断；即使显式图和字面召回完整，报告仍固定声明 `globalImpactComplete=false`，不执行自动改写或删除。领域测试覆盖独立路径、非依赖边过滤、预算截断、未建模正文命中、旧快照/跨作品隔离及源修订失效。依赖规则版本及跨对象作者选择已按后续扩展补齐；语义变更抽取、代词/语义提及、模型语义分析和完整反事实分支仍待落地，故 S4 尚未验收。

S4 修订差异来源切片：上述影响查询可选带同一章节的 `fromRevisionId`/`toRevisionId`，在同一读快照校验项目及对象身份；当前态必须以当前目标修订为 `to`，冻结快照必须以该快照成员为 `from`。差异返回 Unicode 字符范围、截断摘录、稳定 Scene ID 的新增/删除/移动/编辑状态以及标题/章号变化，不把字面差异推断成“叛徒已变卧底”等语义事实；实体变更起点仍由作者显式选择。后续需要从修订差异自动抽取经证据证明的命题/事件/角色变化，再连接依赖与候选修订。

S4 建模候选差异切片：修订差异现额外比较两版来源修订各自唯一已发布的建模批次，将断言除证据锚点外的结构化字段作为候选主张身份；保留 `sourceRevisionId`、`modelingBatchId`、断言序号与原文证据，分别标记 `newlyExtracted` 和 `noLongerExtracted`。先抵消完全相同的断言，避免重复主张误配证据；同一主张仅证据改变时只计证据重锚定，不当作事实变化。任一版缺批次、尚在排队或存在多个已发布批次时返回不可比较且不生成“移除”结果；结果和受影响实体列表均有硬上限与截断标识。这只是两个抽取结果的差异，绝不是世界事实的真伪判断，也不能取代语义召回、作者审定、跨对象影响和反事实验证。

S4 作者可见的只读检查：Electron 桥接现暴露 Author 影响分析，章节页提供已建模实体选择或显式 ID 输入，可对当前保存版本及其父修订发起查询；界面展示显式关系的逐边证据、规则版本、正文命中、建模候选差异和覆盖缺口。未保存的编辑会撤销旧报告并禁止查询，避免把过期分析当成当前稿结论。影响面板不自动改写或采纳，跨对象作者采用由独立 ProposalSet 面板执行；完整反事实分支、模型语义召回和正文块级采用仍未实现。

S4 反事实知识覆盖层首个切片：Author 可在固定的 main 历史快照上创建不可变 hypothesis，指定精确的批次、源修订和断言序号以排除某一条证据，或给该快照中已存在的实体加入标记为 `assumed` 的真假主张。重放仅修改模拟投影，冲突单列为 `hypothesisConflict`；独立来源的同类证据保留，正式知识、Canon 和分支 head 不变。请求有大小上限、幂等键与快照来源校验，跨作品隔离；桌面章节影响面板现读取同一固定快照的 Author 知识投影，供作者逐条选择要排除的带源证据，再追加假设、查看覆盖与冲突，不提供采纳。投影可能截断，未列证据不得视作不存在。该切片不是完整反事实分支：尚无假设下的正文/关系重算、时间演进、模型推理、假设到 ProposalSet 的转化或选择性应用；`globalImpactComplete` 仍为 false。

S4 跨对象提案切片：`story_proposal_sets_v1` 将同一 main head 下至少两个现有 ReviewBundle 对应的候选修订、当时已采用版本、审阅状态与作者声明的操作依赖绑定为不可变 ProposalSet。Author-only 创建和预览接口按作品隔离，拒绝重复对象、循环/未知依赖、阻断性审阅与不属于基线快照的候选。整组采用在同一 SQLite 事务里重新验证版本、审阅、候选、锁、身份/建模检查、声明依赖与所选确认事实的来源闭包；只创建一个结果快照和一次作品版本推进，并保留每个成员的接受记录。整组撤销同样只推进一次版本并逐项回退确认事实与规划影响；单项撤销不能拆开已采用的组。重复请求返回原回执。Author-only Runtime 接口和领域/HTTP 回归已覆盖应用、重复、失败回滚、整组撤销与成员撤销拒绝。提案列表可分页找回；Electron 工作区支持规划、正文和身份候选的作者选择，通用“撤销最近操作”会识别组提交。Detail 的结构读取不承诺可提交；显式 Preview 检查实际选择并可报告 `applyReady=true`，提交事务仍是最终门禁。仍只验证**声明的依赖闭包**与有界事实来源，不能推断全部语义依赖；模型提案生成、跨对象语义影响与文学质量验证尚缺，不能称为完整 ProposalSet 工作流。

S1/S4 整组提交的创作演进分页：一个 ProposalSet 应用或撤销会在同一作品快照下产生多个成员接受/补偿记录。创作演进查询现在按 `(snapshotRowid, acceptanceRowid)` 稳定排序和翻页，游标绑定查询快照；每个组员保留独立变更证据，并带同一 `proposalApplicationId`。领域回归以每页一条跨过两项采用、两项撤销，且验证采用时取得的历史游标在后续撤销后仍能继续读取旧快照。此修正保证有界演进读取不漏组员，不证明跨对象语义依赖已找全。
