# 章节篇幅与编辑体验复核 · 2026-10-02

本轮依据作者反馈“章节内容短、章节 UI 不够简洁”实施。Codex / Cursor 产品视角由协作代理承担，真实桌面操作及真实模型验收由主代理完成；不是厂商员工参与的评审。

当前章节入口以 [2026-10-07 章节操作评审](../../design-reviews/2026-10-07-contextual-chapter-editing.md) 为准：手动工具总入口、技术事实输入、作者侧范围预览、重复分析/讨论入口与生成记录复本已删除。场景操作在正文旁菜单，章节关联在页头设置；保存、发布、正式事实确认和版本对照保留。下文相关旧方案为当时的实施记录。

## 变更概览

- 默认首次起草约 2500 字完整中文章节，为软目标；作者明确的语言、篇幅、计数单位和局部修改要求优先。已有正文不自动扩写，已有标题默认保留。
- 中央保留标题、正文、章节切换及保存 / 发布；场景管理、章节设置和版本对照默认收起。正文保存状态与设定 / 检查未保存状态分别表达。
- AI 写作指令进入右侧唯一对话输入框。准备写作不会自动执行，已有输入不会被默认提示覆盖。
- 当前正文预检和自动保存沿用版本 / 来源 / CAS / 锁定场景门禁；作品或章节切换、编辑器卸载后，迟到结果失效。
- 写作和知识分析期间可以输入下一条指令，发送与 Enter 禁止执行，停止仍可用；普通讨论按实际 advisory 授权追加。草稿不会自动发送。

## 实测根因与修复

1. 初次长章曾因 provider reasoning 单项 11444 conservative tokens 失败。低推理强度后写出完整长章，但后续短章分析仍出现 10163-token reasoning；`low` 无法保证不超限。Flash 当前 Responses 连接改为 `reasoningEffort: none`，显式请求仍优先，并重新资格验证。没有截断或改写推理 / 模型历史，没有提高 10K 守卫。
2. 继续创作时，同一正文同时出现在 `content.body` 与 `sceneGroups`，连同知识和方法说明，两个真实工具项分别达 10469 / 10362 tokens。所有 read_context 用途仅在能按既定分隔符精确重建全文时省略重复 body，并声明 `textRepresentation`；组身份、顺序、锁、标题和版本来源保持完整。非等价正文保留。
3. Runtime 在字节预算之外，复用引擎原有 tokenizer，计算包含转义、MCP 包装及 160 字节调用身份的模型项，任务绑定的上下文及 Writer 预览目标为 9K，留出 1K 包装余量。可选材料省略标记 coverage；必需来源超限返回简短错误，由同一冻结范围分页补读，不冒称全文已读。

4. 同一长章最终分析成功，但工具仅返回摘录有歧义 / 未找到，未标具体数组项，导致 14 次候选提交尝试。追加独立切片 D 已在现有校验错误中标出有界原始数组索引及证据字段，保持原子持久化与原文锚点规则，不输出原文或猜测位置。HTTP 回归已验证失败零业务产物、修正后同批成功；实际模型重试次数改善尚未复验。

提供者接口对推理强度的说明见 [DeepSeek Responses 文档](https://api-docs.deepseek.com/api/create-response/)。这次配置调整的效果以实际资格与创作验收为准，不保证所有模型输出都不会超限或文学质量必然提高。

## 后续章节 UI 评审：连续文档（2026-10-02）

作者再次反馈章节界面不够好。本次仅调整章节呈现和阅读位置；不扩大模型、持久化或发布协议范围。

### 根因与目标

此前即使收起高级功能，主编辑区仍是多层卡片里的固定高度输入框：正文和页面分别滚动、重复标题和散落按钮争夺注意力，底部浮动保存条较重。只去边框不足以解决阅读体验。

目标为单一连续文档、紧凑章节导航与动作、轻量保存状态。正文按内容自动增高，章节由主面板统一滚动；保持正文节点、选区、当前章隔离、场景锁、保存与发布门禁。验收包括长正文尾行可达、不同宽度和主题、切章和版本对照后的阅读位置，以及真实 App 样式加载顺序。

### PRE 与实际实施

五角色 PRE 均批准上述有条件方案：架构由主代理承担；技术 A/Cursor 视角关注相对阅读位置与监听生命周期；技术 B/Codex 视角要求真实主面板夹具和生产样式顺序；产品与 UX 要求消除双重滚动，而不是仅作装饰调整。

- 移除章节视图重复页头，章标题成为唯一主标题。章节切换固定在文档顶部，对话写作、新建与导出合并为紧凑动作组。
- 正文采用内容自适应高度与统一纸面，正文只滚动外层。单场景重复标签视觉隐藏，辅助功能名称保留。
- 保存状态与保存/发布按钮改为平坦底栏。场景管理、版本对照与章节设置仍可按需展开。
- 阅读书签从 textarea 内部偏移改为场景相对主面板的偏移；纯阅读和锁定场景也可记录，不要求先点击正文。版本对照滚动不覆盖正文书签，章节切换清理监听，缓存仍限制 128 章。
- 实机发现通用主题 CSS 覆盖局部纸面和按钮样式，已修正作用范围及优先级。UX 发现键盘焦点线过淡，已使用明确蓝色焦点线。

## 全页面 UI 统一优化（2026-10-02）

### PRE、范围与根因

本轮对应作者“对各个页面都做一次 UI 优化”。五角色 PRE 以统一内容层级、减少装饰卡片、保证窄窗口操作可达和准确反馈为前提批准。架构由主代理承担；技术 A/Cursor 视角负责账户与交互可靠性；技术 B/Codex 视角负责真实 App 夹具；产品及 UX 负责全页语义和视觉复核。这些是代理评审视角，不代表外部公司的实际员工参与。

问题不只在颜色：不同页面重复标题与卡片层级、表单不随实际内容区变窄、账户页没有独立滚动边界，以及版本页把当前章对照混同历史记录。统一页面样式抽出至 page-layout.css；账户样式、故事资料视图、新建作品对话框及版本读取各自独立，不继续扩张 App 的渲染实现。建议审阅按三个完整切片：公共页面与资料视图、账户及新建作品、版本读取状态隔离。原工作树有大量先前修改，本轮未重置或提交这些修改。

### 实际变化

- 覆盖总览、章节、角色、场景、创作简报、长篇大纲、近章规划、情节线、时间线、世界与规则、版本与变更、用户设置，以及登录、创建作者和新建作品弹窗。页面统一标题、内容宽度、间距、焦点线和明暗主题；章节保留已有连续文档。
