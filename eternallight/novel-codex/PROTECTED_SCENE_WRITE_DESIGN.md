# 作者保护场景与统一候选写入

2026-09-28 · S3/S4/S5、C03/C05 · 实施者自检，无独立专家评审。

## 问题与目标

`selectedScenes` 写入会逐场景保留未选内容，但 `wholeChapter` 不执行场景锁校验，
`throughScene` 只保留窗口外的内容。对象整体锁已有保存事务检查，不能代替正文内
作者锁定场景的保护。整章生成不应获得修改受保护结尾的额外权限。

## 实现契约

- 全部 `generateChapter` 保存先执行统一场景保护校验，再执行各自范围校验。
- 保护依据与任务实际创作依据相同：使用现有冻结输入、作者工作版本及任务检查点
  选择规则；不能从别的最新候选拼接锁状态。原来源过期仍由现有水位门禁拒绝。
- 原稿 `locked=true` 的场景必须原样保留在原位置，禁止改正文、元信息、身份、
  解锁、删除或移位。修改未锁场景仍可直接产生候选，不新增逐步审批。
- 模型不能自行把未锁或新场景设为锁定。保护状态由作者控制，不由生成内容授予。
- 场景 ID 必须唯一；聚合正文必须等于场景正文按既有分隔符拼接，不能在另一份
  `body` 中偷偷改写受保护内容。检查失败与候选、回执、任务输出全部同事务回滚。
- 前缀写作由宿主合并未披露后缀时，也必须使用同一工作依据，而不是最新候选；
  模型只收到原范围内的响应，完整正文仅在宿主与数据库中处理。
- 此约束只新增到 Agent 正文写入；不改变作者编辑入口、正式采纳或锁定管理。
  不增加新状态机、schema、兼容路径或上游 Codex 修改。

## 验证

通过实际 HTTP/SQLite 保存验证：整章和前缀任务改写、解锁、移位、删除锁定
场景均失败且作品状态不变；合法修改未锁场景可保存并继续检查点；模型新建锁
失败；选定历史工作稿与最新候选分歧时按作者选择执行。已有局部改稿继续回归。

## 边界

场景保护不是完整作者许可闭包，也不证明“只分析不修改”、跨章授权或文学质量。
对象范围、自然语言保护要求的结构化、真实模型联合旅程和双平台仍需继续验证。

## 实施结果

已将保护校验接入统一 Agent 正文写入；前缀合并和后缀一致性复核共用领域层的
工作依据解析，删除宿主和范围校验中读取最新候选的重复逻辑。模型执行说明
同步约定显式 `locked=false`，连续生成 fixture 同步当前契约，不增加兼容分支。

最终定向验证：`scoped_revision_tests` 4 项、`authoring_run_tests` 7 项（含三章
及后续章节）、`generation_replan_tests` 1 项、`context_scope_tests` 11 项、
`working_source_tests` 2 项、核心 `tasks_tests` 11 项和桌面交接/IPC 41 项通过。
严格 workspace Clippy 与 JavaScript 语法检查通过。核心库 157 项亦在初版统一
保护校验加入后通过；随后工作依据合并调整以以上定向回归验证。不宣称整个
工程测试、真实供应商、作者质量或跨平台验收已完成。
