# 持续创作：生成检查点重规划

2026-09-27 · C05 分阶段实施；实施者自检，非独立专家评审。

## 目标与边界

恢复只用于输入仍有效的原步骤。新增作者专用 replan 操作，在已暂停或
因来源变化阻断的运行上重新确认依据，创建新的意图代次及 stepToken；
不重开终态 Attempt，不重置调用、重试、修稿预算或截止时间。

2026-09-29 补强执行层截止时间：GenerationRun 的 `deadlineAt` 不仅在 Rust 认领
下一步骤时检查，也在桌面生产任务运行器中限制每次 Agent Engine 执行租约和
模型请求预算的时长。作者重规划后仍使用原截止时间；若准备阶段已经过期，
不签发新的模型租约。定向测试覆盖剩余时间递减、30 分钟单任务上限、生产
运行器的租约/预算截止时间和过期拒绝。随后新增的运行总账按引擎终态回执
登记供应商请求/token 用量；`usedTaskAttempts` 仍只统计 Runtime 认领的任务。
这两者不是实际供应商账单，运行中取消、进程恢复与真实费用门槛尚未整体验收。

规划重建覆盖 Brief/Outline/RollingPlan/MaterializeChapter 且无当前章节的
检查点；已有章节须完整连续、全部按当前版本完成建模，数量等于已完成章数。
当前章重写另以 `currentChapter` 起点处理未完成章，保留该章身份和规划绑定，
前文须完成建模。两类路径均拒绝仍在运行的旧尝试，部分章节不会计为完成，
也不通过删除内容来凑齐条件。

作者提交 expectedVersion、expectedProjectRevision、当前 sourceDigest 和
restartFrom（brief / outline / rollingPlan / currentChapter）及补充 instruction。版本/摘要必须由新读取的作品依据取得；这不是模型
自行换水位。捕获前后水位、原阶段、版本、时间及新意图为有界历史记录。
更新复用原有 source-guard + run CAS 写事务；检测跨连接修改时整体拒绝。
消费预算、目标章数和完成章数保持不变，剩余预算须覆盖剩余必需步骤。

阶段由作者明确选择；服务检查前置产物存在，禁止跳过缺失简报或大纲。
存在产物不等于修改后仍然适用，因此不能仅凭存在性自动跳过大纲重建；
作者选择保留上层内容后才从较晚阶段继续，选择及前后依据一并记录。
旧意图继续有效，instruction 是补充而非隐式覆盖。冲突要求仍须作者明确，
不能在本接口里猜测废除哪些原要求。新规划只产生候选，不采用旧/新正文。

## 实施顺序

1. Rust authoring 服务、作者 HTTP 契约与重规划历史，集成测试覆盖正常、
   过期、预算、终态及活动任务拒绝，确认原运行失败不被重置。
2. 桌面端已接预览与明确确认，绑定同一次读取的来源摘要；UI/对话全旅程
   尚未联合认证，不宣称作者已经能从任意中断点无缝继续。
3. 后续处理运行中断/部分产物的核对、关联后继任务和依赖失效闭包。

无 schema 升级/回填/兼容读取，无新 Agent 调度器、模型通道或上游内核改动。
当前类型直接增加必填 replans 数组；不为旧运行状态添加默认反序列化。
测试使用临时项目，不删除用户数据；整体验收仍受 S0–S5 与持续创作计划约束。

## 当前接口

作者调用 `POST /api/projects/{projectId}/generation-runs/{runId}/replan`：

```json
{
  "expectedVersion": 4,
  "expectedProjectRevision": 0,
  "expectedSourceDigest": "同一次预览读取的作品来源摘要",
  "restartFrom": "outline",
  "instruction": "按最新藏信设定重做大纲，再继续本次创作"
}
```

`restartFrom` 选择 brief 时重建简报及后续内容；outline 保留当前简报、
重建大纲及后续规划；rollingPlan 保留当前简报和大纲、重建近章规划。
`currentChapter` 保留当前章身份和规划绑定，从作者当前稿重新执行正文步骤。
四者均沿原运行的剩余章节目标推进，不能借此增加章数或预算。
返回更新后的 GenerationRun，其 `replans` 包含来源、快照、阶段与意图代次
的前后关联。调用 `/next` 使用新 stepToken 和 intentGeneration 创建下一步。

来源或运行版本变化、活动任务未核对、终态、超时、缺失前置产物和剩余预算
不足均拒绝，拒绝时不修改运行。作者应重新读取当前状态并处理对应原因。
候选模型凭据无法调用此入口。桌面端展示保留/重建范围和剩余预算，
提交原预览版本，不在提交时刷新版本并替作者确认新的依据。

## 桌面确认流程

### 本轮联合旅程延伸方案（实施者自检，非独立评审）

真实父工作区接入发现并修复三个当前契约问题：旧 Writer 预览类型与 Rust
Context Pack 不匹配，`sourceExcerpts.find` 会令章节页崩溃；同作品刷新会卸载
确认组件并清除已提交回执；重规划持久提交后的父刷新异常没有捕获。删除
旧预览字段，Renderer 直接消费当前 Context Pack，核对作品、版本、章节和
请求范围；将作者预览与任务冻结依据明确区分，覆盖与语义完整性分别展示。
来源只按实际 `accepted` / `candidate` 权威显示，不用模拟的“选定工作稿”
字段宣称已使用作者工作基线。独立章节提示改以是否存在绑定判断，不能因
绑定的公开投影未返回就误报独立章节。完整工作基线与任务冻结预览的等价性
仍需专门建设和验证，本轮不据此声明已实现。

同作品刷新保留组件生命周期；仅在更换作品时清理。未保存编辑仍以原基线
检测冲突，干净编辑器按新版本重载。父重规划成功提示与刷新错误分别处理，
迟到错误带编辑器身份门禁；刷新失败不回滚运行，也不重复提交。真实
CreativeWorkspaceView + preload + Native HTTP 旅程已覆盖未保存改稿禁用
确认、通过原全局 discard 回调放弃临时本地输入、成功刷新保留关联回执、
简报显示阻断原因、提交成功后注入父刷新故障、重新开窗读取运行中状态，
并继续沿既有建模/提取/评估/检查/下一章规划及实际 Runtime 重启路径。
确认快照覆盖阻断、刷新失败和当前预览的范围/来源/未知语义状态。

本轮联合回归共 8 项通过、0 跳过，包含生产父工作区、重规划和重新关联
组件、IPC/preload 及 Runtime 重启联合用例。3 份联合渲染快照已审阅；
独立截取当前预览后修正说明段落连行问题，修正后联合用例与生产构建再次
通过、截图已检查。构建仍提示现有约 4.1 MB 主包，不视为本轮消除。
本轮未修改 Rust，未重复宣称新的模型、文学效果或 Windows 验收。
迟到刷新错误的编辑器门禁已实现，但本轮故障注入只覆盖即时刷新失败，
不把跨页面延迟故障当作已验证。

父工作区接入方案：联合测试改为挂载生产 `CreativeWorkspaceView`，通过真实
作品读取构造其父输入，保留章节/简报页面切换；确认、编辑锁、状态读取和
重规划由原控制器处理。fixture 仍替换顶层导航壳、读取 IPC 注册与模型产物，
不把它说成完整 App/Codex 验收。运行阻断原因采用作者可理解的章纲变更提示。
重规划已持久提交后的父刷新错误必须捕获，显示“已保存但刷新失败”，不重试
写操作；切换页面/作品后的迟到刷新失败不得污染新编辑器。对此新增真实
Runtime 故障注入和 UI 状态快照，既有未保存编辑与执行锁仍适用。

不增加执行器或状态权威。延伸同一个桌面关联/重规划测试：新 Writer 保存
候选后必须完成原 Task，并沿原 GenerationRun 推进；当前正文未建模时，

不为通过测试绕过来源、权限、任务完成或建模检查。

### 章纲绑定替换的桌面方案

章节页仅在当前规划版本不同于本章绑定时提供“预览章纲调整”。预览读取
当前作品工作区并冻结旧绑定、当前正文和新规划版本；展示两份写作指引、
保留正文片段与完整来源 ID，只允许同章号、唯一且未被其他章节占用的章纲。
作者勾选确认保留正文并撤销旧任务后提交同一预览，不在提交时重新获取依据。
提交期间锁住编辑与其他写操作。失败撤销预览，必须显式重新读取；切换作品
或章节不消费迟到结果。成功显示来源回执，提醒去创作简报重新预览当前章
运行；不会代替作者点击重规划/继续或调用模型。已提交但刷新失败单独提示，
不能把成功变更报告为失败。复用现有受信 IPC 与作者传输，无第二写入路径。

### 联合链路补强：立即阻断过期运行

链路检查发现重新关联虽撤销旧任务，GenerationRun 却要等 `/next` 才反映
过期状态，桌面可能仍显示运行中。绑定替换事务内同步核对唯一的未结束运行：
运行中转 blocked；已暂停保持 paused；已阻断保持 blocked。三者均记录
`chapter_plan_rebound` 原因并推进运行版本，工作任务列表投影同步更新。
预算、截止时间、来源摘要、阶段、意图与旧任务指针不变；不能因关联变更
重新打开终态或自动获取新来源。无运行时仍可完成关联；多个开放运行、版本
或归属损坏、投影缺失使整个关联事务失败。幂等重放不再次移动运行版本。
联合验证使用生产组件/preload/受信注册器、真实 Native HTTP 与临时 SQLite；
fixture main 替换应用生命周期、读取 IPC 注册和模型产物；已包含生产
CreativeWorkspaceView 控制器，仍不包含顶层 App、Codex/MCP 或真实供应商，
因此不能声明完整产品验收。

新增 `rebind-runtime-integration.test.mjs` 已验证：通过桌面明确确认后立即

旧任务 ID 纳入历史，调用预算与截止时间不变。关闭并重新打开窗口后读取

### 规划重新关联的前置完整性

检查发现现有独立章节 `associate-plan` 入口没有在领域层核验正式章纲成员和
章号；UI 下拉筛选不能承担此约束。本轮先补事务内验证：指定章纲 ID 必须
唯一存在于当前正式规划中、章号必须等于目标章节；目标章节和该章纲均不得
已有绑定。拒绝请求不推进作品版本、不写回执或取消正在执行的任务；同一
成功请求按原幂等回执重放。该入口继续只做首次关联，不能冒充旧绑定替换。
重新关联需显式展示旧/新规划与正文来源并形成可追溯的作者决定。

### 显式替换已有章纲绑定（本轮实施）

新增作者专用 `chapters/rebind-plan`，与首次关联分开。作者必须提交同一次
读取的作品版本、旧规划版本/章纲 ID、当前正文版本、新规划版本/章纲 ID。
新规划必须是作品当前选中的工作规划（候选优先，否则正式版本），指定章纲
唯一且章号匹配，不得占用其他章节的绑定；当前正文须存在且未锁定。
所有条件在同一写事务中复核，任何冲突整体拒绝。确认只替换绑定，不修改
正文、不采用规划或正文、不触发模型。旧/新绑定、当前正文来源及结果版本
写入幂等回执，保留既有不可变版本，重复同一请求返回原决定。

关联变更推进作品版本并撤销旧任务写能力。之后作者须重新预览运行并明确
选择 `currentChapter`，不能直接恢复旧尝试。后续正文生成仍通过既有
Codex 引擎与建模流程执行。桌面确认界面与后端分别验证，后端完成不等于
UI 或真实模型联合旅程已通过。

### 作者修改中断章节后的重新绑定

增加 `currentChapter` 重规划起点：只允许当前运行的未完成章，原章身份与
有效规划绑定保留；此前章节目录须连续且所有前文知识对应当前正文，当前章
必须有可编辑工作稿。当前规划头若已改变，要求先处理规划绑定，不猜测替换。
旧活动引用只能指向已完成、失败或取消的尝试，运行中的请求不得被绕开。
作者提交当前来源摘要及补充要求，记录前一尝试 ID，新意图代次从 Draft
重新执行，旧尝试保持终态。重新建模、提取承诺及评估仍必须执行；重试计数、
修稿计数、调用预算和截止时间不重置。旧评估决定仅属于旧版本，清除当前
评估指针与临时修稿提示，历史决定保留。此入口不采用正文或自动确认事实。

### 部分候选的同一步恢复（已实现）

复用作者 retry-failed-task：对失败/取消尝试，允许已保存的候选检查点作为
新尝试的输入，前提是冻结输入核验通过：目标头仍为该任务最后保存的版本，
其他对象、作品版本和知识依据未被外部改动。先捕获来源摘要，再核验，最后
在写事务中复核同一摘要及运行版本，避免核验后发生修改却被重试悄悄接受。
旧尝试及其输出不改写，新 Attempt 仍受原重试上限、模型预算与截止时间限制。
恢复保持原阶段，不将部分候选当完成，不跳过建模/检查；真正完成仍走正常
任务完成契约。作者另行修改候选或其他输入时继续拒绝，后续需显式核对，
不能冒用本路径扩大授权。沿用重试按钮，明确显示“从已保存候选继续”。
