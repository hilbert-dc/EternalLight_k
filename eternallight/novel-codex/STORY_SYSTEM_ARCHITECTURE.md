## 1. 产品目标与设计决策

Writer 的规划输入以 `ChapterBinding.planRevisionId/chapterPlanId` 为唯一依据，
不按章号从最新规划头隐式挑选。工作区公开投影、任务上下文和自动 Draft
复用同一领域读取；绑定的 POV/故事时间随任务冻结，认领事务同时核验整章
范围与阅读位置。非法位置在生成计划写入、关联和建章时拒绝，损坏来源停止
读取而不回退。参见 [绑定章纲与执行依据](BOUND_WRITER_CONTEXT_DESIGN.md)；
这不改变正文工作基线政策，也不表示真实模型、作者质量或 S3 全部验收。

对话派生的章节改稿也沿同一绑定：根任务登记候选时在领域写事务内补齐并
冻结规划 POV/故事时间，显式不一致拒绝；子 Writer 必须认领精确目标，
`wholeChapter` 和 `selectedScenes` 均受同一 Context Pack 披露约束。
详见 [对话派生 Writer 绑定](CONVERSATION_WRITER_BINDING_DESIGN.md)。

S1 新增来源绑定属性 state，与观察 assertion、事件、关系和人物认知分型。有限 stateSchema 用于候选值/区间校验与可复核冲突，其模型声明本身不是世界规则 DSL 或作者批准的全局谓词规则。当前/历史投影、实体身份、通用端点索引、世界演进和审阅均复用原链路；single 不以最新来源覆盖，multiple 成员并存，未知开始时间明确影响覆盖。stateExpired 的 after=null 表示有源主张不再适用，不推导反值。即使作者确认，属性状态也不能作为无时间限制的通用 Context Fact 注入；覆盖报告提示 `typedStateFacts`，模型通过原 `query_story` 的状态步骤按时间读取。详见 [属性状态实现契约](STATE_PROPERTY_DESIGN.md)。

正式属性规则现由独立 `artifact-propertyRules` 的作者候选、审阅采用和撤销管理，不借用事实确认字段。无位置限制的 Author/World 查询以当前 accepted head 和正式回执核对权威，历史查询以快照祖先链还原规则；候选不能改变投影。输出保留原声明，增加有效 schema、规则修订及适用性评估；不符合类型、带未解释例外时有效 schema 为空且覆盖不足，不强制转换或静默推断。有限 Reader/Character/Writer 视角不读取此全局注册表。详见 [作者属性规则契约](PROPERTY_RULES_DESIGN.md)；作者规则 UI 已支持可选编辑、审阅采用和账本撤销，未保存输入受统一导航/关闭保护；候选、结构规则和属性事实明确分离。见 [规则工作区](PROPERTY_RULES_UI_DESIGN.md)。对话规则提案已沿同一任务、Codex/MCP 与候选/恢复账本链提交，基线修订冻结，Context 只给描述，根任务经只读 UTF-8 JSON 页按摘要和连续范围重组完整规则（见 [有界读取](PROPERTY_RULE_INPUT_PAGING_DESIGN.md)），模型来源不伪装作者来源，只有作者审阅采用才生效；见 [对话式规则提案](PROPERTY_RULE_PROPOSAL_DESIGN.md)。完整条件解释、事件效果推演及整体文学验收仍需继续。

S5 展示切片已合并六项诊断为默认折叠入口，不改变 Rust 校验任务的执行权威。折叠保留后台状态和异常摘要；跨作品迟到结果、同帧重复操作和刷新读取并发已隔离。成功读取不隐藏一次失败操作，只读恢复不发起新校验。正文和章节建模屏障仍直接可见，不将局部索引核验称为故事全局或文学质量通过。构建及 12 项 UI 测试通过，详见 [诊断分层契约与验收](WORKSPACE_DIAGNOSTICS_DESIGN.md)；整体完成条件保持不变。

S3 规划效果要求显式 `commitmentRefs`（未关联时为空），每效果最多四项、全计划最多六十四项。根任务在原候选事务核验当前修订、来源及各目标章节前文范围。sourcePlanRefs/chapterPlanId 固定原引用，场景 Critic 的 boundCommitmentInputs 只提供明确绑定的冻结标准，不扩大任意正文查询或 Writer 权限。逐效果 commitmentAssessments 必须完整覆盖引用，推进/兑现/矛盾必须有该效果的场景内事件证据；失效引用只能报告不足。矛盾/不足参与场景汇总并进入原作者接受/修稿门禁，正式承诺状态不自动变化。来源改变使旧评估 stale，原内容不被覆盖。真实供应商、文学语义及全局验收仍未通过，详见 [承诺推进反馈链](COMMITMENT_PROGRESS_FEEDBACK_DESIGN.md)。

**对话驱动、可控迭代的持续创作系统。** 作者通过对话提出目标、调整内容和作出创作决定，系统在明确许可内承担生成、分析、修订和接续。作者不需要先手写大纲、逐个维护 Scene/Beat、填写知识表或每次点击“生成下一场”；已有作品和局部问题同样是一等入口，手工编辑是可选补充。

系统按当前作品状态与作者目标选择构思、检索、规划、生成、知识提取、检查或重规划，不强制每次执行全部阶段；底层持续维护可追溯、有关联、支持全局检索与推理的作品知识。自动生成不等于无限后台执行或自动发布：运行范围、预算、受保护内容和停止条件必须明确。

两层是产品责任划分，不是两个微服务：

- **对话创作层**：理解作者目标，自动组织并推进生成，接收作者的中途调整，解释依据与影响，展示正文和修改，管理运行及正式采纳授权。
- **故事知识与推理层**：保存作品原始信息，构建事实、关系、时间、认知及叙事结构，检索证据，分析冲突与修改影响，维护一致的作品版本。

主要决策：

1. 本地优先、模块化单体；Electron 客户端内配套本机领域进程，不新增必须部署的云端业务服务。
2. 独立 Rust agent-engine 提供通用执行能力；小说领域语义不进入 agent-engine 或上游 codex-rs。
3. 小说领域核心由独立 Rust Story Core 实现；原 Python Creative Runtime 已完成生产迁移并删除。领域能力只有 SQLite/Rust 一套权威，不进入通用 agent-engine/codex-rs。
4. SQLite 保存权威领域记录；全文、图邻接、状态投影、语义索引均可重建。第一版不引入独立图数据库、消息中间件或通用规则 DSL。
5. 原文、作者决定与结构化解释各有明确权威范围；没有一个模型输出能自动覆盖其余来源。
6. 先建立正确的知识、版本与提交闭环，再扩大语义召回、多 Agent 并行和文学评估能力。
7. 测试阶段直接调整当前 schema、API、fixture 与所有调用方，不建设旧数据升级、旧字段兼容或双轨运行。实际删除本地作品前仍须明确确认精确目标，不把测试阶段规则理解成任意删除授权。
8. 区分“系统持续推进的工作稿”与“作者已确认的版本”。工作稿可在一次明确授权的范围内自动保存和接续，不逐场景等待作者采用；自动生成不能覆盖已确认/锁定内容或伪装为作者确认。
9. 模型随创作持续增量更新，而非创作前一次建完；即时保存与异步语义理解分离。数据内容、关系和解释可以演进，身份、来源、版本、权限与事务不变量保持稳定。

### 1.1 “信息完备”的可验收含义

完整保留已纳入作品的原始正文、作者指令及其版本；结构化记录能追溯来源；记录已提取范围、未处理范围、冲突和未知。**不承诺自动理解作品中的所有隐含含义，也不承诺有限检索能证明全书不存在某件事。**

对话原文是创作意图的来源，不自动成为 Canon。保留的是用户可见内容、任务结果与证据，不要求保存模型私有思维过程。

### 1.2 核心用户旅程

| “把师父从叛徒改成卧底” | 澄清或确认意图，查依赖，推演替代解释 | 影响报告与跨章节候选变更 |
| “如果师父没有死呢？” | 建立假设覆盖层，不污染正式状态 | 反事实分析或试写分支 |
| “采用这个版本；撤销刚才的修改” | 将明确目标绑定到具体变更摘要 | 可追溯提交或补偿提交 |
| “第二章太慢，让女主更主动，然后继续” | 更新约束，定位受影响内容，生成修订并重排后续任务 | 修订后的工作稿与下一段生成，不把旧任务结果覆盖回来 |

### 1.3 对话驱动的持续创作主流程

```text
创意 / 大纲 / 已有正文 / 局部问题
  → 对话意图与当前作品依据 → 范围、许可与完成标准
  → 按依赖选择：回答 / 分析 / 补充规划 / 生成 / 修订
  → 领域校验 → 执行 → 可读候选与检查点
  → 检查、更新建模与影响 → 解释交付结果
  → 在剩余许可内继续，或等待必要的作者决定
                       ↑
作者调整 → 区分补充/替代/冲突 → 失效隔离与重新规划
```

起点可以只有一句创意。非关键缺项由系统作出标注清楚、可撤回的假设，不连续追问大量表单。会显著改变创作方向、涉及受保护内容或超出运行授权的决定才停下确认。作者没有提供生成数量时，先展示明确的本次范围和预算，不把“写一部小说”解释为无上限调用。

全书生成是可暂停、可恢复的多次滚动运行，不是一次请求生成整本，也不要求作者为每个场景重新发指令。写作模式支持明确请求的直接创作，不强迫所有用户先走人工大纲审批。

Brief/Outline/Plan/Scene/Beat 是可复用的表达与执行能力，不是所有入口的强制前置表单。
只在任务确实需要、范围允许且已有内容不足时补充；分析任务可以只交付有依据的回答。
系统假设单列来源、适用范围及替换状态，不伪装为作者明确要求，也不因反复使用自动升为事实。

验收重点是“作者仅用对话即可得到、调整并可靠接续真实内容”，而不只是生成数量或“系统拥有大纲、Canon 和 Scene 表”。

```text
                    │                       │

          ├── 独立 Rust agent-engine         │
          │      └── 私有 Codex App Server   │
          │            └── candidate MCP ────┤
          ▼                                 ▼

  Knowledge │ Timeline/State │ Narrative │ Query/Context
  Reasoning │ Impact        │ Proposals │ Commit/Recovery
                    │
                    ▼

                    │ 同事务 outbox
                    ▼

```

领域模块不直接调用具体供应商 SDK；需要语言模型判断时，产生有输入快照与输出 schema 的 AnalysisTask，由已有 Host/engine 执行，结果经领域校验后成为候选。通用引擎不依赖小说模块。

多 Agent 是任务的可选执行方式，不是数据一致性的前提。所有子任务绑定同一个输入快照和权限范围，只提交候选；父任务汇总，唯一 Commit Service 决定是否可提交。单 Agent 也必须能够完成同一领域工作流。

自动生成循环属于小说领域编排，不重写通用引擎的工具调用、子 Agent 调度或取消机制。领域编排决定下一章写什么，引擎负责执行本次任务；两者的预算、取消与终态通过现有任务接口衔接。

## 4. 数据权威与模型

底层不只是保存已有故事的知识库，而是支持自动生成和持续修订的创作模型。核心组成是：**创作意图 + 故事知识 + 叙事设计 + 版本化工作稿 + 依赖与反馈**。全局检索、状态计算与推理建立在这些数据之上，不用一个通用知识图谱替代所有领域结构。

三类模型共享对象身份、来源和快照，但各自拥有明确语义，不是三个独立数据库：

| 模型 | 主要数据 | 责任 |
| --- | --- | --- |
| 故事世界模型 | 实体、事实、关系、事件、时间、人物认知 | 解释世界中发生什么，以及内部是否成立 |
| 叙事设计模型 | 主题、人物弧线、冲突、场景目标、伏笔、披露顺序与叙事承诺 | 决定故事怎样讲，为什么安排这一段 |
| 创作演进模型 | 作者意图、计划修订、工作稿、反馈、修改依赖与采纳记录 | 解释为什么这样写、实际写成什么，以及下一步怎样调整 |

例如，“师父是卧底”是世界命题，“第十章揭露身份”是叙事安排，“作者要求提前到第六章”是创作意图变化。新指令首先影响披露计划与依赖内容，不应自动改写师父的世界身份。

### 4.1 权威范围

| 信息 | 权威记录 | 不能做什么 |
| --- | --- | --- |
| 作者意图与决定 | CreativeIntentRevision 表达要求，AuthorDecision 记录明确决定，两者关联原始消息与对象 | 不把疑问、引用、假设自动升级为决定；意图不等同于执行授权 |
| 实际作品文本 | DocumentRevision + BlockRevision | 不让抽取结果反向覆盖原文 |
| 系统当前生成版本 | WorkingHead + GenerationCheckpoint，引用不可变候选清单 | 不冒充作者已确认版本；不把推测知识混入正式 Canon |
| 已确定世界设定 | 已接受的 AssertionRevision 与作者确认记录 | 不以模型置信度替代作者确认 |
| 计划 | NarrativeNodeRevision、预期变化 | 不当作已经发生的事件 |
| 正文中的事件与状态变化 | 已确认 EventRevision + EvidenceAnchor | 不确认无证据的模型补全 |
| 检索与推理结果 | QueryReport / ReasoningReport | 不自动写回正式事实 |
| 缓存与投影 | 带版本和算法标识的派生记录 | 不成为第二套权威来源 |

作者设定与正文矛盾时保留双方，生成 Conflict；明确选择修改正文、修改设定或标记为有意的不可靠叙述后，才能关闭该冲突。

### 4.2 身份、修订与快照

- `projectId`：租户/作品隔离边界。
- `branchId`：主线或试写线；主线也是显式分支。
- `objectId`：人物、场景、文本块等稳定身份，不依赖名称、章节序号或行号。
- `revisionId`：不可变内容版本；名称、排序和内容改变产生新修订。
- `commitId`：已接受的一组原子变化；第一版每次提交一个父提交，分支合并以目标分支的新提案提交，不实现通用 Git 式合并引擎。
- `snapshotId`：固定 commit 与对象版本清单；候选任务可在其上叠加显式的不可变候选清单。摘要仅用于完整性，不能代替授权。

数据库保存对象注册表与不可变修订，`snapshot_members` 记录快照中可见的对象版本。初版可物化版本清单，后续用共享清单优化存储，但不得改变查询语义。任务运行时不能隐式读取“最新版本”。

### 4.3 领域实体

| 实体 | 必需内容 |
| --- | --- |
| CreativeProject / CreativeBrief | 受众、类型、创作目标、主题、语言风格、读者体验承诺 |
| CreativeIntentRevision | 要求、适用对象与时间范围、约束强度、来源、替代/补充/冲突关系及判断依据 |
| SourceRecord / EvidenceAnchor | 正文或消息版本、稳定块 ID、块内范围、引用摘要；导入来源与提取批次 |
| Entity / EntityAlias | 人物、组织、地点、物品等身份；别名适用范围；待消歧候选 |
| AssertionRevision | 主体、谓词、类型化值/对象、肯定或否定、适用时间、来源、确认状态 |
| EpistemicAttitude | 谁对哪个命题持已知/相信/怀疑/否认等态度，获得时间与证据 |
| RelationRevision | 有方向的端点、关系类型、有效区间、情境、支持证据 |
| StoryEventRevision | 参与者、事件类型、故事时间区间、前提、已确认变化及正文证据 |
| NarrativeNodeRevision | 全书/卷/章/Scene/Beat、排序、目标、冲突、转折、预期效果与落实证据 |
| PlotThread / CharacterArc | 铺设与兑现、人物目标/信念/选择变化、相关场景、待履行承诺 |
| NarrativeCommitmentRevision | 伏笔/悬念/人物转变/关键场面等承诺的来源、兑现条件、预期窗口、落实证据 |
| SceneOutcomeAssessment | 绑定场景计划与正文版本的预期/实际变化比较、偏差、证据和后续处理 |
| DependencyEdge | supports / contradicts / requires / causes / reveals / realizes 等有向关系及来源 |
| WorldRule | 自然语言说明；可选受限结构化条件；例外、作用范围和规则版本 |
| Proposal / Review / Commit | 修改操作、来源快照、证据、检查结果、作者选择、授权与回执 |
| GenerationRun / GenerationCheckpoint | 生成目标、范围、预算、工作稿 head、指令代次、阶段、重试与暂停原因 |
| Projection / Coverage / Finding | 计算依据、处理水位、未知范围、冲突与检查结果 |

正文中的心理、语气与意象保留为文本与叙事注释，不强制数字化。人物信任可描述为“信任其能力，但怀疑其立场”；量表仅在作者选择的特定模型中使用。

`Fact` 使用类型化 Assertion 表达，不另建一套互相覆盖的事实系统。客观事实与人物态度分表；不将“人物确信”当成客观为真。读者层记录已披露信息与作者预期解读，不声称知道真实读者在想什么。

### 4.4 状态分离

以下维度不可共用一个 status：

- 生命周期：候选、已接受、已撤回；历史事实在旧快照仍可见。
- 证据关系：支持、反驳、无法确定；冲突命题可以并存。
- 认知态度：某人物知道/相信/怀疑某命题。
- 叙事落实：计划中的、已在正文落实的、偏离计划的。

初版采用开放世界语义：没有记录不等于否定；存在相互矛盾的证据不以“最后一条覆盖”消解。单值属性的排他性由明确 schema/规则规定，多值关系不能误用通用 latest-wins。

### 4.5 创作意图：持续有效的要求，不只是聊天摘要

```text
CreativeIntentRevision {
  objectId, revisionId, projectId, branchId, sourceMessageRefs[],
  instruction, scope: { targetRefs[], fromNarrativePosition?, untilCondition? },
  strength: preference | requirement | invariant,
  origin: authorExplicit | systemProposed,
  evaluationCriteria[], supplementsRefs[], supersedesRefs[], conflictsWithRefs[]
}
```

例如“让女主更加主动”需要表达是仅修订第二章，还是约束后续章节；判断依据可为“由她的选择触发关键行动”，而不是把人物档案的主动性数字调高。文学判断依据可以是自然语言，不强迫转成确定性测试。

意图修订不可变，当前快照选择生效版本。系统提出的默认风格/目标应标记为 systemProposed，不能升级为作者明确要求。新要求先判断是补充、替代还是冲突，不按消息时间简单覆盖全部旧要求；实质性歧义才澄清。`invariant` 也不能绕过授权，解锁或替换作者保护项须有对应 AuthorDecision。

每个 GenerationRun 的 intentRevision 代次引用当前生效意图清单的摘要及版本集合，不把多条独立要求压成一段不断覆盖的 prompt。源消息、意图解释、AuthorDecision 和 GenerationPermit 分别代表证据、语义、决定与执行许可，不能相互代替。

### 4.6 计划、工作稿与确认内容三个空间

三个空间是类型与可见性边界，不复制三套实体表：

- **计划空间**：拟发生事件、预期效果、人物弧线和结局方向。确认一个计划仍不意味着事件已发生。
- **工作稿空间**：当前已生成正文和有来源的候选知识，供许可范围内自动接续；保留 provisional 标识。
- **确认空间**：作者采纳的正文、设定和计划，各自仍保留其内容类型，不能因被确认就成为同一种“事实”。

查询必须显式区分 `realizedState` 与 `plannedEffects`。状态计算只纳入指定确认快照和工作稿清单中的有效事件；规划只能作为写作目标。工作稿与确认记录冲突时，不以覆盖层默默替换受保护事实，应产生偏差/冲突并决定修订或暂停。

### 4.7 Scene 的预期—实际反馈模型

Scene 沿用稳定身份与 NarrativeNodeRevision，不另建一套场景真相。其计划版本至少记录目标、输入状态引用、人物目标、阻力、代价、转折及 expectedEffects。正文输出通过场景 ID、正文版本与锚点关联实际事件。

`SceneOutcomeAssessment` 绑定 planRevisionId、draftRevisionId、inputSnapshotId、有效意图集合、actualEventRefs、证据、偏差和建议处理。actualEventRefs 引用已提取事件，不再复制一份可独立修改的实际状态。

偏差类型包括：未落实预期变化、额外变化、与约束矛盾、证据不足，以及有意的创作偏离。判断结果区分确定性检查与模型分析，后者始终是可质疑的解释。

处理流程：生成正文 → 提取有来源的候选事件 → 比较预期与实际 → 有限修复/调整未来计划/询问作者 → 保存检查点。不是所有偏差都必须修复：更好的创作发现可更新未锁定的未来规划，但不能违反硬约束或越过当前授权范围。

示例：计划“识破凶手”，正文只写“发现可疑线索”。下一章不得读取“已识破凶手”；系统选择补写当前场景或调整后章认知前提，并记录所选依据。正文或计划任一版本变化，旧 assessment 对新版本失效。

### 4.8 叙事承诺：让自动生成不仅不矛盾，还能推进故事

作者建立进展：提案到独立承诺的 Author-only 领域/HTTP/桌面契约已实现。读取报告返回 snapshotId/projectRevision，逐项建立绑定作者实际看到的报告与 CAS；长期 ID 稳定、来源不可变，报告替换不能覆盖已建立对象。章节页折叠面板显示来源、原文锚点和语义覆盖未知，建立候选不自动确认；明确确认和当前最新确认撤销沿现有 Review，不形成第二正式写入权威。回执丢失通过当前报告持久化身份核对，不重复建立；切换上下文按请求代次隔离。后续变更使旧确认不可直接撤销，UI 依据 undoAvailable 禁用并说明。结构化作者编辑现支持摘要、状态、标准、关系引用、目标章范围和原文锚点，接入现有工作区统一保存/放弃与离开保护；刷新保留输入，保存未知重放原请求，未来未起草章节可作为目标但不伪造正文证据。以下待办仍包括旧报告对象全局列表、完整对话调整、自动派发与体验验收。具体编辑契约见 COMMITMENT_EDITOR_DESIGN.md。

后续目录切片已实现全作品独立承诺的 Author-only 固定快照分页与桌面找回入口，不依赖当前章报告，打开时重读当前详情/控制信息；未生成提案批次不冒充独立对象。源失效对象仍可发现，但不能越过证据校验确认。列表每页最多 20 项，UI 内存保留最近 200 项并明确提示早期加载结果已收起，仍能继续遍历后续对象；尚未加载不冒充全作品完整。迟到读取隔离。此前仅 UI mock 证明未来章窗口可选，服务端只按正文取章号；现增加不可变快照章目录投影并补真实保存/历史位置回归，目录章不升级为正文证据。该进展见 COMMITMENT_CATALOG_DESIGN.md，不等于语义目录检索、完整对话调整、自动派发、双平台或文学验收。

执行进展：extractCommitments 已接通显式对话请求、持久化任务、来源冻结和根任务 MCP 提交，产物是独立于 commitment 的候选提案批次。当前查询协议因此覆盖九类模型任务；下文八类描述的是此前切片。源文不能在预算裁剪时消失，源修订变化阻断旧任务。逐项建立/更新长期承诺、自动创作循环派发和作者 UI 仍待完成；下文“自动抽取尚未实现”具体指这些自动化与作者体验，而非已完成的显式任务执行。详见 [承诺提案提取契约](COMMITMENT_EXTRACTION_DESIGN.md)。

当前 Rust 数据切片：每个承诺为独立 `commitment` 对象，复用不可变修订、候选/确认指针、main 快照、Review 与补偿撤销；Author-only 单对象 API 可保存和读取当前/历史版本。setup 与 fulfillment 必须引用同作品 draft 原文的 Unicode 锚点，保存及采纳复核当前源；部分/全部兑现必须有证据，放弃必须有作者理由。状态仍是作者可质疑的叙事判断，`literaryFulfillmentVerified=false`。稳定已写 chapterId 范围与开放窗口已支持，未写章/相对窗口、模型自动抽取、Writer 排序、对话调整、UI 和质量验收仍未实现；不以数据契约代替完整 S3。具体范围及测试见 [叙事承诺证据契约](NARRATIVE_COMMITMENT_DESIGN.md)。

后续任务读取切片已接通：`relevantCommitments` 从当前快照的来源有效承诺中按持久化 TaskQueryScope 投影，先过滤全部 setup/fulfillment 引用，再有限选择。非 POV 按 open/partial/closed 与稳定 ID 排序；受限任务隐藏未披露绑定的关联/窗口元数据，POV 暂不注入承诺。裁剪、来源与版本绑定纳入同一个 Context Pack 预算、覆盖及 contentHash。此排序仅是稳定工程基线，不是临近窗口/长期未推进/场景语义相关性的理想排序；自动抽取及完整披露证明仍待实现。

`NarrativeCommitmentRevision` 记录 kind（伏笔、悬念、人物转变、目标、关键场面）、sourceRefs、关联 PlotThread/CharacterArc、相关人物、setupEvidenceRefs、fulfillmentCriteria、targetWindow、fulfillmentEvidenceRefs 和取代/放弃原因。

预期窗口使用稳定章节/场景引用或相对顺序约束，可以开放或尚未确定，不强制从开篇就锁定兑现章节。状态为 open/partiallyFulfilled/fulfilled/abandoned；是否临近或超过窗口由当前顺序计算。状态改变须有证据或明确决定，模型不能仅凭“已完成”关闭伏笔。

PlotThread 组织情节线，CharacterArc 组织人物变化，Commitment 统一表达两者中需要推进或兑现的要求；兑现状态只由 Commitment 持有，避免重复维护。系统从正文推测“这像一个伏笔”时创建候选，不强迫作者兑现每一个描写细节。

上下文构建纳入当前场景有关、临近兑现窗口及长时间未推进的承诺；排序受意图和权限约束。有意留白、开放结局与悬念属于合法创作选择，不因未兑现自动判错或擅自补全。

### 4.9 生成依赖与执行信息的边界

依赖链覆盖：CreativeIntentRevision → 规划节点 → 场景计划 → 正文块版本 → 提取知识 → 后续场景；同时允许场景依赖世界事实与叙事承诺。边记录类型、端点版本、来源、建立方式（运行输入清单/作者指定/模型推断）和确认状态。

“本次生成读取过这条资料”是 input_dependency，不等价于“剧情因它而发生”的 causes；运行读取清单是可确定的来源依赖，文学因果通常需要分析。模型推测的依赖只能扩大待检查范围，不能自行证明必须重写。

例如删除收到密函的正文，需要重新核验由该片段支持的认知，再分析后续行动与伏笔；其他独立来源仍能支持同一认知时，不应直接删除它。受影响的派生物标记失效或需复核，正文修订仍走提案协议。

GenerationRun 的模型、预算、阶段、重试、暂停和检查点属于执行记录，不写进 Canon。模型更换、任务重试和应用重启不能自行改变故事事实；只有产生并接受相应内容修订才改变作品状态。

### 4.10 小说与数据模型：双向反馈，不是模板与填空

小说正文是作品的表达，模型是对表达、创作意图及其关联的结构化组织。模型不能完整替代节奏、语气、意象、隐喻和含混；也不能因为暂未提取某个细节就丢弃原文。

作品与操作模型、派生语义承担不同责任。章节与段落身份、版本、作者决定、写入范围、锁定、候选/采用、实际来源和保存回执，是可靠编辑所需结构；模型即使能读取全部正文，也不能代替这些可核验记录。人物状态、事件解释、动机、因果和主题是按任务形成的候选理解；建立更多实体和关系本身不是产品收益。

```text
原文 + 作者决定 + 当前目标 + 按需采用的资料
             ↓ 直接阅读、选择方法与必要分析
         生成/修订正文
             ↓ 当前任务需要时，有源候选提取
      事件、认知、关系与叙事反馈
             ↓ 保留不确定性与依赖，按权限处理
      可复用知识或需复查的问题
```

这不是每次写作都必须走完的流水线。简单润色可以直接读改目标原文；查人物知情范围、解释冲突或跨章修订时，再组织所需检索与分析。作者认可的风格样例和未经结构化的细节仍可直接作为资料。可访问全文、实际读过哪些范围、解释是否正确是三个不同问题；摘要与知识图是有损派生物，争议结论必须能回到原文。

“实际写了什么”由正文版本回答，“作者确定什么”由确认的设定/决定回答，“准备写什么”由计划回答，“这些内容意味着什么”由带证据与不确定性的解释回答。世界事实可由作者直接确立而尚未出现在正文；此时来源是作者决定，不能伪造正文证据。

例如“林夕烧掉父亲的信，却记住了收信人的名字”：可提取焚信事件及获知名字的认知变化；“她决定与父亲决裂”则可能只是解释。两者不使用相同确定性。后续情节重新解释旧行为时新增解释修订，不倒写旧正文中从未出现过的动机。

结构化深度分三档：

- 严格建模：身份、版本、范围、引用、显式事件及授权，使用明确类型和校验。
- 证据支持的柔性建模：动机、因果、人物弧线、主题与风格，允许自然语言、候选解释和分歧。
- 保留原文：无法可靠结构化的细节、歧义和留白，允许尚未建模，不强制补齐字段。

建模质量以创作连贯性、修订准确性、可追溯性与作者负担衡量，不以实体/关系数量衡量。抽取覆盖率只是处理覆盖，不是理解正确率。

#### 原始资料准备与派生分析就绪

原始资料准备检查任务所需正文存在、修订与范围正确、作者要求可读、授权及资源上限有效。派生分析就绪只针对该操作实际声明依赖的知识、状态投影或报告；不因某个无关章节尚未建模而宣称原文不可读，也不把未建模标成语义检查通过。实际读取依赖用于追踪来源，不能自动推断文学因果或要求重写全部后文。

上述是逐操作目标契约。当前 `assessSceneOutcome` 等路径仍校验绑定知识批次和来源；不能把既有 `model_pending` 改为 `ready`、忽略过期错误或删除收尾检查来实现直接阅读。若操作改用原文证据，需明确其允许读取的视角与位置、必需输入、报告如何引用证据、哪些既有问题必须复查，再一次性同步调用方、生产类型、fixture 和测试。无需该分析的新契约与必须具备分析的契约应有明确判定，不能由一次模型自述临时扩大权限。

手动保存维持当前来源失效与持久化规则，不自动启动付费语义提取。按需产生的知识仍绑定不可变来源、作者范围和预算；源变后旧解释失效但保留历史，不静默搬到新稿。正式作者决定、独立支持来源和受保护正文继续沿既有事务处理。

#### 建模收益的独立验证

在同一应用、相同模型/方法/素材与总预算下，比较“原文检索、直接阅读与临时笔记”和“增加按需派生知识”。两组保留相同版本、安全、作者决定及编辑能力，均可反复回读原文；计入知识初建、更新、误抽取纠正和作者维护成本。直接事实、歧义、不可靠叙述、人物知情范围与中途改稿分别评估，报告遗漏、误改、质量、交付率、人工时间与用量。知识收益未证明时维持按需，不据此增加全书强制建模；该比较不替代既有 S0–S5 的退出条件。

### 4.11 关系语义：分类、上下文与可推理边界

| 类别 | 关系示例 | 推理限制 |
| --- | --- | --- |
| 世界结构 | memberOf、locatedAt、owns、parentOf | 每种关系单独规定方向与基数；所有权不默认唯一 |
| 认知与立场 | knows、believes、suspects、conceals | 指向命题并绑定持有者；相信不等于客观为真 |
| 因果与动机 | causes、enables、prevents、motivates | 时间先后不推出因果；动机分析需标记解释性质 |
| 叙事组织 | foreshadows、paysOff、contrasts、echoes、reveals | 呼应不证明创作意图；兑现必须绑定承诺与文本证据 |
| 创作与证据 | derivedFrom、supports、contradicts、supersedes、inputDependency | 使用过资料不等于必须随资料重写；支持也不自动赋予正式效力 |

为关系类型建立代码拥有的 `RelationTypeDefinition`：名称、端点类型、方向、对称/逆关系、基数与作用域、时间要求、允许的推导规则和失效传播规则。默认不传递推理；只有显式类型规则允许时才推导。例如 A 信任 B、B 信任 C 不推出 A 信任 C。逆关系可派生显示，不要求再保存一条独立可变真相。

```text
RelationRevision {
  objectId, revisionId, projectId, branchId, relationType,
  sourceRef, targetRef, contextRefs[], validity,
  evidenceRefs[], origin: author | extraction | inference,
  epistemicOwnerId?, confirmationState, derivationRef?
}
```

参与者、条件、受益方等超过两个角色的关系，优先建模为有角色绑定的事件/断言节点。例如“甲把密函交给乙，并对丙保密”以交付事件关联 giver/recipient/item 和认知证据，不能简化为“甲关联乙”而丢失信件、时间及保密对象。

角色引用通过受限类型注册表验证。人物信任可以带领域情境，如信任能力但怀疑忠诚；不同情境关系并存不等于冲突。模型生成的关系须保存来源与候选标记；程序只能自动确认 schema 与证据存在，不能保证语义正确。

RelationRevision 表达领域关系，DependencyEdge 表达依赖与证据链；二者共用关系类型目录和查询视图，但同一语义关系只由一个领域对象拥有。认知关系以 EpistemicAttitude 为权威，图中仅提供投影，避免多份独立写入状态。

### 4.12 稳定核心与按需扩展

除已有模型，按任务需要支持以下版本化扩展；作者无需在起稿前填写：

| 扩展 | 内容 | 边界 |
| --- | --- | --- |
| CharacterDecision | 当时目标、已知信息、可选行动、选择、代价与证据 | 计划选择与正文已作选择分开；不假装穷尽人物所有可能行为 |
| Conflict | 各方目标、不相容条件、阻力、利害、升级与解决证据 | 不把敌对关系本身当作完整冲突 |
| NarrationStrategy | 视角、叙述者可靠性、信息披露、叙述距离和时间组织 | 控制表达方式，不改写世界事实 |
| StyleProfile / Motif | 声音、语言偏好、意象、主题呼应与文本样例 | 作者要求与模型推断分开，不强制量化审美 |

新增修炼、家族谱系等类型使用当前工程定义并校验的类型化 payload；模型可提出扩展建议，不能执行 DDL、注册任意代码/推理规则或修改权限。暂不支持的概念先保存为带来源的注释/候选，再由工程实现明确 schema；不能把“持续建模”解释为模型随意改数据库。

## 5. 时间、认知与分支

### 5.1 四个独立坐标

1. 故事时间：事件在世界中何时发生；支持区间、相对先后和未知，不强制所有小说使用真实日期。
2. 叙述位置：在当前版本的哪个章节/场景/文本块披露，由稳定 ID 及版本化顺序解析。
3. 认知时间：人物何时获得某命题，以及获知途径。
4. 创作版本：作者在哪个分支、哪次提交确认或改变了它。

不再以 `chapter <= N` 同时代表上述所有含义。未知时间不能用 0 或当前时间代替。相对先后图检查环路；无法确定顺序时返回不确定，而非任意排序。

### 5.2 统一状态查询

当前有限实现见 [全局状态投影选择器](STATE_PROJECTION_SELECTORS.md)：Author/World/Reader/Character 共用权威来源筛选，实体、谓词、视角和时间筛选前移至来源上限之前，当前与冻结快照遵守同一选择语义。截断及未建模来源显式报告，不将结构化覆盖等同于语义完备。

```text
StoryStateQuery {
  projectId, snapshotId,
  worldPosition: { timeRange?, beforeEventId?, afterEventId? },
  narrativePosition?: { chapterId, sceneId?, blockId? },
  perspective: author | narrator | character | reader,
  perspectiveOwnerId?, purpose,
  selectors[], limits
}
```

作用域与 purpose 由已授权任务绑定，不能让模型通过请求参数自行提升权限。

例：第十章倒叙披露师父三年前寄出的信。世界事件发生在三年前，读者第十章获知；徒弟是否获知需另一条认知证据，不能由披露自动推出。

投影键必须包括 snapshot、世界位置、阅读位置、视角、策略与投影器版本。世界状态、人物认知、读者披露状态分别计算。全局作者视图可查秘密；Writer 工具与会话只取得获准信息。隐藏项的标题、摘要、数量提示和图路径也不能泄露秘密。

### 5.3 反事实与修改历史

- “如果师父不死”创建基于固定 snapshot 的假设覆盖层，记录 assumptions，不改变正式记录。
- 应用假设时，重新检查目标分支 head，展示冲突与所选改动；不将推演结果整包覆盖正式作品。
- 前文被修改后，旧来源锚点仍能引用旧版本，但针对新正文的知识标记为需复核，不自动继续作为确定事实。
- 撤销是新的补偿提交。若后续提交依赖被撤销内容，先生成冲突或影响报告，不能删除历史或静默撤销后续作品。

### 5.4 三类演进与变化轨迹

| 演进 | 变化内容 | 驱动与坐标 | 不能混淆的情况 |
| --- | --- | --- | --- |
| 世界演进 | 人物位置、认知、目标、关系和物品归属 | 世界事件、故事时间及认知时间 | 作者删掉死亡情节不是人物在世界中复活 |
| 叙事演进 | 信息披露、悬念、弧线阶段及预期阅读效果 | 版本化阅读顺序与兑现证据 | 读者获知秘密不意味着人物同时获知 |
| 创作演进 | 意图、规划、稿件、分支与解释被调整 | 创作提交/工作稿检查点及作者决定 | “改为卧底”是改设定，不必新增一次世界身份转换事件 |

演进通过现有 StoryEvent、NarrativeCommitment、SceneOutcomeAssessment、修订与提交记录表达，不新增一个同时充当三者权威的通用事件账本。统一 `EvolutionTrace` 只是查询投影：包含 dimension、目标、前后版本/状态、变化原因、证据、时间坐标及适用 snapshot；可以从来源重建。

世界状态轨迹中的变化须有对应世界事件/断言；对既有事件的解释变化则属于创作修订。轨迹可展示“先信任、后怀疑、再修复”，但心理或关系阶段必须有证据或明确设定，缺失时保留 unknown，不用平滑曲线补造过渡。

叙事演进中的“读者紧张/释然”仅表示作者预期或评估结果，不是客观读者状态。角色死亡、立场逆转、悬念兑现等关键变化可单独查询依据与影响，不要求预设固定的人物成长模板。

此为目标逻辑表组，不要求新旧同名表并存。实施时将现有相同职责表整合为唯一实现，明确删除被替代写入路径。

- 统一对象注册表允许端点引用校验；所有跨对象外键包含 projectId，不能只验证 UUID 存在。
- 热查询字段使用显式列与索引；JSON 只承载有 schema 的扩展负载，不用一个巨型 JSON 保存整个作品。
- 关系表建立 source/target 双向索引，按快照可见成员过滤；方向、关系类型和是否可传递必须显式定义。
- 正文锚点绑定不可变块版本和范围。重新分段/编辑可提出 anchor remap，但匹配失败必须标记 dangling，不能把同一行号当作新证据。
- 初版正文和版本元数据同存 SQLite，避免跨文件与数据库的伪原子提交。Markdown/YAML 为导出或只读 Agent 视图，不允许第二条直接写权威文件路径。
- 采用领域修订与提交日志，而不是让所有 UI 操作都事件溯源；区分 StoryEvent（虚构世界事件）与 Commit（编辑操作）。
- 关系类型注册表由受版本控制的代码定义；可选创作扩展复用 object_revisions 并校验类型化 payload，不为每种题材动态建表。EvolutionTrace 为可重建视图，model_applicability_records 只管理知识对特定快照的适用性，不修改历史事实内容。

## 7. 全局检索与上下文构建

当前协议进展：九类模型任务共用领域派生的 `TaskQueryScope`，有限四通道查询可组合进 `read_context`。滚动规划限于起始章之前；建模/场景评估正文绑定源章及修订、结构知识不晚于该章；Writer 保留原位置和 POV 门禁。普通检索复用同一正文范围；建模目录和工作知识按范围保留原始候选身份，独立作者确认不倒灌成原始提取。`queryScope`、策略摘要、来源水位、共享整包预算及覆盖报告均可核对。确定性 HTTP/MCP 场景证明协议链路，语义选择、金标召回、真实模型及双平台质量仍另行验收，详见 QUERY_PLAN_DESIGN.md。

### 7.1 查询管线

```text
作者问题 → 任务类型与作用域 → 实体消歧/查询计划
  → 精确 ID/别名 + 中文全文 + 时间状态 + 有界关系扩展 + 可选语义召回
  → 证据去重与重排 → 矛盾/缺失识别 → Context Pack + Query Report
```

检索前完成作品、快照、分支、视角过滤；扩图和重排也遵守相同过滤。向量召回只是补充通道，不承担事实判断。中文检索必须建立分词或字符 n-gram 索引及专门 fixture，不能把默认 FTS 对中文的效果当作已满足要求。

查询计划由受限操作组成，模型不能生成并执行任意 SQL。身份消歧失败时返回候选，不把同名人物静默合并。

当前查询执行切片见 [任务绑定查询计划](QUERY_PLAN_DESIGN.md)：模型任务可自主提交最多四步的 `query_story`，Rust 在一个授权读快照内执行正文、精确名称、状态和关系通道，返回有界证据报告及来源水位。报告按精确不可变来源去重到共享 evidence 字典，保留不同断言与确认状态；字面相关性排序和预算允许时的通道保底裁剪已实现。当前新增以 literal 报告摘要绑定全部结果的 Codex 语义候选评分，Rust 同快照校验后重排并复用预算；缺项、未知结果、旧摘要或跨任务复用拒绝。见 [语义判断与来源绑定重排](SEMANTIC_QUERY_RANKING_DESIGN.md)。此入口不对 Writer/POV 扩权，不接受任意 SQL 或历史快照选择；候选重排只作用于已返回的基准结果。真实模型排序质量、全书语义召回、通用消歧和全任务语义 Context Pack 验收仍未完成。

### 7.2 有界但覆盖全书

事件条件的具体执行改造见 [长篇条件推理](LONG_FORM_CONDITION_EXECUTION_DESIGN.md)：
区分原始来源验证、相关状态召回、完整范围计算与有限引用展示。
已移除大范围任意前 200 来源的求值路径：有同代次、同算法完整审计证明时，
先按规则属性筛选来源，再执行有限原文重读；没有证明的大范围保持未完成。
小范围直接原文校验，相关来源超预算仍须可恢复全范围求值，不能据此宣称整个
条件推理、长篇性能或文学质量已验收。

当前新增 [原文召回通道](PASSAGE_RECALL_DESIGN.md)：有限操作 `passages` 沿绑定任务、问题、步骤、政策与源水位的游标，直接遍历选中正文，不要求关键词匹配，也不从派生索引推断可见正文全集。每页最多四段、每段 80–400 字符，边界重叠 32 字符；章节/场景/POV 范围在读取前执行。Codex 通过原引擎对读到的片段进行候选相关性判断，Context Pack 复用同报告。页面预算裁剪撤除游标并要求原位置重读。`endOfScopeFromCursor` 仅说明该位置之后的原文末尾，不证明先前页被模型消费；`complete`、`fullScanCertified` 均为 false。持久语义审计、索引加速、真实供应商/人工金标及长篇成本仍需建设与验收。

- 交互查询：按预算返回最相关证据，声明遗漏和当前覆盖范围。
- 全局审计：分页/分片遍历快照内所有相关正文与结构对象，保存检查点，可取消、恢复；每个模型请求仍有界。
- “未发现矛盾”必须绑定扫描范围与检查类型；未扫描或超限时显示“检查未完成”，不生成全局通过结论。
- 相关图扩展不是完整性证明；未提取成关系的正文仍需全文/语义通道和按需全量审计补充。

初始工程预算（待基准调优，不是实测承诺）：交互候选最多 200 条；图最多 3 跳/500 节点/1,000 条边；最多 40 个证据片段；Context Pack UTF-8 总量上限 60KB，并同时受模型可用 token 预算约束。保留现有 MCP 每项 9,000 bytes 限额，超出则切分或拒绝；关键约束放不下时中止，不静默丢弃。

### 7.3 Context Pack 契约

```text
ContextPack {
  id, snapshotId, taskId, purpose, policyDigest,
  target, activeIntentRefs[], hardConstraints, narrativeGoals,
  relevantCommitments[], sceneOutcomeRefs[], plannedEffects[],
  stateFacts[], evidenceRefs[], relevantText[], openQuestions[],
  coverage: { requestedScope, scannedScope, missingScope, truncationReasons },
  sourceWatermarks, budgetsUsed, contentHash
}
```

每项事实与推断可回溯证据；硬约束、文本摘录和模型生成摘要明确标注。摘要保留输入版本和生成器版本，是有损派生数据；回答争议问题必须能回看原文。

当前预算落地：Context Pack 的 `operationContext.modeling` 仅提供最多 100 个范围内来源元数据，不再读取/转发整批实体和断言；实际来源总数单列并保持覆盖缺口。最终包装按 UTF-8 预算裁剪可选的非目标正文、来源元数据和工作知识条目，重算 included 数与候选/确认条数并撤除失效 findings；目标正文、指定建模源、冻结规划及已选确认事实放不下时明确拒绝，不返回缺少必需输入的成功包。哈希与字节统计在裁剪之后生成。百万字生产 fixture 经公开 HTTP 路由的普通/POV Writer 热态 P95 本机最新实测约 127/177 ms，均不超过 60 KB；不包含 TCP 或模型延迟。设计、证据与未完成的语义范围见 [Context Pack 预算设计](CONTEXT_PACK_BUDGET_DESIGN.md)，不能将这两类性能结果外推为所有任务/双平台验收。

九类模型任务现可在 `read_context` 带有限 `queryPlan`，由 Runtime 用真实任务凭证重新查询并核对有效范围来源水位，返回基础包及 `queryReport`，共同受整包预算。Writer 的正文按章/场景前缀裁剪，结构知识严格限前文且不读后来身份合并或确认；POV 只允许绑定人物/时间的认知投影，未经证明的正文和名称目录隐藏。滚动规划、建模与场景评估遵守本节所述派生范围；内层缺口传播到外层，查询报告不可被静默裁剪。未知请求字段、自制报告、受限任务的作者全局视角及范围替换拒绝。所有任务的语义融合质量、组合入口百万字时延、完整身份隔离专项证据与真实模型质量仍需验证。

### 7.4 索引与水位

权威提交内写入 outbox；本地 worker 幂等更新索引、投影与覆盖记录。每种派生物单独记录 snapshot/input digest 与算法版本，不能共用一个含糊的“已索引”标志。

当前正文来源 outbox 仅维护同事务来源失效记录、最新源合并、跨来源依赖失效和匹配发布确认；分页采用单调代次与读快照，支持重开恢复、事务回滚和删除/重建后的游标失效。Author-only `GET /api/projects/{projectId}/modeling-outbox` 返回 `sourceFreshnessOnly` 记录，不提供 due 调度、派发接口或执行许可。手动保存不会创建模型任务；智能体在作者授权的对话中按需请求准确源绑定的知识提取，继承普通任务预算和恢复机制。过期知识仍从当前查询中排除，未建模来源明确报告覆盖缺口。详见 [正文来源新鲜度设计](MODELING_OUTBOX_DESIGN.md)。

索引滞后时可走当前快照的有界权威查询，或等待重建；这是当前运行状态策略，不是历史格式兼容。无法获得要求范围的最新证据时返回 `index_pending` / `coverage_incomplete`，不能用旧索引伪装最新。模型判断不在数据库事务中执行。

### 7.5 实时增量建模：保存即时，理解异步

“实时”指创作变化及时进入可追踪的处理管线，不承诺每次按键都完成模型理解。草稿持久化、知识适用性、语义分析完成度与搜索索引水位分别展示。

本节的语义处理协议适用于已经按当前任务契约选择并获授权的分析。保存触发来源维护，不自动产生付费语义任务；按需编排规则见第7.4节和[当前执行契约](AGENT_TASK_ORCHESTRATION_DESIGN.md)。下述发布、失效及一致性门禁仍适用于实际消费这些知识的操作。

#### 触发与合并

- 输入中先更新编辑缓冲和本地自动保存；只有数据库持久化成功才显示“已保存”。语义建模读取不可变保存版本，不读取正在变化的内存字符串。
- 语义提取由智能体依当前目标、授权、所需分析和剩余预算选择；段落/场景完成可成为分析时点，但保存或停顿本身不构成执行许可。
- 每个作品/分支/目标范围保持有限在途任务；后续改动合并为待处理的最新版本，队列不得随按键无限增长。已进入模型请求的成本仍计入预算。
- 自动生成需要语义分析时优先使用已经保存的场景检查点，不对每个流式 token 调用抽取。来源修订、意图、规划、设定、撤销和分支选择变化首先更新相应依赖的适用性，是否执行重算仍由当前任务契约和授权决定。

#### 处理协议

1. 保存源修订时，在同一事务记录内容差异、直接派生物对新版本的失效范围及 outbox。未知的间接影响标为待分析，不能先宣称全图一致。
2. worker 依据块 ID、来源依赖与内容 hash 确定增量范围；必要时扩大到场景上下文、邻近段落及相关对象。全文/语义补充和全局审计弥补依赖图缺口。
3. 创建 ModelingBatch，冻结 snapshot、workingHead、intentRevision、sourceManifest/hash、scope、权限策略、抽取器/规则版本与预算；状态为 queued/running/ready/stale/failed/cancelled。
4. 生成候选事件、关系、解释及其增删差异。新增或消失的候选不能靠空结果简单推断；明确记录实际扫描范围、完整性和来源是否仍有效。
5. 校验类型、锚点、权限、重复身份、冲突、独立支持证据与范围覆盖。结果依然是可质疑的语义解释，不因程序校验通过而成为正式 Canon。
6. 发布前比较 sourceManifest、scope generation、意图/策略版本与目标 head。v1 使用保守 CAS：任一绑定变化都不发布到当前模型，旧结果只留审计用途；重新合并当前任务，不静默搬运旧结果。
7. 对当前工作稿模型原子发布有效候选清单、知识差异、适用性与本次覆盖水位，然后派发索引/投影更新。分片分析只推进已完成范围，不提前推进全局水位。正式知识改变仍走作者采纳事务。

幂等键包括作品、分支、源清单、分析范围、意图/策略与抽取器版本；重复投递不得重复发布。分析失败不会丢失新正文；显示“正文已保存，知识更新失败/待重试”。旧快照的记录保持有效，对新快照失效不等于删除历史。

#### 生成与建模的一致性屏障

依赖发生变化的知识在新范围返回 stale/unknown，不作为确定状态。下一场景读取 Context Pack 时必须检查相关范围的源清单与建模水位：无关对象可继续，依赖对象未就绪则等待、触发有界重建或返回 `model_pending`。无法证明无关时保守等待，而不是假定安全。

建模头与工作稿头分开记录，发布建模结果不通过新增正文版本制造无限变更。任务明确绑定正文快照、候选知识清单和状态投影版本；只有全部满足策略后才自动接续。图传播超预算时暂停依赖该范围的任务或转后台审计，不能将未分析范围标记干净。

#### 防止自激循环与越权改写

变更记录 origin、causeId 和已有 GenerationPermit。知识分析默认只更新候选理解、适用性与建议，不直接改正文。只有作者命令或已有许可范围内的生成循环才可进入修订阶段；每个场景有修复次数、调用和费用预算上限。

知识候选发布与索引完成不会再次触发同输入提取；源内容/意图确实变化才产生新批次。失败重试有上限，达到上限进入 blocked/待人工处理；模型不可用时仍可保存和编辑，但不能声称已更新语义模型。

#### 回归样例：把“烧掉信件”改成“藏起信件”

保存新正文并令旧“信件已毁”的来源对新版本失效；提取“信件被藏起”的候选；复核物品状态以及依赖信件被毁的后续场景。不能自动推断其他人物知道藏信位置，也不能因一条证据消失就删除由另一独立证据支持的知识。若作者在分析期间又改为“交给同伴”，藏信版本的迟到结果不得发布到当前模型。

## 8. 推理、检查与影响分析

### 8.1 三种计算责任

| 类型 | 执行者 | 示例 | 输出 |
| --- | --- | --- | --- |
| 确定性约束 | 领域程序 | 无效引用、互斥状态、版本冲突、明确时间约束 | 可重复的检查结果 |
| 证据推理 | 关系查询 + 受限模型任务 | 动机是否铺垫、因果链是否缺环 | 带引用、假设和不确定性的分析 |
| 创造性推演 | 模型任务 | 卧底替代剧情、不同结局 | 候选计划/正文，不是既成事实 |

第一版规则使用有限、类型化检查器；不执行作者或模型提供的任意表达式。规则有启用范围、例外及版本。事实不足时给 `unknown`，不能把未描写的旅程判作瞬移矛盾。

ReasoningReport 至少包含 snapshotId、问题、输入证据、检查项、结论类型、简明依据、假设、未覆盖范围、生成配置标识。引用校验能证明来源存在，不能证明文学分析正确；模型分析不能自签“确定性通过”。

### 8.2 影响传播

当前显式传播实现采用固定规则集 `explicit-dependencies-v1`，沿 causes、enables、prevents、motivates、foreshadows、paysOff、reveals、inputDependency 的出向边复核可能影响。依赖过滤在 SQL 邻居召回的 LIMIT 和 frontier 扩展之前完成，不允许非依赖关系挤占预算。报告返回 `dependencyRuleVersion`，每条路径边带 `dependencyRuleId`；历史/当前来源校验及有界结果继续复用关系图。版本表示实际运行的静态规则，不允许模型提交任意可执行表达式；该能力不等于下面所有语义传播步骤均已完成。契约与验收见 DEPENDENCY_PROPAGATION_DESIGN.md。

1. 从提案差异计算变化的命题、事件、角色、场景和叙事目标。
2. 按 requires/causes/reveals/realizes 等类型的传播规则遍历依赖；visited 防环、预算防爆炸。
3. 用全文与语义检索寻找未建立显式依赖的相关正文。
4. 分类为确定失效、需要重新解释、可能受影响、无需改动；每项提供路径与原文。
5. 形成影响清单和候选修复，不自动级联重写全书。
6. 预算用尽或知识抽取不完整时记录范围，必要时转后台全局审计。

例如把“师父为私利背叛”改成“奉命卧底”：可能保留他交出密函的动作，但改变动机解释；徒弟的愤怒也可能保留。关系命中不意味着每处都必须改写。

## 9. 对话编排、授权与原子变更

### 9.1 意图模式

IntentEnvelope 绑定源消息、目标 snapshot、目标对象和模式：`discuss | analyze | propose | generate | revise | simulate | pause | resume | apply | undo`。

讨论/分析只读；草稿/提案/推演只能产生候选。自然语言分类器可以建议 apply，但不能自行生成 author 权限。作者在对话中明确确认已展示的具体提案，或点击同等确认控件后，Author Gateway 才签发绑定 proposal hash、所选操作与 base head 的一次性授权。含糊的“好的”在多个候选之间必须澄清。

同一回合不必出现多个管理面板：先用自然语言解释，再在中央文档展示差异，作者可继续用对话缩小或修改提案。对话控制与按钮使用同一个 Author API，不能出现按钮严格、对话绕过校验的两套规则。

生成授权与正式采纳授权不同：作者发出明确生成/修订命令后，Gateway 可以建立有范围和预算的 GenerationPermit，允许自动推进工作稿；这不授予 Agent author token，也不允许自动移动正式指针。所有确认规则仅在需要相应权限时触发，不能把每一步生成都变成人工审批。

当前对话派生动作支持单项许可与精确范围许可：没有作者许可时，模型
`request_candidate_task` 只持久登记 `proposed`。Author-only 预览/确认入口在
Rust 事务内复核来源、原始作者消息、意图代次、输入版本、规范目标、原预算
余额和截止时间，再保存许可并将覆盖动作与 WorkStep 一起转为 `queued`。
原 advisory 或有持久后继步骤证明的 advisory，只有操作及目标精确匹配、
名额仍可用且许可有效时才能自动排队；范围外仍须确认，模型不能扩权。
作者明确确认0–3轮后继分析；原工作完成、真实候选产物存在、全部费用结算
且来源仍当前时，领域层才在同一 WorkTask 创建后继分析，继承原作者意图、
账户、累计尝试与绝对时限。无新产物不循环，暂停/取消不自动恢复，不自动
改写源修订或扩章。桌面已接入冻结预览、摘要确认、响应丢失后的只读核对
及原步骤推进；不创建新余额，不把候选完成当作正式采用。追加消息具备独立
身份，交付后可分析并重新确认有限范围，旧写权限保持失效；GenerationRun
共享许可及可核验交付条件尚未完成，不能把此切片视为完整自主创作闭环。
契约与验证边界见 [AUTHOR_EXECUTION_PERMIT_DESIGN.md](AUTHOR_EXECUTION_PERMIT_DESIGN.md)。

上一段剩余项中的“独立追加消息身份”现已完成普通advisory及GenerationRun部分，
连续创作反馈决定也不再伪装为作者自由输入。独立消息与决定不替代意图变更后的
新许可、GenerationRun共享范围许可与当前交付条件。

### 9.2 ProposalSet，而非第二套 ChangeSet 引擎

当前作者选择扩展：规划、正文和身份候选均可进入提案面板；正文事实按具体 Review 展示来源与明确决定，不复用另一 Review 的同修订事实列表。Preview 的显式选择 map 与选中操作一一对应，复用 Apply 的 Review/候选/事实来源校验，并在单一只读快照中检查；`applyReady` 只表明本次预检通过，不授权未来提交。正式 Apply 重新执行同一校验。Draft 场景选择仅限定确认事实的来源，不是部分正文采用；未知选择拒绝，缺声明依赖不允许提交。用户调整选择后旧响应不能重新放行提交。具体契约与验收见 PROPOSAL_SELECTION_DESIGN.md；语义依赖和模型提案生成尚未完成。

以现有候选修订、ReviewBundle、AcceptanceCommit 和操作账本演进；ProposalSet 是跨对象提案的统一封装，不并行新增另一个提交系统。

```text
ProposalSet {
  id, projectId, branchId, baseSnapshotId, intentSourceRef,
  operations: [{ id, kind, objectId, expectedObjectRevision, candidateRevisionId }],
  evidenceRefs, dependencyGroups, impactReportId, checks,
  status: building | ready | stale | applied | rejected
}
```

部分采用必须遵守依赖闭包。例如接受“发现密函”的人物知识变化，必须同时接受其证据场景，或引用当前已存在的有效证据；否则拒绝该组合。模型提案保存不会移动正式指针。

### 9.3 提交协议

昂贵的检索/模型分析在事务外完成并绑定快照；最终事务只做权威校验和写入：

1. 校验 Author Gateway 授权、作品/分支、提案 hash、选择集合与请求幂等键。
2. `BEGIN IMMEDIATE`；先检查同幂等键回执，载荷不同则报冲突。
3. 比较 branch head/base snapshot，检查目标版本、锁、来源有效性、选择依赖闭包和检查水位。
4. 写入不可变新版本、确认的知识和依赖、提交清单与正式 head。
5. 同事务写入 operation receipt、失效标记与 outbox，然后提交。
6. 返回稳定回执，异步重建派生物；失败可恢复，不将索引失败伪装为作品提交失败。

事务前崩溃无正式变化；事务中失败全部回滚；事务后回执丢失重试返回原回执。任务取消只阻止后续计算与候选写入，不倒退已完成的正式提交；撤销必须走独立作者操作。

### 9.4 持续创作中的自动工作稿与连续生成模式

GenerationRun 是连续写作的一种领域执行策略，不统管纯讨论、局部分析及所有修订。
通用用户目标、依赖与重规划复用 WorkTask/WorkStep/Attempt；模型仅提出动作，
Rust 依据作品状态、输入版本、依赖、能力、许可与预算决定是否可派发。
下述现有阶段描述连续写作策略的内部检查点，不规定每个目标都必须从 brief 开始。

方法绑定已作为现有任务 inputManifest 的一部分持久保存：Rust 冻结内置 Skill 的版本、正文摘要、来源快照和任务目标，Host 和 Context Pack 共用它。默认只使用必需执行契约，实验性专用方法须由 Author 显式选择并受数量及共享字节预算限制；同一步骤重试保留该选择，不给角色新增工具权限。见 [创作方法注册与冻结绑定](CREATIVE_METHOD_BINDING_DESIGN.md)。这不代表文学方法质量、完整 GenerationPermit 或自动长篇旅程已经通过。

GenerationRun 至少绑定：projectId、branchId、baseSnapshotId、workingHead、intentRevision、写作目标范围/完成条件、受保护对象、token/调用/时长预算、阶段检查点、修复重试上限与状态。章节数量仅是章节生成任务的一项范围条件，不能替代产物、调整效果与知识就绪检查。

- 运行状态为 queued/running/paused/blocked/completed/failed/cancelled；阶段为 brief/outline/rollingPlan/draft/extract/check/revise/checkpoint。完成状态来自产物与目标检查，不信任模型一句“已完成”。
- 每次持久化的工作稿检查点引用不可变正文、规划、已验证来源的候选知识和检查结果，通过工作稿 head CAS 原子保存。它不是作者正式采用提交，但同样由领域服务执行事务与幂等校验，Agent 不直接写指针。
- 下一场景读取“作者确认快照 + 当前运行明确选择的候选覆盖层”，候选知识标为 provisional。只有锚点有效且经过结构与一致性校验的候选才可进入该层；模型语义误提取仍可能存在，不能宣称自动检查等价于作者确认。
- 有争议、无来源或阻断冲突的候选事实不能作为确定前提继续生成。系统先在有限次数内修复；仍不能解决则暂停并解释问题。后续作者采纳时重新验证所选正文与知识的依赖闭包。
- 计划中的事件不进入已写工作稿状态。场景实际效果偏离计划时，以正文提取候选作为反馈，修订未来计划；不能为匹配旧计划静默改写已确认章节。
- 达到范围/预算/时长上限、出现阻断冲突、需要改变锁定内容或用户暂停时停止接续；可读的已保存工作稿保留。崩溃后从检查点显示可恢复状态，默认等待恢复指令，不自动重复模型费用。
- 用户不回复不是新增授权。需要更多章节或更多预算时重新确认；在已有许可范围内，普通写作步骤无需逐次确认。

单次对话、规划按钮与章节按钮都建立相同的任务记录，携带目标、冻结输入、权限和候选产物约束。对话可登记最多三项明确的候选修改请求；分析和预测只读取证据并回复。任务完成后由 Rust 领域服务根据任务与当前正文版本返回后续步骤。普通章节的待建模步骤可按章节重新查询并恢复，无需再次生成正文；多章节 `GenerationRun` 继续使用自身持久化阶段来安排提取，避免重复调度。保存、采用与撤销仍由领域事务处理。

### 9.5 作者中途调整与迟到结果

“女主再主动一些”先解析为适用对象和范围，保留已有明确限制。若作者意图足够清楚，在已授权工作稿内直接生成可撤销修订，不要求先手填变更表。

1. 新的实质调整生成 intentRevision；冻结受影响的后续派发，取消受影响的在途任务。不确定依赖时保守阻断并解释范围；已有充分独立证据的无关任务可继续。
2. 识别要修订的工作稿以及依赖它的后续计划，保留不受影响的已保存结果。
3. 旧 intentRevision 或旧 workingHead 的迟到输出只能留作隔离候选，不允许推进新 head。
4. 修订通过检查后保存新检查点，按更新的许可与剩余预算继续；不默认为每次调整补满预算。
5. 涉及已确认正文、锁定设定或范围外章节时生成提案并等待作者授权。

纯提问（例如“现在写到哪里了？”）不变更创作指令代次，也不无故重启正在运行的任务。

## 10. API、安全与界面

以下是目标逻辑契约，实施时同步生成/校验 Rust、MCP、IPC 与 TypeScript schema。表中完整工具集仍是目标范围；当前生产接口以 `native/story-runtime` 与 `native/story-mcp` 的契约测试为准。

| 类别 | 目标操作 | 权限 |
| --- | --- | --- |
| 查询 | query_story、read_evidence、get_story_state、explain_relation | 绑定任务的只读作用域 |
| 建模观察 | get_modeling_status、query_evolution、read_model_diff | 只读，返回对应范围/版本的状态与证据，不能泄露受限关系 |
| 分析 | analyze_impact、validate_story、simulate_change | 有界任务，可产出报告/假设 |
| 候选 | propose_changes、save_draft_checkpoint、complete_task | candidate，无正式提交能力 |
| 运行控制 | start_generation、revise_generation、pause_generation、resume_generation | 作者指令经 Gateway 建立/调整有界许可；模型不能自增预算或解除暂停 |
| 作者 | preview_proposal、apply_proposal、undo_commit、create_branch | Author Gateway，不暴露给模型 |

已实现的 S1 有限状态证据查询为 Author-only `GET /api/projects/{projectId}/knowledge/state`，参数为 `perspective=author|world|character|reader`，可附独立的 `worldTime`、`epistemicTime`、`readingChapter` 和人物 `ownerId`。`worldTime` 仅过滤世界断言、事件及关系区间；`epistemicTime` 仅过滤人物认知证据。人物视角传 `worldTime`、世界视角传 `epistemicTime` 会报错，不再默默混用两个坐标；作者/读者视角若需要同时限定两类证据，须同时指定两个时间。结果区分候选与已确认的源绑定断言，标示方向、原文版本与覆盖/截断/未知时间；它不是从所有证据推导出的唯一当前世界状态，也不替代未来按 snapshot 和 purpose 授权的 `get_story_state`。Writer 的 `read_context` 只接收冻结目标位置，附带前文有界 `workingKnowledge`，候选和确认事实保持分栏。

公共请求携带 taskId/projectId/snapshotId/target；服务端从可信任务解析 branch、purpose、权限与预算。分页结果返回 nextCursor，游标绑定快照和作用域。错误有稳定 code、恢复动作与 requestId；不回传原始堆栈、凭据或无界数据库内容。

正文、导入文档和检索片段一律是数据，不得作为工具权限或系统指令。子 Agent 不继承超出父任务的读写范围；含作者秘密的分析会话不能复用为受限 Writer 会话。证据片段本身也须裁剪和授权，不能只过滤事实标题。

UI 保持中央正文、右侧对话。按需展示：来源跳转、当前依据版本、影响列表、候选/正式标识、采纳差异与撤销。运行中显示任务阶段；完成回复默认不铺满日志。未知、冲突、索引更新中和检查未完成必须有文字状态；正文编辑不因后台审计被阻塞。

默认回答作者四个问题：这次要完成什么、实际改了什么、哪些内容受影响、接下来为何继续或等待。
系统假设与需要作者决定的分歧按需展开，不用任务日志替代创作交流；仅在越权、关键冲突、保护项或预算边界要求决定，不把每步执行变成审批表单。

中央默认展示当前生成/修订的工作稿，而不是要求作者打开技术表。流式片段明确区别于已保存检查点；失败时不能把未保存流式文本冒充已入库正文。右侧支持自然语言调整、暂停和继续；已有正式版本可一键比较。作者可以只阅读和对话，不必打开知识面板或逐项维护事实。

实时状态分别显示“正文已保存”“知识更新中/失败”“检索索引更新中”；点击可查看变更范围与证据，不要求作者确认每个技术步骤。对话回答声明其依据版本，不能在建模待完成时声称已理解最新改动。

## 11. 代码落位与职责拆分

以下目录已经承接生产运行时；旧 Python 领域实现已删除，不保留转发兼容层：

```text
native/
  story-core/      领域契约、事实、规划、正文、审阅、影响、任务、指标与 SQLite 持久化
  story-runtime/   HTTP 传输、认证、schema 校验和应用服务调用
  story-mcp/       候选写入 MCP、执行身份与任务授权边界
```

`story-runtime` 与 `story-mcp` 只做传输、认证、schema 校验和应用服务调用。Electron 只保留用户授权、进程/任务协调和安全 IPC，不另存故事真相。React 不计算正式状态，不直接组装 SQL 或模型授权。后续自动创作循环应新增为独立 Rust crate，不回填到传输层或 Electron。

NarrativeCommitment 由 narrative 模块拥有；SceneOutcomeAssessment 的契约、比较与报告校验归 reasoning；authoring 根据有效反馈驱动下一步，不能绕过 changes 写正式内容。queries 组装意图、承诺、计划与实际状态时保留上述类型边界。

modeling 调用 knowledge/timeline/narrative 的类型化计算服务，jobs 负责持久队列投递；它不另造引擎级执行器或正式提交服务。关系规则归 contracts/knowledge，EvolutionTrace 查询归 queries，来源失效登记与源保存共用 persistence 事务。

## 12. 分阶段实施与完成门槛

各阶段为可运行的纵向切片，不是先做完全部数据库再做 UI。每阶段同步当前生产接口、fixture、测试和文档，无旧入口兼容。阶段间仍未实现的能力必须明确标为不可用。

| 阶段 | 实施内容 | 可演示验收 | 阻断条件 |
| --- | --- | --- | --- |
| S0 身份与版本基础 | 契约、稳定对象/块、来源锚点、快照、三种内容空间、意图来源引用、现有采用链整合 | 修改一段正文，旧引用仍可回看，过期采用被拒绝；已确认计划不会进入已发生状态 | 存在第二条正式写入路径 |
| S1 知识与认知 | 关系类型规则、候选提取、三类演进、时间/认知投影、增量批次与适用性 | 正确回答“当时谁知道什么”；改“烧信”为“藏信”后知识更新，旧批次不污染新版本 | 未确认提取自动成为事实；错误关系传递；迟到结果发布 |

| S4 全局修改推理 | 意图到正文/知识的依赖传播、反事实分支、跨对象提案、检查器与模型分析 | “叛徒改卧底”展示影响路径与选择性修订；独立证据支持的知识不被误删 | 用有限图遍历声称影响穷尽；把模型推断依赖视为确定因果 |
| S5 长篇可靠性 | 后台全局审计、语义检索、增量/完整重建对照、队列背压、恢复与双平台验证 | 大作品可持续编辑与生成；持续输入无无界队列；确定性投影增量结果与完整重建相同 | 故障恢复破坏正式数据；增量静默漏更新；验收无覆盖说明 |

S3 完成可宣布“对话驱动、可控迭代的持续创作最小闭环”；须覆盖多入口、实际调整与可靠接续，而非仅通过三章生成。S5 所有门槛完成才可宣布“全局知识推理目标验收通过”。不能用 Rust 引擎迁移通过替代小说领域验收，也不能用模型接入认证替代文学质量评估。

## 13. 验证矩阵与可测目标

### 13.1 必须自动验证的领域场景

1. 顺叙、倒叙、插叙：同一命题的世界发生、人物获知和读者获知互不混淆。
2. 谣言、不可靠叙述、同名角色：不把人物相信转为真相，不静默合并实体。
3. 源正文修改、删段、场景重排：锚点有效性和知识适用性正确，旧快照可重现。
4. 候选/主线/反事实分支隔离：查询、摘要、图路径及子任务均不能串线。
5. 选择性采用与撤销：正文、事件、认知及依赖闭包一致；任意失败点可恢复。
6. 并发手工编辑与 Agent 输出：过期结果成为 stale，不覆盖新 head；同键重试不重复提交。
7. outbox 重复投递、进程崩溃、索引落后：权威数据不丢失，派生数据可重建。
8. 全局审计超预算与取消：检查点有效，未完成不能返回全局通过。
9. 内容中的伪指令：不能跨权限读取秘密、执行任意 SQL 或提升为正式提交。
10. 跨平台中文路径、中文检索与证据定位；模型不可用时仍可阅读、编辑及执行确定性检查。
11. 多入口持续创作：分别从模糊创意、已有大纲、已有正文及局部问题进入，不要求重建无关结构；在必要范围内补充规划、生成真实内容并接续。保留“一句创意生成三章”为连续性子用例：后章读取前章检查点状态，规划未落实事件不能成为已发生事实，未经作者采用也能在许可内接续；章数达成不替代调整与质量验收。
12. 生成中调整人物/节奏、暂停和恢复：旧代次迟到结果隔离，剩余预算不重置，询问进度不重启任务，自动生成不改动正式/锁定内容。
13. 预算耗尽、反复质量检查失败、断网和进程崩溃：有限重试、保留可读工作稿、不伪造成功；恢复不重复推进工作稿或重复提交。
14. 意图补充、替代、冲突及局部作用域：修改第二章的要求不无故改变全书；系统假设不冒充作者要求，意图不能自行扩大执行许可。
15. 计划与实际偏差：计划已确认但正文未落实的认知不进入状态；有意偏离可修订未来计划；源版本改变使旧 assessment 失效。
16. 承诺部分兑现、延后、开放结局及撤销兑现片段：依证据更新状态，不提前关闭、不强制补全，不能维护两套不一致的伏笔状态。
17. 输入依赖与剧情因果区分：删除一个证据时保留独立支持来源；更换模型或重试任务不直接改变 Canon。
18. 关系方向、情境及多方事件：信任不传递，先后不推出因果；交付事件保留 giver/recipient/item，各投影不能变成独立可写真相。
19. 世界/叙事/创作演进：删掉死亡情节不产生世界复活事件；旧快照仍能解释旧版本，人物认知与读者披露分别变化。
20. 连续编辑、撤销重做、分支切换与迟到批次：防抖合并有界、发布 CAS 拒绝过期结果；相同批次重复投递不重复发布。
21. 修改/删除/重排文本后的增量与全量确定性重建对照：固定同一已确认事实清单时结果相同；模型提取用固定输出 fixture 验证协议，另做金标语义评估，不要求随机模型重跑逐字一致。
22. 局部知识待更新、抽取失败和索引滞后：分别显示状态，依赖任务暂停，无关任务须有充分范围证据方可继续；不丢正文或伪装最新知识。
23. 模型发布/索引完成不重复触发同输入提取；修复次数与预算限制有效，不出现自动改写自激循环。
24. 柔性扩展与创作留白：动机解释可并存；风格与开放结局不被强行确定；模型提交的新类型不能执行 DDL 或扩大权限。

S5 检索索引已有全量核对/事务重建，以及 Rust Runtime 自动推进的持久分片审计：遍历不可变修订重算字段和字符 gram，检测缺失/多余条目及跨作品错连；审计按最多 100 修订、通常不超过 1 MB 源文本一批持久提交检查点（单条修订可超过字节上限），活跃队列上限 16，支持暂停/取消/重启续跑。源修订清单或索引代次变化使作业转为 stale，已完成报告在读取时也会失去当前一致性标记；只有完整遍历并核查孤立项后才标记 completed，`completed` 仅表示核对结束，须再检查报告的 `complete()` 才能判断索引一致。重建只替换派生数据，递增代次使旧游标失效，不改正文或快照。正常交互查询不会为每次请求运行全量审计，所以普通搜索的 `coverage.complete` 仍不能证明索引未损坏。完整知识投影重建、百万字规模指标、语义检索与双平台验证仍待实现。

S5 实体派生索引已有独立的领域审计与事务重建：从已发布批次的实体候选重算 `story_entity_claims_v2` 和 `story_entity_names_v2`，包括历史 stale 批次；修复仅替换指定作品的派生行，不改模型输出、正文、快照或作者身份决议。Rust Runtime 按最多 25 批次、通常不超过 250 KB 候选源文本一事务持久化审计检查点，后台自动推进并支持暂停、取消、重启续跑，作者入口显示进度与真实一致性状态；新发布源或重建代次使旧检查点过期。生产发布路径与全量重建的等价性、错误修复、坏源回滚、跨作品隔离和不一致时分片/全量报告对照有测试。同步重建尚未作为作者操作开放；这不证明历史快照知识或关系/状态投影可重建。

S5 断言、人物认知索引与当前知识头现在可在同一持久审计作业中按已发布批次分片核对：每事务最多 25 批次，通常不超过 250 KB 源候选（单批可超）；检查两个索引的缺失、变化、多余行，并校验就绪建模批次与当前选中正文修订、知识头的对应关系和唯一性，末尾检查孤立项。只有完整遍历且三者一致才标记当前 `verifiedConsistent=true`。维护端可按作品事务重建当前知识头；无效或歧义就绪源拒绝修复，不修改正文、快照或提取输出。新来源、源失效或索引事务重建会使报告失效；队列有上限，支持暂停、取消、重启续跑，并由 Runtime 后台线程自动推进。作者 UI 可查看进度和控制，候选任务无权访问。该作业不验证模型提取的语义正确性，也不证明历史快照知识、确认事实、世界状态或百万字性能达标。

S5 历史知识现在在创建每个快照成员时记录显式的知识捕获，`NULL` 批次是有意义的“当时未建模”，不同于捕获行丢失。历史读取在捕获行缺失、跨作品/对象、来源修订不符、无发布时间或未就绪时拒绝返回伪造的“待建模”；发布后成为 stale 的知识仍可由其旧快照重放。`audit_snapshot_knowledge` 从快照成员检查缺失、错指、孤立和跨源修订，并报告前 20 个受影响成员。相同审计逻辑现由持久作业按最多 100 个成员/事务推进，暂停、取消、重启续跑及队列背压由 Rust 管理，Runtime 后台自动执行；触发器代次让快照/捕获/来源变化后的旧报告失效，作者 UI 可查看进度和差异，候选任务不能访问。历史捕获不可从当前知识头安全回填，所以没有自动重建；确认事实/状态投影一致性与大规模性能证明仍待完成。

S5 确认事实读取已加最小权威链约束：当前事实列表和历史确认投影在返回前核对事实 payload、采纳记录的作品/操作/修订/快照分支，以及事实撤销指针与采纳记录的撤销指针、撤销记录目标的一致性；不一致时报 `CorruptState`，不能静默把已撤销事实显示为仍然确认。历史投影按所查快照祖先中的采纳与撤销记录计算，而非仅相信事实行的单侧指针。未取得同代次的已完成审计证明时，读取继续执行作品事实链全量校验；此校验不提供作者可用修复或世界状态全量重建。

确认事实链现有与读取共用判定规则的分片持久审计：每次最多 100 条事实，在 SQLite 事务中记录进度、无效关联、无效 payload 与前 20 条受影响事实；作品事实、采纳/撤销记录或快照变化会递增代次，使运行中或已完成的旧报告失效。队列有上限，支持暂停、取消、进程重启续跑；Runtime 后台线程推进，Author-only API 与作者界面显示真实进度和错误，候选任务不能访问。同代次的已完成报告在同一 SQLite 读快照内可作为普通读取跳过重复全量校验的证明；不一致报告使读取直接拒绝，报告缺失或过期则退回全量校验。跨连接 WAL 回归验证证明与事实行不会混用不同事务版本。确认事实属于权威记录，不按当前投影自动修复；事实列表及历史投影本身仍随返回条目数增长，审计只保证结构链和载荷形状，不证明事实语义真实、状态投影一致或百万字规模性能。

任务检索现在在 SQL 召回前应用授权范围：Writer 和章节知识建模任务只能检索获准正文，未来章节和规划文本不进入候选计数或结果；任务水位过期则拒绝查询。检索游标绑定范围，覆盖返回扫描范围。Author 字面检索新增历史 `snapshotId`：仅选快照成员的旧修订，对象类型和标题从不可变修订回放，不依赖当前对象头或可变章节表；翻页不受随后改稿影响，其他作品的快照返回未找到。Agent 任务检索不接受历史范围扩权。人物秘密过滤、实体消歧和完整查询规划仍未完成，不应被解释为 S2 全部权限策略已完成。

Writer 关系扩图增加独立只读 `search_relations`：仅 `generateChapter` 任务可用，先验任务凭证、线程、输入水位和目标章，后由 SQL 只召回目标章之前的有效建模批次及关系端点。返回逐条原始证据、1–3 跳路径和限定范围覆盖；未来章及当前章的关系不会进入遍历或来源计数，作者后来的身份合并与确认决定也不投影为 Writer 事实。任务端点拒绝 `snapshotId`，子 Agent 只能经相同任务权限调用只读检索。领域/HTTP/MCP 测试覆盖隔离与可用性。后续切片已对带 POV 的任务增加保守人物认知门禁；语义消歧、自然语言 Query Planner、长篇质量指标和完整 S2 验收仍未完成。

S1 关系与人物认知现在有可检验的共同命题身份：新发布 `relation` 必须引用同一建模批次内、带原文锚点的 `proposition` 实体；`epistemic` 可以复用该 ID 表达人物知道、怀疑或误信。缺失及错类型在发布前被拒绝，关系派生审计/重建也拒绝缺链接的来源，图查询保留 `propositionId`。认知断言随发布原子写入人物—命题—时间索引，并可核对及事务重建。Writer 图检索若有任务绑定的 POV，只有前文有效源中对该命题有明确正向认知证据的关系可见；未知、怀疑、矛盾和时间不确定均按覆盖不足处理，而非断言人物不知道。完整时序认知状态机、叙事披露隔离与质量验收仍未完成。

POV 认知门禁进一步按关系来源建模批次绑定命题 ID：此前只按 `propositionId` 字符串在前文章节查询，另一批次复用同一局部 ID 时，其「已知」断言可能错误放行本批次的关系。现在图扩展和结构化名称查询均只用关系所属批次的认知证据；跨批次同名 ID 不再自动视为同一命题。后章认知可用下述显式来源批次引用前章命题，不能靠字符串相等推断。

POV 关系检索的故事时间现从已认证 Writer 任务目标读取，不再信任模型提交的 `worldTime`；显式参数与目标不一致时拒绝，省略参数时沿用任务目标。目标没有可信故事时间时，同批次「已知」证据也不能放行关系，覆盖标为不足。这样模型不能通过选取更晚的时间读取人物尚未获知的关系；作者若要查询另一时间，需创建相应冻结目标的任务。此边界仍不是完整的时序认知状态机或正文披露策略。

S1 跨章节认知引用切片：`epistemic` 可显式附带 `propositionSourceBatchId`，指向前文章节当前有效建模批次中的 `propositionId`；本批次只声明人物和带本章原文锚点的认知，不复制旧命题实体。发布事务校验来源作品、批次、源修订、知识头、命题类型及前章顺序；不同作品、未来章、失效源、伪造批次均不能发布。省略该字段仍表示本批次命题，不按字符串自动跨批次合并。派生认知索引持久保存命题来源批次，审计/重建对照原始建模输出及被引用批次；Writer 图与结构化查询只在两者匹配且人物认知时间不晚于任务时间时放行。实体目录每条声明返回 `modelingBatchId` 供建模 Agent 选择具体来源。跨章引用仍是候选证据；若前章改稿或命题歧义，必须重新建模/明确决议，不能把相同 ID 当作正式全局命题。尚无完整撤回/误信状态机与叙事披露推理。

来源失效在读取、采纳和任务前置条件处继续生效：当前人物知识投影、结构化名称检索及确认事实均重新核验被引用命题所在的当前有效批次；历史投影/检索核验该命题是否被同一快照捕获，不以当前知识头覆写历史。前章改稿的同一 SQLite 事务沿显式 `propositionSourceBatchId` 派生索引传递失效，将直接和间接依赖批次标记 stale、清除当前知识头；后章转成 `model_pending`，任务不能把其当作就绪。旧快照仍重放当时捕获的批次。返回认知条目提供 `(batchId, propositionId)` 限定引用，避免同名局部命题合并。若派生索引损坏，读取/采纳端的来源核验仍会阻断伪有效认知，但级联可能不完整，须依靠索引审计/重建修复；自动重建受影响批次、完整时间状态机及模型语义认证尚未实现。

S3 首个运行切片已加入 `story-authoring` Rust crate 与持久化 `GenerationRun`。阶段为 Brief → Outline → RollingPlan → MaterializeChapter → Draft → Extract → Assess → Check；Rust 根据阶段发出有界 `agentTask` 动作，Electron 将它映射到现有 Codex App Server 任务，写入后必须由任务凭证、输出引用和运行版本验证才能推进。所有需要模型推理的创作任务均走现有 Codex 执行通道；确定性的调度、权限、版本校验和知识覆盖判定留在小说领域层。已阻断空输出、失效源、失败子任务、超预算和知识覆盖/冲突；知识已就绪时可跳过重复抽取。运行可列出并继续，无输出失败任务在来源和预算不变时可有限重试，部分写入后不盲目重放。首轮从空作品生成前三章工作稿；已有章节知识就绪时可继续有界续作。确定性 Runtime 集成测试覆盖三章完整阶段，验证第一章生成时追加第二章要求并暂停/恢复，以及第一、二章当前稿排队修订。当前章修订只在 Draft 活动任务已绑定且剩余预算覆盖重写及后续必需步骤时受理；原任务结果仍以旧输入归属保存，新任务才使用新意图。若原任务保存候选后失败，仅允许作者显式重试，先校验原任务输入水位，保留候选并计入失败调用；未排队当前章修订的部分失败仍保持阻断。真实模型连续三章认证、即时中断替换、完整暂停/恢复、完整 Beat 反馈、反馈驱动修订和正式 GenerationPermit 仍未完成，不能视为 S3 验收。

滚动规划现不再只执行首轮：每章的知识检查通过后，若仍有目标章节，下一步重新生成下一章起的规划候选；候选任务绑定 `planFromChapter`，同一运行里的后续规划拥有独立 Step/Attempt 身份，重试仍复用本章 Step。该运行中后续规划的 Context Pack 限定给出已写章节正文及截至上一章的候选工作知识、来源和覆盖信息，不能把规划项冒充事件。调用预算下限及本章重写预留额计入未来规划。三章 Runtime 集成场景验证两次重规划、前章知识位置、候选版本 CAS 和作者中途意图；模型是否真正理解前章实际效果及如何修改 Scene/Beat 计划，仍需独立评估。

S3 规划—正文可追溯链接现已落地：自动建章在同一事务验证当前规划候选的唯一章号、`chapterPlanId` 和本运行规划任务来源，并保存章节绑定；后续自动写稿由服务端生成 `sourcePlanRefs`。滚动规划只读取已完成的最近正文；Context Pack 提供历史计划 Scene/Beat、相应正文 SceneGroup，以及从知识投影按证据偏移定位到场景的事件断言引用。事件引用保留批次、序号、正文修订与确认状态，不将候选知识升级为 Canon。最多 24 个场景链接和每场景 12 条事件引用，条数或字节预算不足时截断并报告覆盖缺口。`assessSceneOutcome` 现在把逐场景比较保存为独立候选分析修订，冻结规划、正文和知识批次，验证事件引用确实落在对应场景的正文证据内；不会自动修改 Canon。链接区分已评估、未评估和失效结果，滚动规划得到有界 `sceneOutcomeRefs`。确定性三章测试覆盖自动评估、来源校验与后续规划读取；真实模型连续认证、偏差自动处理和文学效果测评仍未完成。

S3 预期效果契约补强：`generatePlan` 候选写入现在要求每个场景有非空、稳定 ID 的 `expectedEffects`，每项标明 world / knowledge / relationship / narrative 维度和可核对的文字描述；缺失或重复在任务写入事务内被拒绝。SceneOutcomeAssessment 必须对该场景每一项预期效果分别给出判断与场景内事件引用，整场景 verdict 由逐项 verdict 确定性汇总，不再维护一份可与逐项引用冲突的场景级事件副本。描述仍是创作目标，模型的“已实现”结论仍为可质疑候选；语义正确性、额外非预期变化及偏差决策闭环仍须另行验证。

S3 场景反馈决策切片：`Check` 在知识覆盖通过后读取同一来源校验的当前评估；若任一场景并非 realized/continue，运行以 `scene_feedback_needs_author` 阻断，不再静默进入下一章。作者可绑定评估修订选择“接受现稿并继续”或“重写本章”；决策记录保存章节、评估版本、来源摘要、时间和补充指令，旧评估或过期运行版本拒绝使用。重写有两次及剩余模型调用预算上限，创建新的创作意图代次和工作步骤，重新执行 Draft → Extract → Assess；评估摘要只作为修稿提示，不进入 Canon。界面展示偏差依据并提供两个动作。确定性三章测试覆盖偏差阻断、旧评估拒绝、重写、再次评估、明确接受、末章预算不足及滚动规划读取；真实模型的评估正确性、作者体验和完整 S3 验收仍需独立证明。

重写已保存部分工作稿后若模型中断，作者可走原运行的显式重试：先核对该任务输入，再保留已有候选及反馈提示，创建同一 WorkStep 的新 Attempt；不把部分产物当成完成，也不绕过重试次数和调用预算。三章测试在首章反馈重写中插入部分写入失败并继续到三章完成；UI 对这种状态提供“按评估要求重试本章”。

来源水位现同时覆盖正式作品修订与对象/知识头；仅新增或改动章节目录而未写正文时，运行也会阻断并保留已保存的工作稿。当前活动任务的输入修订在恢复前重新核验，运行自己创建章节则记录新水位；`Check` 的直接调用不能绕过来源或活动任务门禁。回归测试覆盖“正式章目录变化、对象头不变”的任务与运行路径。此处是保守失效策略，未替代 S2 的细粒度查询计划和完整依赖图。

`Check` 评估后的运行更新增加来源 CAS：评估期间若正文、知识、场景评估或正式作品修订改变，最终写事务比较原输入摘要并拒绝推进，不把新水位覆盖进旧检查结果。失败事务不改变 GenerationRun 或 WorkTask；专门的领域回归验证拒绝与原子性。该保护不宣称模型评估正确，也不替代自动创作的完整许可协议。

GenerationRun 的许可现在由数据库层保证同作品仅有一个未终结运行，包含 blocked 状态，不借 UI 最近 20 条列表做授权判断。创建事务在排他写锁内重查章节知识前提、源摘要和主分支快照；检查与写入之间出现外部改稿时不留下新的运行或任务。作者取消旧运行后才能申请新许可，且已有章节需要当前正文及知识就绪。此边界仍缺 token/费用回执及受保护对象的完整许可模型。

取消 GenerationRun 现在以同一事务校验运行版本并撤销活动任务能力，同时更新步骤、尝试及父任务；CAS 失败不会先取消子任务，取消成功后迟到工具写入不能落库。已认领任务在暂停期间仍可完成，恢复时再对账；即时中断与替换仍未实现。

已有章节现在可申请新的至多三章续作许可：章节必须从一连续编号，全部当前正文的建模批次就绪且匹配源修订；起始阶段按当前简报/大纲候选决定，已有二者则从滚动规划进入，锁定规划拒绝覆盖。领域创建事务复核起点、阶段、目标、来源和分支；新意图只从新章节生效，UI 显示本次新增章节进度。三章完成后继续第四章的确定性 Runtime 用例验证了规划上下文和知识屏障；建章、作品修订、来源水位与运行状态现原子提交，故障注入证明事务末端失败不留下半成品，旧版本重复投递不重建章。长篇覆盖、真实模型效果与完整 GenerationPermit 尚未验收。

GenerationRun 的模型调用额度现在在任务认领事务中预扣，失败、进程中断或部分输出也占一次；重试产生新的认领与额度消耗，不再等任务成功完成才计数。最后一个合法认领耗尽额度后仍允许完成该任务及后续确定性检查，禁止再认领下一模型任务。该上限不是实际 token 计费，真实供应商回执与 token 预算仍未接入。

S4 首个只读影响路径切片已接通 Author-only `GET /api/projects/{projectId}/impact-analysis?entityId=...`，可选 `snapshotId`、`worldTime`、`maxHops` 与 `limit`。查询在同一 SQLite 读快照中沿显式 `causes/enables/prevents/motivates/foreshadows/paysOff/reveals/inputDependency` 出向关系枚举至多三跳，逐边返回来源修订、命题、批次、断言序号、原文证据及候选/确认标记；不同证据路径不合并成一个“确定失效”。同一查询按该身份当前/历史有效的名称索引进行有界正文检索，返回带字段路径和字符锚点的 `literalMentionNeedsReview`，因此未建模但字面提及的章节也能成为候选。名称最多 4 项，正文最多 30 项，索引高频上限和截断单独标注；别名缺失、代词和隐性语义提及仍不能召回。节点/边和结果有硬预算，超限报告截断；`explicitGraphComplete` 只说明该显式图的受限查询是否完整，`globalImpactComplete` 固定为 false，并列明未连接正文、语义依赖与其他解释缺口。报告是临时只读假设，不能用 `baseSnapshotId` 单独授权正式采纳，知识批次可在不推进正文快照的情况下变化。测试覆盖独立证据路径、非依赖关系排除、未建模正文命中、截断、旧/跨作品快照与来源失效；语义变更抽取、语义检索、反事实、跨对象提案、作者确认和可撤销应用均未实现，不能宣称 S4 完成。

S4 可选修订差异已与影响查询共用读快照：作者提供同一 draft 的 `fromRevisionId` 与 `toRevisionId`，当前查询要求 `to` 等于当前选中修订，历史快照查询要求 `from` 为该快照成员；缺一、跨对象、跨作品或与分析范围不符均拒绝。返回 Unicode 字符位置的正文变更区间与有界前后摘录，以及稳定 Scene ID 对应的新增、删除、移动和编辑状态。它只证明指定文本版本差异，不推断哪些命题从“烧信”变成“藏信”，不自动选择影响起点或正式应用修改；S4 后续仍需语义差异、反事实和 ProposalSet。

S4 修订差异现附有 `modelCandidateDelta`：两版都有唯一已发布的源绑定建模批次才输出候选主张的新增/不再抽取；排队、缺失或多个已发布批次均返回 `unavailable`，不把抽取缺口解释成事实被删除。候选包含来源修订、批次、断言序号和证据；相同主张仅改变证据锚点会计为重锚定而非语义变化。报告仍声明 `semanticTruthInferred=false`，最多展示 30 条且受字节预算限制，实体列表只从展示的候选推导。后续需补语义提及召回、可靠变更判定、跨对象 ProposalSet 与作者确认。

章节页现接入 Author 只读影响检查：作者可选已建模实体或输入实体 ID，查看关系传播的来源路径、正文的字面提及与当前稿/父稿的候选主张差异；未保存编辑会清掉旧报告并阻止发起新分析。所有空结果都只表示当前有界范围未命中，界面始终提示未证明全书影响完整。Electron 桥接和渲染用例验证版本参数、证据展示及脏稿撤销；这不是反事实模拟或跨章选择性应用。

反事实知识覆盖层初版使用不可变 `story_hypotheses_v1`，记录 Author 提供的意图、固定 main 快照、有限条类型化假设与幂等键。`suppressClaim` 只能命中快照所捕获的建模批次、来源修订、断言序号；`assumeClaim` 只能指向该快照可见实体。重读历史知识状态后，只在返回的模拟投影中移除精确主张或追加 `assumed` 主张，冲突标为 `hypothesisConflict`，不写正式知识、Canon 或主线。独立证据保留；投影上限、未投影的排除、冲突上限和不确定时间均通过 coverage 保守暴露，全局影响始终不宣称完整。Author-only HTTP、Electron 桥接及章节 UI 可读取同一快照的带源主张，选择要排除的原始证据，再追加并查看一条真假假设；选择不会排除未选的同类证据，投影截断时 UI 明示未知。当前不包含全书反事实推理、正文试写、模型任务、假设到跨对象提案的转化和正式应用，仍需按 S4 完整门槛继续建设。

跨对象 ProposalSet 固定当前 main 快照和作品修订，引用至少两个已有的 `story_reviews_v2` 审阅，记录各自候选/已采用修订及作者声明的操作依赖。创建时拒绝未通过的阻断检查、锁定对象、非快照成员、重复对象/审阅与依赖环；Author-only 预览按同一数据库读快照重新检查候选、审阅、锁、head 和版本，报告缺少的依赖与过期操作。结构读取不接受事实选择，故不承诺可提交；显式 Preview 接受作者选择并复用 Apply 校验，`applyReady` 仅针对本次只读预检。正式应用在同一事务内重验所有选中审阅、绑定修订、选择、声明依赖及确认事实来源，然后只推进一次作品版本并建立一个快照；组员保留独立 AcceptanceCommit 证据，但不能被单对象撤销接口拆开。整体撤销也在单一事务内生成补偿快照及每项撤销证据。领域和 Author-only HTTP 测试覆盖组应用、重复、失败回滚及整体撤销。Electron 工作区支持规划、正文和身份候选的创建、分页找回、声明依赖、实际选择预检、采用与撤销；通用撤销入口识别组提交。实际采用成员清单来自持久化回执，不从原始提案推断。创作演进查询以快照和接受记录的复合游标翻页，避免同一组员快照被分页切开时漏记，并把组应用 ID 关联到接受与撤销条目。它只证明声明依赖和有界来源闭包，不证明所有语义证据/跨任务依赖；模型提案生成与全局语义影响仍待实现。

### 原文阅读进度的领域归属

当前 schema 的 `story_reading_checkpoints_v1` 以真实 WorkStep 为主键，保存唯一阅读流的有限最新状态及完整性摘要。任务内 `query_story` 保持只读，`checkpoint_reading` 是根 Agent 显式候选元数据写入，`read_reading_progress` 是重新授权的只读恢复入口；子 Agent 无权读写根步骤检查点。公开 Runtime 同样核验传入的根/子 Agent 身份，不只依赖 MCP 的前置检查。

记录的是可核验原文页面与模型声明，不是世界模型事实或正式内容。来源与查询范围一致才允许跨 Attempt 重绑定位置；来源变化隐藏摘要和游标。连续范围末尾、文学理解质量与任务完成各有不同权威，不可合并成一个“完成”状态。既有恢复账本持有提交回执，检查点不增加另一份调度/小说产物账本。详细契约见 [任务内长篇阅读检查点](READING_CHECKPOINT_DESIGN.md)。

作者 WorkStep 查询增加单独只读投影，与根能力查询区分：归属和来源完整性在同一 WorkTask 事务核验，过期/被撤销的 Attempt 不禁止作者查看历史记录，但绝不授予恢复凭证。只显示有界计数与遍历状态，来源失效和记录损坏不返回计数；数据库故障不能被包装为进度缺失。UI 刷新不创建任务、不写小说或模型结论，不公开候选摘要与游标。见 [阅读进度 UI 与领域契约](READING_PROGRESS_UI_DESIGN.md)。
