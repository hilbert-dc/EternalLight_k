# 无关键词原文召回与 Codex 语义阅读

## 决策与范围

目标是移除“候选必须先字面命中”的限制。新增有限查询操作 `passages`，由当前 Codex 任务按原文游标逐页阅读，在同一任务中用既有 modelSemantic 判断本页相关性。任务/模型/工具执行仍由独立 Agent Engine/Codex 管理，Rust 只选取授权来源、构建字符锚点、校验游标与预算。不新增供应商 SDK、模型分类器、并行调度器或正式写入入口。

这是可遍历授权全书的原文通道，不是向量索引，也不能把读取一页或读到末尾当作全书语义质量通过。模型阅读成本受既有任务预算约束；完整审计的持久检查点与真实模型/人工金标评估仍须继续建设。

## 当前契约

`StoryQueryPlan` 新增 `{type:"passages",cursor:null|string,maxChars:80..400,limit:1..4}`。最多四步、4–9 KB 报告、9 KB 请求计划及共享证据预算保持不变。首次使用 literal ranking，之后可绑定本页摘要提交完整模型判断。候选集不再要求与问题共享词。游标继续请求同一问题和步骤 ID，可降低 limit/maxChars/整包预算重新读取；不允许改变任务、作品、来源水位或视角后沿用。

直接读取当前选中不可变 draft 修订，不依赖可能缺失的派生检索索引。普通范围优先遍历章节正文 `/body`，不重复读取标题、元数据和 scene 副本；当前稿没有非空 body 时读取其 scene 正文。Writer 目标场景前缀只读取已获准场景 `/sceneGroups/{i}/body`，前章优先读 `/body`。按章号、对象身份、场景序号和 Unicode 字符位置稳定翻页，长正文拆片，保留完整字符锚点和源修订。页面边界重叠 32 个字符以减少跨片段线索切断，不跳过原文。每个响应只返回有限片段，不加载整书进模型上下文。

游标有严格长度/格式/位置检查，摘要绑定 Task、project、问题、步骤 ID、原始 TaskQueryScope 政策与来源水位。游标位置只是下一读取位置，不是可信完成证明；作者/模型可选择范围内位置，但不能由此签发已扫描范围。底层授权、取消和来源校验与 query_story 同快照执行。POV 尚无原文认知证明时保守返回固定空集与不足，不输出隐藏章节/正文计数或末尾位置。

报告 coverage 始终 `complete=false`、`semanticCompleteness=unknown`；分别给出 `pageComplete`、`endOfScopeFromCursor`、`startsAtBeginning` 和返回量。非初始游标到末尾不表示之前页面已被模型消费。预算裁剪同时清除页完整/范围末尾标记并撤除下一游标，要求从原页以更小请求重读，不能跨过未返回证据。ModelSemantic 的 candidateScope 改为 `authorizedBaselineResults`，同时覆盖字面检索与原文通道，不保留历史输入格式或双轨实现。

## 单人五视角设计检查

依用户要求单人推进，不召集评审。架构：同一查询/任务链，原文不是第二事实权威；技术 A：源读快照、游标绑定、字符/重叠边界、范围/取消和预算；技术 B：公开 HTTP 与真实仓储遍历/失效/重排/负向回归，MCP schema 和提示同步；产品：改述证据可在无需关键词的情况下进入模型；UX：未扫描/未评价保持明确，不能声称全书已理解。零兼容门禁通过，无新增依赖、数据库迁移或上游内核改动。

## 验收与剩余项

自动验证须证明：无字面词仍可读到证据；多章/长文本/Unicode/重叠扫描无漏字符；只读原文不受索引缺行影响；低预算不能跳页；旧源、异问题、跨任务或伪造越界游标拒绝；滚动/源章/Writer 场景和 POV 隔离；本页可真实语义候选重排；Context Pack 与 MCP 传输保持同契约。

真实供应商自主寻找改述证据、模型检索成本/时延、大作品全量模型阅读、持久全局语义审计、人工金标与 Windows 仍为原目标剩余门槛，不能用人工评分 fixture 替代。后续可增加版本绑定的语义索引作为加速通道，但不能让索引成为正文或语义事实权威。

## 本轮实现与验证记录

原文读取、游标与来源校验已在 Rust Story Core 落地，公开 Runtime HTTP、原生 MCP schema、宿主共享查询指令和 Context Pack 已接通。同一 Codex 任务能够读取两页原文，提交摘要绑定的本页候选评分，再读回包含相同报告的 Context Pack；没有增加独立模型执行路径。

新增一项 Core 原文/派生索引独立性测试、三项 Runtime HTTP 集成测试及一项真实 Codex/Engine/MCP/Runtime 回环测试。覆盖 Unicode 与跨页字符完整性、授权范围、POV 保守隔离、跨任务/来源变化游标失效、预算裁剪重读和语义重排。回环使用可控供应商响应，证明生产工程链路，而不是实际供应商自主检索能力或文学质量。

`CARGO_NET_OFFLINE=true npm run verify` 终态退出码为 0：类型检查、构建、两轮原生测试、引擎与委派/发布测试、146 项宿主测试和 12 项 Electron UI 测试通过；Core 单元测试现为 99 项。原生工作区 `cargo clippy --workspace --all-targets --locked --offline -- -D warnings` 通过。此次验证未运行 Windows 或真实供应商质量认证。

实施后五视角自检：架构保持单一任务与证据权威；技术检查确认原文不依赖派生索引且预算裁剪不跳页；集成检查确认真实内核使用公开工具链；产品获得不依赖关键词的证据入口；UX/报告仍明确区分本页、范围末尾与全局完成。上述为实施者自检，不代表独立专家评审。S1–S5 整体目标尚未据此宣告完成。

## 原文读取规模优化方案

当前 CTE 对授权范围的正文/场景展开 JSON 后再排序取一个字段，分页可能反复解析整个作品。目标是先按章节与对象的键集顺序取得一个授权不可变修订，只解码该修订并按范围输出其正文或已授权场景；源 JSON 的内部解析不等于将整修订暴露给模型。空来源通过同一有界作品顺序推进，不以索引完整性作为正文读取前提。任务授权、来源水位、读事务、字符锚点、场景界限及报告契约保持唯一当前实现。

字符截取改为一次向前读取至片段末尾并检查是否还有字符，不再为每片段计数整个字段。游标仍使用 Unicode 字符位置，不伪装成 O(1) 随机跳转；源 JSON 解码和跳过前缀仍随当前修订大小增长。作品来源清单的核验也仍有规模成本，不缓存过期授权或引入第二权威。

新增独立 release 基准 `npm run bench:passages`，复用生产百万字/50,176 断言构建链，在冻结同一任务下测第一页、连续页及后部游标页，逐项核验来源、字符锚点和未认证全书的覆盖标记，输出环境与首查询/热态 P95。追加从初始页至范围末尾的机械遍历：每章首锚点必须从零开始，后续片段不得有空洞或停止推进，各章末尾与实际正文字符数比较。这只证明确定性分页完整性，不证明模型消费了所有页面、语义召回质量或持久恢复。五视角实施前自检：架构不另建调度/模型路径；技术检查保留授权先于解码及空来源推进；测试包含现有完整 HTTP 回归和真实规模基准；产品减少翻页等待；UX 不改变完成含义。依用户要求由实施者检查，不组织独立评审；无旧格式兼容、迁移、新依赖或上游内核改动。

规模优化实施后：旧整书 JSON 展开路径已替换；新增空章节/场景推进与仅解码所选来源的两项测试，原文 Core 测试共三项，原 HTTP 三项继续通过。release 基准逐章/逐页锚点与完整字符对照通过，详见 [长篇原文读取证据](PASSAGE_READ_BENCHMARK.md)。完整 `npm run verify` 终态退出码为 0（两轮 native、Core 101、引擎 180、委派 2、发布 7、宿主 146、UI 12），严格 native Clippy 通过。当前仍有既有前端大包体警告。

实施后五视角自检确认边界与方案一致：同一 Task/授权链，无新增权威或调度器；空来源不会停止推进；未来章及未获准场景不进入返回片段；生产 HTTP 与真实 Codex 工具回环通过；未知语义覆盖保持未知。未增加兼容层、依赖、schema 或上游内核改动。机械全书遍历已获得规模证据，持久模型阅读检查点、真实供应商/人工金标和双平台仍未完成；本轮是进展，不是 S1–S5 总体验收。

## 连续阅读的持久进度切片

原只读分页保持不变，增加独立的根 Agent 检查点工具，保存连续页的有限候选摘要、计数和下一位置。显式写入会在同一事务重查原报告并匹配 contentHash，不能将跳页、自造已读范围、预算裁剪页或无原文权限的 POV 查询登记为已读。恢复由现有 WorkTask/Attempt 链执行，重新校验来源并重绑定当前凭证，页预算不重置。此切片仅补齐可恢复的声明式页链，不把百万字机械遍历或保存成功升级为全局语义/文学质量证明。详见 [任务内长篇阅读检查点](READING_CHECKPOINT_DESIGN.md)。
