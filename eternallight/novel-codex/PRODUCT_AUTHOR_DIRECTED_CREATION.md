## 1. 核心决策

默认先帮助作者形成认可的故事方向，再逐层展开近期安排，最后写正文。规划不是必须填完的表格，也不是不能修改的剧本。

推荐主路径：构想／故事梗概 → 全书大纲 → 卷纲（可选）→ 单元纲（可选）→ 章纲 → 场景安排（可选）→ 正文。远处粗、近处细；关键不确定点可以先试写，正文中的好发现可以反过来修改规划。

产品承诺是“让作者看见方向、比较关键选择、把认可的安排写成可持续修订的作品”，不是“全自动生成必然更好的小说”。提高文学上限仍是待验证假设。

首个交付目标：从一句构想形成可编辑规划和近三章安排，按明确版本写出第一章；作者能检查本章依据什么、偏离了什么、后两章哪些安排需要重新考虑。

优先级调整：单章可靠性与规划指导基础 → 固定创作依据／取证 → 关键片段探索与规划深审 → 局部修订与组合采用 → 完整分支与连续多章；详细依赖以 v1.1 优化路线为准。当前测试阶段只保留已接通的权威模型；未接通的旧 AG-1 起步 schema 和旧入口不作为兼容面保留。

## 2. 为什么可能提高上限，以及为什么未必

我们的设计判断：规划主要改善方向控制和长篇兑现能力；探索、具体场景、作者经验和反复修改，才可能使作品超出第一版构想。不能把“更符合大纲”直接等同于“更好”。

| 要改善的能力 | 产品机制 | 主要反作用 |
| --- | --- | --- |
| 作者意图不在长篇中丢失 | 有版本的方向、安排与正文来源 | 太早固定平庸构想 |
| 关键想法有机会被发现 | 在真实分歧处比较短试写 | 方案过多、AI 首案造成锚定 |
| 人物和语言有具体质感 | 保留作者原始笔记、样段、修改理由；场景验证 | 变成固定文风模板或人物标签 |
| 长篇能兑现伏笔和关系变化 | 规划依赖、阅读位置、实际正文反馈 | 将情绪、含混和留白误判为缺陷 |
| 作者敢于推翻不好的安排 | 局部改纲、差异预览、可恢复版本 | 无依据的自动改纲扩大漂移 |

有限研究支持：Re3 将规划、当前故事状态和修订结合；DOC 将详细分层大纲与生成控制结合，在各自数千词量级的故事实验中改善连贯性等评价。这支持“让规划真正进入生成与检查”，不证明中文超长连载、专业作者个人表达或文学最高水平必然提高。[Re3 原始论文](https://aclanthology.org/2022.emnlp-main.296/)，[DOC 原始论文](https://aclanthology.org/2023.acl-long.190/)。

反向证据也必须保留：Dramatron 的团队明确指出，自上而下流程并不适合所有作者，研究的是人机共创而非无人写作；一项短故事实验同时观察到 AI 创意辅助与作品间相似性增加。由此提出的产品假设是“保留作者先入材料与可跳过的探索”，不是声称已经解决同质化。[Dramatron 项目说明](https://github.com/google-deepmind/dramatron)，[Doshi 与 Hauser 原始研究](https://arxiv.org/abs/2312.00506)。

## 3. 用户、范围与非目标

优先服务三类中文小说作者：有构想但尚未成书的人；持续连载且有滚动安排的人；习惯从人物或片段探索的人。第一阶段为单作者、本地作品工作区，沿用 Electron/React、Python Runtime/SQLite 与现有模型接入层。

首版包含：故事方向、可跳层规划、近期章纲、单章生成、来源追溯、作者控制、偏离提示和恢复。手写与 AI 生成使用同一版本链。

暂不包含：一键百万字、自动发布、热度预测、文学总分、无人裁决重大剧情、全书任意分支融合、多人实时协作、跨作品自动学习偏好。整本导入、跨卷重构和读者反馈分析留作后续。

术语：

- “构想稿／故事梗概”是对故事的设想，不是正文草稿。
- “单元”是一段可连贯讨论的叙事任务，例如一次调查或一段关系变化；不规定固定章数。
- “规划采用”表示作者认可某版安排，不表示其中事件已经发生。
- “正式稿”表示作者采用的正文；“已发表”是额外状态，不能被自动改写或重新解释。
- “待复核”表示既有依据变化，不等于原文有错，更不等于自动重写。

## 4. 分层规划：每层回答一个问题

| 层级 | 帮作者回答的问题 | 推荐内容，不是必填表 | 展开时机 |
| --- | --- | --- | --- |
| 构想／梗概 | 我想写什么，为什么想写？ | 原始设想、人物关系、期待读感、暂定结局 | 起步；允许只有一句话 |
| 全书大纲 | 这本书总体将走向哪里？ | 核心矛盾、主要因果锚点、人物变化、承诺与待定问题 | 默认先形成粗线条 |
| 卷纲 | 这一阶段会把故事推到什么位置？ | 阶段目标、主要变化、揭示与未兑现事项 | 长篇按需；可以没有卷 |
| 单元纲 | 近期这段故事有什么作用？ | 进入条件、人物选择、关系或认识变化、退出状态 | 当前单元优先细化 |
| 章纲 | 这一章值得写、值得读在哪里？ | 本章作用、承接、视角、允许变化、禁止提前确定的事项 | 下一章详细，后两章概要 |
| 场景安排 | 通过哪些具体行为体现它？ | 在场人物、欲望、阻力、动作、信息、情绪余波 | 需要时展开，可直接写正文 |
| 正文 | 读者实际经历了什么？ | 具体语言和行为；实际结果可能不同于计划 | 生成或作者手写 |

不是所有章节都必须有外部冲突、状态翻转或悬崖结尾。安静、犹豫、气氛、情绪消化都可以是作者目的；也允许作者暂时说不清目的。软件不能因此拒绝保存或采用。

三项规则：

1. 允许全书→章，也允许梗概→单元→章；结构负责组织，不负责限制写法。Beat 始终可选。
2. 远期节点保持简短锚点和未决事项；默认一次只细化当前单元、下一章及后两章概略安排。窗口可调整。
3. 上级安排必须转化为本章可查看的依据。没有相关引用的全书文档，不算已接通规划链。

## 5. 作者控制：少填表，不隐藏决定

### 5.1 状态、保护方式和信息权限彼此独立

状态包括待定、暂定方案、已认可规划、已采用正文；它们不能共用一个含混的“已确认”。待定不是授权模型自行定案，暂定假设只能在允许的试写范围内使用。

保护方式就地操作，不强制作者填结构化字段：

- 保留意图：例如“女儿最终选择留下”，实现方式可以改变；正文是否实现是语义判断。
- 保留安排：例如“本卷不揭父亲身份”，规划字段由作者保护；生成需要带上此要求并检查疑似偏离。
- 锁定原文：保护作者选定的精确文字；模型不能以近义替换绕过，修改必须由作者另行解锁或明确批准替换。
- 可自由发挥：例如本次允许改变餐桌物件、对白和动作细节；不能越过更高层保护内容。

系统可把自然语言整理成一行理解供作者修改，例如“本卷不揭身份〔保留安排〕”。不得悄悄将普通作者描述升级成永久锁定。

### 5.2 哪些地方需要作者认可

方向形成、进入未认可的重要卷／单元、重大偏离、正式采用是四类触发条件，不是四道固定审批。已表达清楚的意图可直接作为本次任务依据，不重复问同一件事。

常规规划细化可以随“采用这个方向并展开当前单元”一次处理；普通正文、被选事实和已审阅的计划变化可集中采用。

改变作者锁定、真凶、核心人物生死／关系、重要揭示时机，或重解释已发表事件，必须展示独立的“方向变更卡”：原安排→建议变化→依据→影响范围。不能藏在“采用本章”里。已展示的多项变更可以一次确认。

AC-1 就提供基本变更说明与明确处理入口：作者主动改动保护项，或系统识别到重大冲突时，先决定修改、保留或驳回疑点；不能悬而不决地顺带采用。AC-2 才增加自动生成的改纲提案及更丰富的影响分析。不承诺模型能发现全部重大语义偏离。

### 5.3 秘密与潜台词

分开维护四种信息：作者不供模型使用的材料；作者允许 AI 使用但读者尚未知晓的幕后信息；每个人物已知／怀疑的信息；读者到当前位置已知的信息。

“仅自己可见”的内容不得出现在任何模型提示、摘要、检索片段、工具结果或错误说明里；连“不得说出凶手是某人”也已经把答案提供给模型。此类模式只能使用不含答案的行为要求。

“可供 AI 创作、暂不揭露”可以帮助潜台词，但不承诺语义零泄漏。作者可以按作品设置并按任务覆盖供规划／供写作权限；使用范围可查。角色说破、叙述者说破可提示疑点；线索是否太明显、暗示是否足够是作者判断，不能自动删除所有伏笔。

权限清单必须参与会话隔离。收紧权限时，使用不继承相关旧历史、摘要和检索缓存的隔离会话，不能只过滤新一轮检索。此前已获准发送的材料不能追溯撤回；排除禁止材料及其泄密派生内容，也不等于保证模型无法从其他线索推断剧情。

## 6. 核心旅程与界面

### 6.1 从空作品开始

1. 作者写一句设想或粘贴原始构想；题材、篇幅、结局可待定，保留原输入。
2. 系统整理一页方向卡，区分作者原意、模型建议和未决问题。只有实质影响近期写作的问题才请求选择。
3. 作者点击“采用方向并展开近期”。生成可编辑全书粗纲和当前单元／卷纲，建立近三章规划身份，不伪造已完成的正式章节。
4. 作者查看或修改章纲，点击“按这些安排写第一章”。任务绑定被认可的确切计划版本，自动组织必要场景、生成、保存、检查。
5. 中央展示可读正文，侧栏展示本章依据、偏离和未检查项；不是只交付聊天里的大纲或一句“已完成”。
6. 作者修改并采用。正文编辑会使旧语义检查过期；系统标明受影响的后续安排，保留没有关联的内容。

首版允许作者手动修改后续章纲并确认已处理；自动提出局部改纲方案在第二阶段交付。

### 6.2 从片段开始／直接写章

保留“直接试写”和“继续已有作品”。作者可只给一场晚餐、对白或章节意图；系统保存最小局部任务快照，缺失设定标为待定，新增设定标为本次候选假设，不强制补全全书。

独立片段可一直独立保存，也可经作者选择用于生成梗概或关联章节。首版可以单候选试写；第二阶段再加入隔离的双候选比较。它们均不得未经采用写入故事正式事实。

### 6.3 第二阶段：关键试写与反向改纲

仅对真实的不确定点提供最多两个短试写，可验证情节、关系、视角、声音或节奏，不要求每章选方案。方向明确时直接执行，不制造虚假分歧。

先展示“区别与后果＋关键片段”，再按需展开长稿。支持都不选、手动组合后生成新候选、沿用作者原案；模型只能解释或推荐，不能以文学总分代替作者选择。

保留偏离时，系统产生局部变更建议：对应原文、旧新计划、受影响节点、保护冲突、仍未知的影响。先标记显式依赖，语义推测另列；不宣称穷尽全书因果。

### 6.4 工作区布局与状态

沿用现有工作区：左侧可折叠作品结构；中央规划／正文编辑；右侧本轮创作决定、依据与检查。章节旁可展开“来自哪个单元、承担什么安排”，稳定 ID 和修订号默认隐藏在详情里。

空态只提供构想、直接试写、继续作品三个入口。生成中显示当前目标、已保存内容和停止；失败或结果未知显示可恢复边界，不自动换成成功。采用后显示实际变化和撤销入口。

作者不应成为批量审稿员：默认优先显示少量高价值提示，可展开全部；限量不能隐藏阻止提交的真实版本或权限错误。审美分歧不作强制阻断。

键盘可操作结构树、折叠、修改和采用；焦点在保存后不跳走；状态不只靠颜色；错误关联具体输入并被辅助技术读出。实际 UI 仍须在实施阶段专门评审。

## 8. 技术方案边界（供实施设计使用）

### 8.1 最小领域对象

下表是概念设计，不是已生效 API 或确定的数据库迁移。优先扩展现有修订／审阅体系，避免再造第二套事实权威。

| 对象 | 最小责任 | 阶段 |
| --- | --- | --- |
| PlanNode | 稳定身份、类型、父节点、顺序、可选关联章节；允许跳层，拒绝环 | AC-1 |
| PlanRevision | 不可变内容、来源、保护字段、父修订；以自然语言为主 | AC-1 |
| PlanBaseline | 作者本次认可的节点→修订映射，可只覆盖局部 | AC-1 |
| TaskInputManifest | 显式操作、目标、作品版本、实际计划引用、位置、权限、上下文与预算 | AC-0／1 |
| Draft provenance | 正文引用任务、输入清单及精确规划修订，而非仅一个自由字符串 | AC-1 |
| PlanImpact | 哪个依据变化使哪些节点待复核；显式依赖与语义建议分开 | AC-1 |
| Experiment／TrialRevision | 待验证问题、两个隔离候选、对照标准、作者选择及理由 | AC-2 |
| PlanChangeProposal | 原文依据、旧新规划、受影响范围、保护冲突和作者决定 | AC-2 |

组织层级是树，跨节点依赖是有向关系，不能把两者混同。章节重排不改变身份；上级修订只标记依赖闭包需要复核，不能静默重写全部子节点。粗粒度版本冲突可先保守拒绝提交，但要说明，不伪装成精确局部判断。

只有本次任务输入固定，作者仍可随时新建修订；旧稿继续可读。无全书规划的片段任务固定局部输入与实际引用集合，不强造完整基线。

### 8.2 从规划到正文的执行链

作者选择目标与范围 → Runtime 创建任务清单 → 按权限编译上下文 → 模型生成并保存候选 → 验证最新目标交付 → 版本化检查 → 作者选择采用内容 → 事务提交 → 影响提示。

规划、试写、正文、审阅使用显式操作和不同写入权限；自由对话可建议操作，但不能靠命中“写”字决定工具权限。模型不得自行改作品、目标章、POV、场景位置或读取目的。

上下文保留：作者本轮意图、相关上级要求、本章安排、当前单元因果、位置允许的原文、已知状态、允许的自由度。全书各层全文不应每轮全部注入。

所有输入来源必须使用同一可解释快照，包括正式稿、临时假设、规划、摘要、搜索与错误内容。引用原文需带修订和位置；检索不到应说明缺材料，不能用模型臆造前文。

保护要求进入不可静默裁剪区。可选材料按优先级删减并报告遗漏；放不下必须缩小任务或暂停。现有 UTF-8 字节预算不是 token 预算；还要核算最终提示包装、工具结果与历史开销，预留输出空间。

完成意味着最新持久化目标输出满足对应操作：非空正文、正确目标、所需完整程度与来源均有效。规划任务必须有对应规划产物；检查未运行或语义不确定不冒充通过。保存部分稿始终允许，不能靠强制标 complete 才保住内容。

### 8.3 试写与采用隔离

两个短试写不依赖完整 AG-1：各有不可变修订与独立候选头，共享固定输入，互不读取、覆盖或把假设写入全局事实。只有跨章承接临时状态时，才需要连续分支的工作提交链。

采用围绕作者本次选中的清单：可以只采用规划，也可以采用正文并保留未处理的非重大规划偏离；已经识别的保护冲突或重大改向须先按第 5.2 节明确处理，作者可以驳回误报。正文、事实、计划不强制三者一起选；但依赖新正文的事实必须与对应正文一起采用，或引用已经采用的有效证据。

Runtime 在提交前检查权限、版本和必要依赖；选中内容全部提交或全部回滚，本地幂等重试返回同一回执。未选择的重大改向不混入事务。后续撤销不能覆盖更新的作者修改，冲突时保留双方版本并要求处理。

### 8.4 边界、恢复与模块

推荐在 Runtime 内拆分规划、上下文编译、影响与试写模块；Electron 负责显式操作与任务调度，React 负责编辑／比较／决定。沿用窄 IPC、输入校验与独立运行环境，不向 `codex-core` 填小说领域业务。

每次任务记录输入版本、提示／schema 版本、模型配置、实际调用尝试与保存边界，便于追溯；不能承诺重新运行产生一字不差的文本。

请求发出后断线可能是“结果未知”，不算零消耗。优先按已有请求／回合标识查询或恢复；无法核实而再生成时，计入新尝试。只承诺本地写入幂等与限制发起次数，不承诺外部模型执行或计费 exactly-once。

作者材料和未公开正文默认不进入外部搜索、公开分享或跨作品记忆。需要外部生成服务时明确发送范围；日志保留必要 ID／统计，不默认记录私密原文或密钥。导出区分正式稿、规划、试写与作者私密资料。

涉及 schema 的后续实施只覆盖当前格式的空库初始化与当前版本故障恢复；fixture 和测试数据库随 schema 同步重建。macOS／Windows 路径及 Linux Runtime 均需覆盖。

## 9. 验收故事：父女晚餐

作者原意：“女儿怀疑父亲隐瞒了过去。想写克制的晚餐，不要当场摊牌；本卷不揭他的身份。”

| 层级／动作 | 示例内容 | 需要验证的能力 |
| --- | --- | --- |
| 全书方向 | 一段以保护为名、逐渐暴露代价的父女关系 | 不把题材模板当作者主题 |
| 当前卷安排 | 女儿从信任转为试探，父亲身份仍不揭露 | 上级保护要求传至当前章 |
| 当前单元 | 三次日常接触中的试探与退让 | 可以没有打斗、反转和悬崖 |
| 第一章计划 | 一次晚餐；读者看见躲闪，不获得身份答案 | POV、读者认知与人物认知分别处理 |
| 正文发现 | 女儿没有追问，反而替父亲盛汤 | 允许好正文偏离预想手段 |
| 作者修改 | 将“偶然发现证据”改成“故意制造试探” | 修改被保留，旧检查过期 |
| 后文提示 | 第二章原先依赖偶然发现的动机待复核；无关支线不变 | 有证据的局部影响，不全书重写 |
| 第二阶段试写 | A：女儿主要在怀疑；B：女儿知道他在撒谎但未知身份 | 差异涉及动机，不用措辞差异伪装方案 |

“女儿知道他撒谎”不等于“女儿知道全部真相”。采用试写不自动确认父亲身份；若建议改变揭晓时机，必须经过方向变更卡。正文是否足够克制由作者裁决，不由一个自动分数决定。

## 12. 如何验证对作者真的有帮助

分清三层结果：可靠性（有没有写错对象或丢稿）、可用性（能否控制和修改作品）、创作价值（是否更愿意保留和继续写）。前两者通过不等于第三者成立。

拟招募 8～12 位中文小说作者，包含连载、完本和新作者，覆盖细纲、滚动规划、探索写作；题材至少含悬疑、人物关系、日常慢节奏。另邀请 1～2 位创作软件产品经理、1～2 位长文本技术人员审查交付可行性。此为招募计划，尚无真人参与。

第一阶段在同一批作者中交叉体验 A“现有单章协作”和 B“分层规划后写章”，平衡先后顺序，使用难度相近但不重复的任务，固定模型、输入材料和总生成预算。记录等待、审阅和修改时间，不把前期规划开销排除在外。

第二阶段只对有真实关键分歧的 4～6 位作者体验 C“规划＋关键试写＋局部改纲”；不把小样本硬拆成三组推断统计优劣。对完成片段可匿名随机顺序盲评，操作体验本身不能盲化。后续再开展 30～50 章持续写作，观察远期兑现与返工。

初次作品回放访谈＋操作约 60～75 分钟；两周内至少三次真实写作，每次两分钟日志，最后二十分钟回访。材料须有作者使用授权，默认不公开原文，可退出和删除研究副本；联系、录制、报酬与材料外发另行征得同意。

关键记录：

- 作者是否认为“更像我想写的”“有值得留下的新发现”“仍然属于我的表达”“愿意继续这部作品”。
- 保留了哪些片段与新想法、为什么拒绝其他方案、实质重写时间、改纲成本、误报阻断与弃用理由。
- 人物动机、因果和信息安排的盲评意见；保留分歧，不合成为统一文学分数。
- 调用次数、实际用量、未知用量、等待时长、作者审阅分钟数和返工次数；金额只用可靠计费信息计算。

不把字数、采纳率、少修改、大纲覆盖率或模型自评分单独设为北极星。先用 pilot 确认指标可收集，再预先约定后续门槛；不事后挑选好案例证明上限提升。

试用预算初值：近期三章规划、单次一章正文、关键处最多两个短试写、最多两轮局部修复；每个任务另有调用次数、输出量和时长上限。这些是可修改的产品假设，不是已验证最优配置。

## 13. 本次结论与待决事项

共识：分层规划应成为默认主路径，但必须可跳层、可试写、可改纲；作者决定方向，软件维护依据并减少机械操作。先验证一章确实受作者规划控制，再扩展连续产量。

保留的风险：细纲可能限制发现；两个试写只提供有限探索；依赖关系不可能穷尽文学影响；知密写作存在泄露风险；语义检查有误报漏报；真实作者是否觉得负担更小尚待验证。

AC-0／AC-1 的纵向主路径已经实施，剩余真实旅程与发布证据见状态文档。下一阶段按 [创作质量提升方案](PRODUCT_CREATIVE_QUALITY_REFACTOR.md) 先准备 Q0 与 F1 创作依据，再按 F2／AC-2／P1/P2／N1/N2／Q1/Q2 的依赖分批开展实施设计和五角色评审。实际对外邀请哪些作者、报酬与材料范围由用户另行授权，本次不执行外部联络。
