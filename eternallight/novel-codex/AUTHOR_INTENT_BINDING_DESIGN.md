# 对话追加指令的作者意图绑定

2026-09-28 · S3/S5、C03–C05 · 实施者设计自检（无独立专家评审）。

## 目标与边界

对话任务的首条作者原话已经冻结在 Task manifest，但运行中的 `agent:steer`
仅发送到 Codex turn，没有领域记录，也没有阻止旧模型输出在新指令后登记动作。
目标是使每次追加指令具有同一 Task 内单调的作者意图代次，并把
`request_candidate_task` 固定到模型实际收到的代次。来源/章纲/作品版本门禁
仍独立执行。没有证据证明作者授权了哪种修改时，模型解释不能自动扩大许可；
后续需继续实现目标、对象和受保护内容的结构化许可闭包。

## 当前版本契约

排队接续设计：认领同一 WorkTask 的候选步骤、知识后续步骤或恢复步骤时，复用
最近创建的 Attempt 的冻结输入与自身检查点作为接续依据，在认领事务内调用
同一输入水位检查。当前 schema 新增持久 `sequence INTEGER PRIMARY KEY AUTOINCREMENT`，
按尝试序列而非可变的隐式 rowid、时间戳或步骤序号选择，后插入的建模
步骤也能成为后继依据；不改写源对话历史，不将外部编辑自动吸收入许可。
GenerationRun 继续使用自身的许可与来源门禁，不混入第二套推进权威。
暂停任务的 `resumeBlockReason`、恢复控制及实际认领共用该校验；外部改稿返回
`inputChanged`，而自身前置产物不造成误阻断。已有部分输出仍沿专门的检查点恢复
入口处理。序列字段直接修改测试阶段 schema，不实现旧数据库迁移。

排队接续实现后验证：当前 schema 下候选绑定 6 项、任务生命周期 11 项、意图
恢复 3 项、HTTP 检查点恢复 3 项通过；其中新测试同时验证外部修改导致认领及
恢复拒绝、无残留尝试，以及同一任务前置产物允许暂停恢复后继续下一动作。
Runtime 上下文 11 项也在本轮通过；核心严格 Clippy 通过。不把这些确定性
测试解释为自然语言授权、任意并行编排或真实模型联合创作已经通过。

来源事务补充：所有新候选动作登记都在同一写事务复核源对话的对象、工作版本及
知识水位，不能只依赖 HTTP 层的提前检查或正式作品 revision。已提交的同键同载荷
回执仍可读取，不重做动作；过期输入不能用新幂等键重新登记。验证作者或其他任务
在原对话读取之后保存候选的情形，确保旧动作请求不增加步骤、预算或回执。

该补充已统一到 `record_task_action` 事务，删除按候选类型重复的局部检查。
`task_action_binding_tests` 4 项和 Runtime `context_scope_tests` 11 项通过，核心
严格 Clippy 通过。新增用例以候选头变化、正式 revision 不变为条件，核验五类
新动作被拒绝、已提交回执可重放、WorkTask 与动作集合无残留变化。这只证明
登记时的来源一致性，不替代排队执行时对前置产物与外部编辑的因果核对。

1. 初始 `authorIntent` 为代次 0。追加指令必须由 Author 通过当前项目、活动
   advisory Task 写入不可变意图记录，绑定任务和实际文本。只允许一个待交付
   追加；任务完成、取消或其他作品不能追加。
2. 新记录先为 `pending`，此时不接受任何候选动作。Codex `turn/steer` 确认
   接收后，主进程将该代次标记 `delivered`；若发送或回执不确定，撤销任务能力
   并中断该 turn，不允许把未交付指令当成已授权。
3. 每个候选动作必须显式携带 `expectedIntentRevision`。领域层在动作登记同一
   SQLite 事务内确认它等于最新已交付代次，并把代次写入动作证据。旧代次、
   待交付代次及伪造未来代次都不能登记；幂等重试仅返回先前已持久的原动作。
4. 每次追加指令还将同一对话中旧代次、尚未领取的 Action/WorkStep 标记为
   `superseded`，历史回执可查询但不能再领取为子任务；新动作只依赖最后一个
   非失效步骤。已开始的候选步骤不允许在原对话中继续追加，以免竞争结果。
5. `agent:steer` IPC 包含 projectId，主进程核对当前活动 advisory Task 的项目
   和执行状态；非 advisory 生成调整走既有 GenerationRun 重规划入口。
6. 显式追加不是自动接受作品变更。候选仍需原有精确目标、来源、写入与作者
   Review 门禁。最终完成时不能有未决意图记录。
7. 候选领取与恢复时，Rust 从源 advisory 的冻结原话及已交付追加日志重建
   `authorIntent`，另存模型的 `candidateInstruction` 与来源绑定。客户端提交的
   文本不能覆盖该依据。桌面只消费新任务 manifest 中的冻结文本。
8. 同一步 advisory 重试继承上次尝试的完整已交付原话；存在 pending 的尝试
   不能通过恢复变成新一轮许可。步骤恢复门禁与任务创建事务共同核验。
   新尝试创建与旧尝试尚未执行的候选失效在同一事务完成，避免重新规划后
   又执行旧计划；历史已完成产物不会因此删除。
9. 完整作者原话累计限制为 24,000 UTF-8 字节，追加在写入 pending 前检查；
   超限不截断、不修改动作或步骤。桌面任务交接不重复嵌入同一作者文本，
   模型候选指令独立呈现，不能冒充作者原话。

本次恢复切片设计自检：复用现有 Task manifest 和尝试链，无新调度器或 schema；
Rust 独占执行依据重建，桌面删除重复拼接。验证首次领取、恢复、客户端篡改、
未交付追加与跨作品绑定，并保留当前接口一致性；按已授权方式由实施者自行复核。

## 设计自检

- 架构：意图记录只是 Task 的不可变输入日志；WorkTask/Step/Attempt 仍是唯一
  执行状态权威，GenerationRun 的许可与预算不被对话日志替代。
- 可靠性：先落库 pending 再通知模型；动作准入和代次比较同一事务。跨进程
  确认失败按不确定交付处理并撤销旧任务，而不猜测模型是否收到消息。
- 产品：作者看到的是“追加指令被接收/失败”，不是提示词注入等于已改稿。
- UX：非对话任务与跨作品操作明确拒绝；失败保留已有候选，不吞回执。
- 零兼容：直接改当前 schema、MCP 工具参数、Runtime、Electron、类型与测试；
  不做字段默认值、旧消息解析、迁移或双轨。

## 必须通过的联合测试

- Router/SQLite：创建 advisory，代次 0 申请动作；登记 pending 后旧动作拒绝；
  delivered 后代次 1 可申请，新旧/未来代次及跨项目登记失败；重复提交只返回
  原回执，不重置原许可或工作成本；完成/取消后不可追加。
- 桌面/IPC：运行中同项目对话可追加且模型收到绑定代次；跨项目、无活动任务、
  非 advisory、发送失败都不能形成可写的新许可；进程重启后的 pending 不被
  当成已交付。

## 实施后复核

Rust `story_task_intents_v1`、Author-only Runtime API、MCP 显式代次及动作/步骤
失效已接通；Electron 在 `turn/steer` 前持久化 pending，确认后 delivered，
失败则取消任务与中断 turn。候选启动会带入初始及追加作者原话，而不是只带入
初始请求；累计原话超出预算时停止追加，不截断。Router/SQLite 联合测试覆盖
待交付、过期/未来代次、旧步骤不能领取、最新步骤能领取、完成门禁及幂等回执；
桌面 fixture 测试覆盖跨作品拒绝、长 Unicode 追加及不确定发送的取消路径。

恢复补充：`task_author_intent_tests` 覆盖数据库重开后的候选领取、失败后同一步
重试、客户端试图覆盖原话、待交付意图阻止恢复、重新规划使旧候选失效，以及
累计预算失败不残留修改。桌面集成测试检查真正交给 Adapter 的模型输入，
确保包含追加要求、不包含旧工作目标，且作者原话只出现一次。

本次恢复切片验证结果：核心库 157 项及 5 组相关集成测试 26 项、Runtime
5 组集成测试 16 项、桌面交接与 IPC 测试 41 项全部通过。严格 workspace
Clippy 与前端构建通过；构建仍提示前端包体超过 500KB，未据此宣称性能验收。
所有计数只表示本次实际执行的测试，不代表完整工程或真实供应商认证。

这仍不是作者许可的语义证明：模型生成的操作/对象是否真正落在原话授权范围内，
还没有 Rust 可验证的结构化闭包。C03–C05、真实模型联合创作、作者质量、规模
和 macOS/Windows 门槛均未据此标为完成。
