# Codex 语义判断与来源绑定的证据重排

## 目标与职责

S2/S5 的下一切片是语义重排，不是向量召回或全书语义验收。查询规划、相关性解释和评分由执行当前任务的 Codex 模型完成，仍走独立 Agent Engine；Rust 不直接请求供应商、不维护题材同义词表、不增加平行 Agent 或任务调度器。下一步的全书语义通道与独立金标仍须继续建设。

后续原文通道已按 [无关键词原文召回](PASSAGE_RECALL_DESIGN.md) 扩展：基准候选可来自 `passages` 而不只来自字面命中，candidateScope 当前为 `authorizedBaselineResults`。重排本身仍不增加候选；Codex 可在同一任务沿版本绑定游标继续读取原文。下文旧切片记录的“字面候选范围”只是该切片当时的边界，不能当作当前仅能关键词检索的限制，也不因此宣称全书语义质量已通过。

## 当前协议

StoryQueryPlan 必须显式包含 ranking：

- `{"type":"literal"}`：首次查询使用现有字面排序、授权过滤、证据共享字典和预算裁剪，返回 contentHash。
- `{"type":"modelSemantic","baseReportHash":"…","judgments":[{"resultId":"…","score":0,"rationale":"…"}]}`：再次提交相同 question、steps 和 byteBudget，仅 ranking 改变。Rust 在同一授权读快照内重建 literal 报告；hash 不匹配即拒绝，不能上传报告、正文或新来源。

重建报告中的全部 resultId 必须一一得到判断，包括不同来源的矛盾主张；重复、缺漏或未知身份拒绝。score 为 0–1000 整数，rationale 非空且最多 256 UTF-8 字节；最多 64 项，完整请求计划最多 9 KB。没有候选时不能伪造判断，继续 literal 查询并说明不足。判断装不下时缩小原计划重新查询，不静默改成部分评价。

报告 plan 保留实际执行的 literal 基准计划，ranking 元数据记录原 hash、Codex 模型候选判断及未认证质量；每行保留原 literalRelevanceScore，再以模型分数重排。模型理由是相关性候选，不是原文证据、可信度、事实确认或执行指令。它不能改变候选/确认状态、身份、证据、冲突或覆盖，也不能声明语义完备。

排序后复用现有整条裁剪、通道保底、孤立证据清理、游标撤除及重新哈希。理由和元数据占同一 4–9 KB 预算；裁剪后的缺口继续传播到 Context Pack，不隐去未评价/未扫描范围。报告的 contentHash 同时绑定最终排序及其模型理由。

## 权限与版本

沿 query_story 和 read_context(queryPlan) 的同一 Task、能力凭证、取消、源水位和 TaskQueryScope 执行。作品切换、改稿、知识发布、计划/问题/预算改变、其他任务或 POV 报告不可重用 hash。子 Agent 仅能在可信根任务相同只读范围内评价；没有新 Author 权限或模型正式写入入口。

Writer、POV、滚动规划、源章建模与场景评估仍先过滤后排序。排序不能返回隐藏正文、后来身份合并、未来关系或他人认知；即使模型猜出隐藏 resultId 也不能纳入结果。使用当前 schema/接口同步替换全部调用方、MCP schema、提示和 fixture，不保留缺省 ranking 的旧格式兼容。

## 单人五视角自检

按用户要求单人实施，不组织独立评审。架构：原 Codex 执行与 Rust 查询权威不变；技术 A：同快照重建、hash 围栏、全项判断和预算；技术 B：公开 HTTP/Context Pack/MCP 与真实仓储范围测试；产品：让模型按问题判断相关性而非词重叠，同时明确不是扩大召回；UX：候选理由不冒充事实，错误与未知保持可理解。零兼容门禁通过，不添加供应商 SDK、依赖、数据库迁移或上游内核修改。

## 验收与剩余项

自动验证：语义候选改变实际顺序；字面分数与矛盾引用保留；跨任务/源/计划的旧 hash 拒绝；缺漏、重复、伪造来源与大理由拒绝；裁剪不留悬空证据或跳过遗漏的游标；Writer/POV 不能借排序扩权；Context Pack 同预算、同政策、同版本；MCP 正确传递当前协议。

完整 Rust/Runtime、相关 Host/MCP、构建及严格 Clippy 验证后记录证据。工程 fixture 中的人工指定评分只验证协议和结果排序，不能当作模型真实推理质量。真实供应商自主规划/打分、语义召回及人工文学/知识金标仍须独立验收；不以本切片宣布 S2/S5 完成。

## 实施与验证记录

已落地独立私有 `query_semantic` 模块与类型化 ranking；查询在原授权读快照内重建基准并校验全部结果。原报告打包拆出共用预算收敛函数，避免第二次证据规范化丢失共享引用。当前 HTTP、Context Pack、MCP schema、可信子任务转发、Host 对话与所有创作操作提示及调用 fixture 已同步替换；没有缺省旧格式兼容或模型供应商分支。

新增三项实际仓储/HTTP 集成覆盖顺序改变、证据/政策/水位保留、Context Pack 哈希与共同预算、确定性重复、跨任务/问题/索引水位的旧摘要拒绝、取消、缺项/重复/未知身份/过大 UTF-8 理由/非法分数，以及 Writer/POV 范围。新增三项核心行为回归覆盖冲突引用和确认状态保留、理由计入同一预算、裁剪后的孤立引用与游标清理，以及无效判断不改变原报告。MCP 转发回归覆盖根任务 literal 与可信子任务 modelSemantic 参数，真实来源校验由领域 HTTP 测试证明，不把模拟传输当作来源认证。

最终 `CARGO_NET_OFFLINE=true npm run verify` 退出 0，包含两遍完整 native 回归（98 项核心单测、新增三项 HTTP 与三项核心重排测试及其余集成）、180 项引擎测试、2 项真实 Codex 委派集成、7 项发布门禁、145 项 Host/Agent 回归和 12 项 Electron UI 回归。native 工作区严格 Clippy（`--workspace --all-targets --locked --offline -- -D warnings`）退出 0。原前端大包体警告仍在。委派与模型回环使用受控端点；本轮未访问真实供应商进行自主规划/打分质量认证，未完成全书语义召回、人工金标、文学质量或 Windows 真机验收。

复用规则：后续评分始终绑定原 literal 模式报告的 contentHash，不能把已重排报告的最终 hash 当作新的基准。初次预算已裁掉的候选不能靠评分恢复；需缩小范围或重新查询，原文通道应从原游标重读。外部 `evaluate:story` 仍测字面基线，不因本协议落地而自动成为真实模型语义评估器。

实施后单人五视角复核：架构保持 Codex 模型执行与 Rust 查询权威；技术 A 的同快照摘要围栏、完整判断和整包预算已验证；技术 B 的 HTTP/Context/MCP 与 Host 回归通过；产品明确区分相关性重排与扩大召回；UX 保留错误、缺口和未认证标记。未组织独立专家评审，无新增依赖、数据库迁移或上游内核修改。
