# 对话驱动创作：目标与交付闭环

本轮范围：让智能体根据作者目标、按需读取的来源和真实保存回执决定后续行动，并在收尾时明确完成程度。不是给作者增加维护面板，也不是宣称程序能够认证文学质量。

## 职责边界

- 智能体：选择必要工具、检查相关来源、说明目标达成与缺口；授权外调整以具体建议回到对话。
- Runtime：写入权限、来源与版本校验、原子持久化、索引一致性、预算和恢复回执。
- 作者：决定新的创作方向及超出原授权的重大内容变动。

## 本轮落地

1. `read_work_status` 按稳定顺序分页，游标绑定作品、任务、版本、来源、回执状态和已选行动。智能体可读取整个任务的证据，不再局限最近三条。
2. 最终 `complete_task` 必须提交交付自检，绑定当前来源并引用所有当前有效修订成果；程序拒绝缺失、过期、跨任务或遗漏成果的引用。
3. 连续创作只在最后一章执行整次交付自检；中间章节不重复全篇检查。最终 checkpoint 检查同一决策任务已保存自检。
4. 部分完成或待作者决定以中文状态和折叠详情呈现；已执行完毕不代表作者目标全部完成。
5. 恢复提示通过真实 Runtime 回执核对消除；删除人工标记写入完成的旧入口，不重放未知写入。
6. 删除仅检查资料是否存在却显示“故事检查通过”的顶栏按钮、IPC 和 Runtime 专用接口。

五角色设计及实施记录分别见 `AGENT_DELIVERY_REVIEW_DESIGN.md`、`WORK_STATUS_PAGINATION_REVIEW.md`、`AGENT_RECOVERY_REVIEW.md`。当前契约直接切换，未增加旧版本兼容、回填、双写或降级。

## 验收边界

自检是有持久证据支撑的智能体判断，不证明文学质量，也不证明逐字阅读。测试中的受控模型旅程与真实 DeepSeek 应用验收分别记录。既有任务的未知保存状态不会被假装清除。

本轮没有把连续创作的授权范围从现有 1–3 章扩大到 100 章；百万字长期创作仍需单独验证跨批次规划、质量和成本，不能由本轮专项通过推断已经达成。
