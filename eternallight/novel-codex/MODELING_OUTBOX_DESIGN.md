# 建模意图 Outbox：保存即时、理解异步

落实 S1 保存、失效和建模之间的持久桥梁，不创建第二套 Task/Step/Attempt。Outbox 是待分析意图，不是模型执行许可。

- 每作品/main/正文对象唯一一行；正文当前选中修订变化与入队同事务。连续保存仅保留最新源，并保留首次/最后编辑时间。
- 跨来源认知依赖失效时，当前受影响对象在同一事务入队一次。未知间接影响不宣称已覆盖。
- 保存后停顿 1 秒或持续编辑窗口达到 5 秒时 due；它只是调度建议，不绕过任务 CAS、资格、预算及暂停/取消。
- 有效建模发布在原事务确认匹配来源的意图。迟到、失败或旧批次不能确认新意图；正文和历史不丢失。
- Author-only 有界分页返回来源、代次、时间和 due；游标绑定队列水位，变化后必须重新读取。单次响应使用读快照。

首个切片覆盖持久生产/合并/确认与恢复读取；现有显式建模和生成后续步骤自然确认意图。下述自动消费切片沿现有任务体系接入，不把持久待办本身称为完整 worker。`originSnapshotId` 仅为入队来源，执行时重新冻结当前输入。

验收：真实仓储/HTTP 覆盖回滚、幂等、合并、重开恢复、发布、迟到拒绝、依赖入队、跨作品隔离及分页过期；due 测试使用显式时钟。实施者按架构、事务、证据、产品恢复和状态理解五方面自检，不召集独立评审。无旧数据回填、schema 迁移或兼容逻辑。

首个切片验证：`CARGO_NET_OFFLINE=true npm run verify` 全流程通过（包括 Rust 全量测试、179 项引擎测试、2 项受控 Codex 子 Agent 集成、7 项发布门禁、131 项 Agent 测试和 9 项 UI 测试）；新增 2 项领域单元测试与 3 项仓储/HTTP 集成测试通过。Rust workspace 严格 Clippy 通过。构建仍有既存的大包体警告。验证环境为本机 macOS，受控模型回环不等同于真实供应商认证，也不证明 Windows 产品旅程或 S1–S5 完成。

## 自动消费实施方案

Runtime 以写事务把一个到期、当前来源的意图转换为既有 WorkTask/WorkStep 和建模批次；持久关联意图代次，不创建第二套执行队列。重复派发返回同一未认领步骤；认领仍通过 `/tasks` 的 Task/Attempt 事务。每来源意图最多三次模型尝试，失败阻断而非自动循环重试，作者从任务面板继续；部分写入仍须人工核对。预算在认领前核验，暂停/取消不被自动派发绕过。源变化只替代未认领且未暂停的排队任务；已运行、暂停或阻断的步骤先由当前任务控制处理，不冒充重新授权。

批次去重只约束相同源/作品修订/算法版本的有效 queued/ready 批次；stale 批次保留历史证据但不阻止当前重新建模。自动消费与显式建模均标记稳定算法版本 `novel-knowledge-v1`，不以随机任务 ID 冒充算法版本。每作品最多一个已排队或执行中的自动派发；已运行步骤的恢复与失败遵守原有任务账本。三次上限是模型任务尝试上限，不等于 token 计费；每次实际执行继续受 Agent Engine 的调用/token 预算约束。当前无自动退避重试、全作品后台消费或供应商成本估算，不伪装为这些能力已完成。

Electron 仅负责当前作品的定时唤醒，在受信页面、作者已登录、当前作品已加载、编辑器无未保存修改、已配置模型且引擎空闲时派发一项，执行复用 `runCreativeAgentTask` 和现有能力凭证、回执、恢复日记。退出登录、页面卸载、关闭窗口/退出时停止领取新任务；这不是对已认领任务的隐式取消。启动后读当前持久任务恢复未认领项。供应商未就绪或任务忙时保留待办，不生成伪造产物。界面通过原任务面板显示自动分析、暂停、取消与有限重试，不将模型候选自动采纳为 Canon。

实施前自检：架构复用单一执行体系；技术可靠性要求事务内派发与认领预算、来源代次 CAS；测试要求重复/崩溃恢复、源替代、暂停取消、次数上限和实际 Host 路径；产品要求失败可见且正文保存不受模型失败影响；UX 复用既有任务控制并显示预算阻断。此为实施者五方面自检，按作者要求不组织独立评审。无兼容层或旧数据迁移。

来源移除后的未认领步骤也按原任务账本取消，不依赖仍存在的队列关联行来识别自动任务。正在执行的尝试继续占据并发槽，即使其意图已经删除；旧来源的认领与发布仍须经过原校验。该清理只处理 running/queued 且从未认领的自动步骤，不取消作者已暂停或阻断的工作。当前 schema 的有效批次去重规则已直接调整，测试数据从空数据库创建，不提供旧数据库升级或回填。
