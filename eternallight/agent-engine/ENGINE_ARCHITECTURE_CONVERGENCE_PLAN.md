# 多模型 Codex 引擎：架构收敛与优化实施方案

日期：2026-09-20  
状态：实施中；仅“实施记录”列出的项目具有本轮验证证据。  
基线：[理想架构](IDEAL_ENGINE_ARCHITECTURE.md)、[架构对齐评审与落地计划](IDEAL_ENGINE_ARCHITECTURE_REVIEW.md)，以及本轮工作区源码和定向复现结果。

## 1. 决策与范围

保留现有架构，做边界收敛和定点重构，不再增加调度层，不重写 Codex 的 Agent 循环或原生多 Agent 系统。

本次目标：让已有模块通过唯一生产入口执行同一份契约，解决生命周期竞态、未知副作用放行、证据加载与执行配置分裂问题。模型能力、内核能力、产品能力继续分离；不同模型不要求具有相同推理质量或一次通过全部高级能力。

测试阶段直接替换旧内部接口、删除重复实现，不建设兼容层。官方 Codex App Server 接口仍按固定版本适配，保持持续合入上游主分支的能力。实施不设置人工角色评审门禁，但必须完成自动化验证和实现自查。

本文是最新评审发现的实施补充：发生状态冲突时，以实际代码和可复现报告为准，不沿用历史文档中“已完成”的判断。既有多 Agent 认证、行为评测、双平台发布待办仍然有效，本方案不替它们宣告完成。

### 实施记录（2026-09-20）

本轮已经完成并验证：准备态执行占位与撤权屏障、迟到 Session 初始化清理、`outcome-unknown` 会话阻塞、Host 生产证据快照门禁、报告内容绑定与原子发布、MCP 服务集合及子并发不可在配置阶段扩大，以及 Novel 的创作/规划评审/自由讨论/线程 review 与 compact 回合统一通过 `AgentEngineHost → CodexSessionRuntime` 执行。Novel 保留 Adapter 和 Bridge 的构造与领域回调，但不再自行装配创作回合的预算和执行租约。

本轮确定性验证：Agent Engine 123/123；Novel Agent 112/112；Novel 前端生产构建通过。真实供应商、Windows/macOS 发布和上游候选晋升不在这些数字内。

仍未完成且不得标记理想架构全面验收：MCP 可执行文件/参数和权限快照的完整 Plan 内容绑定；跨新建 Session 的通用未知写入资源级屏障；完整自治 Profile 所需的 failure/idle/cancel/recovery 独立认证；内置 EngineHost 行为执行器；双平台候选晋升与真实端点报告。因此文档总体状态仍为实施中。

## 3. 必须成立的系统约束

1. 一个 Session 只有一个生命周期所有者；一个 Run 只有一个执行权来源。
2. 准备操作在首次 await 前占位；关闭或撤权后，迟到结果不能重新激活执行。
3. 请求取消立即封锁新工作；完成取消还必须证明在途工作已停止并核对副作用。
4. 未知写入既不是成功也不是普通取消，不能通过关闭、释放 Run 或创建新会话绕过。
5. 只有实际报告、发行来源、必需断言和当前依赖都有效的证据才能授予能力。
6. 工具、权限、路由、预算和影响执行语义的配置来自同一不可变 Plan。
7. 产品只提供领域适配，不重复实现执行调度、撤权、预算和恢复。

## 4. 工作包 A：生命周期与执行权收敛

### A1. 同步占位，异步结果受代次约束

- 在调用 budgetFactory、runtimeFactory 等异步依赖前，同步登记准备记录，包含身份、代次、取消信号、初始化 Promise 和清理责任。
- 每次 await 返回后验证记录仍为当前代次、状态允许继续、未关闭且未撤权。校验失败只允许清理，不得调用下一阶段。
- 异步工厂支持接收取消信号；即使工厂不响应取消，迟到返回的资源也必须被接管并关闭。
- bindExecution 的互斥覆盖预算创建全过程；不能依赖预算创建完成后的 active 字段防重入。
- 不持有会阻止取消的长时锁等待 Provider、工具或进程操作。状态转换同步完成，清理等待异步执行。

### A2. 取消协议：先封锁，再停止，再核对

顺序固定为：记录取消与提升执行代次 → 封锁 Provider/工具新请求 → 中断 App Server 及原生子树 → 等待在途操作结算 → 核对写入回执 → 记录终态。

- 准备阶段也存在可撤销记录，没有 active turn 或 Bridge lease 不是取消错误。
- Bridge 尚未启动时记录撤权意图，后续初始化必须终止；不得先撤权再由迟到的 bind 恢复旧执行权。
- 中断 RPC 返回不等于工作已经停止。只有排空证据成立才能 markDrained，只有核对结果可追溯才能 markReconciled。
- 普通取消、客户端超时、TASK_CANCELLED 和服务端 interrupted 使用同一结算路径，不再在分支中直接标记“已排空、已核对”。
- 取消重复调用共享正在执行的撤权操作。失败时保持执行权已撤销，保留失败原因并进入待恢复状态；不能永久复用一个 rejected Promise 而没有清理/恢复入口。
- 区分“撤权已生效”和“取消已完成”。超时无法证明停止时，不返回 cancelled 成功；保留诊断、资源句柄和恢复记录，禁止发新任务。
- 预算/租约清理失败不能仅吞错。清理操作必须幂等，重复结算不重复扣费、不重复释放预留。

### A3. 关闭与迟到初始化

- closeSession 首先同步进入 closing 并使旧代次失效，之后才等待初始化与清理。
- startSession/resumeSession 的恢复、工厂和 ensure/resume 异步边界均检查状态，不能只判断 closing 而漏掉 closed。
- 未确认资源退出前不删除其所有权记录。超过关闭期限时报告清理未完成，保留受控待清理记录，迟到资源立即关闭。
- 初始化失败也必须撤销订阅并结算资源；最终不能留下不可查询的孤儿 runtime。

### A4. 未知结果与恢复屏障

- Run 保留 outcome-unknown，Session 进入 recovery-blocked，不再统一回到 idle。
- 第一版采用保守策略：阻止整个受影响会话继续；相关领域写入另由稳定 workspace/resource 标识的恢复索引阻止新 Session 绕过。
- 引擎提供通用恢复范围与核对接口，不引入小说实体；领域 Runtime 负责事务、幂等键和提交回执。
- 允许释放事件缓存，不允许通过 closeRun 删除未决副作用记录。进程重启后从持久化索引恢复屏障。
- 核对结果区分已提交、确定未提交、仍未知。确定未提交也不能自动重放非幂等操作；重试必须满足工具契约及产品授权。
- 只有未决项消除、预算恢复完成且 Plan 仍有效时才解除屏障；后续 Run 使用新租约，不复用旧执行权。
- 有写工具的 runtime 不允许默认返回“无未决项”。只读快捷路径必须由已冻结工具契约证明，不依赖调用方口头声明。

## 5. 工作包 B：可信证据加载闭环

### B1. 区分结构合法与证据可信

保留 defineEvidence 作为纯结构校验；生产 Repository 改为从受控存储加载引用，不再将任意数组自动升级为可信快照。

生产加载依次执行：

1. 从受控发布索引定位报告；校验路径边界、文件类型和大小上限。
2. 按版本化规范重算报告内容摘要，并与引用匹配；缺失、截断、篡改报告拒绝采用。
3. 校验本地受控发行记录或明确配置的发行者身份。单纯摘要相等只证明完整性，不证明报告发行可信。
4. 从报告读取断言，核对 capability、suite/version、scope、执行环境、时间和依赖；不相信旁路记录自报 passed。
5. 按能力契约检查完整必需断言集合及失败优先规则，再生成不可变快照。

初版可使用本机受控发行流程，不强制建设签名服务；同用户已完全控制发行存储不属于本机摘要机制可解决的攻击面。外部导入报告需显式信任配置，不能自动采信。

### B2. 发布、测试与失效

- 先完整写入临时报告并校验，再原子发布报告，最后发布证据引用。崩溃允许留下孤立报告，不允许接受失联证据。
- 测试专用 Repository/工厂从测试入口注入；生产入口拒绝 test-baseline-v1，而非只隐藏测试包导出。
- required assertions 由版本化契约决定，不能因记录带一个 certification 标签而跳过实际执行断言。
- 依赖采用范围限定到相关 Codec、连接、构建、suite 和有向边。新增无关模型不使旧连接失效；相关实现变化必须失效。
- 不做旧证据自动升级。新契约无法验证的历史记录标记不可采用，按需重新测量。

## 6. 工作包 C：完整冻结 SessionPlan

### C1. 计划内容

在现有连接、路由、能力和证据之外，解析并冻结：

- 工具目录：命名空间、工具名、输入 schema 摘要、读写/幂等语义、服务身份及允许工具子集。
- 权限快照：工具授权、沙箱约束、审批策略及其版本摘要。运行中审批只能在上限内缩减/授权具体操作，不能扩大 Plan。
- 预算数值：请求、token、时间、并发、深度、各作用域限额和计量缺失时的保守策略。
- 影响执行的配置：子 Agent 指令、功能开关、模型参数、服务启动定义/产物摘要及配置编译版本。

以上参与规范化 Plan 摘要。credentialRef 可进入计划，密钥值不得进入计划、配置、事件或报告。

### C2. 配置编译与运行校验

- 编译器只接受 Plan 和经过约束的运行绑定。MCP 清单、并发、权限、指令不得从额外参数覆盖。
- 临时端口、会话目录、凭据解析等绑定允许动态生成，但必须关联 Plan 中固定的服务身份；不能替换工具程序或扩大授权。
- MCP 发现阶段在不开放写操作的受控路径取得目录；生成 Plan 后对实际暴露目录再校验，并通过网关/允许列表限制工具。动态目录扩大时重新解析，不能静默新增工具。
- 子 Agent 继承权限与预算上限，只允许缩减；父子路由和工具集合均由 Plan 验证。
- UI 的可用 Profile、编译出的功能和实际工具暴露使用同一结果；通过证据但未获授权的能力不显示为可执行。

## 7. 工作包 D：唯一生产入口

目标链路：Novel IPC/领域需求 → AgentEngineHost → CodexSessionRuntime → Codex App Server + Bridge/Codec；原生子 Agent 仍由 Codex 调度。

引擎交付默认组合工厂，统一拥有客户端、Bridge、执行权、预算、恢复及进程清理。注入点仅用于凭据解析、领域 MCP、审批、回执查询、存储位置和受验证构建位置，不把状态机一致性责任交回产品。

实施顺序：

1. 用不依赖 Novel 的最小消费者验证完整启动、执行、取消、恢复及关闭。
2. Novel IPC 映射到 Host API，展示 engine 事件，不再单独推断终态。
3. 移除 main.mjs 中独立 Adapter/Bridge/预算调度以及重复恢复逻辑；保留领域事务和 UI 展示职责。
4. 集成测试验证 Novel 与最小消费者调用同一实现，不仅检查 import 文本。
5. 行为评测内置执行器复用同一 Host；命令插件保留明确证明边界，不能用输出文本声称委派代替真实 trace。

仅在 A/B/C 验收后切换生产入口。测试期无需长期双路径或兼容开关；可按独立提交回退，但同一发布版本只有一个调度入口。

## 8. 工作包 E：继续同步上游与验收证据

- 本次优先修改独立 agent-engine 和产品适配层，不在 codex-core 复制生命周期管理。
- App Server 差异集中在版本化客户端边界；确需内核补丁时登记目的、范围、对应测试及上游状态。
- 固定上游 SHA、补丁集合和构建身份；候选合入后运行协议、原生多 Agent、最小消费者和 Novel 回归。
- macOS/Windows 的关闭、取消、恢复和打包必须实测；真实供应商 smoke 与可控 Provider 内核测试分开保存。
- 候选报告失效、缺平台报告或回归失败时不晋升稳定指针；保留可验证的稳定构建。
- 完整理想架构验收还需补齐 childFailure/idle/cancel/recovery 独立证据和内置行为执行器，不能把本次六项修复视为全部能力完成。

## 10. 验收矩阵

| 场景 | 必须观察到的事实 |
| --- | --- |
| runtimeFactory/budgetFactory/Bridge start/bind 各边界取消 | 撤权后无新增执行授权；迟到资源被清理；调用有明确结果 |
| ensureSession/resume/reconcile 挂起时关闭 | 不返回成功会话；资源最终退出或明确保留清理失败记录 |
| 双重 bind、重复 cancel/close | 仅一个执行所有者，清理幂等，所有调用者得到结果 |
| Provider/MCP/原生子任务运行中取消 | 新请求被拒绝；在途请求与子树停止事实可追踪 |
| interrupt/Bridge/清理失败 | 不假报取消成功，不恢复旧权限，不永久卡住且无诊断 |
| 提交后崩溃、回执未知、重新建会话 | 未知副作用持续阻塞相关执行；无重复写入 |
| 缺报告、篡改、未授权发行、测试 suite | 生产 resolver 拒绝对应能力并返回原因 |
| 不相关模型变更、相关 Codec/suite/子路由变更 | 仅应失效的资格失效，不能全局误伤或漏失效 |
| Plan 外追加 MCP、增加并发、替换指令 | 拒绝或要求重新解析；不能沿用旧 planId |
| MCP 动态目录变化 | 未授权工具不可调用，扩展目录须新 Plan |
| 最小消费者与 Novel 同一任务 | Host 终态、审批、预算、取消与恢复语义一致 |
| 上游候选与真实模型/双平台 | 报告绑定具体构建与环境；缺必要证据不得宣告发布通过 |

测试优先采用可控 Promise 屏障、可控 Provider 和真实 App Server 集成；不用固定 sleep 制造“概率通过”。关键断言包含实际请求数、执行代次、退出确认、持久化未决项和领域回执，不只检查状态标签。
