## 后续修复与验收：Responses 流事件顺序

### 原因与设计

可复现的适配层缺陷：reasoning item 的开始/结束即时转发，但 reasoning_summary_part.added 被延迟至 EOF，导致 Codex 先清空 active item，再收到片段开始。Codex 在该非法状态下进入 error_or_panic；debug 构建会 panic，排在后面的工具未执行，认证 gate 随后超时。

修复不放宽工具校验：只允许安全事件前缀即时传递，完整支持 reasoning 生命周期事件；首次缓存事件后，所有后续事件按原顺序缓存，直到 completed 和 EOF 校验成功才释放。失败或截断不释放缓存的工具。此规则是通用 Responses 协议规则，没有针对 DeepSeek 特判。

### 回归覆盖

- 单元测试深比较完整事件序列，覆盖 reasoning 在工具之前和之后，以及失败流不能释放被缓存的后缀。
- 真实 Codex debug 二进制集成加入完整 reasoning summary 生命周期，再执行父子 Agent 的创建、通信、等待及 MCP；native/message 两种消息模式均通过（2/2）。
- 引擎回归 148/148 通过。技能测试指导促使本次补充真实执行集成，而不止解析器单元测试。
