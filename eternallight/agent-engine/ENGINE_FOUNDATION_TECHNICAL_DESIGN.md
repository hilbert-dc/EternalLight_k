# 多模型 Codex 引擎基础层技术方案

版本：1.1 · 日期：2026-09-20 · 状态：基础实现已落地，外部端点与双平台验收待执行。

本方案按“优先建设底层引擎，区分模型能力与产品能力”的最新要求制定。架构依据为本仓库源码与已有重构方案，不代表全部实现已完成，也不代表 DeepSeek 或其他真实端点已通过验证。当前工作树包含尚未完成收口的重构，不能作为已验收基线。

## 1. 目标与范围

构建一个可被多个独立产品复用的 Codex 引擎接入层：以官方 Codex 为执行内核，通过明确的协议适配、执行契约和能力证据，让不同供应商模型使用其能够正确支持的工具、上下文、原生子 Agent、取消和恢复能力。

本轮交付对象是 `eternallight/agent-engine` 及必要的通用 Codex 集成边界。Novel Codex 是第一个消费者和回归样本。生成大纲、创作评审、章节提交、Story Canon 等业务能力不进入通用引擎的目录、证据、测试任务或授权规则。

验收目标是：相同执行契约、真实能力开放、明确失败原因、可重复验证以及可持续同步上游。协议适配无法保证模型拥有相同推理水平；模型端点无法表达的语义必须报告具体缺项。

本方案优先于旧文档中的能力分层与实施优先级描述。[原重构方案](../novel-codex/MODEL_ADMISSION_AND_UPSTREAM_REFACTOR_PLAN.md) 中的诊断、隔离、上游同步原则继续有效。测试阶段直接替换旧接口和 fixture，不增加历史兼容层。

## 2. 三层能力与组合执行资格

| 层级 | 定义与示例 | 所有者 | 验证方法 |
| --- | --- | --- | --- |
| 模型能力 | 端点可以返回文本、结构化工具调用、终态、用量、多模态输入与供应商推理状态 | Provider/Codec | 协议 fixture 与真实端点探测 |
| 引擎能力 | 工具循环、调用关联、原生子任务创建/消息/等待、取消、恢复、上下文管理 | Codex 内核与通用集成层 | 固定内核构建、可控模型、真实工具的集成测试 |
| 产品能力 | 生成小说、固定多席评审、接受章节变更、领域数据提交 | 产品应用及领域 Runtime | 产品端到端测试 |

“模型具备工具调用”只是引擎运行工具循环的前提，不能证明结果回送、子任务路由、取消恢复已经正确实现。模型是否善于分解任务属于行为质量，也不等同于引擎能否执行子任务。

另行计算 **组合执行资格**：指定模型连接、适配器、内核构建、执行模式、方向性路由及权限下，哪些能力已经具备充分证据。它是解析结果，不是第四份静态能力声明。

```text
模型原语证据 + 内核执行证据 + 组合路径验证 + 当前权限/预算
                         ↓
                 冻结的 SessionPlan
                         ↓
               产品消费可用能力与事件

行为质量报告 ──→ 推荐策略/产品质量标准
```

具体规则：

- 模型目录只包含连接、模型标识、协议选项、原语支持方式和已知限制；不包含小说操作清单，也不将 `childSpawn` 声明为模型原语。
- 引擎能力目录只表达执行语义与依赖，不包含角色名称、评审席数量或生成流程。
- 产品需求由产品声明，并提交为一次请求的能力要求；通用 resolver 不识别 `generateChapter` 等业务名称。
- `native / lossless-adapted / unsupported / unknown` 描述协议支持方式。实际授权读取证据与权限，不能仅凭声明开放。
- `MODEL_CAPABILITIES` 与 `ENGINE_CAPABILITIES` 分开定义；证据 domain 由注册表推导，拒绝与输入 domain 不一致的记录。

## 3. 运行架构与所有权

```text
产品宿主（Electron / CLI / 其他客户端）
  ├─ 领域需求、凭据引用、MCP 工具、业务权限
  └─ Engine Host API
       ├─ Capability Resolver → SessionPlan / ExecutionLease
       ├─ Codex Adapter → 固定构建的 Codex App Server
       │                    ├─ 原生工具循环与上下文
       │                    ├─ 原生子 Agent 调度
       │                    └─ MCP → 产品领域工具
       ├─ Model Bridge → Protocol Codec → Provider Endpoint
       └─ 通用证据、预算、恢复回执与诊断
```

Codex 拥有 Agent 循环、工具执行和子 Agent 生命周期；适配层负责转换、边界校验、路由、预算与观测。适配层不在文本中解析伪工具调用后执行，也不建设替代 Codex 的第二套子 Agent 调度器。

协议应优先按 Responses、Chat Completions、Messages、Generate Content 等协议族实现。供应商差异使用受约束的协议选项；只有已证实的语义差异才增加实现分支。共同工具规则由引擎声明并投影为供应商支持的结构化形式，不能期待一段统一提示词替代 wire protocol 转换。

统一契约不要求删去供应商特有状态。必要的 reasoning/opaque 状态按类型保存并限制在原供应商、原会话范围内；无法保真传递时拒绝相关路径，不能伪造、丢弃后宣称等价。

## 4. 引擎能力目录

以下名称为目标契约；实施时同步替换当前目录与所有调用方。

| 引擎能力 | 必须证明的语义 | 模型前置条件 |
| --- | --- | --- |
| `toolLoop` | 合法调用进入 Codex、参数错误反馈、结果按原 callId 进入后续请求、终态正确 | 文本与结构化工具调用 |
| `childSpawn` | 真实创建子线程，父子身份、深度、资源限额正确 | 工具循环 |
| `childMessageRunning` | 向运行中子任务投递；区分入队、消费与执行 | 工具循环、子任务创建 |
| `childFollowupIdle` | 已空闲子任务可按 Codex 当前契约开启新轮次 | 工具循环、子任务创建 |
| `childWait` | 等待正确目标，区分完成、失败、取消、超时 | 工具循环、子任务创建 |
| `childFailure` | 子失败可被父任务观察，不伪装为成功或永远等待 | 子任务创建、等待 |
| `childCancelTree` | 取消传播到子树和进行中的请求；不再启动新工作 | 子任务创建、宿主取消 |
| `childRecovery` | 重连/重启后核对已有状态，保留未知副作用 | 持久化记录、回执核对 |
| `directedChildRoute` | 仅允许已授权 A→B；A→A、B→A 分别处理 | 对应父子连接路径验证 |
| `contextLifecycle` | 增量历史、工具关联、上下文上限和受支持的压缩行为 | 对应模型协议支持 |

组合 profile 展开成具体依赖。文本请求不强制要求工具；基础工具任务不强制要求子 Agent。基础委派可要求 spawn/wait/失败传播/取消及对应路由，运行中消息、空闲续跑、恢复按请求需要增加。不得因为一项独立能力未通过而一并撤销已验证的无关能力。

当某个 Codex 特性开关同时暴露多项工具时，编译器必须要求整组能力具备执行资格，或使用经过测试的上游工具过滤接口限制暴露。不能只开放半组证据却暴露全部工具。

## 5. 证据契约与依赖范围

沿用现有证据存储与 resolver，调整记录契约，避免维护互不一致的第二套授权系统。

| 记录 | 关键内容 | 是否直接授权执行 |
| --- | --- | --- |
| ConnectionStatus | 访问结果、凭据范围、时间、认证/限流/网络分类 | 用于当前访问约束 |
| ModelEvidence | 模型原语、协议参数、转换保真、终态断言 | 授权对应原语 |
| EngineEvidence | 固定构建下工具/生命周期的实际观测断言 | 授权对应执行能力 |
| RouteEvidence | 父子连接、适用引擎构建、路由与身份断言 | 授权精确有向边 |
| BehaviorEvaluation | 任务集、评分器、样本、质量、延迟、用量来源 | 不直接授予执行权限 |

能力证据至少包含 `capabilityId/domain/status/scope/suiteId/suiteVersion/assertions/dependencies/checkedAt/expiresAt/reportRef/supersedes`。状态区分 passed、failed、unsupported、unknown、not-run；真实失败与没有测量不能混为一谈。

依赖应可解释：

- 协议证据绑定连接定义、模型版本（供应商不可固定时记录这一限制）、Codec 版本及配置、原语契约；不因新增无关模型或修改产品 UI 全部失效。
- 内核证据绑定 source tree、补丁集、工具契约、工具链、平台/架构与实际二进制 BuildIdentity。
- 组合证据同时引用模型与内核依赖；真实端点 smoke 只证明覆盖到的条件。
- 行为证据绑定任务集、提示词、模型设置、评分版本、预算与上述运行依赖。
- 凭据或权限变化触发访问重验；历史执行结论可保留，但不能给新凭据自动续签当前执行租约。

每项通过能力可独立保留。失败有明确范围与替代关系，旧成功不能覆盖新失败；同一连接可以同时拥有基础能力通过、某条子路由失败、恢复未运行的记录。摘要用于完整性验证，发布者可信性由受控构建、签名和分发流程提供。

## 6. 单一解析与宿主接口

目标宿主 API 包含 `inspectConnection`、`qualifyCapabilities`、`resolveSession`、`startTurn`、`cancelRun`、`resumeSession` 和事件订阅。接口具体签名随实施测试确定；名称不代表已经提供。

`resolveSession` 接受连接引用、required/preferred 能力、允许的有向边、工具授权、预算和有效证据，输出不可变计划：模型路由、可执行能力、可暴露工具、缺失能力、证据引用、依赖摘要、有效期及预算约束。

宿主、配置编译器和 Bridge 使用同一计划。不得由 UI 根据模型名重新推断支持能力；也不得在任务中途通过可变全局配置悄悄增加能力或切换模型。需要扩展权限或路径时，在新轮次开始前解析新计划。

执行租约绑定 run、计划与代次；取消/撤销后阻止后续请求。usage 缺失时使用有依据的保守预算预留与结算，并显示估算来源；无法建立硬限制的路径应拒绝执行。

产品向引擎注入领域工具与约束，并自行验证领域提交完成。引擎验证协议和执行完成，不把“模型结束回复”等同于“章节已保存”。

## 7. 测试、行为评估与失败归因

验证分四层，每层单独出报告：

1. **Codec 契约测试**：可控输入、流分片、工具 schema、namespace、callId、错误与终态；验证四类协议。
2. **真实内核确定性测试**：真实 Codex + 可控 Provider + 真实测试 MCP；验证工具循环、并发、生命周期、身份、取消与恢复。
3. **真实端点能力 smoke**：验证指定连接的实际组合路径；模型未选择工具时记录未观察到该能力，不能单凭此推断内核故障。
4. **开放行为评测**：任务描述、事实与约束，不写死 spawn/send/wait 顺序；分别评估明确要求委派和自主判断委派的任务组。

内核测试必须用受控响应和可观测状态屏障建立确定的事件顺序。比如先确认子任务处于运行状态、父消息入队，再释放工具返回；不能用固定 sleep 假设消息已消费。真实端点 smoke 保留模型选择带来的不确定性。

`qualify:model` 形成能力报告和部分准入结果；`evaluate:model` 执行版本化任务集并生成独立质量报告。仅统计已有样本文件的脚本属于报告工具，不能作为开放评测执行器已落地的证明。35 次与 Wilson 下界仅作为可选质量策略，不能充当通用执行门槛。

诊断按以下链路记录：工具提供 → 合法调用 → Codex 接受 → 工具返回 → 结果进入后续输入 → 模型利用 → 正确终态。

| 失败 | 判定依据 |
| --- | --- |
| `tool-not-exposed` | 对应请求确实未提供所需工具 |
| `tool-not-selected` | 提供了工具，但模型没有发出调用 |
| `invalid-tool-arguments` | 结构化参数未通过工具验证，记录反馈与修正情况 |
| `transport-result-missing` | 有明确返回及 callId，但预期后续请求缺少其结果 |
| `result-consumption-failed` | 结果已送达，模型未满足任务事实或约束 |
| `lifecycle-failed` | 状态转换、等待目标或取消传播不符合契约 |
| `inconclusive` | 关键关联丢失、观测窗口不完整或 trace 截断 |

关联使用 run/thread/parent/turn/request/call/connection。父回复未复述 receipt 不能直接证明交付失败；MCP 写了 proof 文件也不能直接证明父模型收到了结果。工具返回、子模型输入、wait 输出进入父输入分别验证。未知写入结果核对回执，禁止盲目重放。

## 8. 工程边界与目录收口

```text
eternallight/agent-engine/
  src/contracts/       模型原语、引擎能力、证据与宿主契约
  src/codecs/          协议转换和供应商状态保真
  src/connections/     连接规格与凭据引用
  src/session/         解析、计划、Codex 配置编译
  src/host/            通用 Codex App Server 接入与执行宿主
  src/bridge/          请求路由、限额、租约与转换
  src/capabilities/    能力探测、证据、准入报告
  src/state/           预算、回执与恢复记录
  src/observability/   有界关联事件与诊断
  tests/               协议与内核执行测试
  qualification/       通用测试 MCP、smoke、开放评测任务与评分
```

这是目标目录。当前 `novel-codex/electron` 中的通用 adapter、conformance runner 与测试 MCP，应在先清除业务依赖后迁入引擎。Novel Codex 保留窗口 IPC、作品 Runtime、领域 MCP、产品操作要求与 UI。引擎不得反向 import Novel Codex，也不使用 `NOVEL_CODEX_*` 作为公共配置契约。

纯迁移和契约行为变更分批审查，迁移时一起移动测试。内部通用包可以直接暴露当前稳定边界；无需为了名义上的独立产品复制 Codex 源码或重新实现其生命周期。

## 9. Codex 上游持续合入

保留完整 Fork 与共同 Git 历史：`origin` 指向 EternalLight 产品仓库，`upstream` 指向官方 `openai/codex`。日常在独立候选分支 merge 官方 main，产品运行绑定已经验证的内核产物。

同步事务：记录已提交的产品基线 → fetch 并固定目标 SHA → 创建 `codex/upstream-sync-<date>-<sha>` 与隔离 worktree → merge 确定 SHA → 记录冲突与接口影响 → 重建并测试 → 形成候选报告 → 验证通过后晋升。

当前工作区未提交变更不自动纳入候选。发生冲突保留候选状态与诊断；产品主分支前进后，需要对新整合结果重新验证。同步工具不自动 stash/reset，也不自动用目录级 ours/theirs 解决冲突。

必要内核补丁登记 ID、动机、上游基线、路径/符号、差异指纹、测试、依赖语义与删除条件。现有 MCP 父子身份补丁按此登记。边界校验必须验证实际差异，不能仅把整个 Rust 文件加入白名单；缺上游 ref 必须失败。上游已有等价能力时先验证再删除本地补丁。

候选报告绑定基线 SHA、上游 SHA、候选 tree、补丁集及平台 BuildIdentity，覆盖 App Server、工具事件、MCP 身份、生命周期、模型请求、配置/schema 与依赖变化。macOS 和 Windows 分别运行真实执行与进程 smoke；单平台通过不授权另一平台。

## 10. 实施顺序与完成标准

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| P0 契约收口 | 三层能力分离、产品字段移出模型目录、依赖图及单一 resolver | 模型声明不能授予引擎能力；未测能力明确缺失；业务名称不进入通用契约 |
| P1 基础执行 | `toolLoop`、结果关联、终态、预算及取消 | 真实 Codex 与可控 Provider 下，成功/参数错误/断流/取消路径可重复通过 |
| P2 原生子 Agent | spawn、消息、idle 续跑、wait、失败、取消树、有向路由 | 生命周期逐项测试；A→B 不开放 B→A；取消后无新增请求 |
| P3 恢复与证据 | 依赖范围、部分准入、回执核对、失效/撤销 | 新失败不会被旧成功覆盖；未知副作用不重放；平台构建变化正确失效 |
| P4 通用工程边界 | adapter/runner/MCP 迁入引擎，准入与评测 CLI 分离 | 引擎无产品反向依赖；可用中性任务完成验证；开放评测不更改执行授权 |
| P5 上游同步 | 补丁登记、固定 SHA 候选、影响报告、双平台门禁 | 缺 ref/未登记差异/冲突/候选变化都有确定处理与证据 |
| P6 真实接入验收 | DeepSeek 与第二协议连接的能力 smoke、独立行为报告 | 真实路径逐项出结论，未通过项保留原因；产品仅做消费接口回归 |

每阶段以可运行、可审查的增量合入，复杂逻辑尽量控制在 500 行内，普通非机械变更不超过 800 行。上游 Rust 补丁单独审查。测试与文档同步更新，不用文档勾选代替行为证据。

当前实现已经完成三层能力拆分、`toolLoop` 独立认证、协议 Codec、Bridge、冻结计划、租约/预算/取消、恢复记录、证据依赖、通用 App Server 客户端、开放评测执行器、补丁登记与固定 SHA 候选同步。基础工具循环失败会阻止子 Agent 认证继续执行，并保留失败证据。

仍需通过外部条件验收的项目不在代码中伪造完成状态：真实 DeepSeek 与第二协议端点 smoke、`childFailure`/idle follow-up/recovery 的逐项真实内核认证、Windows 构建与进程 smoke。当前委派认证覆盖 spawn、运行中消息、wait 和有向路由；取消传播已有真实集成回归，但尚未发布为独立连接能力证据。Novel Codex 中的两个认证场景编排器和测试 MCP 仍是待迁移的通用代码，已先移除其产品依赖并改用本包的 App Server 客户端。

## 11. 最终交付物

最终交付由通用引擎包、版本化能力契约、内核执行报告、真实连接能力矩阵、独立行为报告、上游候选报告和 macOS/Windows 构建报告组成。产品功能文档单独维护。

判断底层引擎是否达标的依据是：不同协议的模型能通过相同宿主接口使用已验证的 Codex 能力；能力限制有准确来源；执行路径可观测、可取消、可恢复；升级上游后可以重新构建和验收。

## 12. MCP 启动生命周期契约

工具就绪与模型协议适配是独立边界。任务必需工具不能按可选后台服务启动，
否则模型请求可能先于工具注册，导致缺失工具、供应商错误与后续重试。

通用 Rust 配置编译器接收每个 MCP 服务的 `required`（布尔，缺省 false）
和 `startupTimeoutMs`（可选整数，范围 1–300000 毫秒），分别生成 Codex
原生 `required` 与 `startup_timeout_sec`。非法类型或越界值直接拒绝。
缺省 false 表示业务主动允许可选服务，不作为旧接口兼容分支；必需服务
由调用产品显式选择，不能由模型名称决定。

就绪屏障使用 Codex 原生必需 MCP 初始化检查，不复制内核调度、增加工具
轮询或改动上游源码。宿主握手、会话创建及恢复使用独立有界启动期限，
普通 RPC 保持普通期限。必需工具失败应在进入模型执行前明确返回，不能
通过增加模型额度或无限重试掩盖。

Novel 将工作区 MCP 配置为必需，启动期限 90 秒。实际生产桌面在 31 秒
MCP 延迟下仍仅产生 2 次脚本模型请求；启动失败产生 0 次模型请求、预算
确认与执行 Attempt。详细复现及验证边界见 Novel 的持续创作验收第 21 节。

## 13. Metering-only 执行策略

任务账本默认只计量。请求、token、持续时间限额为可空值，null 表示对应
维度不设额度上限，而不是缺失执行授权。明确提供的正数限额用于有界认证
和测试；非法数值拒绝。产品的持久 grant 则要求这些字段显式存在。

进程内与进程外模型桥都传递 null duration，不通过 `Date.now() + null`
制造立即过期的任务。App Server 普通回合默认无总时长计时器，启动和 RPC
仍使用各自的请求期限。账本继续记录 reservations、unknown usage、receipt
和终态恢复；无额度不等于无限重试或不记录费用。

执行租约缺省不额外限制为 30 分钟，仍受认证 SessionPlan 的有效期和 epoch
撤销约束。Host 的 `renewRun({ runId, sessionPlan })` 接受同进程可信 resolver
生成的同 scope 新计划，只允许证据及有限有效期更新；不改执行身份、epoch、
预算和定向路由。Runtime 与两种 Bridge 校验后回执，迟到撤销或不确定 IO
使续期失败并阻止旧会话复用。终态不续期，明确 deadline cap 仍保留。
不能直接修改旧证据有效期，也不能复活已经过期的租约。
Novel 的任务 capability 有效期属于另一个权限边界，不与用量额度混用。
