# 独立 Rust 引擎迁移

更新时间：2026-09-23。

目标：引擎迁入本目录的独立 Cargo workspace，不依赖或修改上游 codex-core。保留上游 Codex CLI/App Server 的持续同步边界。Electron/React 和小说业务 Runtime 不在迁移范围。

用户选择单人实施，不启用子 Agent，不组织角色评审。按测试技能补充实际接口和失败路径验证；按变更规模技能分批验收，不把整个迁移作为一个不可审阅的提交。

## 当前状态

引擎的协议、传输、预算、会话生命周期、取消清理、恢复协调与资格认证控制流程已迁入独立 Rust workspace。JavaScript 保留 Node/Electron 宿主句柄、Promise、外部回调与接口封送；产品 UI 和小说业务 Runtime 不在此次迁移范围。此次验收覆盖本地 macOS 与受控供应商夹具，跨平台发布和真实供应商在线认证需另行验收。

## 调用与所有权

独立 workspace 包含：

- `native/engine-core`：协议、流解析、预算、授权、租约等引擎规则。
- `native/stream-guard`：Open → Terminal → Closed 的提交库。
- `native/node-binding`：Node-API cdylib，只作有界参数转换和对象生命周期适配。

`src/native.mjs` 按 platform/arch 加载 `native/bin/<platform>-<arch>/engine.node`，没有 JS 引擎规则 fallback。Node-API 不依赖具体 Node/Electron V8 ABI，但目标 OS/arch 仍须分别构建。

预算、执行授权、路由谱系、执行轨迹、RPC 待处理表、回合、评测、恢复日志和流对象的权威状态留在 Rust。JS 获取的是序列化快照，不允许通过修改快照替换活跃状态。工具目录等请求数据按调用序列化；它们不是独立的授权来源，执行准入仍由 Host/租约控制。

证据入口不再使用 WeakSet 真值标记：每个公开记录/快照关联一个不可变原生所有者，能力选择从原生持有的记录读取，而非调用方传回的快照。报告导入的引用、内容摘要及记录字段绑定由 Rust 复核。注册入口依然是宿主内部可信 API，Node-API 不是对恶意宿主代码的进程安全隔离；不能把内部类构造器开放给模型或不可信插件。

`stableJson` 与 SHA-256 均由 Rust 计算，使用确定性 JSON 键顺序；JS 仅做标准 JSON 参数封送。对象 undefined 字段被省略，数组中的 undefined 归一化为 null。没有旧摘要算法 fallback，不额外添加摘要前缀；普通 JSON 的随包认证清单已通过实际加载回归，但不承诺任意旧 JS 特殊值摘要仍一致。认证采用仍必须匹配当前引擎构建指纹，不能据此绕过重新认证。

新增 Rust 模块按持久化、准入、会话、诊断及认证拆开；不往上游 codex-core 添加迁移逻辑。提交时应按这些可独立验证的阶段拆分，本次没有自动提交工作区。

未提交变更可按协议与网络、预算与恢复、Host 生命周期、资格认证、宿主绑定五组审阅。Rust 控制决策与 JavaScript 宿主回调配套提交，避免拆出无法编译或无法运行的中间版本。

后续追加三个独立阶段：本地 Hyper 监听与响应适配；认证 MCP 与委派证明；规范摘要与原生证据所有者。各阶段有独立模块和集成测试。新增 Hyper server/Tokio macros 依赖只在独立 workspace 的 Cargo.toml/Cargo.lock 中，不改上游 Cargo/Bazel 依赖图。

先前每个 Responses 流一个 JSONL 子进程只是迁移桥接，现已删除其源入口和 JS IPC 实现。构建脚本清理本包旧的生成助手二进制，只发布当前动态库。删除引擎对 Ajv/js-tiktoken 的依赖；小说产品自己的依赖不受影响。

## 保持的安全语义

- 工具名必须来自当前请求目录，保留 namespace、call id、schema 与 tool choice 检查。
- Responses 在终态一致且 EOF 到达前，不放行缓存的工具项；失败、截断、矛盾终态或取消丢弃待提交内容。
- Chat Completions 必须收到合法 finish reason 和 [DONE]，再于 EOF 提交工具。
- 不把无法保真转换的加密/签名推理状态当作普通文字。
- SSE 总字节限制、流事件缓存限额、原生入口长度限制保留；单个坏流不能污染其他流。
- 预算预留幂等结算；未知消耗不返还额度。撤销不可由快照回写恢复，取消终态要求先排空及对账。
- 本阶段修复无效租约时间的 fail-open：不可解析的时间明确拒绝，而不是依赖 NaN 比较。
- 持久预算用 OS 文件锁区分活跃所有者与崩溃遗留实例；恢复不会结算仍活跃的预算。数据库写入失败后实例拒绝继续执行。
- 恢复文件跨实例串行更新；批量对账任意一项失败，不写入部分结果。空回执不能解除未知写入阻塞；损坏记录返回错误而不是 panic。
- 恢复报告使用持久化顺序号保持创建顺序，不依赖 Rust 对象键排序；未知写入仍需真实回执或显式人工处置。
- 能力与认证套件之间若没有定义必需断言，返回 unsupported-suite，不能因空断言集合而通过。
- wait 返回完成与子 Agent 的 FINAL_ANSWER 是独立证据，不能相互替代；密文与工具参数不计为消息可见证据。
- 报告文件名的时间戳须通过解析，避免把路径片段带入文件名；读写分别有字节上限，摘要校验仍在绑定入口完成。
- App Server 子进程使用显式环境、无 shell 启动；JSONL 行、待写队列与事件队列均有上限。关闭保持 stdin 存活直到终止流程结束，避免绕过子进程的优雅退出逻辑；超时后强制终止并回收当前子进程。未声明具备通用后代进程树清理能力。
- RPC 超时使用单调时钟；旧进程响应、旧回合事件和子线程文本不能完成当前请求。回合启动晚于取消时，仍必须发送中断。
- HTTP 默认不跟随重定向、不继承系统代理配置；使用 rustls 公共根证书。自定义代理/CA 尚未提供配置入口，不能宣称这方面与所有原客户端完全等价。
- HTTP 全局最多 128 个在途交换，每个交换使用 8 槽、每片最多 16 KiB 的交付队列；消费者减速会暂停读取。累计响应上限 32 MiB，配置可收紧；取消丢弃任务，超时覆盖响应头和响应体。
- 行为任务上限 10,000 个样本、结果 16 MiB；样本只允许单个在途、只结算一次。预算超支不能报告通过，评测结果仍不授予任何能力。
- 恢复日志只在持久化成功后更新状态；失败允许重新提议同一动作。缺失权威回执的写入保持 uncertain；Host 完成事件不使整个 run 终态化。
- 协议探测按有界、去重的协议列表单次推进。401/429 封闭当前认证会话；不能因错误消息提到 tool_choice 而继续重试。仅 400/422 的明确工具选择不支持错误允许一次去强制选择重试。
- 流式探测解析 403 的认证错误标记；认证失败撤销本次协议探测结果，不降为 streaming unknown。流和普通响应遵守同一配置字节上限，工具往返要求恰好一次且参数完整匹配。
- 探测诊断在进入证据前过滤本次传入密钥的原文，并限制长度；原生 HTTP 超时以 TimeoutError 传到探测分类边界。
- Host 关闭/恢复阻塞不会被迟到的准备回调解除；非当前 run 不能清除 session 的活跃运行。取消失败状态不会被普通运行事件覆盖；终态更新前先校验运行转换，再结算授权状态。
- Host 事件每项参数最多 256 KiB，回放同时受条数及 16 MiB 总字节限制；过期游标明确拒绝，返回的快照不能回写权威状态。
- Bridge 原生进程启动为单次共享操作；关闭等待延迟凭证解析并回收实际子进程。父端 RPC 绑定进程 generation，双向请求有原生容量与时间上限；旧进程消息不能完成新进程请求。worker 的 JSONL 读写与控制循环由 Rust 管理；Node 入口加载动态库，当前未发布独立 worker 可执行文件。
- 恢复协调候选最多 10,000 条且总量最多 8 MiB，拒绝重复或外部 run 的请求身份。未确认持久化成功不推进下一操作；完成前重新查询未知操作，缺失回执不能报告 committed。
- Bridge 策略的子请求计数由 Rust 保存，最多 10,000 个子线程，失败授权不消耗阶段；新租约清空旧执行阶段。命名空间工具、强制工具选择和完成后的禁用工具统一判断。
- SessionRuntime 拒绝绑定期间和重复的回合发送；错误发送不能清理其他正在执行的回合。原生 generation 隔离迟到回调，取消后的迟到获取仍进入清理清单；清理失败必须关闭运行时，不允许继续绑定。
- Bridge 崩溃后的预算恢复写入失败不阻断 RPC 拒绝，也不解除重启限制；显式结束预算时等待先前恢复尝试并重试持久化，失败仍保持阻塞。
- 本地监听最多 128 个连接，合法请求并发可在 1–128 内配置；头部读取超时 10 秒，上传有独立截止时间和最多 4 MiB 可配置上限。监听只绑定 127.0.0.1；认证失败不交付宿主。
- 响应使用 8 槽原生队列、每个响应总量最多 32 MiB；JS 适配的待写缓存同样有 32 MiB 限额。取消已发送响应头的流会产生 HTTP 传输错误，而不是正常 EOF，避免误提交已缓存工具。取消未完成上传释放并发槽但不关闭监听端口。
- 原生 MCP 每行最多 1 MiB、轨迹有大小限制，错误不泄露令牌或文件细节。gate 与 echo 必须是同一可信子身份，其他子线程即使持有相同 follow-up 也不能取得回执；回执文件原子写入。

## 构建、身份与平台

`npm run build:native` 构建 Rust release 动态库并内容比较、原子替换。开发、应用测试、认证和 staging 前自动构建。ASAR 外加载动态库，不打包 target 目录。

资格上下文摘要和发布 manifest 改为绑定实际 `engine.node`，不是已退役助手程序。任何引擎动态库变更都会使旧认证失效。

CI 的 Linux/macOS/Windows job 运行 Rust 测试及 Node-API 协议、流、授权测试。当前仅本地 macOS 实测，不能声明 Windows/Linux 已验收。

## 本地整体验收（2026-09-23）

验收范围是独立引擎、Novel Codex 应用接入和受控真实 Codex 工具/多 Agent 链路。测试状态见 [VALIDATION_REPORT.md](VALIDATION_REPORT.md)。

本次整体验证发现 Responses 完成事件的 token 用量被 Rust 序列化为浮点数（例如 20.0），而上游 Codex 消费整数。这导致 Chat Completions、Messages 和 Generate Content 三条真实工具循环失败。修复统一规范响应中的计数序列化，并增加直接按整数结构反序列化的 Rust 回归测试，防止 JavaScript 的数值类型掩盖线协议差异。

仍保留以下交付边界：

- JavaScript 宿主层及测试夹具仍存在，不将本项目描述为无 Node 依赖的独立 Rust 应用。
- 本次没有 Windows/Linux 实机打包验收，没有新增 DeepSeek 在线认证。
- 当前动态库变更仍需要重新生成对应构建指纹的在线能力认证；本地测试不能替代该证据。
- 现有前端大包警告和 Python 测试数据库未关闭警告记录于验收报告，未在引擎迁移中扩大范围修改。
