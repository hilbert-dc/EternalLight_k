# 独立 Rust 引擎迁移

更新时间：2026-09-21。

目标：引擎迁入本目录的独立 Cargo workspace，不依赖或修改上游 codex-core。保留上游 Codex CLI/App Server 的持续同步边界。Electron/React 和小说业务 Runtime 不在迁移范围。

用户选择单人实施，不启用子 Agent，不组织角色评审。按测试技能补充实际接口和失败路径验证；按变更规模技能分批验收，不把整个迁移作为一个不可审阅的提交。

## 当前状态

**协议、持久化、准入、会话编译、供应商 HTTP 传输、App Server 进程通信、评测调度与恢复日志状态已迁入 Rust；本地 Bridge 监听、worker IPC 与 Host 上层异步调度仍未完成。整个引擎尚未全部 Rust 化。**

| 模块 | 实现及状态 |

## 调用与所有权

独立 workspace 包含：

- `native/engine-core`：协议、流解析、预算、授权、租约等引擎规则。
- `native/stream-guard`：Open → Terminal → Closed 的提交库。
- `native/node-binding`：Node-API cdylib，只作有界参数转换和对象生命周期适配。

`src/native.mjs` 按 platform/arch 加载 `native/bin/<platform>-<arch>/engine.node`，没有 JS 引擎规则 fallback。Node-API 不依赖具体 Node/Electron V8 ABI，但目标 OS/arch 仍须分别构建。

预算、执行授权、路由谱系、执行轨迹、RPC 待处理表、回合、评测、恢复日志和流对象的权威状态留在 Rust。JS 获取的是序列化快照，不允许通过修改快照替换活跃状态。工具目录等请求数据按调用序列化；它们不是独立的授权来源，执行准入仍由 Host/租约控制。

证据入口中的 WeakSet 可信来源登记以及现有 `stableJson`/SHA-256 摘要边界仍在 JS；Rust 接收的是经过入口检查的记录及摘要。不能把这部分称为已经完全原生化的证据信任链。后续迁移必须一并处理摘要格式与可信句柄，不能直接用另一个 JSON 序列化器替换并假设历史摘要不变。

新增 Rust 模块按持久化、准入、会话、诊断及认证拆开；不往上游 codex-core 添加迁移逻辑。提交时应按这些可独立验证的阶段拆分，本次没有自动提交工作区。

先前每个 Responses 流一个 JSONL 子进程只是迁移桥接，现已删除其源入口和 JS IPC 实现。构建脚本清理本包旧的生成助手二进制，只发布当前动态库。删除引擎对 Ajv/js-tiktoken 的依赖；小说产品自己的依赖不受影响。

## 保持的安全语义

- 工具名必须来自当前请求目录，保留 namespace、call id、schema 与 tool choice 检查。
- Responses 在终态一致且 EOF 到达前，不放行缓存的工具项；失败、截断、矛盾终态或取消丢弃待提交内容。
- Chat Completions 必须收到合法 finish reason 和 [DONE]，再于 EOF 提交工具。
- 不把无法保真转换的加密/签名推理状态当作普通文字。
- SSE 总字节限制、流事件缓存限额、原生入口长度限制保留；单个坏流不能污染其他流。
- 预算预留幂等结算；未知消耗不返还额度。撤销不可由快照回写恢复，取消终态要求先排空及对账。
- 本阶段修复无效租约时间的 fail-open：不可解析的时间明确拒绝，而不是依赖 NaN 比较。
- 持久预算用 OS 文件锁区分活跃所有者与崩溃遗留实例；恢复不会结算仍活跃的预算。数据库写入失败后实例拒绝继续执行。
- 恢复文件跨实例串行更新；批量对账任意一项失败，不写入部分结果。空回执不能解除未知写入阻塞；损坏记录返回错误而不是 panic。
- 恢复报告使用持久化顺序号保持创建顺序，不依赖 Rust 对象键排序；未知写入仍需真实回执或显式人工处置。
- 能力与认证套件之间若没有定义必需断言，返回 unsupported-suite，不能因空断言集合而通过。
- wait 返回完成与子 Agent 的 FINAL_ANSWER 是独立证据，不能相互替代；密文与工具参数不计为消息可见证据。
- 报告文件名的时间戳须通过解析，避免把路径片段带入文件名；读写分别有字节上限，摘要校验仍在绑定入口完成。
- App Server 子进程使用显式环境、无 shell 启动；JSONL 行、待写队列与事件队列均有上限。关闭保持 stdin 存活直到终止流程结束，避免绕过子进程的优雅退出逻辑；超时后强制终止并回收当前子进程。未声明具备通用后代进程树清理能力。
- RPC 超时使用单调时钟；旧进程响应、旧回合事件和子线程文本不能完成当前请求。回合启动晚于取消时，仍必须发送中断。
- HTTP 默认不跟随重定向、不继承系统代理配置；使用 rustls 公共根证书。自定义代理/CA 尚未提供配置入口，不能宣称这方面与所有原客户端完全等价。
- HTTP 全局最多 128 个在途交换，每个交换使用 8 槽、每片最多 16 KiB 的交付队列；消费者减速会暂停读取。累计响应上限 32 MiB，配置可收紧；取消丢弃任务，超时覆盖响应头和响应体。
- 行为任务上限 10,000 个样本、结果 16 MiB；样本只允许单个在途、只结算一次。预算超支不能报告通过，评测结果仍不授予任何能力。
- 恢复日志只在持久化成功后更新状态；失败允许重新提议同一动作。缺失权威回执的写入保持 uncertain；Host 完成事件不使整个 run 终态化。

## 构建、身份与平台

`npm run build:native` 构建 Rust release 动态库并内容比较、原子替换。开发、应用测试、认证和 staging 前自动构建。ASAR 外加载动态库，不打包 target 目录。

资格上下文摘要和发布 manifest 改为绑定实际 `engine.node`，不是已退役助手程序。任何引擎动态库变更都会使旧认证失效。

CI 的 Linux/macOS/Windows job 运行 Rust 测试及 Node-API 协议、流、授权测试。当前仅本地 macOS 实测，不能声明 Windows/Linux 已验收。

## 剩余实施顺序与验收

1. **本地 Bridge 与 worker**：供应商 HTTP 已迁移；剩余本地 listener、worker IPC、租约与预算回调编排。完整保留取消排空、认证撤销、未知预算和消费者背压测试，不把仅替换网络调用当成整个 Bridge 迁移完成。
2. **恢复协调**：持久化、HostRecoveryJournal 状态及回执校验已迁移；剩余 RecoveryCoordinator 的跨组件协调和产品回调适配。不要把领域回执识别硬编码进通用引擎。
3. **可信句柄及 Host 生命周期**：会话编译、证据规则、进程通信、RPC 和回合已迁移；剩余可信来源登记、摘要序列化、EngineHost/CodexSessionRuntime 和初始化编排。继续保留上游同步边界。
4. **资格探测调度**：评分、认证校验、诊断、行为调度、命令执行及网络传输已迁移；剩余 CapabilityVerifier 探测策略与 qualification runner/MCP。保留用户自定义回调边界，不放宽断言，不把 wait 返回误当作子任务完成。
5. **交付验收**：删除被替换的 Node 引擎业务代码；跨平台打包与真实供应商重新认证。最终未通过项必须明确保留，不能把“编译成功”称为“全部迁移完成”。
